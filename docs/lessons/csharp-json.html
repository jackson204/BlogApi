C# 補充：JSON（格式、轉成物件、轉成 Dictionary）

JSON 是 API 來回傳資料用的文字格式。這頁講它的寫法、C# 物件與 JSON 怎麼互轉、名字大小寫對不上時為什麼不報錯、少欄位與型別不對各會怎樣、時間的格式，以及不想寫類別時怎麼轉成 Dictionary。

1. JSON 的格式

JSON 是一段文字，用固定的寫法描述資料。API 的請求與回應、設定檔（appsettings.json）都是它。

{
  "Id": 5,
  "Customer": "小華",
  "Paid": true,
  "Note": null,
  "Total": 285.5,
  "OrderedAt": "2026-10-15T09:30:00+08:00",
  "Items": [
    {
      "Name": "可樂",
      "Quantity": 6
    },
    {
      "Name": "餅乾",
      "Quantity": 2
    }
  ]
}
JSON 的寫法名稱例子C# 對應的型別
{ "名字": 值, … }物件最外層那一對大括號class，或 Dictionary
[ 值, 值, … ]陣列"Items": [ … ]List<T>、陣列
"文字"字串"小華"string；時間也是用字串表示
285.5、5數字"Total": 285.5int、decimal…
true、false布林"Paid": truebool
null沒有值"Note": nullnull
  • 名字一定要用雙引號包起來，後面接冒號
  • 每一項之間用逗號分隔，最後一項後面不能有逗號
  • 字串用雙引號，不能用單引號；數字、true、false、null 不加引號。"5" 是字串，5 是數字，兩者不同
  • 可以一層包一層：物件裡放陣列，陣列裡放物件
  • JSON 沒有「日期」這種型別，時間是用字串寫的，格式是雙方的約定

2. 物件轉 JSON

using System.Text.Json;

var order = new Order
{
    Id = 5, Customer = "小華", Paid = true, Note = null, Total = 285.5m,
    OrderedAt = new DateTimeOffset(2026, 10, 15, 9, 30, 0, TimeSpan.FromHours(8)),
    Items = [new Item { Name = "可樂", Quantity = 6 }, new Item { Name = "餅乾", Quantity = 2 }],
};

string json = JsonSerializer.Serialize(order);

class Order
{
    public int Id { get; set; }
    public string Customer { get; set; } = string.Empty;
    public bool Paid { get; set; }
    public string? Note { get; set; }
    public decimal Total { get; set; }
    public DateTimeOffset OrderedAt { get; set; }
    public List<Item> Items { get; set; } = new();
}

class Item
{
    public string Name { get; set; } = string.Empty;
    public int Quantity { get; set; }
}

結果就是上一節那段 JSON（上一節為了好讀有換行與縮排）。規則很單純：屬性的名稱變成 JSON 的名字，屬性的值變成 JSON 的值。

預設的輸出有兩個地方和想像的不一樣：

Console.WriteLine(JsonSerializer.Serialize(new { Name = "可樂" }));
// {"Name":"\u53EF\u6A02"}      ← 不換行；中文被寫成 \uXXXX

var pretty = new JsonSerializerOptions
{
    WriteIndented = true,                                    // 換行與縮排
    Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping,   // 中文直接輸出
};
Console.WriteLine(JsonSerializer.Serialize(order, pretty));

var camel = new JsonSerializerOptions { PropertyNamingPolicy = JsonNamingPolicy.CamelCase };
Console.WriteLine(JsonSerializer.Serialize(new Item { Name = "可樂", Quantity = 6 }, camel));
// {"name":"可樂","quantity":6}  ← 名字的第一個字母變小寫
  • \u53EF\u6A02 和「可樂」是同一個字串的兩種寫法，讀回來完全一樣。只是人不好讀，原因見編碼器那一頁
  • ASP.NET Core 的 Web API 預設會用 camelCase 輸出（name 而不是 Name），除非專案另外設定

3. JSON 轉物件

var json = """{"Id":5,"Customer":"小華","Paid":true,"Note":null,"Total":285.5,"OrderedAt":"2026-10-15T09:30:00+08:00","Items":[{"Name":"可樂","Quantity":6},{"Name":"餅乾","Quantity":2}]}""";

Order back = JsonSerializer.Deserialize<Order>(json)!;

Console.WriteLine(back.Customer);          // 小華
Console.WriteLine(back.Items.Count);       // 2
Console.WriteLine(back.Items[1].Name);     // 餅乾
  • Deserialize<Order>：尖括號裡寫要轉成哪個型別
  • 做法是反過來：先建立一個空的 Order，再照 JSON 裡的每個名字找同名的屬性，把值填進去
  • 結尾的 !：這個方法的回傳型別是 Order?，因為 JSON 的內容如果剛好是 null，結果就是 null。! 是告訴編譯器「我確定不是 null」
  • """…""" 是原始字串，裡面的雙引號不用加反斜線

Web API 的 Controller 收到 [FromBody] Order order 時，框架做的就是這件事。

4. 最容易踩的坑：名字的大小寫

var lower = """{"id":5,"customer":"小華"}""";       // 名字是小寫開頭

var x1 = JsonSerializer.Deserialize<Order>(lower)!;
Console.WriteLine($"Id={x1.Id} Customer=\"{x1.Customer}\"");
// Id=0 Customer=""        ← 沒有丟例外，但值都沒填進去

var x2 = JsonSerializer.Deserialize<Order>(lower, new JsonSerializerOptions { PropertyNameCaseInsensitive = true })!;
// Id=5 Customer=小華

var x3 = JsonSerializer.Deserialize<Order>(lower, JsonSerializerOptions.Web)!;
// Id=5 Customer=小華

⚠️ 對不上名字不會報錯。JsonSerializer 預設區分大小寫，JSON 的 id 對不上屬性 Id，它就當作「JSON 裡沒有這個欄位」，屬性停在預設值。你拿到的是一個看起來正常、但內容全是 0 與空字串的物件。

設定id 對得上 Id 嗎用在哪
預設（new JsonSerializerOptions()）對不上自己呼叫 JsonSerializer 而且沒帶設定時
PropertyNameCaseInsensitive = true對得上只想放寬大小寫
JsonSerializerOptions.Web對得上，輸出也變 camelCaseASP.NET Core 的 Web API 預設就是這一組

所以同一段 JSON，Controller 收得到、自己用 JsonSerializer.Deserialize 卻收不到，通常就是這個原因。

5. 少欄位、多欄位、型別不對

JSON 的狀況結果實際輸出
少了某個欄位那個屬性停在預設值，不報錯只送 {"Id":7} → Customer=""、Paid=False、Total=0、OrderedAt=0001-01-01、Items.Count=0
多了類別沒有的欄位被忽略，不報錯{"Id":7,"Unknown":"abc"} → Id=7
明確送 null蓋掉屬性的預設值{"Id":7,"Items":null} → Items is null = True
數字送成字串丟 JsonException{"Id":"7"} → The JSON value could not be converted to System.Int32. Path: $.Id
布林送成字串丟 JsonException{"Paid":"true"} → could not be converted to System.Boolean. Path: $.Paid
JSON 本身寫錯丟 JsonException少一個大括號 → '7' is an invalid end of a number. Expected a delimiter.
整段 JSON 是 null回傳 nullDeserialize<Order>("null") → null

「沒送」和「送 null」不一樣

類別裡寫了 public List<Item> Items { get; set; } = new();，意思是預設給一個空清單。

  • JSON 裡沒有 Items：沒人去動這個屬性，它保持空清單。Items.Count 是 0
  • JSON 裡寫 "Items": null：轉換時把 null 填進去，空清單被蓋掉。之後 Items.Count 會丟 NullReferenceException

所以接 API 請求時，屬性有預設值不代表它一定不是 null。重要的欄位要自己檢查。

錯誤訊息裡的 Path

Path: $.Id 指出是哪個欄位出問題：$ 是最外層，$.Id 是最外層的 Id，$.Items[1].Name 是 Items 第二個的 Name。

放寬「數字送成字串」

var options = new JsonSerializerOptions { NumberHandling = JsonNumberHandling.AllowReadingFromString };
var x = JsonSerializer.Deserialize<Order>("""{"Id":"7"}""", options)!;   // Id=7

時間的格式

JSON 裡的時間轉成 DateTimeOffset
"2026-10-15T09:30:00+08:00"成功ISO 8601，帶時區。最不會出錯的寫法
"2026-10-15T09:30:00"成功，但時區用的是這台電腦的在台灣的電腦上變成 +08:00，放到別的時區的伺服器上就不一樣
"2026/10/15 09:30:00"丟 JsonException斜線與空格的寫法不收

第二種最危險：不會報錯，本機測試也正常，到了伺服器上時間卻差了幾個小時。

6. JSON 轉 Dictionary

JSON 的物件就是一堆「名字：值」，和 Dictionary 是同一種形狀。不想為了讀一段 JSON 特地寫一個類別，或名字事先不知道時，可以轉成 Dictionary。

值的型別都一樣

var d1 = JsonSerializer.Deserialize<Dictionary<string, int>>("""{"可樂":30,"綠茶":25,"咖啡":60}""")!;
Console.WriteLine(d1.Count);        // 3
Console.WriteLine(d1["綠茶"]);      // 25

Console.WriteLine(JsonSerializer.Serialize(d1));   // {"可樂":30,"綠茶":25,"咖啡":60}（Dictionary 也能轉回 JSON）

var d4 = JsonSerializer.Deserialize<Dictionary<string, List<string>>>("""{"飲料":["可樂","綠茶"],"零食":["餅乾"]}""")!;
Console.WriteLine(string.Join(", ", d4["飲料"]));   // 可樂, 綠茶

var d5 = JsonSerializer.Deserialize<Dictionary<int, string>>("""{"1":"可樂","2":"綠茶"}""")!;
Console.WriteLine(d5[2]);           // 綠茶      ← JSON 的名字一定是字串，但可以轉成 int 的 key

值的型別不一樣

訂單那段 JSON，值有數字、字串、布林、陣列。用 Dictionary<string, int> 會失敗：

JsonException: The JSON value could not be converted to System.Int32. Path: $.Customer

這時 value 的型別用 JsonElement，它代表「JSON 裡的任何一種值」，要用的時候再指定要當成什麼讀：

var d2 = JsonSerializer.Deserialize<Dictionary<string, JsonElement>>(json)!;

foreach (var (name, value) in d2)
{
    Console.WriteLine($"{name}: ValueKind={value.ValueKind} raw={value.GetRawText()}");
}

Console.WriteLine(d2["Id"].GetInt32());                                  // 5
Console.WriteLine(d2["Customer"].GetString());                           // 小華
Console.WriteLine(d2["Items"][0].GetProperty("Name").GetString());       // 可樂
Id: ValueKind=Number raw=5
Customer: ValueKind=String raw="小華"
Paid: ValueKind=True raw=true
Note: ValueKind=Null raw=null
Total: ValueKind=Number raw=285.5
OrderedAt: ValueKind=String raw="2026-10-15T09:30:00+08:00"
Items: ValueKind=Array raw=[{"Name":"可樂","Quantity":6},{"Name":"餅乾","Quantity":2}]
想轉成什麼時候用注意
自己寫的 class形狀固定、欄位已知。大部分情況用這個名字的大小寫（第 4 節）
Dictionary<string, int> 等名字不固定，但值都是同一種型別有一個值的型別不同就整個失敗
Dictionary<string, JsonElement>名字不固定，值的型別也不一定讀的時候要自己用 GetInt32()、GetString() 等取值
Dictionary<string, object>不建議value 實際上還是 JsonElement，不是 int 或 string，直接轉型會失敗

JSON 陣列

var list = JsonSerializer.Deserialize<List<Item>>("""[{"Name":"可樂","Quantity":6},{"Name":"餅乾","Quantity":2}]""")!;
Console.WriteLine(list.Count);       // 2
Console.WriteLine(list[0].Name);     // 可樂

最外層是 [ 就轉成 List<T>，是 { 就轉成 class 或 Dictionary。兩者弄反會丟 JsonException: The JSON value could not be converted to Item. Path: $。

7. 完全不知道形狀時：JsonNode

using System.Text.Json.Nodes;

var node = JsonNode.Parse(json)!;

Console.WriteLine(node["Customer"]);                    // 小華
Console.WriteLine(node["Items"]![1]!["Quantity"]);      // 2
Console.WriteLine(node["NoSuch"] is null);              // True   ← 沒有這個名字時是 null，不會丟例外

node["Customer"] = "小明";                              // 可以直接改

JsonNode 把 JSON 讀成一棵可以用 ["名字"] 與 [位置] 一層一層走的樹，不用事先定義任何型別。適合只想從一大段 JSON 裡拿一兩個值，或要修改後再輸出的情況。

做法要不要先寫型別適合
Deserialize<class>要形狀固定。有型別檢查，寫錯屬性名稱編譯就會發現
Deserialize<Dictionary<…>>不用名字不固定的一層對照表
JsonNode.Parse不用形狀不確定、只取其中幾個值、要修改

enum 進出 JSON 時是數字還是名字，見 enum 那一頁第 5 節。
