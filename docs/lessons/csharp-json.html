C# 補充：JSON（格式、轉成物件、轉成 Dictionary）

JSON 是 API 來回傳資料用的文字格式。這頁講它的寫法、C# 物件與 JSON 怎麼互轉、名字大小寫對不上時為什麼不報錯、少欄位與型別不對各會怎樣、時間的格式，以及不想寫類別時怎麼轉成 Dictionary。

📌 這頁和專案無關，用的是 .NET 內建的 System.Text.Json。Web API 收請求、回回應時框架會自動做這些轉換，知道規則才看得懂「為什麼這個欄位沒收到」。

每一節都從最簡單的寫法開始，一步只多一樣東西。頁面上的輸出、例外訊息和編譯訊息都是單檔程式實際執行的結果（.NET 10）。丟例外的地方，「輸出」只列例外的型別和訊息那一行；實際執行時那一行前面還有 Unhandled exception.，後面接著幾行出錯位置，程式在那裡結束。

用單檔程式（dotnet run xxx.cs）跑這頁的範例時，檔案第一行要加 #:property PublishAot=false。實測不加這一行，呼叫 JsonSerializer.Serialize 會丟 InvalidOperationException: Reflection-based serialization has been disabled for this application.。

1. JSON 的格式

JSON 是一段文字，用固定的寫法描述資料。API 的請求與回應、設定檔（appsettings.json）都是它。這一節用一張訂單當例子，從只有一項資料的 JSON 開始，一步加一種寫法，最後寫出完整的訂單。

程式裡的顏色：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或不建議的寫法。

第 1 步：一個名字配一個值

{
  "Id": 5
}
  • 最外面一對大括號 { } 叫物件，裡面放「名字：值」
  • 名字一定要用雙引號包起來，後面接冒號，再接值
  • 這裡的值 5 是數字，不加引號

第 2 步：多一項，用逗號隔開

{
  "Id": 5,
  "Customer": "小華"
}
  • 每一項之間用逗號分隔。最後一項後面不能有逗號
  • "小華" 是字串，用雙引號，不能用單引號

第 3 步：值還有布林、null、小數、時間

{
  "Id": 5,
  "Customer": "小華",
  "Paid": true,
  "Note": null,
  "Total": 285.5,
  "OrderedAt": "2026-10-15T09:30:00+08:00"
}
  • true、false 是布林，null 是「沒有值」。這三個字都是小寫，不加引號
  • 數字可以有小數點，不加引號。"5" 是字串，5 是數字，兩者不同
  • JSON 沒有「日期」這種型別。時間是用字串寫的，要用什麼格式是傳的人和收的人之間的約定

第 4 步：值是一串東西時用中括號

一張訂單有好幾個品項。中括號 [ ] 叫陣列，裡面的值用逗號隔開。這裡每一個值是一個物件，就是第 1 步那種大括號：

{
  "Id": 5,
  "Customer": "小華",
  "Paid": true,
  "Note": null,
  "Total": 285.5,
  "OrderedAt": "2026-10-15T09:30:00+08:00",
  "Items": [
    {
      "Name": "可樂",
      "Quantity": 6
    },
    {
      "Name": "餅乾",
      "Quantity": 2
    }
  ]
}

物件裡可以放陣列，陣列裡可以放物件，可以一層一層往裡面放。這就是完整的訂單，後面幾節都用這一段。

第 5 步：寫錯一個符號，整段都讀不了

下面每一段只錯一個地方。錯誤訊息是 .NET 的 JsonDocument.Parse 讀這段文字時實際丟出來的（LineNumber 從 0 開始算）：

兩項之間少了逗號

{
  "Id": 5 
  "Customer": "小華"
}

JsonReaderException: '"' is invalid after a value. Expected either ',', '}', or ']'. LineNumber: 2 | BytePositionInLine: 2.

最後一項後面多了逗號

{
  "Id": 5,
  "Customer": "小華",
}

JsonReaderException: The JSON object contains a trailing comma at the end which is not supported in this mode. Change the reader options. LineNumber: 3 | BytePositionInLine: 0.

字串用了單引號

{
  "Id": 5,
  "Customer": '小華'
}

JsonReaderException: ''' is an invalid start of a value. LineNumber: 2 | BytePositionInLine: 14.

名字沒有用雙引號

{
  Id: 5
}

JsonReaderException: 'I' is an invalid start of a property name. Expected a '"'. LineNumber: 1 | BytePositionInLine: 2.

true 寫成大寫開頭

{
  "Paid": True
}

JsonReaderException: 'T' is an invalid start of a value. LineNumber: 1 | BytePositionInLine: 10.

2. 物件轉 JSON

把 C# 的物件變成 JSON 文字叫序列化（serialize），用 JsonSerializer.Serialize。這一節先轉一個只有兩個屬性的小物件，再一步一步處理中文、巢狀的物件、換行、名字的大小寫。

顏色和前面一樣：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或不建議的寫法。

第 1 步：轉一個最小的物件

#:property PublishAot=false
using System.Text.Json;

var item = new Item { Name = "Cola", Quantity = 6 };

string json = JsonSerializer.Serialize(item);
Console.WriteLine(json);

class Item
{
    public string Name { get; set; } = string.Empty;
    public int Quantity { get; set; }
}

// 輸出：
// {"Name":"Cola","Quantity":6}

規則：屬性的名稱變成 JSON 的名字，屬性的值變成 JSON 的值。string 變成有雙引號的字串，int 變成數字。結果是一個 string，全部在同一行，沒有空白。

下面每一步都沿用這個 Item 類別和開頭那兩行。

第 2 步：值是中文時，輸出變成一串代碼

var item = new Item { Name = "可樂", Quantity = 6 };
Console.WriteLine(JsonSerializer.Serialize(item));

// 輸出：
// {"Name":"\u53EF\u6A02","Quantity":6}

「可樂」被寫成 \u53EF\u6A02。這是同一個字串的另一種寫法，JSON 的規格允許：把這段 JSON 再轉回物件，Name 還是「可樂」（實際轉回來比對過）。資料沒有壞，只是人不好讀。預設這樣輸出的原因見編碼器那一頁。

第 3 步：傳一組設定，讓中文直接輸出

Serialize 的第二個參數可以傳一個 JsonSerializerOptions，裡面是各種輸出的設定。Encoder 這一項決定哪些字要寫成代碼：

using System.Text.Encodings.Web;
using System.Text.Json;

var item = new Item { Name = "可樂", Quantity = 6 };

var options = new JsonSerializerOptions
{
    Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping,
};
Console.WriteLine(JsonSerializer.Serialize(item, options));

// 輸出：
// {"Name":"可樂","Quantity":6}

JavaScriptEncoder 在 System.Text.Encodings.Web 這個 namespace，所以最上面多一行 using。

第 4 步：屬性有各種型別，其中一個是清單

換成第 1 節那張訂單。Order 的屬性有各種型別，其中 Items 是一個 List<Item>，清單裡每一個是前面的 Item：

class Order
{
    public int Id { get; set; }
    public string Customer { get; set; } = string.Empty;
    public bool Paid { get; set; }
    public string? Note { get; set; }
    public decimal Total { get; set; }
    public DateTimeOffset OrderedAt { get; set; }
    public List<Item> Items { get; set; } = new();
}
var order = new Order
{
    Id = 5,
    Customer = "小華",
    Paid = true,
    Note = null,
    Total = 285.5m,
    OrderedAt = new DateTimeOffset(2026, 10, 15, 9, 30, 0, TimeSpan.FromHours(8)),
    Items = new List<Item>
    {
        new Item { Name = "可樂", Quantity = 6 },
        new Item { Name = "餅乾", Quantity = 2 },
    },
};

Console.WriteLine(JsonSerializer.Serialize(order, options));

// 輸出（同一行）：
// {"Id":5,"Customer":"小華","Paid":true,"Note":null,"Total":285.5,"OrderedAt":"2026-10-15T09:30:00+08:00","Items":[{"Name":"可樂","Quantity":6},{"Name":"餅乾","Quantity":2}]}

285.5m 結尾的 m 表示這個數字是 decimal。呼叫的寫法沒有變。規則還是同一條，只是每種型別各有對應：bool 變 true、C# 的 null 變 null、decimal 變數字、DateTimeOffset 變成帶時區的字串、List<Item> 變成陣列，裡面每個 Item 各變成一個物件。

內容和第 1 節那段一樣，但全部擠在同一行。

第 5 步：設定裡加 WriteIndented，換行與縮排

var pretty = new JsonSerializerOptions
{
    Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping,
    WriteIndented = true,
};
Console.WriteLine(JsonSerializer.Serialize(order, pretty));

// 輸出：
// {
//   "Id": 5,
//   "Customer": "小華",
//   "Paid": true,
//   "Note": null,
//   "Total": 285.5,
//   "OrderedAt": "2026-10-15T09:30:00+08:00",
//   "Items": [
//     {
//       "Name": "可樂",
//       "Quantity": 6
//     },
//     {
//       "Name": "餅乾",
//       "Quantity": 2
//     }
//   ]
// }

這就是第 1 節第 4 步那段。有沒有換行只影響人好不好讀，資料一樣。

第 6 步：設定裡加 PropertyNamingPolicy，名字的第一個字母變小寫

C# 的屬性習慣大寫開頭（Name），JavaScript 那邊習慣小寫開頭（name）。這種「第一個字母小寫」的寫法叫 camelCase：

var camel = new JsonSerializerOptions
{
    Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping,
    PropertyNamingPolicy = JsonNamingPolicy.CamelCase,
};
Console.WriteLine(JsonSerializer.Serialize(item, camel));

// 輸出：
// {"name":"可樂","quantity":6}

類別沒有改，改的只是輸出時 JSON 的名字。以 ASP.NET Core 為例，它的 Web API 預設就用 camelCase 輸出（name 而不是 Name），除非另外設定。

3. JSON 轉物件

反方向：把 JSON 文字變回 C# 的物件，叫反序列化（deserialize），用 JsonSerializer.Deserialize。這一節先解決「JSON 文字怎麼寫進 C# 的字串」，再轉一個小物件，最後轉整張訂單。Item 和 Order 是上一節的類別。

顏色和前面一樣：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或不建議的寫法。

第 1 步：把 JSON 文字寫進 C# 的字串

JSON 裡到處是雙引號，而 C# 的字串也用雙引號包。所以裡面每一個雙引號前面都要加反斜線：

string json = "{\"Name\":\"可樂\",\"Quantity\":6}";
Console.WriteLine(json);

// 輸出：
// {"Name":"可樂","Quantity":6}

可以用，但很難讀，也容易漏掉一個反斜線。

第 2 步：改用三個雙引號的原始字串

string json = """{"Name":"可樂","Quantity":6}""";
Console.WriteLine(json);

// 輸出：
// {"Name":"可樂","Quantity":6}

前後各用三個雙引號包起來的叫原始字串，裡面的雙引號照寫，不用加反斜線。兩種寫法得到的字串一樣（實際用 == 比過是 True）。後面的範例都用這種寫法。

第 3 步：Deserialize，尖括號裡寫要轉成哪個型別

string json = """{"Name":"可樂","Quantity":6}""";

var item = JsonSerializer.Deserialize<Item>(json);
Console.WriteLine(item.Name);

// 輸出：
// 可樂
//
// 編譯時多一行警告，指的是 item.Name 那裡：
// warning CS8602: 可能 null 參考的取值 (dereference)。

Deserialize<Item> 做的事和上一節相反：先建立一個空的 Item，再照 JSON 裡的每個名字找同名的屬性，把值填進去。

程式跑得出結果，但編譯器給了一個警告，說 item 可能是 null。

第 4 步：為什麼可能是 null，以及結尾的 !

Deserialize<Item> 的回傳型別是 Item?，不是 Item。因為 JSON 文字的內容可以整段就是 null，這時沒有東西可以建立：

Item? nothing = JsonSerializer.Deserialize<Item>("null");
Console.WriteLine(nothing is null);

// 輸出：
// True

知道拿到的 JSON 一定是一個物件時，在結尾加 !，告訴編譯器「我確定這裡不是 null」，警告就不見了：

var item = JsonSerializer.Deserialize<Item>(json)!;
Console.WriteLine(item.Name);
Console.WriteLine(item.Quantity + 1);      // Quantity 是 int，可以直接拿來算

// 輸出：
// 可樂
// 7

! 只是讓警告消失，執行時不會幫忙檢查。JSON 真的是 null 時，下一行用到 item.Name 照樣丟 NullReferenceException（實際執行過）。

第 5 步：轉整張訂單

var json = """{"Id":5,"Customer":"小華","Paid":true,"Note":null,"Total":285.5,"OrderedAt":"2026-10-15T09:30:00+08:00","Items":[{"Name":"可樂","Quantity":6},{"Name":"餅乾","Quantity":2}]}""";

Order back = JsonSerializer.Deserialize<Order>(json)!;

Console.WriteLine(back.Customer);
Console.WriteLine(back.Total);
Console.WriteLine(back.OrderedAt.Year);
Console.WriteLine(back.Note is null);
Console.WriteLine(back.Items.Count);
Console.WriteLine(back.Items[1].Name);

// 輸出：
// 小華
// 285.5
// 2026
// True
// 2
// 餅乾

只換了尖括號裡的型別。JSON 的陣列填進 List<Item>，陣列裡每個物件各變成一個 Item；時間的字串變成 DateTimeOffset，所以可以用 .Year。

以 ASP.NET Core 為例：Controller 的方法參數寫 [FromBody] Order order 時，框架對請求的內容做的就是這件事。

4. 最容易踩的坑：名字的大小寫

上一節說「照 JSON 裡的名字找同名的屬性」。這一節看名字只差在大小寫時會怎樣。類別還是 Item，屬性是 Name 和 Quantity。

顏色和前面一樣：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或不建議的寫法。

第 1 步：名字大小寫一樣，值填得進去

var upper = """{"Name":"可樂","Quantity":6}""";

var x0 = JsonSerializer.Deserialize<Item>(upper)!;
Console.WriteLine($"Name=\"{x0.Name}\" Quantity={x0.Quantity}");

// 輸出：
// Name="可樂" Quantity=6

第 2 步：JSON 的名字是小寫開頭，值沒填進去，也沒報錯

var lower = """{"name":"可樂","quantity":6}""";

var x1 = JsonSerializer.Deserialize<Item>(lower)!;
Console.WriteLine($"Name=\"{x1.Name}\" Quantity={x1.Quantity}");

// 輸出：
// Name="" Quantity=0

⚠️ 對不上名字不會報錯。JsonSerializer 預設區分大小寫，JSON 的 name 對不上屬性 Name，它就當作「JSON 裡沒有這個欄位」，屬性停在預設值。拿到的是一個看起來正常、但內容全是 0 與空字串的物件。

第 3 步：設定 PropertyNameCaseInsensitive，比對名字時不分大小寫

Deserialize 的第二個參數也可以傳 JsonSerializerOptions：

var ignoreCase = new JsonSerializerOptions
{
    PropertyNameCaseInsensitive = true,
};

var x2 = JsonSerializer.Deserialize<Item>(lower, ignoreCase)!;
Console.WriteLine($"Name=\"{x2.Name}\" Quantity={x2.Quantity}");

// 輸出：
// Name="可樂" Quantity=6

第 4 步：JsonSerializerOptions.Web，一組現成的設定

.NET 內建一組給 Web API 用的設定，不用自己 new：

var x3 = JsonSerializer.Deserialize<Item>(lower, JsonSerializerOptions.Web)!;
Console.WriteLine($"Name=\"{x3.Name}\" Quantity={x3.Quantity}");

Console.WriteLine(JsonSerializer.Serialize(x3, JsonSerializerOptions.Web));

// 輸出：
// Name="可樂" Quantity=6
// {"name":"\u53EF\u6A02","quantity":6}

它一次設定了幾件事（實際印出這組設定的屬性確認過）：讀的時候名字不分大小寫、寫的時候名字用 camelCase、數字寫成字串（"6"）也收。中文的輸出沒有包含在裡面，所以第二行還是代碼。

三種設定的差別

設定name 對得上 Name 嗎用在哪
預設（不傳設定）對不上自己呼叫 JsonSerializer 而且沒帶設定時
PropertyNameCaseInsensitive = true對得上只想放寬大小寫
JsonSerializerOptions.Web對得上，輸出也變 camelCase以 ASP.NET Core 為例，它的 Web API 預設就是這一組

所以同一段 JSON，Controller 收得到、自己用 JsonSerializer.Deserialize 卻收不到，通常就是這個原因。

5. 少欄位、多欄位、型別不對

收到的 JSON 不一定和類別完全對得上。這一節一次只弄壞一個地方，從「不會報錯」的情況開始，走到「會丟例外」的情況。每一步都是把一小段 JSON 轉成 Order。

顏色和前面一樣：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或不建議的寫法。

第 1 步：少了欄位，屬性停在預設值

var a = JsonSerializer.Deserialize<Order>("""{"Id":7}""")!;

Console.WriteLine(a.Id);
Console.WriteLine($"\"{a.Customer}\"");
Console.WriteLine(a.Paid);
Console.WriteLine(a.Total);
Console.WriteLine(a.OrderedAt.ToString("yyyy-MM-dd"));
Console.WriteLine(a.Items.Count);

// 輸出：
// 7
// ""
// False
// 0
// 0001-01-01
// 0

不報錯。JSON 裡沒有的名字，對應的屬性沒有人去動，保持建立物件時的值：類別裡寫了 = string.Empty 的 Customer 是空字串，寫了 = new() 的 Items 是空清單，其他是型別的預設值。

第 2 步：多了類別沒有的欄位，被忽略

var b = JsonSerializer.Deserialize<Order>("""{"Id":7,"Unknown":"abc"}""")!;
Console.WriteLine(b.Id);

// 輸出：
// 7

不報錯。Order 沒有 Unknown 這個屬性，這一項直接跳過。

第 3 步：明確送 null，屬性原本的值被換成 null

「沒送」和「送 null」不一樣。第 1 步沒送 Items，它是空清單。這次明確寫 "Items": null：

var c = JsonSerializer.Deserialize<Order>("""{"Id":7,"Items":null}""")!;

Console.WriteLine(c.Items is null);
Console.WriteLine(c.Items.Count);

// 輸出：
// True
// NullReferenceException: Object reference not set to an instance of an object.
  • JSON 裡沒有 Items：沒人去動這個屬性，它保持空清單，Items.Count 是 0
  • JSON 裡寫 "Items": null：轉換時把 null 填進屬性，原本的空清單被換掉。之後 Items.Count 丟 NullReferenceException

轉換本身還是沒有報錯。所以接 API 請求時，屬性有預設值不代表它一定不是 null，重要的欄位要自己檢查。

第 4 步：數字送成字串，丟 JsonException

從這一步開始會丟例外。Id 是 int，JSON 裡卻是有引號的 "7"：

var d = JsonSerializer.Deserialize<Order>("""{"Id":"7"}""")!;

// 輸出：
// JsonException: The JSON value could not be converted to System.Int32. Path: $.Id | LineNumber: 0 | BytePositionInLine: 9.

訊息的意思是「這個 JSON 的值沒辦法轉成 int」。第 1 節說過 "7" 是字串、7 是數字，JsonSerializer 預設不會幫忙轉。

第 5 步：用訊息裡的 Path 找出是哪個欄位

Path: $.Id 指出問題在哪裡：$ 是最外層，$.Id 是最外層的 Id。錯在比較裡面時，Path 會一層一層寫出來：

var json = """{"Id":7,"Items":[{"Name":"可樂","Quantity":6},{"Name":"餅乾","Quantity":"兩個"}]}""";
var e = JsonSerializer.Deserialize<Order>(json)!;

// 輸出：
// JsonException: The JSON value could not be converted to System.Int32. Path: $.Items[1].Quantity | LineNumber: 0 | BytePositionInLine: 84.

$.Items[1].Quantity 是 Items 的第 1 個（從 0 算，也就是第二個）的 Quantity。

第 6 步：放寬「數字送成字串」

對方就是會把數字送成字串、又沒辦法請對方改時，可以用設定放寬：

using System.Text.Json.Serialization;

var options = new JsonSerializerOptions
{
    NumberHandling = JsonNumberHandling.AllowReadingFromString,
};
var f = JsonSerializer.Deserialize<Order>("""{"Id":"7"}""", options)!;
Console.WriteLine(f.Id);

// 輸出：
// 7

JsonNumberHandling 在 System.Text.Json.Serialization 這個 namespace。引號裡不是數字時（例如 "七"），加了這個設定還是丟同樣的 JsonException。

第 7 步：布林送成字串，丟 JsonException

var g = JsonSerializer.Deserialize<Order>("""{"Paid":"true"}""")!;

// 輸出：
// JsonException: The JSON value could not be converted to System.Boolean. Path: $.Paid | LineNumber: 0 | BytePositionInLine: 14.

上一步的 NumberHandling 只管數字。帶著那組設定再轉一次，這裡丟的例外一模一樣。

第 8 步：JSON 本身寫錯，丟 JsonException

// 少了結尾的大括號
var h = JsonSerializer.Deserialize<Order>("""{"Id":7""")!;

// 輸出：
// JsonException: '7' is an invalid end of a number. Expected a delimiter. Path: $.Id | LineNumber: 0 | BytePositionInLine: 7.

這種是第 1 節第 5 步那類格式錯誤，和類別長什麼樣子無關。

第 9 步：整段 JSON 是 null，回傳 null

var i = JsonSerializer.Deserialize<Order>("null");
Console.WriteLine(i is null);

// 輸出：
// True

不丟例外，回傳值是 null。這就是第 3 節說回傳型別是 Order? 的原因。

時間的格式：三種寫法，三種結果

JSON 的時間是字串。同一個時間用三種寫法，轉成 DateTimeOffset 的屬性 OrderedAt：

帶時區的 ISO 8601：成功

var t1 = JsonSerializer.Deserialize<Order>("""{"OrderedAt":"2026-10-15T09:30:00+08:00"}""")!;
Console.WriteLine(t1.OrderedAt.ToString("yyyy-MM-dd HH:mm:ss zzz"));

// 輸出：
// 2026-10-15 09:30:00 +08:00

最不會出錯的寫法：時區寫在字串裡，在哪一台電腦上轉都一樣。

沒寫時區：成功，但時區是補上去的

var t2 = JsonSerializer.Deserialize<Order>("""{"OrderedAt":"2026-10-15T09:30:00"}""")!;
Console.WriteLine(t2.OrderedAt.ToString("yyyy-MM-dd HH:mm:ss zzz"));

// 輸出（這台電腦的時區是台北）：
// 2026-10-15 09:30:00 +08:00

字串裡沒有時區，結果卻有 +08:00，用的是執行這段程式的電腦的時區。這種最危險：不會報錯，在台灣的電腦上測試也正常。放到別的時區的伺服器上，補上去的時差會不一樣（這一點沒有在別的時區的電腦上實測）。

斜線與空格的寫法：丟 JsonException

var t3 = JsonSerializer.Deserialize<Order>("""{"OrderedAt":"2026/10/15 09:30:00"}""")!;

// 輸出：
// JsonException: The JSON value could not be converted to System.DateTimeOffset. Path: $.OrderedAt | LineNumber: 0 | BytePositionInLine: 34.

6. JSON 轉 Dictionary

JSON 的物件就是一堆「名字：值」，和 Dictionary 是同一種形狀。不想為了讀一段 JSON 特地寫一個類別，或名字事先不知道時，可以轉成 Dictionary。這一節從值都是同一種型別的 JSON 開始，再處理值的型別混在一起的情況。

顏色和前面一樣：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或不建議的寫法。

第 1 步：值都是數字，轉成 Dictionary<string, int>

var d1 = JsonSerializer.Deserialize<Dictionary<string, int>>("""{"可樂":30,"綠茶":25,"咖啡":60}""")!;

Console.WriteLine(d1.Count);
Console.WriteLine(d1["綠茶"]);

// 輸出：
// 3
// 25

JSON 的名字變成 key，值變成 value。尖括號裡寫的不是自己的類別，是 Dictionary<string, int>，所以 JSON 裡有哪些名字都可以，不用事先知道。

反方向也可以，Dictionary 能轉回 JSON（options 是第 2 節第 3 步那組讓中文直接輸出的設定）：

Console.WriteLine(JsonSerializer.Serialize(d1, options));

// 輸出：
// {"可樂":30,"綠茶":25,"咖啡":60}

第 2 步：value 和 key 換成別的型別

值都是「字串的陣列」時，value 的型別寫 List<string>：

var d4 = JsonSerializer.Deserialize<Dictionary<string, List<string>>>("""{"飲料":["可樂","綠茶"],"零食":["餅乾"]}""")!;

Console.WriteLine(d4["飲料"].Count);
Console.WriteLine(d4["飲料"][1]);

// 輸出：
// 2
// 綠茶

JSON 的名字一定是字串，但名字的內容是數字時，key 的型別可以寫 int：

var d5 = JsonSerializer.Deserialize<Dictionary<int, string>>("""{"1":"可樂","2":"綠茶"}""")!;

Console.WriteLine(d5[2]);

// 輸出：
// 綠茶

第 3 步：值的型別不一樣，Dictionary<string, int> 失敗

拿訂單那段 JSON 來轉（json 是第 3 節第 5 步那個字串）。它的值有數字、字串、布林、陣列：

var bad = JsonSerializer.Deserialize<Dictionary<string, int>>(json)!;

// 輸出：
// JsonException: The JSON value could not be converted to System.Int32. Path: $.Customer | LineNumber: 0 | BytePositionInLine: 27.

第一項 Id 是數字，過了；第二項 Customer 是字串，轉不成 int。有一個值的型別不合，整個轉換就失敗。

第 4 步：value 改成 object，轉得過，但拿不出 int

object 什麼都能放，直覺上 value 的型別寫 object 就好：

var d3 = JsonSerializer.Deserialize<Dictionary<string, object>>(json)!;

Console.WriteLine(d3.Count);
Console.WriteLine(d3["Id"]);

int id = (int)d3["Id"];

// 輸出：
// 7
// 5
// InvalidCastException: Unable to cast object of type 'System.Text.Json.JsonElement' to type 'System.Int32'.

轉換成功，印出來也是 5。但要把它當 int 用時失敗了。訊息說這個 value 實際的型別是 JsonElement，不是 int。印 d3["Customer"].GetType() 也是 System.Text.Json.JsonElement，不是 string。

所以不建議用 Dictionary<string, object>：型別寫 object，裡面放的其實全是 JsonElement。

第 5 步：value 直接寫 JsonElement，用 GetXxx() 取值

JsonElement 代表「JSON 裡的任何一種值」。要用的時候呼叫對應的方法，指定要當成什麼讀：

var d2 = JsonSerializer.Deserialize<Dictionary<string, JsonElement>>(json)!;

Console.WriteLine(d2["Id"].GetInt32() + 1);
Console.WriteLine(d2["Customer"].GetString());
Console.WriteLine(d2["Paid"].GetBoolean());
Console.WriteLine(d2["Total"].GetDecimal());

// 輸出：
// 6
// 小華
// True
// 285.5

GetInt32() 回傳的是真的 int，所以可以 + 1。方法和值的種類不合時會丟例外，例如對字串呼叫 GetInt32()：

Console.WriteLine(d2["Customer"].GetInt32());

// 輸出：
// InvalidOperationException: The requested operation requires an element of type 'Number', but the target element has type 'String'.

第 6 步：不知道值是哪一種時，先看 ValueKind

foreach (var (name, value) in d2)
{
    Console.WriteLine($"{name}: ValueKind={value.ValueKind} raw={value.GetRawText()}");
}

// 輸出：
// Id: ValueKind=Number raw=5
// Customer: ValueKind=String raw="小華"
// Paid: ValueKind=True raw=true
// Note: ValueKind=Null raw=null
// Total: ValueKind=Number raw=285.5
// OrderedAt: ValueKind=String raw="2026-10-15T09:30:00+08:00"
// Items: ValueKind=Array raw=[{"Name":"可樂","Quantity":6},{"Name":"餅乾","Quantity":2}]

ValueKind 說這個值是 JSON 六種值裡的哪一種（布林分成 True 和 False 兩個）。GetRawText() 是它在 JSON 裡原本的那段文字。

第 7 步：值是陣列或物件時，往裡面走

d2["Items"] 是一個陣列，裡面是物件。JsonElement 用 [位置] 拿陣列的第幾個，用 GetProperty("名字") 拿物件裡的某一項：

Console.WriteLine(d2["Items"].GetArrayLength());
Console.WriteLine(d2["Items"][0].GetProperty("Name").GetString());
Console.WriteLine(d2["Items"][1].GetProperty("Quantity").GetInt32());

// 輸出：
// 2
// 可樂
// 2

最外層是陣列時，轉成 List

var list = JsonSerializer.Deserialize<List<Item>>("""[{"Name":"可樂","Quantity":6},{"Name":"餅乾","Quantity":2}]""")!;

Console.WriteLine(list.Count);
Console.WriteLine(list[0].Name);

// 輸出：
// 2
// 可樂

最外層是 [ 就轉成 List<T>，是 { 就轉成 class 或 Dictionary。兩者弄反會丟例外：

// 最外層是陣列，卻轉成 Item
JsonSerializer.Deserialize<Item>("""[{"Name":"可樂","Quantity":6},{"Name":"餅乾","Quantity":2}]""");
// JsonException: The JSON value could not be converted to Item. Path: $ | LineNumber: 0 | BytePositionInLine: 1.

// 最外層是物件，卻轉成 List<Item>
JsonSerializer.Deserialize<List<Item>>("""{"Name":"可樂","Quantity":6}""");
// JsonException: The JSON value could not be converted to System.Collections.Generic.List`1[Item]. Path: $ | LineNumber: 0 | BytePositionInLine: 1.

要轉成哪一種

想轉成什麼時候用注意
自己寫的 class形狀固定、欄位已知。大部分情況用這個名字的大小寫（第 4 節）
Dictionary<string, int> 等名字不固定，但值都是同一種型別有一個值的型別不同就整個失敗
Dictionary<string, JsonElement>名字不固定，值的型別也不一定讀的時候要自己用 GetInt32()、GetString() 等取值
Dictionary<string, object>不建議value 實際上還是 JsonElement，不是 int 或 string，直接轉型會失敗

7. 完全不知道形狀時：JsonNode

上一節的 Dictionary<string, JsonElement> 可以讀任何形狀的 JSON。這一節先看它做不到的兩件事，再換成 JsonNode。json 還是訂單那個字串。

顏色和前面一樣：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或不建議的寫法。

第 1 步：用 JsonElement 改不了值，名字不存在會丟例外

想把顧客改成「小明」：

var d2 = JsonSerializer.Deserialize<Dictionary<string, JsonElement>>(json)!;

d2["Customer"] = "小明";

error CS0029: 無法將類型 'string' 隱含轉換成 'System.Text.Json.JsonElement'

編譯不過。value 的型別是 JsonElement，不能直接放一個 string 進去。

讀一個不存在的名字，則是 Dictionary 的中括號丟例外：

Console.WriteLine(d2["NoSuch"]);

// 輸出：
// KeyNotFoundException: The given key 'NoSuch' was not present in the dictionary.

第 2 步：JsonNode.Parse，用 ["名字"] 讀

using System.Text.Json.Nodes;

var node = JsonNode.Parse(json)!;

Console.WriteLine(node["Customer"]);
Console.WriteLine(node["Id"]);

// 輸出：
// 小華
// 5

JsonNode.Parse 不用在尖括號裡寫任何型別。它把 JSON 讀成一棵樹，node 是最外層那個物件，node["Customer"] 是裡面叫 Customer 的那一項。JsonNode 在 System.Text.Json.Nodes 這個 namespace。

第 3 步：用 [位置] 和 ["名字"] 一層一層往裡走

Console.WriteLine(node["Items"]![1]!["Quantity"]);
Console.WriteLine(node["Items"]![0]!["Name"]);

// 輸出：
// 2
// 可樂

陣列用 [位置]，物件用 ["名字"]，寫法都是中括號。每一層後面的 ! 和第 3 節的意思一樣：中括號的回傳型別是 JsonNode?，! 告訴編譯器「我確定這一層有東西」。

第 4 步：名字不存在時是 null，不丟例外

Console.WriteLine(node["NoSuch"] is null);

// 輸出：
// True

這就是中括號回傳 JsonNode? 的原因。可以先用 is null 檢查再往下走。不檢查就接著往裡走（node["NoSuch"]!["Name"]），實際執行會丟 NullReferenceException。

JSON 裡的值本來就是 null 時也一樣：node["Note"] is null 是 True。

第 5 步：直接改值，再輸出成 JSON

node["Customer"] = "小明";
node["Items"]![1]!["Quantity"] = 3;

Console.WriteLine(node.ToJsonString(options));

// 輸出：
// {"Id":5,"Customer":"小明","Paid":true,"Note":null,"Total":285.5,"OrderedAt":"2026-10-15T09:30:00+08:00","Items":[{"Name":"可樂","Quantity":6},{"Name":"餅乾","Quantity":3}]}

第 1 步編譯不過的那一行，在 JsonNode 上可以寫。ToJsonString 把整棵樹輸出成 JSON 文字；options 是第 2 節第 3 步那組讓中文直接輸出的設定。

JsonNode 適合只想從一大段 JSON 裡拿一兩個值，或要修改後再輸出的情況。

三種做法怎麼選

做法要不要先寫型別適合
Deserialize<class>要形狀固定。有型別檢查，寫錯屬性名稱編譯就會發現
Deserialize<Dictionary<…>>不用名字不固定的一層對照表
JsonNode.Parse不用形狀不確定、只取其中幾個值、要修改

enum 進出 JSON 時是數字還是名字，見 enum 那一頁講進出 API 的那一節。
