C# 補充：enum（程式裡是名字，資料庫裡是數字）

enum 在 C# 裡是有名字的選項，存進資料庫、轉成 JSON 時卻要換成數字或文字。這頁講它背後的數字、在 C# 裡怎麼轉換、EF Core 怎麼存、查詢時翻成什麼 SQL、進出 API 時的約定、幾個不會報錯的坑，最後是「顯示用的狀態」與「資料庫的狀態」怎麼用對應表互換。

1. enum 是什麼：名字與數字的對照

public enum OrderStatus
{
    Pending = 0,
    Paid = 1,
    Shipped = 2,
    Cancelled = 3
}

enum 是一組有名字的數字。程式裡寫 OrderStatus.Paid，電腦實際記的是 1。這個例子就是 LINQ 實驗室裡訂單的狀態。

為什麼不直接用問題
數字 if (order.Status == 1)看不出 1 是什麼意思；打成 11 編譯器也不會說話
字串 if (order.Status == "Paid")打成 "paid" 或 "Payed" 編譯器也不會說話
enum if (order.Status == OrderStatus.Paid)打錯名字編譯就不會過；輸入 OrderStatus. 編輯器會列出所有選項

背後的型別

public enum OrderStatus { … }          // 沒寫，背後是 int（4 個位元組）
public enum Priority : byte { … }      // 冒號後面指定背後的型別，這裡是 byte（1 個位元組，0 到 255）

Console.WriteLine(sizeof(OrderStatus));   // 4
Console.WriteLine(sizeof(Priority));      // 1

平常不用寫。會寫 : byte 通常是為了配合資料庫欄位的型別（第 3 節）。

  • 沒有寫 = 數字 時，第一個是 0，之後每個加 1。建議都明確寫出數字，原因見第 6 節
  • default(OrderStatus) 是數字 0 對應的成員，這裡是 Pending。如果沒有任何成員是 0，default 會是一個沒有名字的 0

2. 在 C# 裡轉換

Console.WriteLine((int)OrderStatus.Paid);                 // 1          enum → 數字
Console.WriteLine((OrderStatus)2);                        // Shipped    數字 → enum
Console.WriteLine(OrderStatus.Shipped.ToString());        // Shipped    enum → 名字（字串）
Console.WriteLine(Enum.Parse<OrderStatus>("Cancelled"));  // Cancelled  名字 → enum
Console.WriteLine(Enum.TryParse<OrderStatus>("Refunded", out _));   // False     沒有這個名字

Console.WriteLine(string.Join(", ", Enum.GetValues<OrderStatus>()));
// Pending, Paid, Shipped, Cancelled
想做的事寫法失敗時
enum → 數字(int)status不會失敗
數字 → enum(OrderStatus)數字不會失敗，就算沒有這個數字（第 6 節）
enum → 名字status.ToString()不會失敗
名字 → enumEnum.Parse<OrderStatus>("Paid")沒有這個名字會丟 ArgumentException；不確定時用 Enum.TryParse
列出所有成員Enum.GetValues<OrderStatus>()—

Enum.GetValues<OrderStatus>() 回傳這個 enum 定義的所有成員，依數字由小到大。常見用途是「使用者沒指定就當作全部」：

public OrderStatus? Status { get; set; }       // 使用者可以不選

public IReadOnlyList<OrderStatus> Statuses()
{
    return Status is null
        ? Enum.GetValues<OrderStatus>()         // 沒選 → 四種全部
        : [Status.Value];                       // 有選 → 只有那一種
}

3. EF Core 怎麼存進資料庫

資料庫沒有 enum 這種型別，所以要換成資料庫有的型別來存。EF Core 預設存數字。

public class Ticket
{
    public int Id { get; set; }
    public OrderStatus StatusAsInt { get; set; }      // 背後是 int 的 enum
    public Priority PriorityAsByte { get; set; }      // 背後是 byte 的 enum
    public OrderStatus StatusAsText { get; set; }     // 另外設定成存文字
}

protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Ticket>().Property(t => t.StatusAsText).HasConversion<string>().HasMaxLength(20);
}

EF Core 依這個模型產生的建表語法

CREATE TABLE [Tickets] (
    [Id] int NOT NULL IDENTITY,
    [StatusAsInt] int NOT NULL,
    [PriorityAsByte] tinyint NOT NULL,
    [StatusAsText] nvarchar(20) NOT NULL,
    CONSTRAINT [PK_Tickets] PRIMARY KEY ([Id])
);
C# 的宣告資料庫欄位存進去的內容
enum OrderStatus（背後是 int）int1
enum Priority : bytetinyint1
加上 HasConversion<string>()nvarcharPaid

欄位的型別跟著 enum 背後的型別走。資料表是別人早就建好的、欄位是 tinyint 時，C# 這邊的 enum 就宣告成 : byte 來配合。

存數字還是存文字

存數字（預設）存文字（HasConversion<string>()）
直接看資料表看到 1、2、3，要對照程式才知道意思看到 Paid、Shipped，一眼就懂
空間與比較小、快比較大
改成員的名字沒影響，資料庫裡是數字舊資料裡還是舊名字，讀不回來
改成員的數字、調順序舊資料的意思整個變掉沒影響
排序依數字依字母（Cancelled、Paid、Pending、Shipped）

兩種都有人用。重點是決定之後，另一邊就不能隨便動：存數字就不要改數字，存文字就不要改名字。

4. 查詢時怎麼翻成 SQL

在 LINQ 裡用 enum 寫條件，EF Core 會把它換成資料庫裡存的那個值。完整的實驗在 LINQ 實驗室 L4-11。

// 一個值
db.Orders.Where(o => o.Status == OrderStatus.Paid)

// 一組值
var wanted = new List<OrderStatus> { OrderStatus.Paid, OrderStatus.Shipped };
db.Orders.Where(o => wanted.Contains(o.Status))

// 排序
db.Orders.OrderBy(o => o.Status)

存數字時

WHERE [o].[Status] = 1

-- Parameters=[@wanted1='1', @wanted2='2']
WHERE [o].[Status] IN (@wanted1, @wanted2)

ORDER BY [o].[Status]

同樣的 LINQ，欄位設定成存文字時

WHERE [o].[Status] = N'Paid'

-- Parameters=[@wanted1='Paid', @wanted2='Shipped']
WHERE [o].[Status] IN (@wanted1, @wanted2)
  • C# 這邊的寫法完全一樣，SQL 裡出現的是資料庫存的那種值。你不用自己轉
  • wanted.Contains(o.Status) 不是在 C# 裡執行，而是整行被翻成 IN (…)。細節見 L4-10
  • 排序依的是資料庫裡的值。存數字時是 Pending (0)、Paid (1)、Shipped (2)、Cancelled (3)；存文字時會變成字母順序
  • 讀回來的時候反過來：資料庫回 1，C# 這邊拿到的是 OrderStatus.Paid

5. 進出 API 時：數字還是名字

enum 轉成 JSON 時也有同樣的選擇（JSON 的基本規則見 JSON 那一頁）。預設是數字：

var dto = new OrderDto { Id = 5, Status = OrderStatus.Paid };

Console.WriteLine(JsonSerializer.Serialize(dto));
// {"Id":5,"Status":1}

var withNames = new JsonSerializerOptions { Converters = { new JsonStringEnumConverter() } };
Console.WriteLine(JsonSerializer.Serialize(dto, withNames));
// {"Id":5,"Status":"Paid"}

收進來的時候：

JSON 送的是預設加了 JsonStringEnumConverter
數字 "Status": 2成功，得到 Shipped成功，得到 Shipped
名字 "Status": "Shipped"丟 JsonException：The JSON value could not be converted to OrderStatus. Path: $.Status成功，得到 Shipped
不存在的數字 "Status": 99成功，得到一個沒有名字的 99—
  • 前端與後端要先講好 enum 用數字還是名字。後端沒有加轉換器時只收數字，前端送名字整個請求就會失敗
  • 不同的框架預設不同。舊的 ASP.NET MVC 兩種都收，換到 ASP.NET Core 之後只收數字，搬移 API 時要特別確認
  • 不存在的數字不會被擋下來（下一節）

6. 常見的坑

不存在的數字也能轉成 enum

var weird = (OrderStatus)99;

Console.WriteLine(weird);                                // 99      ← 沒有丟例外，印出來是數字
Console.WriteLine(Enum.IsDefined(weird));                // False
Console.WriteLine(Enum.IsDefined(OrderStatus.Paid));     // True

enum 只是「有名字的數字」，C# 不會檢查數字有沒有對應的名字。從外面進來的值（API 的請求、資料庫裡的舊資料）都可能是沒定義的數字。在意的話用 Enum.IsDefined 檢查，或在 switch 寫 default: 處理沒預期到的值。

改了數字，舊資料的意思就變了

// 原本                          // 有人在中間插了一個
public enum OrderStatus          public enum OrderStatus
{                                {
    Pending,     // 0                Pending,     // 0
    Paid,        // 1                Confirmed,   // 1   ← 新增
    Shipped,     // 2                Paid,        // 2
    Cancelled    // 3                Shipped,     // 3
}                                    Cancelled    // 4
                                 }

資料庫裡原本存 1 的訂單是「已付款」，程式更新後讀出來變成「已確認」。資料沒動，意思卻變了，而且不會有任何錯誤。

  • 每個成員都明確寫 = 數字，新成員用新的數字加在最後面
  • 已經在用的數字不要改，也不要拿去給別的意思用

兩個 enum 的數字相同，意思不一定相同

Console.WriteLine((int)OrderStatus.Paid == (int)Priority.Normal);   // True，兩個都是 1

OrderStatus.Paid 和 Priority.Normal 背後都是 1，但意思毫無關係。編譯器不讓你直接拿兩種不同的 enum 互相比較，就是為了擋這種錯。如果為了「讓它能比」而先轉成數字，就把這層保護拿掉了。

7. 顯示用的狀態與資料庫的狀態：對應表

資料庫裡的狀態通常分得很細，給使用者看的卻只需要幾種。例如訂單有四種狀態，畫面上只想分成三種進度：

資料庫的狀態給使用者看的進度
Pending (0)進行中
Paid (1)進行中
Shipped (2)已完成
Cancelled (3)已取消

做法是用一個 Dictionary 當對應表：key 是資料庫的狀態，value 是顯示用的狀態。

var progressMapping = new Dictionary<OrderStatus, string>
{
    [OrderStatus.Pending] = "進行中",
    [OrderStatus.Paid] = "進行中",
    [OrderStatus.Shipped] = "已完成",
    [OrderStatus.Cancelled] = "已取消",
};

這張表會被用兩次，方向相反：

查詢前查詢後
手上有的使用者選的進度（value）資料庫回來的狀態（key）
要換成資料庫的狀態（key），可能有好幾個顯示用的進度（value），剛好一個
寫法.Where(pair => pair.Value == 進度).Select(pair => pair.Key)progressMapping[order.Status]
用途放進查詢條件顯示給使用者
// 使用者選「進行中」
var statuses = progressMapping
    .Where(pair => pair.Value == "進行中")
    .Select(pair => pair.Key)
    .ToList();                                   // [Pending, Paid]

var orders = await db.Orders
    .Where(o => statuses.Contains(o.Status))     // 翻成 WHERE [o].[Status] IN (0, 1)
    .ToListAsync();

foreach (var order in orders)
{
    Console.WriteLine($"訂單 {order.Id}：{progressMapping[order.Status]}");
}

為什麼反查要取 key，不是 value

statuses.Contains(o.Status) 兩邊要是同一種東西才能比。o.Status 是資料庫的狀態（OrderStatus），所以清單裡也必須是 OrderStatus，也就是對應表的 key。

型別是什麼
對應表的 keyOrderStatus資料庫認得的值
對應表的 valuestring給使用者看的文字，資料庫不認得
statusesList<OrderStatus>反查出來的 key
o.StatusOrderStatus資料表的欄位

完整的實驗（含 SQL 與使用者選了不存在的進度時會怎樣）在 LINQ 實驗室 L4-12。有好幾張表、每張表的狀態 enum 不同時，反查的那三行可以寫成一個泛型方法共用，見 default 那一頁第 5 節。
