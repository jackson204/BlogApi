C# 補充：enum（程式裡是名字，資料庫裡是數字）

enum 在 C# 裡是有名字的選項，存進資料庫、轉成 JSON 時卻要換成數字或文字。這頁講它背後的數字、在 C# 裡怎麼轉換、EF Core 怎麼存、查詢時翻成什麼 SQL、進出 API 時的約定、幾個不會報錯的坑，最後是「顯示用的狀態」與「資料庫的狀態」怎麼用對應表互換。

1. enum 是什麼：名字與數字的對照

訂單有四種狀態：等待付款、已付款、已出貨、已取消。程式要記住一張訂單現在是哪一種。這一節先用數字記、再用字串記，看兩種各有什麼問題，再換成 enum：一組有名字的數字。這個例子就是 LINQ 實驗室裡訂單的狀態。

程式裡的顏色：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或不建議的寫法。

第 1 步：用數字記狀態

最直接的做法：自己規定 0 是等待付款、1 是已付款、2 是已出貨、3 是已取消。

int status = 1;

if (status == 1)
{
    Console.WriteLine("已付款，可以出貨");
}

// 輸出：
// 已付款，可以出貨

能用，但有兩個問題。第一，只看 status == 1 看不出 1 是什麼意思，要去翻規定。第二，數字打錯了不會有人提醒：

int status = 1;

if (status == 11)
{
    Console.WriteLine("已付款，可以出貨");
}

// 可以編譯，沒有任何錯誤或警告。執行後什麼都沒印

第 2 步：改用字串

把數字換成文字，意思就看得出來了：

string status = "Paid";

if (status == "Paid")
{
    Console.WriteLine("已付款，可以出貨");
}

// 輸出：
// 已付款，可以出貨

但打錯字的問題還在。大小寫不同就是不同的字串：

string status = "Paid";

if (status == "paid")
{
    Console.WriteLine("已付款，可以出貨");
}

// 可以編譯，沒有任何錯誤或警告。執行後什麼都沒印

數字和字串的共同問題：編譯器不知道「合法的狀態只有四種」，所以什麼值都讓你寫。

第 3 步：用 enum 把四種狀態列出來

enum 宣告一個新的型別，大括號裡列出它所有的成員。程式裡要寫這個型別的值，就寫「型別名稱.成員名稱」：

OrderStatus status = OrderStatus.Paid;

if (status == OrderStatus.Paid)
{
    Console.WriteLine("已付款，可以出貨");
}

enum OrderStatus
{
    Pending,
    Paid,
    Shipped,
    Cancelled
}

// 輸出：
// 已付款，可以出貨

現在名字打錯，編譯就不會過。前兩步那種寫法也被擋下來：

// 名字打錯
if (status == OrderStatus.Payed)
error CS0117: 'OrderStatus' 未包含 'Payed' 的定義

// 拿數字來比
if (status == 1)
error CS0019: 運算子 '==' 不可套用至類型為 'OrderStatus' 和 'int' 的運算元

// 拿字串來比
if (status == "Paid")
error CS0019: 運算子 '==' 不可套用至類型為 'OrderStatus' 和 'string' 的運算元

另一個好處是在編輯器裡輸入 OrderStatus.，會列出所有成員讓你選。

第 4 步：每個名字背後是一個數字

enum 的成員不是字串，電腦實際記的是數字。直接把成員指派給 int 變數不行，要在前面寫 (int) 明確轉換：

int number = OrderStatus.Paid;
error CS0266: 無法將類型 'OrderStatus' 隱含轉換成 'int'。已存在明確轉換 (是否漏了轉型?)
Console.WriteLine((int)OrderStatus.Pending);
Console.WriteLine((int)OrderStatus.Paid);
Console.WriteLine((int)OrderStatus.Shipped);
Console.WriteLine((int)OrderStatus.Cancelled);

// 輸出：
// 0
// 1
// 2
// 3

第 3 步的宣告沒有寫任何數字，編譯器照順序給：第一個成員是 0，之後每個加 1。

第 5 步：自己寫明每個成員的數字

數字也可以自己指定，在成員後面寫 = 數字：

enum OrderStatus
{
    Pending = 0,
    Paid = 1,
    Shipped = 2,
    Cancelled = 3
}

// 第 4 步那四行的輸出不變：
// 0
// 1
// 2
// 3

寫明之後，每個成員是多少直接看得到，不用從順序去數。這一頁後面的 OrderStatus 都是這個版本。

第 6 步：背後的數字是哪種型別

沒有特別寫的話，背後的數字是 int（4 個位元組）。在 enum 名稱後面加冒號，可以指定成別的整數型別，例如 byte（1 個位元組，0 到 255）：

Console.WriteLine(sizeof(OrderStatus));
Console.WriteLine(sizeof(Priority));

enum Priority : byte
{
    Low = 0,
    Normal = 1,
    High = 2
}

// 輸出：
// 4
// 1

sizeof 印出一個型別佔幾個位元組。指定成 byte 之後，成員的數字超過 255 編譯不會過：寫 TooBig = 256 會得到 error CS0031: 常數值 '256' 不可轉換成 'byte'。只在 C# 裡用的 enum 不需要寫 : byte。

第 7 步：沒有設定時是數字 0 的那個成員

enum 的變數或屬性沒有設定過時，背後的數字是 0，所以印出來是數字 0 對應的成員：

Console.WriteLine(default(OrderStatus));

var order = new Order();           // 沒有設定 Status
Console.WriteLine(order.Status);

class Order
{
    public OrderStatus Status { get; set; }
}

// 輸出：
// Pending
// Pending

如果沒有任何成員是 0，例如三個成員分別是 Low = 10、Middle = 20、High = 30，default 印出來就是 0：一個沒有名字的數字（實際執行過）。default 的規則見 default 那一頁第 1 節。

2. 在 C# 裡轉換

enum 有三種樣子：成員（OrderStatus.Paid）、數字（1）、名字的字串（"Paid"）。上一節第 4 步用 (int) 把成員轉成數字；這一節一步看一個其他的方向，每一步都先看直接指派為什麼不行。顏色和上一節一樣：藍色是新的寫法，紅色是會出錯的寫法。

第 1 步：數字 → enum，前面寫 (OrderStatus)

手上有一個數字（例如從資料庫讀出來的 2），想知道它是哪個狀態。直接指派不行：

OrderStatus status = 2;
error CS0266: 無法將類型 'int' 隱含轉換成 'OrderStatus'。已存在明確轉換 (是否漏了轉型?)

和 enum 轉數字一樣，要明確寫出轉換，只是括號裡換成 enum 的名稱：

int number = 2;
OrderStatus status = (OrderStatus)number;
Console.WriteLine(status);

// 輸出：
// Shipped

這個轉換不會檢查數字有沒有對應的成員。把 2 換成 99，照樣可以編譯、執行，印出來是 99，沒有例外。

第 2 步：enum → 名字，用 ToString()

想拿到成員名字的字串。直接指派給 string 不行：

string name = OrderStatus.Shipped;
error CS0029: 無法將類型 'OrderStatus' 隱含轉換成 'string'
string name = OrderStatus.Shipped.ToString();
Console.WriteLine(name);
Console.WriteLine(name.Length);

// 輸出：
// Shipped
// 7

Console.WriteLine(OrderStatus.Shipped) 和 $"狀態：{OrderStatus.Shipped}" 會自動做同一件事，所以印出來的也是名字，不是數字。

第 3 步：名字 → enum，用 Enum.Parse

反過來，手上有一個字串 "Cancelled"。直接指派不行，前面加 (OrderStatus) 也不行：

OrderStatus status = "Cancelled";
error CS0029: 無法將類型 'string' 隱含轉換成 'OrderStatus'

OrderStatus status = (OrderStatus)"Cancelled";
error CS0030: 無法將類型 'string' 轉換成 'OrderStatus'

要呼叫 Enum.Parse，角括號裡寫要轉成哪個 enum：

OrderStatus status = Enum.Parse<OrderStatus>("Cancelled");
Console.WriteLine(status);
Console.WriteLine((int)status);

// 輸出：
// Cancelled
// 3

第 4 步：名字不存在時，Parse 丟例外，改用 TryParse

字串如果是從外面來的，可能根本不是任何成員的名字：

OrderStatus status = Enum.Parse<OrderStatus>("Refunded");

// 執行：
// Unhandled exception. System.ArgumentException: Requested value 'Refunded' was not found.

不確定字串對不對的時候，用 Enum.TryParse。它不丟例外，用回傳的 bool 告訴你成不成功；成功時轉出來的成員放進 out 後面的變數：

if (Enum.TryParse<OrderStatus>("Refunded", out var status))
{
    Console.WriteLine($"轉換成功：{status}");
}
else
{
    Console.WriteLine("沒有這個名字");
}

// 輸出：
// 沒有這個名字

只想知道有沒有這個名字、不需要轉出來的成員時，寫 out _：Enum.TryParse<OrderStatus>("Refunded", out _) 是 False。

第 5 步：列出所有成員，用 Enum.GetValues

前四步都是一次轉一個。要拿到這個 enum 定義的所有成員（例如做下拉選單），用 Enum.GetValues：

OrderStatus[] all = Enum.GetValues<OrderStatus>();

Console.WriteLine(all.Length);
Console.WriteLine(string.Join(", ", all));

// 輸出：
// 4
// Pending, Paid, Shipped, Cancelled

回傳的是陣列，順序依數字由小到大，和宣告時寫的順序無關（把成員宣告成 C = 3, A = 1, B = 2，拿到的是 A, B, C，實際執行過）。

第 6 步：用在「沒指定就當作全部」

GetValues 常見的用途：篩選條件裡的狀態可以不選，沒選就當作四種都要。屬性宣告成 OrderStatus?，沒選時是 null：

var filter = new OrderFilter();
Console.WriteLine(string.Join(", ", filter.Statuses()));     // 沒選

filter.Status = OrderStatus.Shipped;
Console.WriteLine(string.Join(", ", filter.Statuses()));     // 選了 Shipped

class OrderFilter
{
    public OrderStatus? Status { get; set; }

    public IReadOnlyList<OrderStatus> Statuses()
    {
        if (Status is null)
        {
            return Enum.GetValues<OrderStatus>();     // 沒選：四種全部
        }

        return [Status.Value];                        // 有選：只有那一種的清單
    }
}

// 輸出：
// Pending, Paid, Shipped, Cancelled
// Shipped

不管有沒有選，呼叫的人拿到的都是一份清單，後面的程式不用再分兩種情況。

五種轉換整理

想做的事寫法失敗時
enum → 數字(int)status不會失敗
數字 → enum(OrderStatus)數字不會失敗，就算沒有這個數字
enum → 名字status.ToString()不會失敗

3. EF Core 怎麼存進資料庫

資料庫沒有 enum 這種型別，所以 enum 的屬性要換成資料庫有的型別才能存。這一節從一個只有一個 enum 屬性的類別開始，請 EF Core 印出它會建立的資料表，看欄位是什麼型別；之後一步改一個地方，看欄位怎麼跟著變。藍色是這一步多出來的寫法，綠色是 SQL 裡跟著變的地方。

第 1 步：一個 enum 屬性，欄位是 int

#:package Microsoft.EntityFrameworkCore.SqlServer@10.0.15
#:property PublishAot=false
using Microsoft.EntityFrameworkCore;

using var db = new ShopDb();
Console.WriteLine(db.Database.GenerateCreateScript());

class Ticket
{
    public int Id { get; set; }
    public OrderStatus Status { get; set; }
}

class ShopDb : DbContext
{
    public DbSet<Ticket> Tickets => Set<Ticket>();

    protected override void OnConfiguring(DbContextOptionsBuilder options)
    {
        options.UseSqlServer("Server=none;Database=none");
    }
}

enum OrderStatus
{
    Pending = 0,
    Paid = 1,
    Shipped = 2,
    Cancelled = 3
}

GenerateCreateScript() 回傳 EF Core 依這個模型會用的建表語法，是一段文字。它不會連線，所以連線字串隨便寫也能執行。開頭的 #:property PublishAot=false 是單檔程式用 EF Core 時要加的設定；沒加的話，執行時會丟 InvalidOperationException: Model building is not supported when publishing with NativeAOT。

輸出

CREATE TABLE [Tickets] (
    [Id] int NOT NULL IDENTITY,
    [Status] int NOT NULL,
    CONSTRAINT [PK_Tickets] PRIMARY KEY ([Id])
);
GO

沒有做任何設定，Status 欄位是 int。EF Core 預設存 enum 背後的數字。

第 2 步：背後是 byte 的 enum，欄位是 tinyint

在 Ticket 多加一個屬性，型別是第 1 節第 6 步的 Priority（enum Priority : byte）：

class Ticket
{
    public int Id { get; set; }
    public OrderStatus Status { get; set; }
    public Priority Priority { get; set; }
}

// 輸出：
CREATE TABLE [Tickets] (
    [Id] int NOT NULL IDENTITY,
    [Status] int NOT NULL,
    [Priority] tinyint NOT NULL,
    CONSTRAINT [PK_Tickets] PRIMARY KEY ([Id])
);
GO

欄位的型別跟著 enum 背後的型別走：int 對 int，byte 對 tinyint。這就是會寫 : byte 的常見原因：資料表是別人早就建好的、欄位是 tinyint 時，C# 這邊的 enum 就宣告成 : byte 來配合。

第 3 步：想在資料表裡直接看到名字，加 HasConversion<string>()

存數字的話，直接打開資料表看到的是 1、2、3，要對照程式才知道意思。在 ShopDb 裡加一段設定，指定 Status 這個屬性要轉成字串再存：

class ShopDb : DbContext
{
    public DbSet<Ticket> Tickets => Set<Ticket>();

    protected override void OnConfiguring(DbContextOptionsBuilder options)
    {
        options.UseSqlServer("Server=none;Database=none");
    }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<Ticket>().Property(t => t.Status).HasConversion<string>();
    }
}

// 輸出：
CREATE TABLE [Tickets] (
    [Id] int NOT NULL IDENTITY,
    [Status] nvarchar(max) NOT NULL,
    [Priority] tinyint NOT NULL,
    CONSTRAINT [PK_Tickets] PRIMARY KEY ([Id])
);
GO

Ticket 類別和 enum 都沒有改，Status 的型別還是 OrderStatus。只有資料庫那一邊變了：欄位從 int 變成文字，存進去的是成員的名字，例如 Paid。

第 4 步：nvarchar(max) 太大，加 HasMaxLength

EF Core 不知道名字最長會多長，所以給了 nvarchar(max)。成員的名字最長是 Cancelled（9 個字），接著寫 HasMaxLength(20) 指定長度：

modelBuilder.Entity<Ticket>().Property(t => t.Status).HasConversion<string>().HasMaxLength(20);

// 輸出：
CREATE TABLE [Tickets] (
    [Id] int NOT NULL IDENTITY,
    [Status] nvarchar(20) NOT NULL,
    [Priority] tinyint NOT NULL,
    CONSTRAINT [PK_Tickets] PRIMARY KEY ([Id])
);
GO

四步看到的三種對應：

C# 的宣告資料庫欄位存進去的內容
enum OrderStatus（背後是 int）int1
enum Priority : bytetinyint1
加上 HasConversion<string>()nvarcharPaid

存數字還是存文字

存數字（預設）存文字（HasConversion<string>()）
直接看資料表看到 1、2、3，要對照程式才知道意思看到 Paid、Shipped，一眼就懂
空間與比較小、快比較大
改成員的名字沒影響，資料庫裡是數字舊資料裡還是舊名字，讀不回來
改成員的數字、調順序舊資料的意思整個變掉沒影響
排序依數字依字母（Cancelled、Paid、Pending、Shipped）

兩種都有人用。重點是決定之後，另一邊就不能隨便動：存數字就不要改數字，存文字就不要改名字。

這一節的建表語法是 SQL Server provider 產生的。「實際存進去的內容」「排序的結果」「舊名字讀不回來」這三件事要真的寫入資料庫才看得到，這裡是用 SQLite 的記憶體資料庫跑同樣的模型確認的，沒有連到 SQL Server：欄位裡是 1 和 Paid；依文字欄位排序得到 Cancelled、Paid、Pending、Shipped；把欄位裡的文字改成 enum 沒有的名字再讀，EF Core 丟 InvalidOperationException: Cannot convert string value 'Payed' from the database to any value in the mapped 'OrderStatus' enum.

4. 查詢時怎麼翻成 SQL

在 LINQ 裡用 enum 寫條件，EF Core 會把它換成資料庫裡存的那個值。這一節從一個條件開始，一步換一種查詢，每一步都用 ToQueryString() 印出 EF Core 產生的 SQL；最後把欄位改成存文字，看同樣的 LINQ 翻出來的 SQL 哪裡不同。完整的實驗在 LINQ 實驗室 L4-11。藍色是這一步多出來的寫法，綠色是 SQL 裡跟著變的地方。

第 1 步：比對一個值

#:package Microsoft.EntityFrameworkCore.SqlServer@10.0.15
#:property PublishAot=false
using Microsoft.EntityFrameworkCore;

using var db = new ShopDb();

var query = db.Orders.Where(o => o.Status == OrderStatus.Paid);
Console.WriteLine(query.ToQueryString());

class Order
{
    public int Id { get; set; }
    public OrderStatus Status { get; set; }
}

class ShopDb : DbContext
{
    public DbSet<Order> Orders => Set<Order>();

    protected override void OnConfiguring(DbContextOptionsBuilder options)
    {
        options.UseSqlServer("Server=none;Database=none");
    }
}

enum OrderStatus
{
    Pending = 0,
    Paid = 1,
    Shipped = 2,
    Cancelled = 3
}

輸出

SELECT [o].[Id], [o].[Status]
FROM [Orders] AS [o]
WHERE [o].[Status] = 1

C# 寫的是 OrderStatus.Paid，SQL 裡出現的是 1。轉換是 EF Core 做的，不用自己寫 (int)。下面每一步只換 var query = … 那一行，其他不動。

第 2 步：比對一組值，Contains 變成 IN

要找「已付款或已出貨」的訂單。把要的狀態放進一個清單，條件寫成「清單裡有沒有這張訂單的狀態」：

var wanted = new List<OrderStatus> { OrderStatus.Paid, OrderStatus.Shipped };
var query = db.Orders.Where(o => wanted.Contains(o.Status));

// 輸出：
DECLARE @wanted1 int = 1;
DECLARE @wanted2 int = 2;

SELECT [o].[Id], [o].[Status]
FROM [Orders] AS [o]
WHERE [o].[Status] IN (@wanted1, @wanted2)

wanted.Contains(o.Status) 不是在 C# 裡一筆一筆比，而是整個條件被翻成 IN (…)。清單裡的兩個成員變成兩個參數 @wanted1、@wanted2；開頭兩行 DECLARE 是 ToQueryString() 用來列出參數值的寫法，值是 1 和 2。細節見 L4-10。

第 3 步：依狀態排序

var query = db.Orders.OrderBy(o => o.Status);

// 輸出：
SELECT [o].[Id], [o].[Status]
FROM [Orders] AS [o]
ORDER BY [o].[Status]

排序是資料庫做的，依的是欄位裡的值。欄位存數字，順序就是 Pending (0)、Paid (1)、Shipped (2)、Cancelled (3)。

第 4 步：欄位改成存文字，LINQ 一個字都不改

在 ShopDb 加上第 3 節第 4 步的設定，讓 Status 存文字：

protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Order>().Property(o => o.Status).HasConversion<string>().HasMaxLength(20);
}

前三步的 LINQ 原封不動再跑一次：

// 第 1 步的查詢
SELECT [o].[Id], [o].[Status]
FROM [Orders] AS [o]
WHERE [o].[Status] = N'Paid'

// 第 2 步的查詢
DECLARE @wanted1 nvarchar(20) = N'Paid';
DECLARE @wanted2 nvarchar(20) = N'Shipped';

SELECT [o].[Id], [o].[Status]
FROM [Orders] AS [o]
WHERE [o].[Status] IN (@wanted1, @wanted2)

// 第 3 步的查詢
SELECT [o].[Id], [o].[Status]
FROM [Orders] AS [o]
ORDER BY [o].[Status]
  • C# 這邊的寫法完全一樣，SQL 裡出現的是資料庫存的那種值：存數字時是 1，存文字時是 N'Paid'
  • 排序的 SQL 看起來沒變，但欄位裡現在是文字，所以排出來是字母順序：Cancelled、Paid、Pending、Shipped
  • 讀回來的時候反過來：資料庫回 1（或 Paid），C# 這邊拿到的是 OrderStatus.Paid
  • 上面兩點要真的執行查詢才看得到，是用 SQLite 的記憶體資料庫確認的，沒有連到 SQL Server

5. 進出 API 時：數字還是名字

enum 轉成 JSON 時，也要選數字或名字（JSON 的基本規則見 JSON 那一頁）。這一節先看什麼都不設定時轉出去、收進來各是什麼，再看對方送名字進來會怎樣，最後才加上轉換器。藍色是這一步多出來的寫法，紅色是會出錯或要小心的地方。

第 1 步：轉成 JSON，預設是數字

#:property PublishAot=false
using System.Text.Json;
using System.Text.Json.Serialization;

var dto = new OrderDto { Id = 5, Status = OrderStatus.Paid };
Console.WriteLine(JsonSerializer.Serialize(dto));

class OrderDto
{
    public int Id { get; set; }
    public OrderStatus Status { get; set; }
}

enum OrderStatus
{
    Pending = 0,
    Paid = 1,
    Shipped = 2,
    Cancelled = 3
}

// 輸出：
// {"Id":5,"Status":1}

Status 轉出來是 1，不是 "Paid"。下面每一步的 OrderDto、OrderStatus 和開頭三行都一樣，只列有變的部分。開頭的 #:property PublishAot=false 是單檔程式用 JsonSerializer 時要加的設定，沒加的話執行時會丟 InvalidOperationException: Reflection-based serialization has been disabled for this application。

第 2 步：收進來，數字可以

var dto = JsonSerializer.Deserialize<OrderDto>("""{"Id":5,"Status":2}""")!;
Console.WriteLine(dto.Status);

// 輸出：
// Shipped

第 3 步：對方送名字進來，整個轉換失敗

var dto = JsonSerializer.Deserialize<OrderDto>("""{"Id":5,"Status":"Shipped"}""")!;

// 執行：
// Unhandled exception. System.Text.Json.JsonException: The JSON value could not be converted to OrderStatus. Path: $.Status | LineNumber: 0 | BytePositionInLine: 26.

預設只收數字。名字明明是對的，還是丟 JsonException，而且是整個物件轉換失敗，不是只有 Status 這一個屬性沒設定到。

第 4 步：加上 JsonStringEnumConverter，改用名字

建立一個 JsonSerializerOptions，在 Converters 裡加一個 JsonStringEnumConverter，轉換時把這個設定傳進去：

var withNames = new JsonSerializerOptions { Converters = { new JsonStringEnumConverter() } };

var dto = JsonSerializer.Deserialize<OrderDto>("""{"Id":5,"Status":"Shipped"}""", withNames)!;
Console.WriteLine(dto.Status);
Console.WriteLine(JsonSerializer.Serialize(dto, withNames));

// 輸出：
// Shipped
// {"Id":5,"Status":"Shipped"}

收名字成功了，轉出去也變成名字。加了轉換器之後，另外兩種情況（實際執行過）：

  • 送數字 "Status": 2：還是收，得到 Shipped
  • 送不存在的名字 "Status": "Refunded"：丟 JsonException，訊息同樣是 The JSON value could not be converted to OrderStatus

第 5 步：不存在的數字不會被擋下來

var dto = JsonSerializer.Deserialize<OrderDto>("""{"Id":5,"Status":99}""")!;
Console.WriteLine(dto.Status);

// 輸出：
// 99

沒有 99 這個成員，轉換照樣成功，Status 是一個沒有名字的 99。加了第 4 步的轉換器也一樣：收進來是 99，再轉出去是 {"Id":5,"Status":99}（實際執行過）。原因和第 2 節第 1 步的 (OrderStatus)99 相同。

  • 前端與後端要先講好 enum 用數字還是名字。後端沒有加轉換器時只收數字，前端送名字，整個請求就會失敗
  • 不同的框架預設不同。舊的 ASP.NET MVC 兩種都收，換到 ASP.NET Core 之後只收數字，搬移 API 時要特別確認（這一點沒有在這台機器上實測）

6. 常見的坑

三個彼此無關的坑，共同點是程式不會報錯，結果卻不對。每一個都先讓它發生，再看怎麼避開。藍色是避開的寫法，紅色是出問題的地方。

不存在的數字也能轉成 enum

第 2 節第 1 步看過 (OrderStatus)99 不會失敗。enum 只是有名字的數字，C# 不會檢查數字有沒有對應的名字：

var weird = (OrderStatus)99;

Console.WriteLine(weird);

// 輸出：
// 99

從外面進來的值（API 的請求、資料庫裡的舊資料）都可能是沒定義的數字。Enum.IsDefined 可以檢查一個值是不是定義過的成員：

Console.WriteLine(Enum.IsDefined(weird));
Console.WriteLine(Enum.IsDefined(OrderStatus.Paid));

// 輸出：
// False
// True

另一個地方是 switch。四個成員各寫一個 case，看起來每種情況都處理到了，但 status 還可能是 99。在最後加 default:，處理沒預期到的值：

Console.WriteLine(Describe(OrderStatus.Paid));
Console.WriteLine(Describe((OrderStatus)99));

static string Describe(OrderStatus status)
{
    switch (status)
    {
        case OrderStatus.Pending:
            return "等待付款";
        case OrderStatus.Paid:
            return "已付款";
        case OrderStatus.Shipped:
            return "已出貨";
        case OrderStatus.Cancelled:
            return "已取消";
        default:
            return $"不認得的狀態（{(int)status}）";
    }
}

// 輸出：
// 已付款
// 不認得的狀態（99）

把藍色那兩行拿掉，這個方法編譯不會過：error CS0161: 'Describe(OrderStatus)': 不是所有程式碼路徑都有傳回值。編譯器也知道四個 case 沒有涵蓋所有可能的值。

改了數字，舊資料的意思就變了

用沒有寫數字的 enum，把「已付款」存進資料庫。存進去的是數字：

Console.WriteLine((int)OrderStatus.Paid);

enum OrderStatus
{
    Pending,
    Paid,
    Shipped,
    Cancelled
}

// 輸出：
// 1

資料庫裡現在有一筆 1。後來有人在 Pending 和 Paid 中間加了一個新狀態。程式更新後，把資料庫裡那個 1 讀回來：

Console.WriteLine((OrderStatus)1);

enum OrderStatus
{
    Pending,
    Confirmed,
    Paid,
    Shipped,
    Cancelled
}

// 輸出：
// Confirmed

存進去的時候是「已付款」，讀出來變成「已確認」。沒有寫數字時，數字是照順序給的（第 1 節第 4 步），中間插一個，後面的成員全部往後移一號：Paid 變成 2。資料沒動，意思卻變了，而且不會有任何錯誤。

避開的方法是每個成員都寫明數字，新成員用一個沒用過的數字：

Console.WriteLine((OrderStatus)1);

enum OrderStatus
{
    Pending = 0,
    Paid = 1,
    Shipped = 2,
    Cancelled = 3,
    Confirmed = 4
}

// 輸出：
// Paid
  • 每個成員都明確寫 = 數字，新成員用新的數字加在最後面。寫明之後，就算把 Confirmed = 4 那一行搬到 Pending 和 Paid 中間，(OrderStatus)1 還是 Paid（實際執行過）
  • 已經在用的數字不要改，也不要拿去給別的意思用

兩個 enum 的數字相同，意思不一定相同

OrderStatus.Paid 和 Priority.Normal 背後都是 1，但意思毫無關係。直接拿兩種 enum 互相比較，編譯器會擋下來：

Console.WriteLine(OrderStatus.Paid == Priority.Normal);
error CS0019: 運算子 '==' 不可套用至類型為 'OrderStatus' 和 'Priority' 的運算元

如果為了讓它能編譯，兩邊都先轉成數字：

Console.WriteLine((int)OrderStatus.Paid == (int)Priority.Normal);

// 輸出：
// True

可以編譯了，結果是 True：「已付款」等於「普通優先」。編譯器那個錯誤本來就是在擋這種比較，轉成數字等於自己把這層保護拿掉。看到要加 (int) 才能比的時候，先確認兩邊是不是同一種東西。

7. 顯示用的狀態與資料庫的狀態：對應表

資料庫裡的狀態通常分得很細，給使用者看的卻只需要幾種。例如訂單有四種狀態，畫面上只想分成三種進度。這一節先做「狀態 → 進度」這個方向，再做反方向，最後把反查的結果放進查詢。藍色是這一步多出來的寫法，紅色是會出錯的寫法。

資料庫的狀態給使用者看的進度
Pending (0)進行中
Paid (1)進行中
Shipped (2)已完成
Cancelled (3)已取消

第 1 步：把上面那張表寫成 Dictionary，用狀態查進度

用一個 Dictionary 當對應表：key 是資料庫的狀態，value 是顯示用的進度。手上有一個狀態時，用中括號就查得到進度：

var progressMapping = new Dictionary<OrderStatus, string>
{
    [OrderStatus.Pending] = "進行中",
    [OrderStatus.Paid] = "進行中",
    [OrderStatus.Shipped] = "已完成",
    [OrderStatus.Cancelled] = "已取消",
};

OrderStatus status = OrderStatus.Paid;
Console.WriteLine(progressMapping[status]);
Console.WriteLine(progressMapping[OrderStatus.Cancelled]);

// 輸出：
// 進行中
// 已取消

這個方向用在查詢之後：資料庫回來的每一筆訂單都有 Status，查表換成要顯示的文字。

第 2 步：反過來，用進度查狀態，中括號不能用

使用者在畫面上選的是「進行中」。要去資料庫查，得先知道「進行中」是哪幾個狀態。照第 1 步的寫法把文字放進中括號：

Console.WriteLine(progressMapping["進行中"]);
error CS1503: 引數 1: 無法從 'string' 轉換成 'OrderStatus'

中括號裡只能放 key，這張表的 key 是 OrderStatus。而且「進行中」對應到兩個狀態，答案不會只有一個。

第 3 步：用 Where 挑出 value 是「進行中」的那幾組

Dictionary 裡的每一組 key 和 value 可以一組一組拿出來看。Where 留下 value 等於「進行中」的：

var pairs = progressMapping.Where(pair => pair.Value == "進行中");

foreach (var pair in pairs)
{
    Console.WriteLine($"{pair.Key} → {pair.Value}");
}

// 輸出：
// Pending → 進行中
// Paid → 進行中

四組剩下兩組。每一組還是 key 和 value 一起。

第 4 步：用 Select 只留下 key

要拿去查資料庫的只有狀態，文字不需要。Select 從每一組裡只取 Key，ToList 把結果做成清單：

var statuses = progressMapping
    .Where(pair => pair.Value == "進行中")
    .Select(pair => pair.Key)
    .ToList();

Console.WriteLine(string.Join(", ", statuses));

// 輸出：
// Pending, Paid

statuses 的型別是 List<OrderStatus>。

第 5 步：把反查出來的清單放進查詢條件

接下來就是第 4 節第 2 步的寫法：清單 Contains 訂單的狀態。db、Order 沿用第 4 節第 1 步的程式（欄位存數字）：

var query = db.Orders.Where(o => statuses.Contains(o.Status));
Console.WriteLine(query.ToQueryString());

// 輸出：
DECLARE @statuses1 int = 0;
DECLARE @statuses2 int = 1;

SELECT [o].[Id], [o].[Status]
FROM [Orders] AS [o]
WHERE [o].[Status] IN (@statuses1, @statuses2)

使用者選的「進行中」，到資料庫變成 IN 兩個參數，值是 0 和 1，也就是 Pending 和 Paid。

第 6 步：為什麼反查要取 key，不是 value

如果第 4 步的 Select 取的是 pair.Value，拿到的清單是 List<string>，放進查詢條件編譯不會過：

var labels = progressMapping
    .Where(pair => pair.Value == "進行中")
    .Select(pair => pair.Value)
    .ToList();

var query = db.Orders.Where(o => labels.Contains(o.Status));
error CS1503: 引數 1: 無法從 'OrderStatus' 轉換成 'string'

Contains 兩邊要是同一種東西才能比。o.Status 是資料庫的狀態（OrderStatus），所以清單裡也必須是 OrderStatus，也就是對應表的 key。

型別是什麼
對應表的 keyOrderStatus資料庫認得的值
對應表的 valuestring給使用者看的文字，資料庫不認得
statusesList<OrderStatus>反查出來的 key
o.StatusOrderStatus資料表的欄位

第 7 步：同一張表用兩次，方向相反

把前面幾步接起來，就是一次完整的查詢：

// 查詢前：使用者選「進行中」，用 value 找 key（第 3、4 步）
var statuses = progressMapping
    .Where(pair => pair.Value == "進行中")
    .Select(pair => pair.Key)
    .ToList();

// 查詢：清單放進條件（第 5 步）
var orders = await db.Orders
    .Where(o => statuses.Contains(o.Status))
    .ToListAsync();

// 查詢後：每一筆訂單用 key 找 value（第 1 步）
foreach (var order in orders)
{
    Console.WriteLine($"訂單 {order.Id}：{progressMapping[order.Status]}");
}

ToListAsync() 會真的連上資料庫執行查詢，所以這一段沒有附輸出；查詢條件翻成的 SQL 見第 5 步。

查詢前：手上有的是使用者選的進度（value），要換成資料庫的狀態（key），可能有好幾個。換出來的清單放進查詢條件。

查詢後：手上有的是資料庫回來的狀態（key），要換成顯示用的進度（value），剛好一個。換出來的文字顯示給使用者。

完整的實驗（含 SQL 與使用者選了不存在的進度時會怎樣）在 LINQ 實驗室 L4-12。有好幾張表、每張表的狀態 enum 不同時，反查的那三行可以寫成一個泛型方法共用，見 default 那一頁第 5 節。
