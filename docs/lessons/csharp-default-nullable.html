C# 補充：default、可空型別、?. 與會加工的屬性

讀別人的程式時常卡住的幾個小語法：== default 到底在跟什麼比、加了 ?. 之後為什麼判斷就不對了、?? 與 ??=、屬性的 set => field = …，最後用一個例子看泛型什麼時候值得用。

default== default可空型別Nullable?.????=field屬性 setter泛型where T : struct, Enum

📌 這頁是 C# 語法，和專案無關。每一節都從最短的寫法開始，一步只多一樣東西；可以遇到的時候再回來查其中一節。頁面上的輸出和編譯器訊息，都是單檔程式實際執行的結果（.NET 10）。

目錄
  1. default 是多少：看型別
  2. ?. 會讓 default 的意思變掉
  3. ?? 與 ??=：沒有值時補上
  4. 會加工的屬性：set => field = …
  5. 泛型：把「型別」也變成參數

1. default 是多少：看型別

default 的意思是「這個型別什麼都沒設定時的值」。它不是固定的一個值，依型別而定。這一節先看沒設定過的屬性裡面是什麼，再看怎麼用 default 寫出同一個值，最後才到 == default。

程式裡的顏色：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或結果和預期不同的寫法。

第 1 步：沒有設定過的屬性，印出來是什麼

建立一個物件，五個屬性都不設定，直接印：

var box = new Box();

Console.WriteLine(box.Count);
Console.WriteLine(box.Price);
Console.WriteLine(box.IsOpen);
Console.WriteLine(box.CreatedAt);
Console.WriteLine(box.Name is null);

class Box
{
    public int Count { get; set; }
    public decimal Price { get; set; }
    public bool IsOpen { get; set; }
    public DateTime CreatedAt { get; set; }
    public string? Name { get; set; }
}

// 輸出：
// 0
// 0
// False
// 0001/1/1 上午 12:00:00
// True

沒有設定不代表「裡面沒有東西」，每個屬性都有一個值：數字是 0，bool 是 False，DateTime 是西元 1 年 1 月 1 日 0 點，string 是 null。日期印出來的樣子跟著電腦的地區設定，這台是 zh-TW，所以是 0001/1/1 上午 12:00:00。

第 2 步：用 default(型別) 直接寫出這個值

第 1 步要先有一個物件才看得到那些值。default(型別) 可以直接寫出「這個型別沒設定時的值」：

Console.WriteLine(default(int));              // 0
Console.WriteLine(default(decimal));          // 0
Console.WriteLine(default(bool));             // False
Console.WriteLine(default(DateTime));         // 0001/1/1 上午 12:00:00
Console.WriteLine(default(DateTimeOffset));   // 0001/1/1 上午 12:00:00 +00:00
Console.WriteLine(default(string) is null);   // True
Console.WriteLine(default(int?) is null);     // True

前四個和第 1 步印出來的一樣。default(string) is null 那一行編譯時有一個 warning CS8520: 指定的運算式永遠符合提供的常數。，意思是編譯器已經知道結果一定是 True。各種型別整理成一張表：

型別default為什麼
int、decimal 等數字0值型別：所有位元都是 0
boolfalse同上
DateTime西元 1 年 1 月 1 日 0 點同上，剛好等於 DateTime.MinValue
DateTimeOffset西元 1 年 1 月 1 日 0 點，時差 +00:00同上，等於 DateTimeOffset.MinValue
enum數字 0 對應的那個成員enum 背後是數字，見enum 那一頁
string、class、List<T>null參考型別：沒有指向任何物件
int?、DateTime? 等可空型別null可空型別的「沒有值」

第 3 步：旁邊已經有型別時，括號可以不寫

宣告變數時左邊已經寫了型別，右邊再寫一次 default(int) 是重複的。只寫 default，編譯器會用左邊的型別：

int count = default;                  // 左邊是 int，所以是 default(int)
DateTimeOffset begin = default;       // 左邊是 DateTimeOffset，所以是 default(DateTimeOffset)
string? name = default;               // 左邊是 string?，所以是 null

Console.WriteLine(count);
Console.WriteLine(begin);
Console.WriteLine(name is null);

// 輸出：
// 0
// 0001/1/1 上午 12:00:00 +00:00
// True

旁邊沒有型別可以看的時候，只寫 default 編譯不會過：

var count = default;
error CS8716: 預設常值沒有目標類型。

var 是請編譯器從右邊推出型別，右邊的 default 又要從左邊拿型別，兩邊都沒有。

第 4 步：== default，型別看另一邊

比較的時候也一樣。== 的一邊是 default，編譯器就用另一邊的型別來決定它是哪個 default：

var box = new SearchBox();     // 沒有設定 TimeBegin

Console.WriteLine(box.TimeBegin == default(DateTimeOffset));    // 寫明型別
Console.WriteLine(box.TimeBegin == default);                    // 左邊是 DateTimeOffset，所以是同一件事
Console.WriteLine(box.TimeBegin == DateTimeOffset.MinValue);    // 同一個值

box.TimeBegin = new DateTimeOffset(2026, 1, 1, 0, 0, 0, TimeSpan.Zero);
Console.WriteLine(box.TimeBegin == default);                    // 設定過了

class SearchBox
{
    public DateTimeOffset TimeBegin { get; set; }
}

// 輸出：
// True
// True
// True
// False

這就是 == default 常見的用途：判斷一個屬性「有沒有被設定過」。以 JSON 為例，用 JsonSerializer.Deserialize<SearchBox>("{}") 把一段沒有 TimeBegin 欄位的 JSON 轉成物件，轉出來的 TimeBegin == default 是 True（實際執行過），所以可以用它判斷「對方沒送這個欄位」。

想自己看：Rider 把游標移到 default 上會顯示它被推斷成哪個型別；或在中斷點的 Evaluate 視窗輸入 default(DateTimeOffset)。

2. ?. 會讓 default 的意思變掉

上一節最後的 box.TimeBegin == default 判斷得出「時間沒設定」。這一節從那一行開始，看物件本身可能是 null 時，為了不丟例外加上 ?.，同一個判斷的結果為什麼會跟著變。

程式裡的顏色：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或結果和預期不同的寫法。

第 1 步：物件一定存在時，判斷是對的

var search = new SearchBox();     // 沒設定 TimeBegin

Console.WriteLine(search.TimeBegin == default);

class SearchBox
{
    public DateTimeOffset TimeBegin { get; set; }
}

// 輸出：
// True

下面每一步的 SearchBox 都是這個類別，不再重複列出。

第 2 步：物件可能是 null，取屬性會丟例外

變數的型別寫成 SearchBox?，表示它可能是 null。這時直接寫 maybe.TimeBegin：

SearchBox? maybe = null;

Console.WriteLine(maybe.TimeBegin == default);

warning CS8602: 可能 null 參考的取值 (dereference)。

// 執行：
// Unhandled exception. System.NullReferenceException: Object reference not set to an instance of an object.

編譯時有警告，執行時 maybe 是 null，取不到 TimeBegin，丟出例外。

第 3 步：點前面加一個 ?，是 null 就不取

maybe?.TimeBegin 的意思是「maybe 不是 null 才取 TimeBegin；是 null 的話，整個算式的結果就是 null」：

SearchBox? maybe = null;

Console.WriteLine(maybe?.TimeBegin is null);

// 輸出：
// True

警告和例外都沒有了。

第 4 步：物件存在、時間沒設定，結果卻是 False

既然 ?. 不會丟例外，就把它用在第 1 步的判斷上。這次 maybe 裡有物件，時間沒有設定，和第 1 步是同一種情況：

SearchBox? maybe = new SearchBox();     // 有物件，沒設定 TimeBegin

Console.WriteLine(maybe.TimeBegin == default);     // 沒有 ?.
Console.WriteLine(maybe?.TimeBegin == default);    // 有 ?.

// 輸出：
// True
// False

同一個物件、同一個屬性，只差一個 ?，結果相反。有 ?. 的那一行沒有判斷出「時間沒設定」。

第 5 步：原因是 ?. 算出來的型別不一樣

第 3 步說過，maybe?.TimeBegin 的結果可能是 null。DateTimeOffset 放不了 null，所以這個算式的型別不是 DateTimeOffset。把它指派給一個 DateTimeOffset 變數，編譯器會說出它真正的型別：

SearchBox? maybe = new SearchBox();

DateTimeOffset begin = maybe?.TimeBegin;
error CS0266: 無法將類型 'System.DateTimeOffset?' 隱含轉換成 'System.DateTimeOffset'。已存在明確轉換 (是否漏了轉型?)

型別是 DateTimeOffset?，多了一個問號，是「可以是 null 的 DateTimeOffset」。上一節第 4 步的規則是 default 看另一邊的型別，所以兩行裡的 default 不是同一個值：

  • maybe.TimeBegin == default：左邊是 DateTimeOffset，default 是西元 1 年 1 月 1 日。沒設定的時間正好是這個值，所以 True
  • maybe?.TimeBegin == default：左邊是 DateTimeOffset?，default 是 null。左邊算出來是西元 1 年 1 月 1 日，不是 null，所以 False

把變數的型別改成 DateTimeOffset? 就能編譯，可以直接印出來確認：

DateTimeOffset? begin = maybe?.TimeBegin;

Console.WriteLine(begin);                                // 0001/1/1 上午 12:00:00 +00:00
Console.WriteLine(begin is null);                        // False
Console.WriteLine(default(DateTimeOffset?) is null);     // True

第 6 步：三種情況放在一起看

SearchBox? nothing = null;                 // 沒有物件
SearchBox? unset = new SearchBox();        // 有物件，時間沒設定
SearchBox? filled = new SearchBox { TimeBegin = new DateTimeOffset(2026, 1, 1, 0, 0, 0, TimeSpan.Zero) };

Console.WriteLine(nothing?.TimeBegin == default);
Console.WriteLine(unset?.TimeBegin == default);
Console.WriteLine(filled?.TimeBegin == default);

// 輸出：
// True
// False
// False
  • nothing：True，但原因是整個物件是 null，不是時間沒設定
  • unset：False。時間沒設定，卻和下一行有設定時間的結果一樣
  • filled：False

⚠️ 這個錯不會有任何警告。有沒有 ?. 都能編譯、都不會丟例外，只是 == default 比的東西不同。加了 ?. 之後，「時間沒設定」的情況就判斷不出來。

第 7 步：分兩次判斷

先判斷物件是不是 null，確定不是之後再用沒有 ?. 的寫法判斷屬性。用上一步的三個變數各呼叫一次：

Check(nothing);
Check(unset);
Check(filled);

void Check(SearchBox? maybe)
{
    if (maybe is null)
    {
        Console.WriteLine("整個物件沒有");
    }
    else if (maybe.TimeBegin == default)     // 這裡沒有 ?.，左邊的型別是 DateTimeOffset
    {
        Console.WriteLine("物件有，但時間沒設定");
    }
    else
    {
        Console.WriteLine("時間有設定");
    }
}

// 輸出：
// 整個物件沒有
// 物件有，但時間沒設定
// 時間有設定

三種情況各走一條路。else if 那一行沒有第 2 步的警告，因為前面的 if 已經排除了 null。

3. ?? 與 ??=：沒有值時補上

「每頁幾筆」這種設定常常宣告成 int?：對方沒給就是 null。真正要用的時候需要一個確定的數字，所以要把 null 換成預設值。這一節從最直接的寫法開始，看 ?? 和 ??= 各省掉了什麼。

程式裡的顏色：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或結果和預期不同的寫法。

第 1 步：int? 不能直接當 int 用

int? count = null;

int size = count;
error CS0266: 無法將類型 'int?' 隱含轉換成 'int'。已存在明確轉換 (是否漏了轉型?)

count 可能是 null，int 放不了 null，編譯器不讓過。

第 2 步：用 if 分成兩種情況

int? count = null;

int size;
if (count is null)
{
    size = 10;                // 沒有值：用 10
}
else
{
    size = count.Value;       // 有值：.Value 取出 int? 裡面的那個 int
}

Console.WriteLine(size);

// 輸出：
// 10

可以用了，但「沒有就用 10」這麼簡單的一件事，寫了一整段 if / else。

第 3 步：?? 把那一段寫成一行

a ?? b 的意思是：a 不是 null 就用 a，是 null 就用 b。

int? count = null;

int size = count ?? 10;

Console.WriteLine(size);              // 10
Console.WriteLine(count is null);     // True  ← count 本身沒有變

int? given = 30;
Console.WriteLine(given ?? 10);        // 30    ← 有值就用原本的值

?? 只是算出一個值，不會改到左邊的變數：算完之後 count 還是 null。

第 4 步：想讓 count 自己變成 10

如果後面還有好幾個地方要用 count，每個地方都寫 count ?? 10 很容易漏掉一個。可以把算出來的值指派回 count：

int? count = null;

count = count ?? 10;
Console.WriteLine(count);

// 輸出：
// 10

count 這個名字在同一行寫了兩次。

第 5 步：??= 把那一行再縮短

a ??= b 的意思是：a 是 null 才把 b 指派給 a；a 已經有值就什麼都不做。

int? count = null;

count ??= 10;                 // count 是 null，所以變成 10
Console.WriteLine(count);

count ??= 99;                 // count 已經是 10，這一行什麼都不做
Console.WriteLine(count);

// 輸出：
// 10
// 10

兩個寫法的差別只有一個：會不會改到左邊。

寫法意思會不會改到左邊
a ?? ba 不是 null 就用 a，是 null 就用 b不會，只是算出一個值
a ??= ba 是 null 才把 b 指派給 a會

什麼時候用哪一個：只有這一個地方需要補預設值，用 ??；之後每個地方都要拿到補好的值，用 ??= 先補一次。

4. 會加工的屬性：set => field = …

目標是看懂 set => field = value is < 0 or > MaxCount ? MaxCount : value; 這一行。它一次用了五種寫法，所以從最普通的 { get; set; } 開始，一步換一種。每一步都用同一段程式測試：先印初始值，再依序設成 40、500、-1，各印一次。

程式裡的顏色：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或結果和預期不同的寫法。

var page = new PageSetting();
Console.WriteLine(page.Count);
page.Count = 40;
Console.WriteLine(page.Count);
page.Count = 500;
Console.WriteLine(page.Count);
page.Count = -1;
Console.WriteLine(page.Count);

第 1 步：{ get; set; } 設什麼就是什麼

class PageSetting
{
    public int Count { get; set; }
}

// 輸出：
// 0
// 40
// 500
// -1

Count 是每頁幾筆。一頁 500 筆太多，-1 筆沒有意義，但這個屬性照單全收。想要的是：超出 0 到 100 的值，一律改成 100。

第 2 步：把 { get; set; } 做的事自己寫出來

要在設定值的時候加檢查，得先有地方寫程式。{ get; set; } 其實是下面這一段的簡寫：一個放資料的欄位，加上讀和寫各一段程式。

class PageSetting
{
    private int _count;

    public int Count
    {
        get { return _count; }
        set { _count = value; }
    }
}

// 輸出和第 1 步一樣：
// 0
// 40
// 500
// -1
  • _count：真正放資料的欄位。private，外面只能透過 Count 讀寫
  • get { … }：外面讀 page.Count 時執行，回傳 _count
  • set { … }：外面寫 page.Count = 500 時執行。value 是外面要設定進來的值，這時是 500

第 3 步：在 set 裡加上檢查

class PageSetting
{
    private int _count;

    public int Count
    {
        get { return _count; }
        set
        {
            if (value < 0 || value > 100)
            {
                _count = 100;
            }
            else
            {
                _count = value;
            }
        }
    }
}

// 輸出：
// 0
// 40
// 100     ← 設 500，放進欄位的是 100
// 100     ← 設 -1，放進欄位的是 100

功能到這裡就完成了。第 4 步到第 8 步都只是把同一件事寫短，輸出和這一步相同。

第 4 步：100 寫了兩次，給它一個名字

上限如果要改成 200，兩個 100 都要改，漏一個就錯。用 const 宣告一個常數，之後只改一個地方：

class PageSetting
{
    private const int MaxCount = 100;
    private int _count;

    public int Count
    {
        get { return _count; }
        set
        {
            if (value < 0 || value > MaxCount)
            {
                _count = MaxCount;
            }
            else
            {
                _count = value;
            }
        }
    }
}

const 的值寫下去就不能再改。在類別的方法裡寫 MaxCount = 200; 會得到 error CS0131: 指派的左側必須是變數、屬性或索引子。

第 5 步：if / else 換成 條件 ? A : B

if 和 else 兩邊都是「把某個值放進 _count」，只差放的是哪個值。條件 ? A : B 是一個算式：條件成立算出 A，不成立算出 B。

    public int Count
    {
        get { return _count; }
        set { _count = (value < 0 || value > MaxCount) ? MaxCount : value; }
    }

八行變成一行，_count = 只寫一次。

第 6 步：條件裡的 value 寫了兩次，換成 is … or …

        set { _count = value is < 0 or > MaxCount ? MaxCount : value; }

value is < 0 or > MaxCount 讀成「value 小於 0，或大於 MaxCount」，和 value < 0 || value > MaxCount 是同一個條件，value 只要寫一次。

第 7 步：只有一句的大括號換成 =>

get 和 set 的大括號裡現在都只有一句。只有一句時可以改寫成 =>：get => X 等於 get { return X; }，set => 一句話 等於 set { 一句話; }。

class PageSetting
{
    private const int MaxCount = 100;
    private int _count;

    public int Count
    {
        get => _count;
        set => _count = value is < 0 or > MaxCount ? MaxCount : value;
    }
}

第 8 步：用 field，不用自己宣告 _count

_count 這個欄位只有 Count 屬性在用，卻要另外宣告、另外取名字。在屬性裡寫 field，編譯器會替這個屬性產生一個欄位，field 就是它：

class PageSetting
{
    private const int MaxCount = 100;

    public int Count
    {
        get;
        set => field = value is < 0 or > MaxCount ? MaxCount : value;
    }
}

// 輸出：
// 0
// 40
// 100
// 100

private int _count; 那一行刪掉了。get 沒有要加工，寫回 get; 就好，意思是「回傳那個欄位」。field 是比較新的寫法，舊的程式裡看到的會是第 7 步的樣子，兩者做的事一樣。

第 9 步：初始值不要是 0

到目前為止，每一步的第一行輸出都是 0：沒有人設定過 Count，它就是 int 的 default（第 1 節）。每頁 0 筆不合理。在屬性的大括號後面寫 = 10;，物件一建立它就是 10：

class PageSetting
{
    private const int MaxCount = 100;

    public int Count
    {
        get;
        set => field = value is < 0 or > MaxCount ? MaxCount : value;
    } = 10;
}

// 輸出：
// 10      ← 初始值
// 40
// 100
// 100

這就是一開始要看懂的那一行。不用 field 的版本，初始值寫在欄位上：private int _count = 10;，輸出相同。

初始值不會經過 set 的檢查：把 = 10; 改成 = 500;，new PageSetting().Count 印出來是 500，不是 100（實際執行過）。初始值要自己寫成合理的數字。

什麼時候這樣寫：這個值有固定的合理範圍，而且希望不管誰來設定，物件裡的值都在範圍內，使用它的程式就不用各自再檢查一次。只是單純放資料的屬性，維持 { get; set; } 就好。

5. 泛型：把「型別」也變成參數

有時候幾個方法的內容一模一樣，只差在用的型別不同。方法簽章那一頁看過 <T> 的讀法；這一節從一個不用泛型的方法開始，看到什麼時候才需要它。

程式裡的顏色：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或結果和預期不同的寫法。

例子用到兩個 enum，下面每一步都有這兩個宣告，不再重複列出：

enum OrderStatus
{
    Pending = 0,
    Paid = 1,
    Shipped = 2,
    Cancelled = 3
}

enum Priority : byte
{
    Low = 0,
    Normal = 1,
    High = 2
}

第 1 步：一張對應表，一個方法

有一張對應表，key 是訂單狀態，value 是顯示用的文字。要做的事：給一個文字，找出對應到它的所有 key。

var progressMapping = new Dictionary<OrderStatus, string>
{
    [OrderStatus.Pending] = "進行中",
    [OrderStatus.Paid] = "進行中",
    [OrderStatus.Shipped] = "已完成",
    [OrderStatus.Cancelled] = "已取消",
};

Console.WriteLine(string.Join(", ", KeysOf(progressMapping, "進行中")));

static List<OrderStatus> KeysOf(Dictionary<OrderStatus, string> mapping, string label)
{
    return mapping
        .Where(pair => pair.Value == label)
        .Select(pair => pair.Key)
        .ToList();
}

// 輸出：
// Pending, Paid

只有這一張表的話，到這裡就夠了，不需要泛型。

第 2 步：來了第二張表，傳不進去

第二張對應表的 key 是另一個 enum。想用同一個 KeysOf：

var sizeMapping = new Dictionary<Priority, string>
{
    [Priority.Low] = "不急",
    [Priority.Normal] = "不急",
    [Priority.High] = "要快",
};

Console.WriteLine(string.Join(", ", KeysOf(sizeMapping, "不急")));
error CS1503: 引數 1: 無法從 'System.Collections.Generic.Dictionary<Priority, string>' 轉換成 'System.Collections.Generic.Dictionary<OrderStatus, string>'

KeysOf 的參數寫明了要 Dictionary<OrderStatus, string>，key 是 Priority 的表不是這個型別。

第 3 步：複製一份，只改型別

Console.WriteLine(string.Join(", ", ProgressKeysOf(progressMapping, "進行中")));
Console.WriteLine(string.Join(", ", SizeKeysOf(sizeMapping, "不急")));

static List<OrderStatus> ProgressKeysOf(Dictionary<OrderStatus, string> mapping, string label)
{
    return mapping
        .Where(pair => pair.Value == label)
        .Select(pair => pair.Key)
        .ToList();
}

static List<Priority> SizeKeysOf(Dictionary<Priority, string> mapping, string label)
{
    return mapping
        .Where(pair => pair.Value == label)
        .Select(pair => pair.Key)
        .ToList();
}

// 輸出：
// Pending, Paid
// Low, Normal

可以用了。但兩個方法的本體一個字都沒有不同，只差紅色那四個型別。每多一張對應表就要再複製一次；哪天本體要改，每一份都要改。

第 4 步：把型別換成一個之後再決定的名字

在方法名稱後面寫 <TKey>，宣告一個「之後再決定的型別」，名字是自己取的。原本寫 OrderStatus 的兩個地方都換成 TKey，方法只留一個：

Console.WriteLine(string.Join(", ", KeysOf(progressMapping, "進行中")));
Console.WriteLine(string.Join(", ", KeysOf(sizeMapping, "不急")));

static List<TKey> KeysOf<TKey>(Dictionary<TKey, string> mapping, string label)
{
    return mapping
        .Where(pair => pair.Value == label)
        .Select(pair => pair.Key)
        .ToList();
}

// 輸出：
// Pending, Paid
// Low, Normal
  • Dictionary<TKey, string> mapping：傳進來的對應表 key 是哪種型別，TKey 就是那種
  • List<TKey>：回傳的清單也是同一種型別。傳 progressMapping 進去拿到 List<OrderStatus>，傳 sizeMapping 進去拿到 List<Priority>

兩張表都能用了。不過編譯時多了一個警告：

warning CS8714: 型別 'TKey' 無法作為型別參數 'TKey' 用於泛型型別或方法 'Dictionary<TKey, TValue>' 中。型別引數 'TKey' 的可 Null 性與 'notnull' 限制式不符合。

Dictionary 規定 key 的型別不能是可為 null 的型別。現在的 TKey 沒有任何限制，什麼型別都能填，編譯器沒辦法確定它符合 Dictionary 的規定。另外，這個方法本來只打算給 enum 的對應表用，現在連 Dictionary<string, string> 也傳得進去（實際執行過，可以編譯也跑得出結果）。

第 5 步：用 where 限制 TKey 只能是 enum

static List<TKey> KeysOf<TKey>(Dictionary<TKey, string> mapping, string label)
    where TKey : struct, Enum
{
    return mapping
        .Where(pair => pair.Value == label)
        .Select(pair => pair.Key)
        .ToList();
}

// 兩張 enum 對應表的輸出不變，警告沒有了：
// Pending, Paid
// Low, Normal

where TKey : struct, Enum 是對 TKey 的限制：只能填 enum 型別。傳別的型別進來，編譯不會過：

var cityMapping = new Dictionary<string, string>
{
    ["TPE"] = "北部",
    ["KHH"] = "南部",
};

Console.WriteLine(string.Join(", ", KeysOf(cityMapping, "北部")));
error CS0453: 類型 'string' 必須是不可為 null 的實值類型，才可在泛型類型或方法 'KeysOf<TKey>(Dictionary<TKey, string>, string)' 中用做為參數 'TKey'

限制裡的兩個字各擋一種情況（各自單獨寫時的結果都實際編譯過）：

  • 只寫 struct：TKey 必須是值型別。string 被擋下，但 Dictionary<int, string> 還是傳得進去
  • 只寫 Enum：int 和 string 都被擋下，但 Dictionary<Enum, string> 傳得進去。Enum 這個型別本身可以放任何一種 enum 的值，這種表裡不同 enum 的成員會混在一起
  • 兩個都寫：只剩 OrderStatus、Priority 這種具體的 enum 型別能填

第 6 步：呼叫時角括號可以不寫

完整的呼叫寫法是在方法名稱後面填型別。前兩步都沒有寫，是因為編譯器從傳進去的對應表就知道 TKey 是誰：

Console.WriteLine(string.Join(", ", KeysOf<OrderStatus>(progressMapping, "進行中")));   // 寫明 TKey 是 OrderStatus
Console.WriteLine(string.Join(", ", KeysOf(progressMapping, "進行中")));                // 不寫，編譯器自己推出來

// 輸出：
// Pending, Paid
// Pending, Paid

什麼時候值得用泛型：像第 3 步那樣，發現自己在複製貼上一個方法、只改型別的時候。只有一個型別在用時（第 1 步），不用急著寫成泛型。

這個例子裡 pair.Key、pair.Value 的意思見 Dictionary 那一頁；用它做「顯示狀態 ↔ 資料庫狀態」的對應見 enum 那一頁的第 7 節。
