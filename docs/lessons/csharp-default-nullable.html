1. default 是多少：看型別

default 的意思是「這個型別什麼都沒設定時的值」。它不是固定的一個值，而是依型別而定。

Console.WriteLine(default(int));              // 0
Console.WriteLine(default(decimal));          // 0
Console.WriteLine(default(bool));             // False
Console.WriteLine(default(DateTime));         // 0001-01-01 00:00:00
Console.WriteLine(default(DateTimeOffset));   // 0001-01-01 00:00:00 +00:00
Console.WriteLine(default(string) is null);   // True
Console.WriteLine(default(int?) is null);     // True
型別default為什麼
int、decimal 等數字0值型別：所有位元都是 0
boolfalse同上
DateTime0001-01-01 00:00:00同上，剛好等於 DateTime.MinValue
DateTimeOffset0001-01-01 00:00:00 +00:00同上，等於 DateTimeOffset.MinValue
enum數字 0 對應的那個成員enum 背後是數字，見enum 那一頁
string、class、List<T>null參考型別：沒有指向任何物件
int?、DateTime? 等可空型別null可空型別的「沒有值」

== default 怎麼知道是哪個型別

只寫 default 沒寫型別時，編譯器看另一邊的型別來決定：

DateTimeOffset timeBegin = ...;

if (timeBegin == default)                    // 左邊是 DateTimeOffset，所以這裡的 default 是 default(DateTimeOffset)
if (timeBegin == default(DateTimeOffset))    // 同一件事，寫明型別
if (timeBegin == DateTimeOffset.MinValue)    // 同一個值

常見的用途：一個屬性「沒有被設定過」時，它的值就是 default。例如 API 的請求物件有一個 DateTimeOffset TimeBegin，JSON 裡沒送這個欄位，轉換後它就停在 0001-01-01。用 == default 可以判斷「對方沒送」。

想自己看：Rider 把游標移到 default 上會顯示它被推斷成哪個型別；或在中斷點的 Evaluate 視窗輸入 default(DateTimeOffset)。

2. ?. 會讓 default 的意思變掉

a?.B 的意思是「a 不是 null 才取 B，否則結果是 null」。所以它的結果一定是可以為 null 的型別：B 原本是 DateTimeOffset，a?.B 就變成 DateTimeOffset?。

型別一變，上一節的規則就會讓 default 跟著變：

var search = new SearchBox();     // 沒設定 TimeBegin，所以它是 0001-01-01
SearchBox? maybe = search;

Console.WriteLine(search.TimeBegin == default);    // True   ← default 是 default(DateTimeOffset)
Console.WriteLine(maybe?.TimeBegin == default);    // False  ← default 變成 default(DateTimeOffset?)，也就是 null

class SearchBox
{
    public DateTimeOffset TimeBegin { get; set; }
}
寫法左邊的型別default 代表結果
search.TimeBegin == defaultDateTimeOffset0001-01-01True，正確判斷出「沒設定」
maybe?.TimeBegin == defaultDateTimeOffset?nullFalse。0001-01-01 不是 null，所以沒判斷出來
nothing?.TimeBegin == default（nothing 是 null）DateTimeOffset?nullTrue，但原因是整個物件是 null，不是時間沒設定

⚠️ 這個錯不會有任何警告。兩種寫法都能編譯、都不會丟例外，只是判斷的意思不同。加了 ?. 之後「沒設定時間」的情況就悄悄漏掉了。

比較穩的寫法是分兩步：先判斷物件是不是 null，再判斷欄位。

if (maybe is null)
{
    // 整個物件沒有
}
else if (maybe.TimeBegin == default)     // 這裡沒有 ?.，型別是 DateTimeOffset
{
    // 物件有，但時間沒設定
}

3. ?? 與 ??=：沒有值時補上

int? count = null;

Console.WriteLine(count ?? 10);   // 10   ← count 是 null，所以用右邊的 10。count 本身沒變

count ??= 10;                     // count 是 null 才把 10 存進去
Console.WriteLine(count);         // 10

count ??= 99;                     // count 已經有值，這行什麼都不做
Console.WriteLine(count);         // 10
寫法意思會不會改到左邊
a ?? ba 不是 null 就用 a，是 null 就用 b不會，只是算出一個值
a ??= ba 是 null 才把 b 存進 a會

典型用法是補預設值：API 的每頁筆數是 int? Count，對方沒送就是 null，用 Count ?? 10 補成 10。

4. 會加工的屬性：set => field = …

一般的屬性 { get; set; } 是設什麼就存什麼。如果想在存進去之前先修正，可以自己寫 set：

class PageSetting
{
    private const int MaxCount = 100;

    public int Count
    {
        get;
        set => field = value is < 0 or > MaxCount ? MaxCount : value;
    } = 10;
}

var page = new PageSetting();
Console.WriteLine(page.Count);   // 10   ← 初始值
page.Count = 40;
Console.WriteLine(page.Count);   // 40
page.Count = 500;
Console.WriteLine(page.Count);   // 100  ← 超過上限，存成 100
page.Count = -1;
Console.WriteLine(page.Count);   // 100  ← 負數也存成 100
片段意思
value外面要設定進來的值。寫 page.Count = 500 時，value 就是 500
value is < 0 or > MaxCount「value 小於 0，或大於 100」。等同 value < 0 || value > MaxCount
條件 ? A : B條件成立取 A，不成立取 B
field這個屬性背後真正放資料的地方。編譯器自動產生，不用自己宣告
結尾的 = 10初始值：建立物件時還沒有人設定，它就是 10

field 是比較新的寫法。以前要自己多宣告一個欄位，效果完全一樣：

private int _count = 10;

public int Count
{
    get => _count;
    set => _count = value is < 0 or > MaxCount ? MaxCount : value;
}

好處是「這個物件不管怎麼建立，值都是合理的」。使用它的程式不用再檢查一次。

5. 泛型：把「型別」也變成參數

有時候幾個方法的內容一模一樣，只差在用的型別不同。方法簽章那一頁看過 <T>，這裡用一個實際會遇到的例子。

有兩張對應表，key 是不同的 enum，value 都是顯示用的文字。想做的事相同：給一個文字，找出對應到它的所有 key。

var progressMapping = new Dictionary<OrderStatus, string>
{
    [OrderStatus.Pending] = "進行中", [OrderStatus.Paid] = "進行中",
    [OrderStatus.Shipped] = "已完成", [OrderStatus.Cancelled] = "已取消",
};
var sizeMapping = new Dictionary<Priority, string>
{
    [Priority.Low] = "不急", [Priority.Normal] = "不急", [Priority.High] = "要快",
};

Console.WriteLine(string.Join(", ", KeysOf(progressMapping, "進行中")));   // Pending, Paid
Console.WriteLine(string.Join(", ", KeysOf(sizeMapping, "不急")));         // Low, Normal

static List<TKey> KeysOf<TKey>(Dictionary<TKey, string> mapping, string label)
    where TKey : struct, Enum
{
    return mapping
        .Where(pair => pair.Value == label)
        .Select(pair => pair.Key)
        .ToList();
}
片段意思
KeysOf<TKey>TKey 是「之後再決定的型別」。名字是自己取的
Dictionary<TKey, string> mapping傳進來的對應表，key 是哪種型別，TKey 就是那種
List<TKey>回傳的清單也是同一種型別
where TKey : struct, Enum限制：TKey 只能是 enum。傳別的型別進來編譯就不會過

呼叫時不用寫 KeysOf<OrderStatus>(…)，編譯器從傳進去的對應表就知道 TKey 是誰。

不用泛型的話要寫兩個方法，內容完全相同，只有型別不同：

static List<OrderStatus> ProgressKeysOf(Dictionary<OrderStatus, string> mapping, string label) { /* 同樣三行 */ }
static List<Priority> SizeKeysOf(Dictionary<Priority, string> mapping, string label) { /* 同樣三行 */ }

什麼時候值得用泛型：發現自己在複製貼上一個方法、只改型別的時候。只有一個使用者時不用急著寫成泛型。

這個例子裡 pair.Key、pair.Value 的意思見 Dictionary 那一頁；用它做「顯示狀態 ↔ 資料庫狀態」的對應見 enum 那一頁的第 7 節。
