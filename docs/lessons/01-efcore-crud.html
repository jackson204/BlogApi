1. 這一課要解決的問題

第 0 課已經有一個空的 BlogDb。部落格最基本的功能是文章的 CRUD：

功能CRUDHTTP網址
新增文章CreatePOST/api/posts
文章列表、關鍵字搜尋ReadGET/api/posts?keyword=xxx
單篇文章ReadGET/api/posts/{id}
修改文章UpdatePUT/api/posts/{id}
刪除文章DeleteDELETE/api/posts/{id}

如果不用任何工具，C# 程式要自己開連線、組 SQL 字串、執行、再把每一列結果一欄一欄塞回物件。每多一張表就要重寫一次，還很容易寫出 SQL Injection 漏洞。

EF Core 的想法：你只寫 C# 的 class 和 LINQ，它負責翻譯成 SQL、執行、再把結果轉回物件。這類工具叫做 ORM（Object-Relational Mapping，物件關聯對應）。

2. 原理

2-1. 一個 API 請求從進來到回應，經過哪些地方？

sequenceDiagram participant C as 前端 / .http 檔 participant K as ASP.NET Core participant PC as PostsController participant DB as BlogDbContext participant SQL as SQL Server C->>K: GET /api/posts?keyword=Docker K->>K: Routing：找到對應的 Controller 和方法 K->>PC: 建立 PostsController，並把 BlogDbContext 傳進建構子 PC->>DB: _db.Posts.Where(...).ToListAsync() DB->>DB: 把 LINQ 翻譯成 SQL DB-)SQL: 送出 SELECT ... WHERE ... LIKE ...（await 等待中，不佔住執行緒） SQL--)DB: 回傳資料列 DB->>DB: 每一列轉成 Post 物件 DB-->>PC: List of Post PC-->>K: return posts K-->>C: 200 OK + JSON
實線箭頭：同步呼叫　開口箭頭：非同步（await）　虛線：回傳

「把 BlogDbContext 傳進建構子」這件事叫做依賴注入（DI），第 3 課會專門講。這一課先照著寫就好。

2-2. ORM：class 和資料表怎麼對應？

C#（EF Core）資料庫說明
Entity class Post資料表 Posts一個 class 對應一張表
屬性 Title欄位 Title一個屬性對應一個欄位
一個 Post 物件一列資料
DbSet<Post> Posts代表整張 Posts 表對它下 LINQ，就是對這張表查詢
DbContext一次和資料庫的「工作階段」管理連線、追蹤物件變化、SaveChanges 時一次寫入
屬性名稱叫 Id主鍵 + 自動編號（IDENTITY）EF Core 的慣例，不用另外設定

2-3. Migration：C# 改了，資料表怎麼跟著改？

你修改 Entity class 後，資料庫不會自己變。Migration 會比對「現在的 class」和「上一次的快照」，產生一份變更紀錄（C# 檔），再由它產生 SQL 去改資料庫。

flowchart LR A["Post.cs
BlogDbContext.cs"] -- "dotnet ef migrations add 名稱" --> B["Migrations 資料夾
xxxx_InitialCreate.cs
（變更紀錄，要 commit）"] B -- "dotnet ef database update" --> C["產生 SQL
CREATE TABLE Posts ..."] C --> D[("BlogDb
Posts 表")] C --> E[("__EFMigrationsHistory
記錄已套用到哪一版")]
Migration 就像資料庫的 git commit，每一次變更都有紀錄，可以追蹤、也可以退回

2-4. Change Tracking：為什麼要呼叫 SaveChanges？

DbContext 會追蹤透過它查出來或加進去的物件。你對物件做的事情只是在「記帳」，呼叫 SaveChangesAsync() 時才一次產生 SQL 寫進資料庫。

stateDiagram-v2 [*] --> Added: _db.Posts.Add(post) Added --> Unchanged: SaveChanges 時送出 INSERT [*] --> Unchanged: 查詢出來，例如 FindAsync Unchanged --> Modified: 修改屬性 post.Title = ... Modified --> Unchanged: SaveChanges 時送出 UPDATE Unchanged --> Deleted: _db.Posts.Remove(post) Deleted --> [*]: SaveChanges 時送出 DELETE
忘了呼叫 SaveChanges，資料就只停留在「記帳」階段，不會進資料庫

2-5. LINQ 什麼時候才真的查資料庫？

Where、OrderBy 只是在組合查詢條件，還沒送出任何 SQL。要等到呼叫 ToListAsync()、FirstOrDefaultAsync()、CountAsync() 這類「要拿結果」的方法，才會真的執行。這叫做延遲執行（deferred execution）。

flowchart LR A["_db.Posts"] --> B[".Where(...)"] --> C[".OrderByDescending(...)"] --> D[".ToListAsync()"] D == "這時候才送出 SQL" ==> E[("SQL Server")] A -.-|"到這裡都還沒查資料庫"| C

所以可以先 var query = _db.Posts.AsQueryable();，再依照條件決定要不要加 Where。最後只會送出一句組合好的 SQL。

3-4. 連線字串：用 User Secrets，不要寫進 appsettings

⚠️ 你的 repo 是 public 的。appsettings.Development.json 會被 commit，裡面的密碼全世界都看得到。

User Secrets 把機密存在專案資料夾以外（Windows 的 %APPDATA%\Microsoft\UserSecrets\），所以不會被 commit。開發環境（Development）執行時，.NET 會自動讀它。

dotnet user-secrets init                       # 在 csproj 加上 UserSecretsId
dotnet user-secrets set "區段:鍵" "值"           # 冒號代表 JSON 的階層
dotnet user-secrets list                       # 看目前存了什麼

"ConnectionStrings:BlogDb" 等同 JSON 的 { "ConnectionStrings": { "BlogDb": "..." } }。Rider 也可以對專案按右鍵 → Tools → .NET User Secrets 直接編輯。

3-5. 註冊 DbContext

builder.Services.AddDbContext<名稱DbContext>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("連線字串名稱")));

要寫在 Program.cs 的 builder.Build() 之前。這行的意思是「之後有人需要 DbContext 時，用這個連線字串建立一個給它」，第 3 課講 DI 時會再細講。

3-6. Migration 指令

dotnet ef migrations add 名稱          # 產生變更紀錄（名稱自己取，例如 InitialCreate、AddPostSummary）
dotnet ef database update              # 套用到資料庫
dotnet ef migrations script            # 只印出 SQL，不執行（想看它會做什麼時很好用）
dotnet ef migrations remove            # 移除「最後一個還沒套用」的 migration

這些指令要在專案資料夾（有 .csproj 的那層）執行，或加上 --project 專案資料夾。

3-7. Controller 骨架

[ApiController]                       // 自動做模型驗證、自動從 body 讀 JSON
[Route("api/[controller]")]           // [controller] 會換成類別名稱去掉 Controller → api/posts
public class PostsController : ControllerBase
{
    [HttpGet]            // GET    api/posts
    [HttpGet("{id}")]    // GET    api/posts/5   → 參數 int id 會自動拿到 5
    [HttpPost]           // POST   api/posts
    [HttpPut("{id}")]    // PUT    api/posts/5
    [HttpDelete("{id}")] // DELETE api/posts/5
}
回傳方法HTTP 狀態碼什麼時候用
return 物件; 或 Ok(物件)200 OK查詢成功
CreatedAtAction(nameof(查單筆方法), new { id = ... }, 物件)201 Created新增成功，回應的 Location header 會附上新資料的網址
NoContent()204 No Content修改、刪除成功，沒有內容要回傳
NotFound()404 Not Found找不到這個 id
（自動）400 Bad Request[ApiController] 發現傳進來的資料驗證失敗時，自動回傳

BlogApi/Models/Post.cs

using System.ComponentModel.DataAnnotations;

namespace BlogApi.Models;

public class Post
{
    public int Id { get; set; }

    [MaxLength(200)]
    public string Title { get; set; } = string.Empty;

    public string Content { get; set; } = string.Empty;

    public DateTime CreatedAt { get; set; }

    public DateTime? UpdatedAt { get; set; }
}

BlogApi/Data/BlogDbContext.cs

using BlogApi.Models;
using Microsoft.EntityFrameworkCore;

namespace BlogApi.Data;

public class BlogDbContext : DbContext
{
    public BlogDbContext(DbContextOptions<BlogDbContext> options) : base(options)
    {
    }

    public DbSet<Post> Posts => Set<Post>();
}
  • = string.Empty：專案有開 Nullable，string 代表「不可以是 null」，所以要給預設值，不然編譯器會警告
  • DbSet<Post> Posts => Set<Post>();：官方文件也常見 public DbSet<Post> Posts { get; set; }，兩種都可以。用 => Set<Post>() 的好處是不會有 nullable 警告

題 6：PostsController 五支 API

需求：完成第 1 節表格裡的 5 支 API。另外：

  • 新增、修改時，前端只能傳 title 和 content。Id、CreatedAt 由後端決定，不能讓前端亂傳
  • title、content 必填，title 最多 200 字；不符合要回 400
  • 列表依 CreatedAt 新到舊排序；有傳 keyword 時只回傳標題包含關鍵字的文章
  • 找不到 id 時回 404
  • 全部使用 async 版本的方法

💡 提示：每支 API 用到什麼

APIEF Core 方法成功時回傳
GET 列表Where、OrderByDescending、ToListAsync200 + 陣列
GET 單筆FindAsync(id)200 + 物件
POSTAdd → SaveChangesAsync201 CreatedAtAction
PUTFindAsync → 改屬性 → SaveChangesAsync204 NoContent
DELETEFindAsync → Remove → SaveChangesAsync204 NoContent

「前端只能傳 title 和 content」：另外寫一個只有這兩個屬性的 record 當參數型別，不要直接用 Post。驗證可以用 [Required]、[MaxLength]。

✅ 驗收：用題 7 的 .http 檔，每支 API 都回傳正確的狀態碼

參考答案（寫完再打開）

BlogApi/Models/PostRequest.cs

using System.ComponentModel.DataAnnotations;

namespace BlogApi.Models;

// 新增、修改文章時，前端只能傳這兩個欄位
public record PostRequest(
    [Required, MaxLength(200)] string Title,
    [Required] string Content);

BlogApi/Controllers/PostsController.cs

using BlogApi.Data;
using BlogApi.Models;
using Microsoft.AspNetCore.Mvc;
using Microsoft.EntityFrameworkCore;

namespace BlogApi.Controllers;

[ApiController]
[Route("api/[controller]")]
public class PostsController : ControllerBase
{
    private readonly BlogDbContext _db;

    public PostsController(BlogDbContext db)
    {
        _db = db;
    }

    // GET api/posts?keyword=docker
    [HttpGet]
    public async Task<ActionResult<List<Post>>> GetAll(string? keyword)
    {
        var query = _db.Posts.AsQueryable();

        if (!string.IsNullOrWhiteSpace(keyword))
        {
            query = query.Where(p => p.Title.Contains(keyword));
        }

        var posts = await query
            .OrderByDescending(p => p.CreatedAt)
            .ToListAsync();

        return posts;
    }

    // GET api/posts/5
    [HttpGet("{id}")]
    public async Task<ActionResult<Post>> GetById(int id)
    {
        var post = await _db.Posts.FindAsync(id);
        if (post is null)
        {
            return NotFound();
        }

        return post;
    }

    // POST api/posts
    [HttpPost]
    public async Task<ActionResult<Post>> Create(PostRequest request)
    {
        var post = new Post
        {
            Title = request.Title,
            Content = request.Content,
            CreatedAt = DateTime.UtcNow
        };

        _db.Posts.Add(post);
        await _db.SaveChangesAsync();

        return CreatedAtAction(nameof(GetById), new { id = post.Id }, post);
    }

    // PUT api/posts/5
    [HttpPut("{id}")]
    public async Task<IActionResult> Update(int id, PostRequest request)
    {
        var post = await _db.Posts.FindAsync(id);
        if (post is null)
        {
            return NotFound();
        }

        post.Title = request.Title;
        post.Content = request.Content;
        post.UpdatedAt = DateTime.UtcNow;

        await _db.SaveChangesAsync();
        return NoContent();
    }

    // DELETE api/posts/5
    [HttpDelete("{id}")]
    public async Task<IActionResult> Delete(int id)
    {
        var post = await _db.Posts.FindAsync(id);
        if (post is null)
        {
            return NotFound();
        }

        _db.Posts.Remove(post);
        await _db.SaveChangesAsync();
        return NoContent();
    }
}
  • 為什麼不用 Post 當參數？如果前端傳 {"id": 999, "createdAt": "1999-01-01"}，這些值會被直接寫進去。這叫做 over-posting。用 PostRequest 就只收得到兩個欄位
  • PUT 為什麼沒有呼叫 Update()？FindAsync 查出來的物件已經被追蹤（Unchanged），改屬性後會自動變成 Modified，SaveChangesAsync 就會送出 UPDATE（見 2-4）
  • CreatedAt 用 DateTime.UtcNow：存 UTC 時間，前端再依照使用者的時區顯示，避免伺服器搬到其他時區時時間錯亂

5. 觀察 SQL：LINQ 對照產生的 SQL

以下是題 7 實際執行時，EF Core 10 印出的 SQL（只保留重點）：

C#產生的 SQL
_db.Posts
  .OrderByDescending(p => p.CreatedAt)
  .ToListAsync()
 
SELECT [p].[Id], [p].[Content], [p].[CreatedAt],
       [p].[Title], [p].[UpdatedAt]
FROM [Posts] AS [p]
ORDER BY [p].[CreatedAt] DESC
 
.Where(p => p.Title.Contains(keyword))
 
WHERE [p].[Title] LIKE @keyword_contains ESCAPE N'\'
-- @keyword_contains = N'%Docker%'
 
_db.Posts.FindAsync(id)
 
SELECT TOP(1) [p].[Id], [p].[Content], ...
FROM [Posts] AS [p]
WHERE [p].[Id] = @p
 
_db.Posts.Add(post);
await _db.SaveChangesAsync();
 
INSERT INTO [Posts] ([Content], [CreatedAt],
                     [Title], [UpdatedAt])
OUTPUT INSERTED.[Id]
VALUES (@p0, @p1, @p2, @p3);
 
post.Title = ...;
post.Content = ...;
post.UpdatedAt = ...;
await _db.SaveChangesAsync();
 
UPDATE [Posts] SET [Content] = @p0, [Title] = @p1,
                   [UpdatedAt] = @p2
OUTPUT 1
WHERE [Id] = @p3;
 
_db.Posts.Remove(post);
await _db.SaveChangesAsync();
 
DELETE FROM [Posts]
OUTPUT 1
WHERE [Id] = @p0;

從 SQL 看出來的重點

  • 全部都是參數化查詢（@p0、@keyword_contains），值不會直接拼進 SQL 字串，所以不會有 SQL Injection
  • OUTPUT INSERTED.[Id]：INSERT 時順便把資料庫產生的自動編號拿回來，這就是 SaveChangesAsync() 之後 post.Id 會有值的原因
  • UPDATE 只更新有改的欄位：CreatedAt 沒改，所以不在 SET 裡面。這是 Change Tracking 的功勞
  • PUT 和 DELETE 都是兩句 SQL：先 SELECT TOP(1)（FindAsync），再 UPDATE / DELETE。之後的課會介紹 ExecuteUpdateAsync / ExecuteDeleteAsync，可以一句完成
  • Contains 變成 LIKE '%...%'：前後都有 %，資料量大時用不到索引，第 4 課談效能時會再提

6. 優缺點 & 常見坑

優點

  • 用 C# 型別寫查詢，打錯欄位名稱編譯時就會發現
  • 自動參數化，預設就能防 SQL Injection
  • Migration 讓資料庫結構有版本紀錄，換電腦一個指令就能重建

缺點

  • 產生的 SQL 不一定是最佳寫法，要養成看 SQL log 的習慣
  • 多了一層抽象，出問題時要同時懂 C# 和 SQL 才好排查

常見坑
