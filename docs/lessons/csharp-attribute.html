C# 補充：Attribute（貼在程式碼上的標記）

類別或方法上面那一行方括號，例如 [Obsolete]、[Required]、[HttpGet]，叫 attribute。這頁講它是什麼、怎麼寫、為什麼貼上去不一定有效果，以及什麼時候才需要自己寫一個。

1. attribute 是什麼

attribute 是貼在程式碼上的標記，寫在方括號裡，放在類別、方法、屬性或參數的前面。它替那段程式碼附加一筆說明，讓別的程式可以讀到。

public class Calc
{
    [Obsolete("請改用 Add")]                 // 貼在方法上的標記
    public int OldAdd(int a, int b) => a + b;

    public int Add(int a, int b) => a + b;
}

[Obsolete("請改用 Add")] 沒有改變 OldAdd 的內容，方法照樣算得出結果。它只是在這個方法上留了一筆資料：「這個方法過時了，說明文字是『請改用 Add』」。

中文資料有時把 attribute 翻成「特性」。中文版的編譯器訊息把它翻成「屬性」，和 property（{ get; set; } 那種）是同一個詞，看錯誤訊息時要從上下文分辨。這頁一律寫 attribute。

2. 寫法

attribute 本身是一個繼承 Attribute 的類別，方括號裡能寫什麼，由這個類別的建構子和屬性決定。這一節自己寫一個 [Label]，從空的類別開始，一步加一樣東西。類別、建構子、繼承的寫法見「類別與物件」。

程式裡的顏色：藍色是這一步在 attribute 類別裡多寫的東西，綠色是貼的地方跟著變的寫法，紅色是編譯不過的寫法。這一節每個程式都只有一行 Console.WriteLine("編譯通過")，看的是編譯過不過。

第 1 步：最短的 attribute，一個空的類別

Console.WriteLine("編譯通過");

public class LabelAttribute : Attribute { }

[Label]
public class Apple { }

// 輸出：
// 編譯通過

類別裡什麼都沒有，就已經可以貼了。兩件事：

  • 類別名稱是 LabelAttribute，貼的時候寫 [Label]。attribute 的類別名稱都用 Attribute 結尾，貼的時候可以省略這個結尾；寫完整的 [LabelAttribute] 也可以。所以 [Obsolete] 和 [ObsoleteAttribute] 是同一個
  • : Attribute 不能少。拿掉之後貼的地方編譯不過：
public class LabelAttribute { }      // 沒有繼承 Attribute

[Label]
public class Apple { }

error CS0616: 'LabelAttribute' 不是屬性類別

第 2 步：括號裡帶一個值，類別要有建構子

想在標記上寫文字，像第 1 節的 [Obsolete("請改用 Add")] 那樣。直接在空的 LabelAttribute 上這樣貼：

public class LabelAttribute : Attribute { }

[Label("蘋果")]
public class Apple { }

error CS1729: 'LabelAttribute' 未包含使用 1 個引數的建構函式

編譯器在找「收一個值的建構子」。括號裡的值，是照順序傳給 attribute 類別的建構子。補上建構子就過了：

Console.WriteLine("編譯通過");

public class LabelAttribute : Attribute
{
    public string Text { get; }

    public LabelAttribute(string text)
    {
        Text = text;
    }
}

[Label("蘋果")]
public class Apple { }

// 輸出：
// 編譯通過

現在建構子一定要一個 string，所以第 1 步那種不帶值的貼法反而不過了：

[Label]
public class Apple { }

error CS7036: 未提供任何可對應到 'LabelAttribute.LabelAttribute(string)' 之必要參數 'text' 的引數

第 3 步：名稱 = 值，設定 attribute 的屬性

再加一個顏色，但不想讓每個貼的地方都非給不可。在括號裡寫 Color = "紅" 試試：

[Label("蘋果", Color = "紅")]
public class Apple { }

error CS0246: 找不到類型或命名空間名稱 'Color' (是否遺漏了 using 指示詞或組件參考?)

LabelAttribute 裡沒有叫 Color 的東西。名稱 = 值 是設定 attribute 類別的某個屬性，所以類別裡要有一個可以設定的 Color 屬性：

Console.WriteLine("編譯通過");

public class LabelAttribute : Attribute
{
    public string Text { get; }
    public string Color { get; set; } = "沒有指定";

    public LabelAttribute(string text)
    {
        Text = text;
    }
}

// "蘋果" 傳給建構子的 text；Color = "紅" 設定 Color 屬性
[Label("蘋果", Color = "紅")]
public class Apple { }

// 沒有寫 Color，就是屬性的預設值「沒有指定」
[Label("香蕉")]
public class Banana { }

// 輸出：
// 編譯通過

名稱 = 值 可以不寫，要寫就寫在照順序的值後面。順序反過來編譯不過：

[Label(Color = "紅", "蘋果")]
public class Apple { }

error CS1016: 必須是具名屬性引數

第 4 步：一個方括號貼兩個

同一個地方要貼兩個 attribute 時，可以分兩行，也可以寫在同一個方括號裡用逗號隔開。以 .NET 內建的 [Required] 和 [MaxLength] 為例，下面兩個屬性貼的東西一樣（實際編譯過，兩個屬性讀出來都是這兩個 attribute）：

using System.ComponentModel.DataAnnotations;

public class Item
{
    [Required, MaxLength(100)]
    public string Name { get; set; } = "";

    [Required]
    [MaxLength(100)]
    public string Title { get; set; } = "";
}

四步出現過的寫法

寫法意思
[Obsolete]不帶任何值
[Obsolete("請改用 Add")]括號裡的值照順序傳給 attribute 的建構子
[Label("蘋果", Color = "紅")]名稱 = 值 是設定 attribute 的某個屬性，寫在照順序的值後面
[Required, MaxLength(100)]一次貼兩個，和分兩行寫 [Required]、[MaxLength(100)] 一樣
[ObsoleteAttribute]和 [Obsolete] 一樣，類別名稱結尾的 Attribute 可以省略

括號裡只能放編譯時就確定的值

標記是編譯的時候就寫進程式裡的，所以括號裡只能放字串、數字、true／false、enum、typeof(…)、nameof(…) 這類不用執行程式就知道的值。

✗ 編譯不過：值要執行了才知道

[Label(DateTime.Now.ToString())]
public class Apple { }
error CS0182: 屬性引數必須是常數運算式、typeof 運算式
或屬性參數類型的陣列建立運算式

✓ 可以：值寫死在程式碼裡

[Label("蘋果")]
public class Apple { }

需要執行時才決定的值，不適合放在 attribute，改用一般的屬性或方法參數。

這一節每個編譯過的程式，執行結果都只有「編譯通過」那一行。「蘋果」和「紅」寫進去了，執行時卻看不到它們出現在任何地方。

3. 標記自己不做事，要有人讀它

attribute 只是一筆附在程式碼上的資料。沒有任何程式去讀它，它就沒有任何效果。這是 attribute 最容易誤會的地方。這一節先確認「沒有人讀」是什麼情況，再一步一步加上讀它的程式。

程式裡的顏色：藍色是這一步多出來的寫法。

第 1 步：貼了標記，沒有人讀

LabelAttribute 的建構子裡放了一行印字，用來看它有沒有被執行：

var apple = new Apple();
Console.WriteLine("程式照常執行，[Label] 沒有任何效果");

public class LabelAttribute : Attribute
{
    public string Text { get; }

    public LabelAttribute(string text)
    {
        Text = text;
        Console.WriteLine("LabelAttribute 的建構子被呼叫了");
    }
}

[Label("蘋果")]
public class Apple { }
程式照常執行，[Label] 沒有任何效果

Apple 被建立了，但「LabelAttribute 的建構子被呼叫了」沒有印出來。貼了標記、也建立了被貼的類別的物件，attribute 的程式碼一行都沒有執行。

第 2 步：加一行，去讀 Apple 身上的標記

LabelAttribute 和 Apple 都不動，只改最上面幾行：

using System.Reflection;

var apple = new Apple();
Console.WriteLine("Apple 建立好了，接下來讀標記");

var label = typeof(Apple).GetCustomAttribute<LabelAttribute>();
Console.WriteLine($"標記上的文字：{label!.Text}");

// 輸出：
// Apple 建立好了，接下來讀標記
// LabelAttribute 的建構子被呼叫了
// 標記上的文字：蘋果

typeof(Apple) 拿到「Apple 這個類別本身」的資料，GetCustomAttribute<LabelAttribute>() 問它「你身上有沒有 [Label]」。有的話回傳一個 LabelAttribute 物件，沒有就回傳 null。

看輸出的順序：建構子是在 GetCustomAttribute 那一行才被呼叫的，不是 new Apple() 的時候。有人來讀，[Label("蘋果")] 括號裡的值才真的傳進建構子。

在程式執行時查「這個類別有哪些成員、貼了哪些標記」的做法叫 reflection（反射）。GetCustomAttribute<T>() 就是 reflection 的方法，它放在 System.Reflection 這個 namespace 裡，所以最上面多了一行 using。

第 3 步：把建構子的值和屬性的值都讀出來

用同一個讀法，讀第 2 節第 3 步那個有 Text 和 Color 的 LabelAttribute：

using System.Reflection;

var a = typeof(Apple).GetCustomAttribute<LabelAttribute>();
Console.WriteLine($"{a!.Text} / {a.Color}");
var b = typeof(Banana).GetCustomAttribute<LabelAttribute>();
Console.WriteLine($"{b!.Text} / {b.Color}");

public class LabelAttribute : Attribute
{
    public string Text { get; }
    public string Color { get; set; } = "沒有指定";

    public LabelAttribute(string text)
    {
        Text = text;
    }
}

// "蘋果" 傳給建構子的 text；Color = "紅" 設定 Color 屬性
[Label("蘋果", Color = "紅")]
public class Apple { }

// 寫完整的類別名稱也可以；沒有設定 Color，用預設值
[LabelAttribute("香蕉")]
public class Banana { }
蘋果 / 紅
香蕉 / 沒有指定

方括號裡寫的值，在這裡才看得到：照順序的值進了建構子，Color = "紅" 設定了屬性，沒寫的用預設值。

第 4 步：一次找出所有貼了標記的類別

第 2、3 步要先知道去問哪個類別。下面最上面那個 foreach 把這個程式裡所有的類別找出來，一個一個問「你身上有沒有 [Label]」，有的話把上面的文字印出來：

using System.Reflection;

// 讀標記的人：找出這個程式裡所有貼了 [Label] 的類別，把標記上的文字印出來
foreach (var type in Assembly.GetExecutingAssembly().GetTypes())
{
    var label = type.GetCustomAttribute<LabelAttribute>();
    if (label is not null)
    {
        Console.WriteLine($"{type.Name} 的標記文字：{label.Text}");
    }
}

public class LabelAttribute : Attribute
{
    public string Text { get; }

    public LabelAttribute(string text)
    {
        Text = text;
    }
}

[Label("蘋果")]
public class Apple { }

[Label("香蕉")]
public class Banana { }

public class Cherry { }
Apple 的標記文字：蘋果
Banana 的標記文字：香蕉

Cherry 沒有貼標記，GetCustomAttribute 回傳 null，所以沒有印出來。GetTypes() 也是 reflection。

整個機制就是這兩半：

做什麼上面的例子
貼標記的人在類別或方法上寫 […][Label("蘋果")]
讀標記的人用 reflection 找出標記，依標記的內容決定要做什麼第 4 步最上面的 foreach

4. 誰在讀

平常寫程式多半只當「貼標記的人」，讀的人是編譯器、函式庫或框架。看到一個 attribute，先問「誰會讀它、什麼時候讀」，就知道它什麼情況下有效。

讀的人什麼時候讀例子
編譯器編譯時[Obsolete]：有人呼叫被標記的方法，編譯器就發出警告
函式庫有人呼叫它的時候[Required]：Validator 檢查物件時，讀屬性上的標記
框架通常是程式啟動時以 ASP.NET Core 為例，啟動時讀 Controller 方法上的 [HttpGet]，決定哪個網址交給哪個方法

編譯器讀：[Obsolete]

var c = new Calc();
Console.WriteLine(c.OldAdd(1, 2));

public class Calc
{
    [Obsolete("請改用 Add")]
    public int OldAdd(int a, int b) => a + b;

    public int Add(int a, int b) => a + b;
}
warning CS0618: 'Calc.OldAdd(int, int)' 已經過時: '請改用 Add'
3

程式照樣執行、印出 3，只是編譯時多了一個警告，警告裡的文字就是括號裡寫的那一句。

函式庫讀：[Required]

using System.ComponentModel.DataAnnotations;

var item = new Item { Name = "" };
Console.WriteLine($"物件建立成功，Name 是空字串：[{item.Name}]");

var results = new List<ValidationResult>();
bool ok = Validator.TryValidateObject(item, new ValidationContext(item), results, validateAllProperties: true);
Console.WriteLine($"呼叫 Validator 之後：通過 = {ok}");
foreach (var r in results)
{
    Console.WriteLine($"  {r.ErrorMessage}");
}

public class Item
{
    [Required]
    public string Name { get; set; } = "";
}
物件建立成功，Name 是空字串：[]
呼叫 Validator 之後：通過 = False
  The Name field is required.

[Required] 沒有阻止 Name 被設成空字串，物件照樣建立成功。要等到有人呼叫 Validator.TryValidateObject，它去讀屬性上的 [Required]，才檢查出問題。

5. 貼了卻沒效果

標記貼對了卻沒有效果，原因幾乎都是「讀的人沒有來」。

✗ 以為貼上去就會生效

public class Item
{
    [Required]
    public string Name { get; set; } = "";
}

var item = new Item { Name = "" };   // 不會出錯

沒有任何程式去讀 [Required]，空字串照樣放得進去。

✓ 確認有人會讀

Validator.TryValidateObject(
    item, new ValidationContext(item),
    results, validateAllProperties: true);

自己呼叫讀取的程式，或確認使用的框架在這個情況下會替你呼叫。

遇到「貼了沒效果」，照這個順序查：

  1. 這個 attribute 是誰在讀：編譯器、某個函式庫，還是框架
  2. 讀的人在這個情況下有沒有執行。框架常常要先經過設定，才會去讀某一類標記
  3. 標記貼的位置是不是讀的人會看的地方。貼在類別上和貼在方法上，讀的人不一定都看

貼錯位置：有些 attribute 會擋，有些不會

寫 attribute 的人可以用 [AttributeUsage] 限制它能貼在哪裡，貼錯地方編譯就不過：

[AttributeUsage(AttributeTargets.Class)]   // 只能貼在類別上
public class LabelAttribute : Attribute
{
    public string Text { get; }
    public LabelAttribute(string text) { Text = text; }
}

public class Apple
{
    [Label("重量")]                         // 貼在屬性上
    public int Weight { get; set; }
}
error CS0592: 屬性 'Label' 在此宣告類型上無效。其只有在 '類別' 宣告上才有效。

訊息裡的「屬性 'Label'」指的是 attribute。沒有寫 [AttributeUsage] 的 attribute 哪裡都能貼，貼錯地方編譯器不會說話，只是讀的人不會看到它。

6. 什麼時候自己寫一個

情況
用現成的就好絕大多數時候。編譯器、函式庫、框架已經定義好一批 attribute，照文件貼上去
自己寫同一件事要套用在很多個類別或方法上，而且「要不要套用、套用時的設定」想直接寫在那段程式碼旁邊。這時要寫兩樣東西：attribute 類別，以及讀它的程式
不要用 attribute值要執行時才知道；只有一兩個地方用到；用一般的方法參數或 if 就能表達

自己寫的時候記得：只寫 attribute 類別、沒寫讀它的程式，等於什麼都沒做。
