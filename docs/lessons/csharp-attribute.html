C# 補充：Attribute（貼在程式碼上的標記）

類別或方法上面那一行方括號，例如 [Obsolete]、[Required]、[HttpGet]，叫 attribute。這頁講它是什麼、怎麼寫、為什麼貼上去不一定有效果，以及什麼時候才需要自己寫一個。

1. attribute 是什麼

attribute 是貼在程式碼上的標記，寫在方括號裡，放在類別、方法、屬性或參數的前面。它替那段程式碼附加一筆說明，讓別的程式可以讀到。

public class Calc
{
    [Obsolete("請改用 Add")]                 // 貼在方法上的標記
    public int OldAdd(int a, int b) => a + b;

    public int Add(int a, int b) => a + b;
}

[Obsolete("請改用 Add")] 沒有改變 OldAdd 的內容，方法照樣算得出結果。它只是在這個方法上留了一筆資料：「這個方法過時了，說明文字是『請改用 Add』」。

中文資料有時把 attribute 翻成「特性」。中文版的編譯器訊息把它翻成「屬性」，和 property（{ get; set; } 那種）是同一個詞，看錯誤訊息時要從上下文分辨。這頁一律寫 attribute。

2. 寫法

寫法意思
[Obsolete]不帶任何值
[Obsolete("請改用 Add")]括號裡的值照順序傳給 attribute 的建構子
[Label("蘋果", Color = "紅")]名稱 = 值 是設定 attribute 的某個屬性，寫在照順序的值後面
[Required, MaxLength(100)]一次貼兩個，和分兩行寫 [Required]、[MaxLength(100)] 一樣
[ObsoleteAttribute]和 [Obsolete] 一樣。attribute 的類別名稱都用 Attribute 結尾，貼的時候可以省略這個結尾

attribute 本身是一個繼承 Attribute 的類別。方括號裡的寫法對應到這個類別的建構子和屬性：

using System.Reflection;

var a = typeof(Apple).GetCustomAttribute<LabelAttribute>();
Console.WriteLine($"{a!.Text} / {a.Color}");
var b = typeof(Banana).GetCustomAttribute<LabelAttribute>();
Console.WriteLine($"{b!.Text} / {b.Color}");

public class LabelAttribute : Attribute
{
    public string Text { get; }
    public string Color { get; set; } = "沒有指定";

    public LabelAttribute(string text)
    {
        Text = text;
    }
}

// "蘋果" 傳給建構子的 text；Color = "紅" 設定 Color 屬性
[Label("蘋果", Color = "紅")]
public class Apple { }

// 寫完整的類別名稱也可以；沒有設定 Color，用預設值
[LabelAttribute("香蕉")]
public class Banana { }
蘋果 / 紅
香蕉 / 沒有指定

類別、建構子、繼承的寫法見「類別與物件」。

括號裡只能放編譯時就確定的值

標記是編譯的時候就寫進程式裡的，所以括號裡只能放字串、數字、true／false、enum、typeof(…)、nameof(…) 這類不用執行程式就知道的值。

✗ 編譯不過：值要執行了才知道

[Label(DateTime.Now.ToString())]
public class Apple { }
error CS0182: 屬性引數必須是常數運算式、typeof 運算式
或屬性參數類型的陣列建立運算式

✓ 可以：值寫死在程式碼裡

[Label("蘋果")]
public class Apple { }

需要執行時才決定的值，不適合放在 attribute，改用一般的屬性或方法參數。

3. 標記自己不做事，要有人讀它

attribute 只是一筆附在程式碼上的資料。沒有任何程式去讀它，它就沒有任何效果。這是 attribute 最容易誤會的地方。

先看沒有人讀的情況。LabelAttribute 的建構子裡放了一行印字，用來看它有沒有被執行：

var apple = new Apple();
Console.WriteLine("程式照常執行，[Label] 沒有任何效果");

public class LabelAttribute : Attribute
{
    public string Text { get; }

    public LabelAttribute(string text)
    {
        Text = text;
        Console.WriteLine("LabelAttribute 的建構子被呼叫了");
    }
}

[Label("蘋果")]
public class Apple { }
程式照常執行，[Label] 沒有任何效果

Apple 被建立了，但「LabelAttribute 的建構子被呼叫了」沒有印出來。貼了標記、也建立了被貼的類別的物件，attribute 的程式碼一行都沒有執行。

再加上讀標記的程式。下面最上面那個 foreach 就是「讀的人」：它找出這個程式裡所有的類別，一個一個問「你身上有沒有 [Label]」，有的話把上面的文字印出來。

using System.Reflection;

// 讀標記的人：找出這個程式裡所有貼了 [Label] 的類別，把標記上的文字印出來
foreach (var type in Assembly.GetExecutingAssembly().GetTypes())
{
    var label = type.GetCustomAttribute<LabelAttribute>();
    if (label is not null)
    {
        Console.WriteLine($"{type.Name} 的標記文字：{label.Text}");
    }
}

public class LabelAttribute : Attribute
{
    public string Text { get; }

    public LabelAttribute(string text)
    {
        Text = text;
    }
}

[Label("蘋果")]
public class Apple { }

[Label("香蕉")]
public class Banana { }

public class Cherry { }
Apple 的標記文字：蘋果
Banana 的標記文字：香蕉

Cherry 沒有貼標記，GetCustomAttribute 回傳 null，所以沒有印出來。在程式執行時查「這個類別有哪些成員、貼了哪些標記」的做法叫 reflection（反射），GetTypes()、GetCustomAttribute<T>() 都屬於它。

整個機制就是這兩半：

做什麼上面的例子
貼標記的人在類別或方法上寫 […][Label("蘋果")]
讀標記的人用 reflection 找出標記，依標記的內容決定要做什麼最上面的 foreach

4. 誰在讀

平常寫程式多半只當「貼標記的人」，讀的人是編譯器、函式庫或框架。看到一個 attribute，先問「誰會讀它、什麼時候讀」，就知道它什麼情況下有效。

讀的人什麼時候讀例子
編譯器編譯時[Obsolete]：有人呼叫被標記的方法，編譯器就發出警告
函式庫有人呼叫它的時候[Required]：Validator 檢查物件時，讀屬性上的標記
框架通常是程式啟動時以 ASP.NET Core 為例，啟動時讀 Controller 方法上的 [HttpGet]，決定哪個網址交給哪個方法

編譯器讀：[Obsolete]

var c = new Calc();
Console.WriteLine(c.OldAdd(1, 2));

public class Calc
{
    [Obsolete("請改用 Add")]
    public int OldAdd(int a, int b) => a + b;

    public int Add(int a, int b) => a + b;
}
warning CS0618: 'Calc.OldAdd(int, int)' 已經過時: '請改用 Add'
3

程式照樣執行、印出 3，只是編譯時多了一個警告，警告裡的文字就是括號裡寫的那一句。

函式庫讀：[Required]

using System.ComponentModel.DataAnnotations;

var item = new Item { Name = "" };
Console.WriteLine($"物件建立成功，Name 是空字串：[{item.Name}]");

var results = new List<ValidationResult>();
bool ok = Validator.TryValidateObject(item, new ValidationContext(item), results, validateAllProperties: true);
Console.WriteLine($"呼叫 Validator 之後：通過 = {ok}");
foreach (var r in results)
{
    Console.WriteLine($"  {r.ErrorMessage}");
}

public class Item
{
    [Required]
    public string Name { get; set; } = "";
}
物件建立成功，Name 是空字串：[]
呼叫 Validator 之後：通過 = False
  The Name field is required.

[Required] 沒有阻止 Name 被設成空字串，物件照樣建立成功。要等到有人呼叫 Validator.TryValidateObject，它去讀屬性上的 [Required]，才檢查出問題。

5. 貼了卻沒效果

標記貼對了卻沒有效果，原因幾乎都是「讀的人沒有來」。

✗ 以為貼上去就會生效

public class Item
{
    [Required]
    public string Name { get; set; } = "";
}

var item = new Item { Name = "" };   // 不會出錯

沒有任何程式去讀 [Required]，空字串照樣放得進去。

✓ 確認有人會讀

Validator.TryValidateObject(
    item, new ValidationContext(item),
    results, validateAllProperties: true);

自己呼叫讀取的程式，或確認使用的框架在這個情況下會替你呼叫。

遇到「貼了沒效果」，照這個順序查：

  1. 這個 attribute 是誰在讀：編譯器、某個函式庫，還是框架
  2. 讀的人在這個情況下有沒有執行。框架常常要先經過設定，才會去讀某一類標記
  3. 標記貼的位置是不是讀的人會看的地方。貼在類別上和貼在方法上，讀的人不一定都看

貼錯位置：有些 attribute 會擋，有些不會

寫 attribute 的人可以用 [AttributeUsage] 限制它能貼在哪裡，貼錯地方編譯就不過：

[AttributeUsage(AttributeTargets.Class)]   // 只能貼在類別上
public class LabelAttribute : Attribute
{
    public string Text { get; }
    public LabelAttribute(string text) { Text = text; }
}

public class Apple
{
    [Label("重量")]                         // 貼在屬性上
    public int Weight { get; set; }
}
error CS0592: 屬性 'Label' 在此宣告類型上無效。其只有在 '類別' 宣告上才有效。

訊息裡的「屬性 'Label'」指的是 attribute。沒有寫 [AttributeUsage] 的 attribute 哪裡都能貼，貼錯地方編譯器不會說話，只是讀的人不會看到它。

6. 什麼時候自己寫一個

情況
用現成的就好絕大多數時候。編譯器、函式庫、框架已經定義好一批 attribute，照文件貼上去
自己寫同一件事要套用在很多個類別或方法上，而且「要不要套用、套用時的設定」想直接寫在那段程式碼旁邊。這時要寫兩樣東西：attribute 類別，以及讀它的程式
不要用 attribute值要執行時才知道；只有一兩個地方用到；用一般的方法參數或 if 就能表達

自己寫的時候記得：只寫 attribute 類別、沒寫讀它的程式，等於什麼都沒做。
