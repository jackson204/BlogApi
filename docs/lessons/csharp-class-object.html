C# 補充：類別與物件（this、建構子、static、繼承、介面）

先分清楚「類別」和「物件」，再看懂方法裡的 this 是誰、建構子什麼時候被呼叫、static 為什麼沒有 this、: base(…) 在做什麼，最後把 abstract 類別和介面放進同一張圖。

類別物件newthisstatic 建構子readonlyrecordinitwith主要建構子 繼承baseprotectedvirtualoverride abstract介面

📌 這頁是 C# 語法，和專案無關：類別和物件的差別、this、建構子、static、: base(…)、override、abstract、介面。頁面上的範例都是單檔程式實際跑過的，編譯錯誤也是實際的訊息。

擴充方法參數前面的 this string title 是另一回事，在簽章頁第 2 節；這頁講的 this 是「這個物件自己」。

1. 類別與物件：圖紙和成品

類別（class）是圖紙，寫一次；物件（object）是照圖紙做出來的成品，new 一次做一個。同一張圖紙 new 幾次就有幾個物件，每個物件的屬性值各自獨立。

同一張圖紙 new 兩次，得到兩個互不相干的物件；方法只有一份，但 this 每次指向被呼叫的那個物件

簡單範例：兩個物件互不影響（實際執行過）

var post1 = new Post { Title = "Docker 入門" };
var post2 = new Post { Title = "Hi" };

post1.Title = "Docker 入門（修訂）";      // 只改 post1

Console.WriteLine($"post1.Title = {post1.Title}");
Console.WriteLine($"post2.Title = {post2.Title}");
Console.WriteLine(post1.Describe());
Console.WriteLine(post2.Describe());

class Post
{
    public string Title { get; set; } = string.Empty;

    public string Describe()
    {
        // this.Title 和 Title 是同一個東西：被呼叫的那個物件的 Title
        return $"標題「{this.Title}」，長度 {Title.Length}";
    }
}

// 輸出：
// post1.Title = Docker 入門（修訂）
// post2.Title = Hi
// 標題「Docker 入門（修訂）」，長度 13
// 標題「Hi」，長度 2

改 post1.Title，post2 完全沒動。Describe() 這段程式只寫了一份，卻對兩個物件印出不同的結果，差別在方法裡的 this 每次指的物件不同。

2. this：這個物件自己

在實例方法裡，this 就是「這次被呼叫的那個物件」。寫 post2.Describe()，方法本體執行時 this 就是 post2；寫 post1.Describe()，this 就是 post1。this.Title 和直接寫 Title 是同一件事，所以平常都省略不寫。

一定要寫 this 的情況：參數和欄位同名

簡單範例：有寫 this 和沒寫 this（實際執行過）

var a = new Author("小明");
Console.WriteLine(a.Describe());

var b = new AuthorBug("小明");
Console.WriteLine(b.Describe());

class Author
{
    private readonly string name;

    public Author(string name)
    {
        this.name = name;   // 左邊 this.name 是欄位，右邊 name 是參數
    }

    public string Describe() => $"作者：{name}";
}

class AuthorBug
{
    private string name = "";

    public AuthorBug(string name)
    {
        name = name;        // 兩邊都是參數，欄位沒被設定
    }

    public string Describe() => $"作者：{name}";
}

// 輸出：
// 作者：小明
// 作者：

AuthorBug 編譯會過，但 Rider 和編譯器都會警告：warning CS1717: 對同一個變數進行指派; 您是否想要指派別的東西?。參數 name 把欄位 name 遮住了，不寫 this. 就碰不到欄位。

常見的做法是欄位用底線開頭命名（_name）、參數叫 name，名稱不同就不會遮住，也就不用寫 this.。

省略 this 的不只欄位：在 Author 裡呼叫自己的 Describe()，其實是 this.Describe()；從父類別繼承來的方法也一樣，寫方法名稱就是對「這個物件」呼叫（第 5 節）。

⚠️ 同一個字，三種用法

寫在哪意思在哪一頁
實例方法本體裡：this.name這個物件自己這一節
建構子後面：: this(name, "未分配")先呼叫同一個類別的另一個建構子第 3 節
擴充方法第一個參數前：this string title參數修飾詞，「點前面的東西填進這個參數」，和物件無關簽章頁第 2 節

3. 建構子：物件誕生時跑的那段程式

建構子（constructor）是名稱和類別相同、沒有回傳型別的特殊方法。new 的時候執行，每個物件剛好執行一次，執行完這個物件才能被使用。它的工作是把物件的欄位設成可用的狀態。

什麼時候被呼叫：每一個 new

規則只有一條：每一次 new 就呼叫一次建構子。不管那個 new 是自己寫的，還是別人的程式（例如框架）替你寫的，建構子都在那一刻跑一次，物件做好才交到你手上。

沒寫建構子時，以及三段程式的順序

類別裡一個建構子都沒寫，編譯器會補一個無參數的，什麼都不做。一個只寫了屬性的類別，new Post() 和 new Post { Title = "Hi" } 都合法。後者的大括號叫物件初始設定式，它不是建構子的一部分，是 new 完之後再逐一設定屬性。三段程式的順序：

Console.WriteLine("開始 new Post { Title = \"Hi\" }");
var post = new Post { Title = "Hi" };
Console.WriteLine($"new 完成，post.Title = {post.Title}");

class Post
{
    private string _title = Init();

    public string Title
    {
        get => _title;
        set
        {
            Console.WriteLine($"  ③ 物件初始設定式：Title = 「{value}」");
            _title = value;
        }
    }

    public Post()
    {
        Console.WriteLine($"  ② 建構子本體，這時 Title 是「{Title}」");
    }

    private static string Init()
    {
        Console.WriteLine("  ① 屬性初始設定式 = string.Empty");
        return string.Empty;
    }
}

// 輸出：
// 開始 new Post { Title = "Hi" }
//   ① 屬性初始設定式 = string.Empty
//   ② 建構子本體，這時 Title 是「」
//   ③ 物件初始設定式：Title = 「Hi」
// new 完成，post.Title = Hi

順序固定是：① 欄位和屬性宣告時的 = … → ② 建構子本體 → ③ { … } 裡的設定。所以一個屬性宣告時寫了 = string.Empty，new 的時候又用 { Title = "Hi" } 蓋掉，兩段都會跑，最後留下的是 ③ 的值。

有參數的建構子

建構子收參數，就能要求「做這個物件一定要給我這些東西」。第 2 節的 Author(string name) 就是：new Author("小明") 一定要給名字。而且只要你自己寫了任何一個建構子，編譯器就不再補無參數的那個：

var a = new Author();          // 想用無參數的建構子

class Author
{
    private readonly string name;

    public Author(string name)
    {
        this.name = name;
    }
}

// 編譯錯誤：
// error CS7036: 未提供任何可對應到 'Author.Author(string)' 之必要參數 'name' 的引數

多個建構子，用 : this(…) 共用

一個類別可以有好幾個建構子，參數不同就行（多載）。要避免重複寫，一個建構子可以用 : this(…) 先呼叫另一個：

Console.WriteLine("== new Author(\"小明\")");
var a = new Author("小明");
Console.WriteLine(a.Describe());

Console.WriteLine("== new Author(\"小華\", \"編輯部\")");
var b = new Author("小華", "編輯部");
Console.WriteLine(b.Describe());

class Author
{
    private readonly string name;
    private readonly string department;

    // : this(name, "未分配")：先呼叫下面那個兩個參數的建構子，再跑自己的本體
    public Author(string name) : this(name, "未分配")
    {
        Console.WriteLine("  一個參數的建構子本體");
    }

    public Author(string name, string department)
    {
        Console.WriteLine("  兩個參數的建構子本體");
        this.name = name;
        this.department = department;
    }

    public string Describe() => $"作者：{name}（{department}）";
}

// 輸出：
// == new Author("小明")
//   兩個參數的建構子本體
//   一個參數的建構子本體
// 作者：小明（未分配）
// == new Author("小華", "編輯部")
//   兩個參數的建構子本體
// 作者：小華（編輯部）

注意順序：被 : this(…) 指到的那個先跑完，才輪到自己的本體。第 5 節的 : base(…) 寫法一樣，只是呼叫的是父類別的建構子。

readonly：只有建構子能設

readonly 加在欄位上，意思是這個欄位只能在宣告時或建構子裡設定，之後任何方法都改不了。想保證「這個東西 new 完就不會被換掉」，就標它：

var a = new Author("小明");
a.Rename("小華");

class Author
{
    private readonly string name;

    public Author(string name)
    {
        this.name = name;          // 建構子裡可以設
    }

    public void Rename(string newName)
    {
        name = newName;            // 建構子以外不能設
    }
}

// 編譯錯誤：
// error CS0191: 無法指派給唯讀欄位 (除非位於建構函式內; 或位於已定義此欄位的類型中，僅供初始化的 Setter 內; 或位於變數初始設定式內)

常見用法：建構子收進來、之後整個物件生命期都不該被換掉的東西（設定、別的服務物件），就標 readonly，讓編譯器替你擋。

record：專門裝資料的類別

record 是一種 class，專門用來裝資料。宣告時把屬性直接寫在名稱後面的括號裡：record PostRequest(string Title, string Content);，這一行就同時宣告了建構子 PostRequest(string Title, string Content) 和兩個唯讀屬性 Title、Content。除此之外，編譯器還替你多做了幾件「裝資料的類別」都需要的事。同樣一份資料，用 class 要自己寫建構子和兩個屬性，而且還是少了下面幾項：

record PostRequest(string Title, string Content)自己寫的 class
宣告一行建構子和屬性自己寫
屬性唯讀（init）：new 完就不能改你自己決定
ToString()印出每個屬性的值只印型別名稱
==、Equals比內容：每個屬性都相同就相等比「是不是同一個物件」
with複製一份、只換幾個屬性沒有
解構var (title, content) = a;沒有

範例：同一份資料，record 和 class 的差別（實際執行過）

var a = new PostRequest("Docker 入門", "Docker 是打包工具");
var b = new PostRequest("Docker 入門", "Docker 是打包工具");
var c = new PostRequestClass("Docker 入門", "Docker 是打包工具");
var d = new PostRequestClass("Docker 入門", "Docker 是打包工具");

Console.WriteLine("== ToString");
Console.WriteLine(a);                                   // record 自動有：印出每個屬性
Console.WriteLine(c);                                   // class 只印型別名稱

Console.WriteLine("== 內容相同的兩個物件 ==");
Console.WriteLine($"record：{a == b}");                 // record 比內容
Console.WriteLine($"class：{c == d}");                  // class 比「是不是同一個物件」

Console.WriteLine("== with：複製一份、只換 Title");
var e = a with { Title = "Docker 入門（修訂）" };
Console.WriteLine(e);
Console.WriteLine(a);                                   // a 沒被改

Console.WriteLine("== 解構：照位置拆回變數");
var (title, content) = a;
Console.WriteLine($"{title} / {content}");

// 一行：建構子 + 兩個唯讀屬性 + ToString + 比內容的 == + with + 解構
record PostRequest(string Title, string Content);

// 用 class 自己寫，只做到建構子 + 兩個唯讀屬性
class PostRequestClass
{
    public string Title { get; }
    public string Content { get; }

    public PostRequestClass(string title, string content)
    {
        Title = title;
        Content = content;
    }
}

// 輸出：
// == ToString
// PostRequest { Title = Docker 入門, Content = Docker 是打包工具 }
// PostRequestClass
// == 內容相同的兩個物件 ==
// record：True
// class：False
// == with：複製一份、只換 Title
// PostRequest { Title = Docker 入門（修訂）, Content = Docker 是打包工具 }
// PostRequest { Title = Docker 入門, Content = Docker 是打包工具 }
// == 解構：照位置拆回變數
// Docker 入門 / Docker 是打包工具

new 完想直接改屬性：

var a = new PostRequest("Docker 入門", "內容");
a.Title = "改標題";                 // 位置參數的屬性是 init，new 完就不能改

record PostRequest(string Title, string Content);

// 編譯錯誤：
// error CS8852: 只有物件初始設定式中，或執行個體建構函式中 'this' 或 'base' 上僅供初始化的屬性或索引子 'PostRequest.Title' 或 'init' 存取子可以指派。

要「改」只能用 with 做一份新的。這就是 record 適合的場合：只需要裝著、不改內容、比內容的資料。會在原地被修改、靠編號認身分的東西，維持 class。

主要建構子（primary constructor）

類別名稱後面直接接括號和參數，這叫主要建構子。上面 record 的寫法就是一種；一般的 class 從 C# 12 起也能這樣寫，參數在整個類別裡都能直接用，不用宣告欄位、不用寫建構子本體：

var c = new Counter(10);
c.Bump();
c.Bump();
Console.WriteLine($"Current = {c.Current}");

// 主要建構子：參數寫在類別名稱後面，整個類別裡都能用 start
class Counter(int start)
{
    public void Bump()
    {
        start++;               // 參數可以被改，編譯器不會擋；readonly 欄位就不行
    }

    public int Current => start;
}

// 輸出：
// Current = 12

和「欄位加建構子」的寫法差別只有一個：主要建構子的參數不是 readonly，類別裡任何地方都能改它，編譯器不會擋（上面的 start++ 編譯會過、輸出 12）。要不要用，看你喜不喜歡多那層保護；這份筆記的範例都維持 private readonly 加建構子的寫法。Rider 看到「欄位加建構子」的類別，可能會提議改成主要建構子，接不接受都可以。

4. static：屬於類別，不屬於物件

前三節的欄位、方法、建構子都是「每個物件各有一份」：post1 有自己的 Title，post2 有自己的 Title。但有些東西天生只該有一份，例如「到目前為止 new 了幾個 Author」，它不屬於哪一個 Author，屬於整個類別。這種成員加 static。

簡單範例：三個物件共用同一份 Count（實際執行過）

Console.WriteLine($"還沒 new：Author.Count = {Author.Count}");

var a = new Author("小明");
var b = new Author("小華");
var c = new Author("小芳");

Console.WriteLine($"new 了三個：Author.Count = {Author.Count}");
Console.WriteLine(a.Describe());
Console.WriteLine(c.Describe());

class Author
{
    public static int Count;            // static 欄位：整個類別只有一份，不屬於任何物件

    private readonly string name;       // 實例欄位：每個物件各有一份
    private readonly int number;

    public Author(string name)
    {
        this.name = name;
        Count++;                        // 三個物件的建構子改的是同一份 Count
        number = Count;
    }

    public string Describe() => $"第 {number} 位作者：{name}";
}

// 輸出：
// 還沒 new：Author.Count = 0
// new 了三個：Author.Count = 3
// 第 1 位作者：小明
// 第 3 位作者：小芳

三個物件的建構子改的是同一個 Count，所以最後是 3；number 沒有 static，每個物件各記自己的號碼。存取 static 成員用類別名稱：Author.Count，不用先 new。反過來用物件去存取它是編譯錯誤：

var a = new Author("小明");
Console.WriteLine(a.Count);                 // 用物件存取 static 成員

// 編譯錯誤：
// error CS0176: 成員 'Author.Count' 無法以執行個體參考進行存取; 請改用類型名稱

static 方法：用類別名稱呼叫，裡面沒有 this

方法也可以 static。它不屬於任何物件，所以不用 new、用類別名稱呼叫；也因為不屬於任何物件，本體裡沒有 this，碰不到實例欄位：

Console.WriteLine(Author.Describe());

class Author
{
    private string name = "小明";

    public static string Describe()
    {
        return $"作者：{this.name}";   // static 方法裡沒有「這個物件」
    }
}

// 編譯錯誤：
// error CS0026: 關鍵字 'this' 在靜態屬性、靜態方法或靜態欄位初始設定式中無效

Author.Describe() 用類別名稱呼叫，點前面沒有物件，所以 this 沒有東西可以指。static 方法只能用 static 的成員和自己的參數，適合放「只靠參數就能算出結果」的工具方法。

static class：整個類別都不能 new

一個類別裡全部都是 static 成員（工具類別）時，類別本身也標 static，編譯器就會擋掉 new：

var tools = new StringTools();              // new 一個 static class

static class StringTools
{
    public static string Repeat(string text, int count = 2) => string.Concat(Enumerable.Repeat(text, count));
}

// 編譯錯誤：
// error CS0712: 無法建立靜態類別 'StringTools' 的執行個體

簽章頁第 1 節的 StringTools.Repeat("ab")、第 2 節的擴充方法，放的都是這種類別。

屬於類別的，和屬於物件的

實例成員（沒有 static）靜態成員（有 static）
屬於誰每個物件各有一份整個類別只有一份
怎麼存取a.Describe()，要先有物件Author.Count、StringTools.Repeat("ab")，用類別名稱，不用 new
裡面有 this 嗎有，就是點前面的那個物件沒有，寫了是編譯錯誤
什麼時候用資料和行為屬於某一個物件計數器、共用的設定、只靠參數就能算的工具方法

這頁後面的繼承、abstract、介面，都是「沒有 static」那一邊的事。

5. 繼承：base、protected、virtual / override

class 子類別 : 父類別 的意思是：子類別拿到父類別所有 public 和 protected 的成員，自己再加新的或換掉其中幾個。

.NET 的框架大多這樣用：你寫一個子類別，繼承框架給的父類別，父類別裡寫好的方法不用寫就有，你只補自己的部分。

建構子的順序：父類別先跑，: base(…) 把東西交上去

new 一個子類別物件時，父類別的建構子一定先跑完，才輪到子類別的本體。父類別的建構子要參數的話，子類別用 : base(…) 交給它。

sequenceDiagram participant Code as 你的程式 participant Staff as Staff 的建構子 participant Author as Author 的建構子（父類別） Code->>Staff: new Staff("小華", "編輯部") { Note = "兼職" } Staff->>Author: : base(name) 先把 name 交給父類別 Note over Author: ① Author 本體：this.name = name Author-->>Staff: 父類別跑完 Note over Staff: ② Staff 本體：this.department = department Staff-->>Code: 物件做好了 Note over Code: ③ 物件初始設定式：Note = "兼職"
父類別建構子 → 子類別建構子本體 → 物件初始設定式。第 3 節的順序多了一層「父類別先跑」
Console.WriteLine("開始 new Staff(\"小華\", \"編輯部\") { Note = \"兼職\" }");
var s = new Staff("小華", "編輯部") { Note = "兼職" };
Console.WriteLine("new 完成");
Console.WriteLine(s.Describe());

class Author
{
    protected readonly string name;      // protected：子類別 Staff 用得到，外面用不到
    private string _note = "";

    public string Note
    {
        get => _note;
        set
        {
            Console.WriteLine($"  ③ 物件初始設定式：Note = 「{value}」");
            _note = value;
        }
    }

    public Author(string name)
    {
        Console.WriteLine("  ① Author 建構子本體");
        this.name = name;
    }

    public virtual string Describe() => $"作者：{name}";
}

class Staff : Author
{
    private readonly string department;

    // : base(name)：把 name 交給父類別 Author 的建構子，父類別先跑完才輪到這裡的本體
    public Staff(string name, string department) : base(name)
    {
        Console.WriteLine("  ② Staff 建構子本體");
        this.department = department;
    }

    public override string Describe() => base.Describe() + $"（{department}）";
}

// 輸出：
// 開始 new Staff("小華", "編輯部") { Note = "兼職" }
//   ① Author 建構子本體
//   ② Staff 建構子本體
//   ③ 物件初始設定式：Note = 「兼職」
// new 完成
// 作者：小華（編輯部）

父類別只有「要參數的建構子」時，子類別一定要寫 : base(…)，不然編譯器不知道要拿什麼交上去：

class Staff : Author
{
    private readonly string department;

    public Staff(string name, string department)     // 沒寫 : base(name)
    {
        this.department = department;
    }
}

// 編譯錯誤（指在 Staff 建構子那一行）：
// error CS7036: 未提供任何可對應到 'Author.Author(string)' 之必要參數 'name' 的引數

和第 3 節 new Author() 的錯誤是同一個編號：沒寫 : base(…) 等於寫 : base()，也就是想呼叫父類別的無參數建構子，但它不存在。

protected：子類別用得到，外面用不到

前面只用到 public 和 private。protected 在中間：自己和子類別看得到，其他類別看不到。上面的 protected readonly string name 就是讓 Staff 的 Describe 能讀 name，但類別外面不能寫 s.name。框架常把「給子類別覆寫、外面不該直接呼叫」的方法標成 protected。

virtual / override：父類別允許你換掉它的方法

父類別把方法標 virtual，意思是「子類別可以換成自己的版本」；子類別用 override 換掉；換掉之後還想用父類別原本的，寫 base.方法()。上面的 Staff.Describe 就是三件事一起用：override 換掉、本體裡 base.Describe() 拿父類別的結果再補一段。一般原則：不確定父類別的版本做了什麼，就在自己的 override 裡先呼叫 base.XXX(…)，多呼叫一個空方法沒有成本，漏呼叫一個有內容的方法會出怪事。

子類別物件可以放進父類別型別的變數

Staff 是一種 Author，所以 Author 型別的變數、List<Author>、收 Author 的參數，都能放 Staff 物件。呼叫 virtual 方法時，跑的是物件實際型別的版本，不是變數型別的版本：

// 變數型別是父類別 Author，但放進去的可以是 Author 或它的子類別
List<Author> people = [new Author("小明"), new Staff("小華", "編輯部")];

foreach (var person in people)
{
    Console.WriteLine(person.Describe());    // 同一行程式，跑的是各自那個類別的 Describe
}

Author one = new Staff("小芳", "行銷部");    // 子類別物件放進父類別型別的變數
Console.WriteLine(one.Describe());
Console.WriteLine($"one 的實際型別：{one.GetType().Name}");

// 輸出：
// 作者：小明
// 作者：小華（編輯部）
// 作者：小芳（行銷部）
// one 的實際型別：Staff

簽章頁 第 1 節的泛型限制 where T : Author 就是這件事：填進去的可以是 Author，也可以是 Staff。

6. abstract 類別和介面

第 5 節的 Author 自己可以 new，也可以被繼承。有時候父類別只是用來被繼承的，自己 new 出來沒意義，甚至有些方法它寫不出來、要子類別才知道怎麼做。這就是 abstract；再極端一點，連一行程式都沒有、只剩「約定」，就是介面（interface）。

一般類別abstract 類別介面
可以 new 嗎可以不行不行
裡面有寫好的程式嗎有可以有，也可以有「只有簽章」的 abstract 方法只有簽章，沒有本體
子類別一定要做什麼不用把每個 abstract 方法 override 寫完把每個方法都寫出來（實作）
一個類別可以接幾個父類別只能有一個介面可以同時實作很多個
讀法「X 是一種 Y」「X 做得到 Y」

範例：abstract 類別 Content，介面 IPublishable（實際執行過）

Console.WriteLine("== 用父類別 Content 裝");
List<Content> contents = [new Post("Docker 入門", "Docker 是把程式和環境一起打包的工具"), new Page("關於我")];
foreach (var content in contents)
{
    Console.WriteLine(content.Summary());
}

Console.WriteLine("== 用介面 IPublishable 裝");
List<IPublishable> queue = [new Post("Docker 入門", "…"), new Page("關於我")];
foreach (var item in queue)
{
    item.Publish();
}

// abstract 類別：不能 new，可以有寫好的方法，也可以有「只有簽章」的 abstract 方法
abstract class Content
{
    public string Title { get; }

    protected Content(string title)
    {
        Title = title;
    }

    public abstract string Summary();                              // 只有簽章，子類別一定要 override

    public string Describe() => $"[{GetType().Name}] {Title}";     // 寫好的方法，子類別直接有
}

// 介面：只有簽章，沒有本體；一個類別可以同時實作很多個介面
interface IPublishable
{
    void Publish();
}

class Post : Content, IPublishable
{
    private readonly string body;

    public Post(string title, string body) : base(title)
    {
        this.body = body;
    }

    public override string Summary() => $"{Describe()}：{body[..Math.Min(6, body.Length)]}…";

    public void Publish() => Console.WriteLine($"發佈文章「{Title}」");
}

class Page : Content, IPublishable
{
    public Page(string title) : base(title)
    {
    }

    public override string Summary() => $"{Describe()}（靜態頁面，沒有摘要）";

    public void Publish() => Console.WriteLine($"發佈頁面「{Title}」");
}

// 輸出：
// == 用父類別 Content 裝
// [Post] Docker 入門：Docker…
// [Page] 關於我（靜態頁面，沒有摘要）
// == 用介面 IPublishable 裝
// 發佈文章「Docker 入門」
// 發佈頁面「關於我」

class Post : Content, IPublishable：冒號後面第一個可以是父類別，後面全部是介面。abstract 類別的建構子標 protected 就夠了，反正外面不能 new 它，只有子類別會用 : base(title) 呼叫。

真的去 new 一個 abstract 類別或介面：

var content = new Content("x");        // abstract 類別不能 new
var item = new IPublishable();         // 介面也不能 new

// 編譯錯誤：
// error CS0144: 無法建立抽象類型或介面 'Content' 的執行個體
// error CS0144: 無法建立抽象類型或介面 'IPublishable' 的執行個體

.NET 本身到處是這兩種東西：所有集合都實作 IEnumerable<T> 這個介面，所以 foreach 和 LINQ 對 List、陣列都能用；框架給你繼承的父類別很多是 abstract，自己不能 new，一定要寫子類別才用得到。

7. 練習：單檔程式

和簽章頁一樣用單檔程式（file-based apps）：建 class-lab.cs，在那個資料夾執行 dotnet run class-lab.cs。

題 1：建構子、繼承、介面各寫一個

需求，三小步都在同一個檔案：

  1. 類別 Author：一個 private readonly string name 欄位；建構子 Author(string name)，參數名稱故意和欄位一樣，本體先印「Author 建構子」再用 this. 設定欄位；方法 Describe() 回傳「作者：小明」這種字串。new Author("小明") 然後印 Describe()
  2. 類別 Staff : Author：多一個 department 欄位；建構子 Staff(string name, string department) 用 : base(name) 把名字交上去，本體印「Staff 建構子」；Describe() 要 override，結果是父類別的結果再加「（編輯部）」。new Staff("小華", "編輯部")，看兩行「建構子」印出的順序
  3. 介面 IPrintable，只有一個方法 void Print()。讓 Author 實作它，內容是印出 Describe()。把第 1、2 步的兩個物件放進 List<IPrintable>，迴圈呼叫 Print()，看 Staff 那筆印的是哪個版本

💡 提示：第 2 步要 override，父類別的 Describe 就得先標 virtual。第 3 步 Staff 不用再寫 : IPrintable，繼承 Author 就一起繼承了它實作的介面。

✅ 驗收：(1) 一行「Author 建構子」加一行「作者：小明」；(2) 先「Author 建構子」再「Staff 建構子」，最後「作者：小華（編輯部）」；(3) 兩行作者，Staff 那行有部門

參考答案（寫完再打開）

class-lab.cs

Console.WriteLine("== (1) 建構子和 this");
var ming = new Author("小明");
Console.WriteLine(ming.Describe());

Console.WriteLine("== (2) 繼承：建構子順序和 override");
var hua = new Staff("小華", "編輯部");
Console.WriteLine(hua.Describe());

Console.WriteLine("== (3) 介面");
List<IPrintable> items = [ming, hua];
foreach (var item in items)
{
    item.Print();
}

interface IPrintable
{
    void Print();
}

class Author : IPrintable
{
    private readonly string name;

    public Author(string name)
    {
        Console.WriteLine("  Author 建構子");
        this.name = name;
    }

    public virtual string Describe() => $"作者：{name}";

    public void Print() => Console.WriteLine($"  {Describe()}");
}

class Staff : Author
{
    private readonly string department;

    public Staff(string name, string department) : base(name)
    {
        Console.WriteLine("  Staff 建構子");
        this.department = department;
    }

    public override string Describe() => $"{base.Describe()}（{department}）";
}

輸出（實際執行）

== (1) 建構子和 this
  Author 建構子
作者：小明
== (2) 繼承：建構子順序和 override
  Author 建構子
  Staff 建構子
作者：小華（編輯部）
== (3) 介面
  作者：小明
  作者：小華（編輯部）

三個觀察：

  • (2) 的兩行「建構子」順序是先 Author 再 Staff：: base(name) 讓父類別先跑完
  • (3) 的 Print() 寫在 Author 裡，本體呼叫的是 Describe()，也就是 this.Describe()。對 Staff 物件呼叫時 this 是 Staff，所以跑的是 override 過的版本，印出有部門的那行
  • List<IPrintable> 裡放的是 Author 和 Staff 兩種物件，迴圈那行只知道「它做得到 Print」，不用知道實際是哪個類別
