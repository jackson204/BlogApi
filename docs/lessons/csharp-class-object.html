📌 這頁是 C# 語法，和專案無關：類別和物件的差別、this、建構子、static、: base(…)、override、abstract、介面。頁面上的範例都是單檔程式實際跑過的，編譯錯誤也是實際的訊息。

1. 類別與物件：圖紙和成品

類別（class）是圖紙，寫一次；物件（object）是照圖紙做出來的成品，new 一次做一個。這一節從沒有類別的寫法開始，一步加一樣東西。

這一頁程式裡的顏色：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或有問題的寫法。輸出和錯誤訊息都實際執行過。

第 1 步：沒有類別，資料散在變數裡

兩篇文章，各有標題和瀏覽次數：

string title1 = "Docker 入門";
int views1 = 120;
string title2 = "Hi";
int views2 = 3;

Console.WriteLine($"{title1}，{views1} 次瀏覽");
Console.WriteLine($"{title2}，{views2} 次瀏覽");

// 輸出：
// Docker 入門，120 次瀏覽
// Hi，3 次瀏覽

一篇文章的資料分在兩個變數裡，只靠名稱後面的 1、2 知道誰和誰是一組。文章變成一百篇，或一篇文章多一個欄位，變數就多到管不住；title1 配到 views2，編譯器也不會說話。

第 2 步：寫一個類別，把一篇文章的資料放在一起

var post1 = new Post();
post1.Title = "Docker 入門";
post1.Views = 120;
Console.WriteLine($"{post1.Title}，{post1.Views} 次瀏覽");

class Post
{
    public string Title = "";
    public int Views;
}

// 輸出：
// Docker 入門，120 次瀏覽
  • class Post { … } 是圖紙：寫明「一篇文章有 Title 和 Views」。寫了圖紙，還沒有任何一篇文章
  • new Post() 照圖紙做出一個物件，放進變數 post1
  • 用「物件.名稱」讀寫它裡面的資料。類別裡宣告的變數叫欄位；前面的 public 表示類別外面的程式也能讀寫

第 3 步：new 兩次，得到兩個互不影響的物件

var post1 = new Post();
post1.Title = "Docker 入門";
post1.Views = 120;

var post2 = new Post();
post2.Title = "Hi";
post2.Views = 3;

post1.Views = 121;            // 只改 post1

Console.WriteLine($"{post1.Title}，{post1.Views} 次瀏覽");
Console.WriteLine($"{post2.Title}，{post2.Views} 次瀏覽");

// 輸出：
// Docker 入門，121 次瀏覽
// Hi，3 次瀏覽

圖紙只有一張，new 幾次就有幾個物件。每個物件有自己的一份 Title 和 Views，改 post1 的，post2 的沒有動。

第 4 步：把「對這份資料做的事」也寫進類別

印出「標題，幾次瀏覽」那一行，每個物件都要寫一次，格式還得一樣。把它寫成類別裡的方法：

Console.WriteLine(post1.Describe());
Console.WriteLine(post2.Describe());

class Post
{
    public string Title = "";
    public int Views;

    public string Describe()
    {
        return $"{Title}，{Views} 次瀏覽";
    }
}

// 輸出（post1、post2 的內容和第 3 步改之前一樣）：
// Docker 入門，120 次瀏覽
// Hi，3 次瀏覽

Describe() 只寫了一份，對兩個物件呼叫卻印出不同的結果：方法裡的 Title、Views 讀的是「被呼叫的那個物件」的。

同一張圖紙 new 兩次，得到兩個互不相干的物件；方法只有一份，但 this 每次指向被呼叫的那個物件

2. this：這個物件自己

方法裡的 this 就是「這次被呼叫的那個物件」。寫 post2.Describe()，方法執行時 this 就是 post2。

第 1 步：方法裡的 Title 其實是 this.Title

Console.WriteLine(post1.Describe());
Console.WriteLine(post2.Describe());
Console.WriteLine(post1.IsSame(post1));
Console.WriteLine(post1.IsSame(post2));

class Post
{
    public string Title = "";

    public string Describe()
    {
        // this.Title 和 Title 是同一個東西
        return $"標題「{this.Title}」，長度 {Title.Length}";
    }

    public bool IsSame(Post other)
    {
        // this 和 other 是不是同一個物件
        return ReferenceEquals(this, other);
    }
}

// 輸出（post1 的 Title 是 Docker 入門，post2 是 Hi）：
// 標題「Docker 入門」，長度 9
// 標題「Hi」，長度 2
// True
// False

this.Title 和直接寫 Title 是同一件事，所以平常省略不寫。post1.IsSame(post1) 是 True：方法裡的 this 就是點前面的 post1。

第 2 步：一定要寫 this 的情況，參數和欄位同名

寫一個設定標題的方法，參數也叫 title：

var post = new Post();
post.SetTitle("Docker 入門");
Console.WriteLine(post.Describe());

class Post
{
    public string title = "";

    public void SetTitle(string title)
    {
        title = title;          // 兩邊都是參數，欄位沒被設定
    }

    public string Describe()
    {
        return $"標題「{title}」";
    }
}

warning CS1717: 對同一個變數進行指派; 您是否想要指派別的東西?

// 輸出：
// 標題「」

編譯會過，但標題是空的。在 SetTitle 裡面，參數 title 把欄位 title 遮住了，title = title 是把參數指派給它自己。要碰到欄位，得寫 this.：

    public void SetTitle(string title)
    {
        this.title = title;     // 左邊 this.title 是欄位，右邊 title 是參數
    }

// 輸出：
// 標題「Docker 入門」

另一個常見的做法是欄位用底線開頭命名（_title）、參數叫 title。名稱不同就不會遮住，也就不用寫 this.。

⚠️ 同一個字，三種用法

寫在哪意思在哪一頁
實例方法本體裡：this.name這個物件自己這一節
建構子後面：: this(name, "未分配")先呼叫同一個類別的另一個建構子第 3 節
擴充方法第一個參數前：this string title參數修飾詞，「點前面的東西填進這個參數」，和物件無關簽章頁第 2 節

3. 建構子：物件誕生時跑的那段程式

建構子（constructor）是 new 的時候執行的那段程式，每個物件剛好執行一次。它的工作是讓物件一做出來就是可用的狀態。

第 1 步：沒有建構子，new 出來的物件是空的

var post = new Post();          // 忘了設定 Title
Console.WriteLine(post.Describe());

class Post
{
    public string Title = "";
    public int Views;

    public string Describe()
    {
        return $"標題「{Title}」，{Views} 次瀏覽";
    }
}

// 輸出：
// 標題「」，0 次瀏覽

一篇沒有標題的文章被做出來了，而且可以照常使用。「文章一定要有標題」這件事，全靠寫 new 的人記得在下一行補上，忘了也不會有任何錯誤。

第 2 步：寫一個建構子，new 的時候一定要給標題

Console.WriteLine("new 之前");
var post = new Post("Docker 入門");
Console.WriteLine("new 之後");
Console.WriteLine(post.Describe());
var post2 = new Post("Hi");

class Post
{
    public string Title;
    public int Views;

    public Post(string title)
    {
        Console.WriteLine($"  建構子執行，title 是「{title}」");
        Title = title;
    }

    public string Describe()
    {
        return $"標題「{Title}」，{Views} 次瀏覽";
    }
}

// 輸出：
// new 之前
//   建構子執行，title 是「Docker 入門」
// new 之後
// 標題「Docker 入門」，0 次瀏覽
//   建構子執行，title 是「Hi」
  • 建構子的寫法：名稱和類別相同、沒有回傳型別。參數寫在括號裡，new Post("…") 括號裡的值就傳給它
  • 每一次 new 就執行一次建構子。上面 new 了兩次，印了兩行。不管那個 new 是自己寫的，還是別人的程式替你寫的，都一樣
  • 建構子跑完，物件才交到 post 這個變數裡

現在不給標題就做不出文章：

var post = new Post();
error CS7036: 未提供任何可對應到 'Post.Post(string)' 之必要參數 'title' 的引數

第 1 步的 new Post() 之所以能寫，是因為類別裡一個建構子都沒寫時，編譯器會補一個沒有參數、什麼都不做的。只要自己寫了任何一個建構子，編譯器就不再補。

第 3 步：new 完之後，外面還是能把資料改壞

var post = new Post("Docker 入門");
post.Title = "";                // 建構子擋不到這一行
Console.WriteLine($"標題「{post.Title}」");

// 輸出：
// 標題「」

Title 是 public 的欄位，類別外面隨時可以改。建構子只管得到 new 的那一刻。要擋住，有兩種寫法，差在外面還能不能讀：

改成 private：外面不能讀、也不能寫

class Post
{
    private string title;

    public Post(string title)
    {
        this.title = title;
    }
}

post.title = "";
error CS0122: 'Post.title' 由於其保護層級之故，所以無法存取

private 的成員只有這個類別自己的方法碰得到。外面要用這份資料，得透過類別提供的方法（例如 Describe()）。

改成只有 get 的屬性：外面可以讀、不能寫

class Post
{
    public string Title { get; }

    public Post(string title)
    {
        Title = title;
    }
}

Console.WriteLine(post.Title);     // 可以讀 → Docker 入門
post.Title = "";
error CS0200: 無法指派為屬性或索引子 'Post.Title' -- 其為唯讀

名稱後面接 { get; } 的叫屬性。get 是「可以讀」，set 是「可以寫」：{ get; } 只能讀，只有建構子裡可以設定它；{ get; set; } 讀寫都可以，例如瀏覽次數寫成 public int Views { get; set; }，外面 post.Views = 5 是合法的。

什麼時候用哪一種：物件內部自己用、外面不需要知道的資料用 private 欄位；要給外面讀的資料用屬性，要不要讓外面改，就看有沒有 set。

第 4 步：一次 new 裡，三段程式的順序

類別裡一個建構子都沒寫，編譯器會補一個無參數的，什麼都不做。一個只寫了屬性的類別，new Post() 和 new Post { Title = "Hi" } 都合法。後者的大括號叫物件初始設定式，它不是建構子的一部分，是 new 完之後再逐一設定屬性。

欄位宣告時的 = …、建構子本體、大括號裡的設定，這三段哪一段先跑？下面的程式在三個地方各印一行來看（為了能印，Title 的 get 和 set 寫成完整的本體，value 是被設定進來的值）：

Console.WriteLine("開始 new Post { Title = \"Hi\" }");
var post = new Post { Title = "Hi" };
Console.WriteLine($"new 完成，post.Title = {post.Title}");

class Post
{
    private string _title = Init();

    public string Title
    {
        get => _title;
        set
        {
            Console.WriteLine($"  ③ 物件初始設定式：Title = 「{value}」");
            _title = value;
        }
    }

    public Post()
    {
        Console.WriteLine($"  ② 建構子本體，這時 Title 是「{Title}」");
    }

    private static string Init()
    {
        Console.WriteLine("  ① 屬性初始設定式 = string.Empty");
        return string.Empty;
    }
}

// 輸出：
// 開始 new Post { Title = "Hi" }
//   ① 屬性初始設定式 = string.Empty
//   ② 建構子本體，這時 Title 是「」
//   ③ 物件初始設定式：Title = 「Hi」
// new 完成，post.Title = Hi

順序固定是：① 欄位和屬性宣告時的 = … → ② 建構子本體 → ③ { … } 裡的設定。所以一個屬性宣告時寫了 = string.Empty，new 的時候又用 { Title = "Hi" } 蓋掉，兩段都會跑，最後留下的是 ③ 的值。

第 5 步：多個建構子，用 : this(…) 共用

一個類別可以有好幾個建構子，參數不同就行（多載）。要避免重複寫，一個建構子可以用 : this(…) 先呼叫另一個：

Console.WriteLine("== new Author(\"小明\")");
var a = new Author("小明");
Console.WriteLine(a.Describe());

Console.WriteLine("== new Author(\"小華\", \"編輯部\")");
var b = new Author("小華", "編輯部");
Console.WriteLine(b.Describe());

class Author
{
    private readonly string name;
    private readonly string department;

    // : this(name, "未分配")：先呼叫下面那個兩個參數的建構子，再跑自己的本體
    public Author(string name) : this(name, "未分配")
    {
        Console.WriteLine("  一個參數的建構子本體");
    }

    public Author(string name, string department)
    {
        Console.WriteLine("  兩個參數的建構子本體");
        this.name = name;
        this.department = department;
    }

    public string Describe() => $"作者：{name}（{department}）";
}

// 輸出：
// == new Author("小明")
//   兩個參數的建構子本體
//   一個參數的建構子本體
// 作者：小明（未分配）
// == new Author("小華", "編輯部")
//   兩個參數的建構子本體
// 作者：小華（編輯部）

順序是：被 : this(…) 指到的那個先跑完，才輪到自己的本體。

Describe() => … 是「方法本體只有一句 return」的簡寫，和寫成大括號加 return 完全一樣。這一頁後面的短方法都用這個寫法。

第 6 步：readonly，只有建構子能設

readonly 加在欄位上，意思是這個欄位只能在宣告時或建構子裡設定，之後任何方法都改不了。想保證「這個東西 new 完就不會被換掉」，就標它：

var a = new Author("小明");
a.Rename("小華");

class Author
{
    private readonly string name;

    public Author(string name)
    {
        this.name = name;          // 建構子裡可以設
    }

    public void Rename(string newName)
    {
        name = newName;            // 建構子以外不能設
    }
}

// 編譯錯誤：
// error CS0191: 無法指派給唯讀欄位 (除非位於建構函式內; 或位於已定義此欄位的類型中，僅供初始化的 Setter 內; 或位於變數初始設定式內)

常見用法：建構子收進來、之後整個物件生命期都不該被換掉的東西（設定、別的服務物件），就標 readonly，讓編譯器替你擋。

第 7 步：record，專門裝資料的類別

record 是一種 class，專門用來裝資料。宣告時把屬性直接寫在名稱後面的括號裡：record PostRequest(string Title, string Content);，這一行就同時宣告了建構子 PostRequest(string Title, string Content) 和兩個唯讀屬性 Title、Content。除此之外，編譯器還替你多做了幾件「裝資料的類別」都需要的事。同樣一份資料，用 class 要自己寫建構子和兩個屬性，而且還是少了下面幾項：

  • 宣告：record 一行；class 要自己寫建構子和屬性
  • 屬性：record 的屬性是唯讀的，new 完就不能改；class 由你自己決定
  • ToString()：record 印出每個屬性的值；class 只印型別名稱
  • ==、Equals：record 比內容，每個屬性都相同就相等；class 比「是不是同一個物件」
  • with：record 可以複製一份、只換幾個屬性；class 沒有
  • 解構：record 可以寫 var (title, content) = a; 照位置拆回變數；class 沒有

範例：同一份資料，record 和 class 的差別（實際執行過）

var a = new PostRequest("Docker 入門", "Docker 是打包工具");
var b = new PostRequest("Docker 入門", "Docker 是打包工具");
var c = new PostRequestClass("Docker 入門", "Docker 是打包工具");
var d = new PostRequestClass("Docker 入門", "Docker 是打包工具");

Console.WriteLine("== ToString");
Console.WriteLine(a);                                   // record 自動有：印出每個屬性
Console.WriteLine(c);                                   // class 只印型別名稱

Console.WriteLine("== 內容相同的兩個物件 ==");
Console.WriteLine($"record：{a == b}");                 // record 比內容
Console.WriteLine($"class：{c == d}");                  // class 比「是不是同一個物件」

Console.WriteLine("== with：複製一份、只換 Title");
var e = a with { Title = "Docker 入門（修訂）" };
Console.WriteLine(e);
Console.WriteLine(a);                                   // a 沒被改

Console.WriteLine("== 解構：照位置拆回變數");
var (title, content) = a;
Console.WriteLine($"{title} / {content}");

// 一行：建構子 + 兩個唯讀屬性 + ToString + 比內容的 == + with + 解構
record PostRequest(string Title, string Content);

// 用 class 自己寫，只做到建構子 + 兩個唯讀屬性
class PostRequestClass
{
    public string Title { get; }
    public string Content { get; }

    public PostRequestClass(string title, string content)
    {
        Title = title;
        Content = content;
    }
}

// 輸出：
// == ToString
// PostRequest { Title = Docker 入門, Content = Docker 是打包工具 }
// PostRequestClass
// == 內容相同的兩個物件 ==
// record：True
// class：False
// == with：複製一份、只換 Title
// PostRequest { Title = Docker 入門（修訂）, Content = Docker 是打包工具 }
// PostRequest { Title = Docker 入門, Content = Docker 是打包工具 }
// == 解構：照位置拆回變數
// Docker 入門 / Docker 是打包工具

new 完想直接改屬性：

var a = new PostRequest("Docker 入門", "內容");
a.Title = "改標題";                 // 位置參數的屬性是 init，new 完就不能改

record PostRequest(string Title, string Content);

// 編譯錯誤：
// error CS8852: 只有物件初始設定式中，或執行個體建構函式中 'this' 或 'base' 上僅供初始化的屬性或索引子 'PostRequest.Title' 或 'init' 存取子可以指派。

要「改」只能用 with 做一份新的。這就是 record 適合的場合：只需要裝著、不改內容、比內容的資料。會在原地被修改、靠編號認身分的東西，維持 class。

主要建構子（primary constructor）

類別名稱後面直接接括號和參數，這叫主要建構子。上面 record 的寫法就是一種；一般的 class 從 C# 12 起也能這樣寫，參數在整個類別裡都能直接用，不用宣告欄位、不用寫建構子本體：

var c = new Counter(10);
c.Bump();
c.Bump();
Console.WriteLine($"Current = {c.Current}");

// 主要建構子：參數寫在類別名稱後面，整個類別裡都能用 start
class Counter(int start)
{
    public void Bump()
    {
        start++;               // 參數可以被改，編譯器不會擋；readonly 欄位就不行
    }

    public int Current => start;
}

// 輸出：
// Current = 12

和「欄位加建構子」的寫法差別只有一個：主要建構子的參數不是 readonly，類別裡任何地方都能改它，編譯器不會擋（上面的 start++ 編譯會過、輸出 12）。要不要用，看你喜不喜歡多那層保護；這份筆記的範例都維持 private readonly 加建構子的寫法。Rider 看到「欄位加建構子」的類別，可能會提議改成主要建構子，接不接受都可以。

4. static：屬於類別，不屬於物件

前三節的欄位、方法、建構子都是「每個物件各有一份」：post1 有自己的 Title，post2 有自己的 Title。但有些東西天生只該有一份，例如「到目前為止 new 了幾個 Author」，它不屬於哪一個 Author，屬於整個類別。這種成員加 static。

簡單範例：三個物件共用同一份 Count（實際執行過）

Console.WriteLine($"還沒 new：Author.Count = {Author.Count}");

var a = new Author("小明");
var b = new Author("小華");
var c = new Author("小芳");

Console.WriteLine($"new 了三個：Author.Count = {Author.Count}");
Console.WriteLine(a.Describe());
Console.WriteLine(c.Describe());

class Author
{
    public static int Count;            // static 欄位：整個類別只有一份，不屬於任何物件

    private readonly string name;       // 實例欄位：每個物件各有一份
    private readonly int number;

    public Author(string name)
    {
        this.name = name;
        Count++;                        // 三個物件的建構子改的是同一份 Count
        number = Count;
    }

    public string Describe() => $"第 {number} 位作者：{name}";
}

// 輸出：
// 還沒 new：Author.Count = 0
// new 了三個：Author.Count = 3
// 第 1 位作者：小明
// 第 3 位作者：小芳

三個物件的建構子改的是同一個 Count，所以最後是 3；number 沒有 static，每個物件各記自己的號碼。存取 static 成員用類別名稱：Author.Count，不用先 new。反過來用物件去存取它是編譯錯誤：

var a = new Author("小明");
Console.WriteLine(a.Count);                 // 用物件存取 static 成員

// 編譯錯誤：
// error CS0176: 成員 'Author.Count' 無法以執行個體參考進行存取; 請改用類型名稱

static 方法：用類別名稱呼叫，裡面沒有 this

方法也可以 static。它不屬於任何物件，所以不用 new、用類別名稱呼叫；也因為不屬於任何物件，本體裡沒有 this，碰不到實例欄位：

Console.WriteLine(Author.Describe());

class Author
{
    private string name = "小明";

    public static string Describe()
    {
        return $"作者：{this.name}";   // static 方法裡沒有「這個物件」
    }
}

// 編譯錯誤：
// error CS0026: 關鍵字 'this' 在靜態屬性、靜態方法或靜態欄位初始設定式中無效

Author.Describe() 用類別名稱呼叫，點前面沒有物件，所以 this 沒有東西可以指。static 方法只能用 static 的成員和自己的參數，適合放「只靠參數就能算出結果」的工具方法。

static class：整個類別都不能 new

一個類別裡全部都是 static 成員（工具類別）時，類別本身也標 static，編譯器就會擋掉 new：

var tools = new StringTools();              // new 一個 static class

static class StringTools
{
    public static string Repeat(string text, int count = 2) => string.Concat(Enumerable.Repeat(text, count));
}

// 編譯錯誤：
// error CS0712: 無法建立靜態類別 'StringTools' 的執行個體

簽章頁第 1 節的 StringTools.Repeat("ab")、第 2 節的擴充方法，放的都是這種類別。

屬於類別的，和屬於物件的

實例成員（沒有 static）靜態成員（有 static）
屬於誰每個物件各有一份整個類別只有一份
怎麼存取a.Describe()，要先有物件Author.Count、StringTools.Repeat("ab")，用類別名稱，不用 new
裡面有 this 嗎有，就是點前面的那個物件沒有，寫了是編譯錯誤
什麼時候用資料和行為屬於某一個物件計數器、共用的設定、只靠參數就能算的工具方法

這頁後面的繼承、abstract、介面，都是「沒有 static」那一邊的事。

5. 繼承：base、protected、virtual / override

class 子類別 : 父類別 的意思是：父類別有的成員，子類別不用再寫一次就有，自己只補新的，或換掉其中幾個。.NET 的框架大多這樣用：繼承框架給的父類別，父類別寫好的方法直接有，只補自己的部分。

第 1 步：兩個類別，大部分內容一樣

作者有名字。員工也是作者，只是多一個部門。不用繼承，就是兩個類別各寫一次：

class Author
{
    private readonly string name;

    public Author(string name)
    {
        this.name = name;
    }

    public string Describe()
    {
        return $"作者：{name}";
    }
}

class Staff
{
    private readonly string name;
    private readonly string department;

    public Staff(string name, string department)
    {
        this.name = name;
        this.department = department;
    }

    public string Describe()
    {
        return $"作者：{name}";
    }
}

紅色的部分和 Author 一模一樣。Author 的 Describe 改了格式，Staff 的也要記得改。

第 2 步：寫上 : Author，先遇到一個錯誤

在類別名稱後面寫 : Author，先什麼都不加：

class Staff : Author
{
}

error CS7036: 未提供任何可對應到 'Author.Author(string)' 之必要參數 'name' 的引數

編譯不過，錯誤指在 Staff 那一行。做一個 Staff 物件時，裡面屬於 Author 的那一部分也要做出來，而 Author 的建構子要一個 name，現在沒有人給它。

第 3 步：用 : base(…) 把參數交給父類別的建構子

Console.WriteLine("開始 new Staff");
var s = new Staff("小華");
Console.WriteLine("new 完成");
Console.WriteLine(s.Describe());       // Staff 裡沒有寫 Describe

class Author
{
    private readonly string name;

    public Author(string name)
    {
        Console.WriteLine("  Author 建構子本體");
        this.name = name;
    }

    public string Describe()
    {
        return $"作者：{name}";
    }
}

class Staff : Author
{
    public Staff(string name) : base(name)
    {
        Console.WriteLine("  Staff 建構子本體");
    }
}

// 輸出：
// 開始 new Staff
//   Author 建構子本體
//   Staff 建構子本體
// new 完成
// 作者：小華
  • : base(name) 把 name 交給父類別 Author 的建構子
  • 父類別的建構子先跑完，才輪到子類別的本體
  • Staff 裡沒有寫 Describe，s.Describe() 卻能呼叫：這是從 Author 繼承來的

第 2 步的錯誤，原因是沒寫 : base(…) 等於寫 : base()，也就是要呼叫父類別沒有參數的建構子，但 Author 沒有那一個。

第 4 步：子類別要用父類別的欄位，private 改成 protected

替 Staff 加上部門，再寫一個方法把名字和部門一起印出來：

class Staff : Author
{
    private readonly string department;

    public Staff(string name, string department) : base(name)
    {
        this.department = department;
    }

    public string DescribeWithDepartment()
    {
        return $"作者：{name}（{department}）";
    }
}

error CS0122: 'Author.name' 由於其保護層級之故，所以無法存取

name 在 Author 裡是 private，只有 Author 自己的方法碰得到，連子類別也不行。把它改成 protected：

class Author
{
    protected readonly string name;
    …
}

// new Staff("小華", "編輯部").DescribeWithDepartment() 的輸出：
// 作者：小華（編輯部）

protected 在 public 和 private 中間：自己和子類別碰得到，其他類別碰不到。類別外面寫 s.name 還是同一個 CS0122 錯誤。

第 5 步：子類別要換掉父類別的方法，virtual 和 override

另外取一個方法名稱 DescribeWithDepartment 不理想：用的人要知道員工得呼叫另一個方法。想要的是 Staff 的 Describe() 自己就帶部門。先直接在 Staff 裡寫一個同名的方法：

Staff s = new Staff("小華", "編輯部");
Author a = s;                        // 同一個物件，放進 Author 型別的變數
Console.WriteLine(s.Describe());
Console.WriteLine(a.Describe());

class Staff : Author
{
    …
    public string Describe()
    {
        return $"作者：{name}（{department}）";
    }
}

warning CS0108: 'Staff.Describe()' 會隱藏繼承的成員 'Author.Describe()'。若本意即為要隱藏，請使用 new 關鍵字。

// 輸出：
// 作者：小華（編輯部）
// 作者：小華

同一個物件，印出兩種結果。兩個類別現在各有一個 Describe，呼叫哪一個是看變數的型別：變數是 Staff 就用 Staff 的，變數是 Author 就用 Author 的。編譯器的警告就是在說這件事。

要讓它不管放在哪種變數裡，都用 Staff 的版本：父類別的方法標 virtual（允許子類別換掉），子類別的標 override（換掉它）：

class Author
{
    …
    public virtual string Describe()
    {
        return $"作者：{name}";
    }
}

class Staff : Author
{
    …
    public override string Describe()
    {
        return $"作者：{name}（{department}）";
    }
}

// 輸出：
// 作者：小華（編輯部）
// 作者：小華（編輯部）

兩個要成對。父類別沒標 virtual，子類別就寫 override，會得到 error CS0506: 'Staff.Describe()': 無法覆寫繼承的成員 'Author.Describe()'，因為其未標記為 virtual、abstract 或 override。

換掉之後還想用父類別原本的版本，寫 base.方法()。Staff 的 Describe 前半段和父類別一樣，可以不用重寫：

    public override string Describe()
    {
        return base.Describe() + $"（{department}）";
    }

// 輸出一樣：
// 作者：小華（編輯部）

不確定父類別的版本做了什麼時，就在自己的 override 裡先呼叫 base.方法(…)。多呼叫一個空的方法沒有成本，漏呼叫一個有內容的方法會出問題。

第 6 步：子類別物件可以放進父類別型別的變數

Staff 是一種 Author，所以 Author 型別的變數、List<Author>、收 Author 的參數，都能放 Staff 物件。呼叫 virtual 方法時，跑的是物件實際型別的版本，不是變數型別的版本：

// 變數型別是父類別 Author，但放進去的可以是 Author 或它的子類別
List<Author> people = [new Author("小明"), new Staff("小華", "編輯部")];

foreach (var person in people)
{
    Console.WriteLine(person.Describe());    // 同一行程式，跑的是各自那個類別的 Describe
}

Author one = new Staff("小芳", "行銷部");    // 子類別物件放進父類別型別的變數
Console.WriteLine(one.Describe());
Console.WriteLine($"one 的實際型別：{one.GetType().Name}");

// 輸出：
// 作者：小明
// 作者：小華（編輯部）
// 作者：小芳（行銷部）
// one 的實際型別：Staff

簽章頁 第 1 節的泛型限制 where T : Author 就是這件事：填進去的可以是 Author，也可以是 Staff。

六步合起來：一次 new 的完整順序

把 : base(…)、protected、virtual、override 放進同一個程式，再加上第 3 節的物件初始設定式，看一次 new 裡每一段的順序（實際執行過）：

sequenceDiagram participant Code as 你的程式 participant Staff as Staff 的建構子 participant Author as Author 的建構子（父類別） Code->>Staff: new Staff("小華", "編輯部") { Note = "兼職" } Staff->>Author: : base(name) 先把 name 交給父類別 Note over Author: ① Author 本體：this.name = name Author-->>Staff: 父類別跑完 Note over Staff: ② Staff 本體：this.department = department Staff-->>Code: 物件做好了 Note over Code: ③ 物件初始設定式：Note = "兼職"
父類別建構子 → 子類別建構子本體 → 物件初始設定式。第 3 節的順序多了一層「父類別先跑」
Console.WriteLine("開始 new Staff(\"小華\", \"編輯部\") { Note = \"兼職\" }");
var s = new Staff("小華", "編輯部") { Note = "兼職" };
Console.WriteLine("new 完成");
Console.WriteLine(s.Describe());

class Author
{
    protected readonly string name;      // protected：子類別 Staff 用得到，外面用不到
    private string _note = "";

    public string Note
    {
        get => _note;
        set
        {
            Console.WriteLine($"  ③ 物件初始設定式：Note = 「{value}」");
            _note = value;
        }
    }

    public Author(string name)
    {
        Console.WriteLine("  ① Author 建構子本體");
        this.name = name;
    }

    public virtual string Describe() => $"作者：{name}";
}

class Staff : Author
{
    private readonly string department;

    // : base(name)：把 name 交給父類別 Author 的建構子，父類別先跑完才輪到這裡的本體
    public Staff(string name, string department) : base(name)
    {
        Console.WriteLine("  ② Staff 建構子本體");
        this.department = department;
    }

    public override string Describe() => base.Describe() + $"（{department}）";
}

// 輸出：
// 開始 new Staff("小華", "編輯部") { Note = "兼職" }
//   ① Author 建構子本體
//   ② Staff 建構子本體
//   ③ 物件初始設定式：Note = 「兼職」
// new 完成
// 作者：小華（編輯部）

6. abstract 類別和介面

有些父類別只是用來被繼承的，自己 new 出來沒有意義，這種標 abstract。再進一步，連一行程式都沒有、只規定「要有哪些方法」，就是介面（interface）。

第 1 步：一般的父類別，有兩個地方擋不住

文章和頁面都是「內容」，都有標題，也都要能產生摘要。先用第 5 節的寫法，父類別 Content 是一般的類別：

class Content
{
    public string Title { get; }

    public Content(string title)
    {
        Title = title;
    }

    public virtual string Summary()
    {
        return "";             // 父類別不知道摘要該怎麼產生，只能先回空字串
    }
}

class Post : Content
{
    private readonly string body;

    public Post(string title, string body) : base(title)
    {
        this.body = body;
    }

    public override string Summary()
    {
        return $"{Title}：{body.Substring(0, 6)}…";
    }
}

class Page : Content
{
    public Page(string title) : base(title)
    {
    }
    // 忘了寫 Summary
}
var content = new Content("x");       // 一個不是文章也不是頁面的「內容」
Console.WriteLine($"[{content.Summary()}]");
var page = new Page("關於我");
Console.WriteLine($"[{page.Summary()}]");

// 輸出：
// []
// []

兩個問題，編譯器都沒有擋：

  • new Content("x") 做出一個沒有意義的物件
  • Page 忘了寫自己的 Summary，結果用到父類別那個回空字串的版本，執行時才發現摘要是空的

第 2 步：父類別標 abstract

abstract class Content
{
    public string Title { get; }

    protected Content(string title)
    {
        Title = title;
    }

    // 只有簽章、沒有本體，結尾是分號
    public abstract string Summary();
}

兩個地方加了 abstract，第 1 步的兩個問題都變成編譯錯誤：

var content = new Content("x");
error CS0144: 無法建立抽象類型或介面 'Content' 的執行個體

class Page : Content       // 沒有寫 Summary
error CS0534: 'Page' 未實作繼承的抽象成員 'Content.Summary()'
  • 類別標 abstract：不能 new，只能被繼承
  • 方法標 abstract：父類別不寫本體，每個子類別一定要 override，沒寫就編譯不過

abstract 類別裡還是可以有寫好的方法和屬性（上面的 Title），子類別直接有。建構子標 protected 就夠了：外面不能 new 它，只有子類別會用 : base(title) 呼叫。

第 3 步：沒有共同的父類別，卻都做得到同一件事，用介面

文章可以發佈，電子報也可以發佈。這兩個東西沒有共同的資料，硬找一個父類別不合理；而且一個類別只能有一個父類別。想表達的只是「它做得到發佈」：

List<IPublishable> queue = [new Post("Docker 入門"), new Newsletter("十一月號")];
foreach (var item in queue)
{
    item.Publish();
}

interface IPublishable
{
    void Publish();             // 只有簽章，沒有本體
}

class Post : IPublishable
{
    public string Title { get; }

    public Post(string title)
    {
        Title = title;
    }

    public void Publish()
    {
        Console.WriteLine($"發佈文章「{Title}」");
    }
}

class Newsletter : IPublishable
{
    public string Issue { get; }

    public Newsletter(string issue)
    {
        Issue = issue;
    }

    public void Publish()
    {
        Console.WriteLine($"寄出電子報「{Issue}」");
    }
}

// 輸出：
// 發佈文章「Docker 入門」
// 寄出電子報「十一月號」
  • 介面只列出方法的簽章，沒有本體，也沒有欄位。名稱習慣用 I 開頭
  • 類別在冒號後面寫介面名稱，表示「我做得到這些方法」，然後每一個都要寫出來。少寫一個：error CS0535: 'Post' 未實作介面成員 'IPublishable.Publish()'
  • List<IPublishable> 可以同時放 Post 和 Newsletter。迴圈那一行只知道「它做得到 Publish」，不用知道實際是哪個類別

介面和 abstract 類別一樣不能 new：new IPublishable() 是 error CS0144: 無法建立抽象類型或介面 'IPublishable' 的執行個體。

第 4 步：一個類別可以同時有父類別和介面

冒號後面第一個可以是父類別，後面全部是介面。父類別只能有一個，介面可以有很多個：

範例：abstract 類別 Content，介面 IPublishable（實際執行過）

Console.WriteLine("== 用父類別 Content 裝");
List<Content> contents = [new Post("Docker 入門", "Docker 是把程式和環境一起打包的工具"), new Page("關於我")];
foreach (var content in contents)
{
    Console.WriteLine(content.Summary());
}

Console.WriteLine("== 用介面 IPublishable 裝");
List<IPublishable> queue = [new Post("Docker 入門", "…"), new Page("關於我")];
foreach (var item in queue)
{
    item.Publish();
}

// abstract 類別：不能 new，可以有寫好的方法，也可以有「只有簽章」的 abstract 方法
abstract class Content
{
    public string Title { get; }

    protected Content(string title)
    {
        Title = title;
    }

    public abstract string Summary();                              // 只有簽章，子類別一定要 override

    public string Describe() => $"[{GetType().Name}] {Title}";     // 寫好的方法，子類別直接有
}

// 介面：只有簽章，沒有本體；一個類別可以同時實作很多個介面
interface IPublishable
{
    void Publish();
}

class Post : Content, IPublishable
{
    private readonly string body;

    public Post(string title, string body) : base(title)
    {
        this.body = body;
    }

    public override string Summary() => $"{Describe()}：{body[..Math.Min(6, body.Length)]}…";

    public void Publish() => Console.WriteLine($"發佈文章「{Title}」");
}

class Page : Content, IPublishable
{
    public Page(string title) : base(title)
    {
    }

    public override string Summary() => $"{Describe()}（靜態頁面，沒有摘要）";

    public void Publish() => Console.WriteLine($"發佈頁面「{Title}」");
}

// 輸出：
// == 用父類別 Content 裝
// [Post] Docker 入門：Docker…
// [Page] 關於我（靜態頁面，沒有摘要）
// == 用介面 IPublishable 裝
// 發佈文章「Docker 入門」
// 發佈頁面「關於我」

class Post : Content, IPublishable：冒號後面第一個可以是父類別，後面全部是介面。abstract 類別的建構子標 protected 就夠了，反正外面不能 new 它，只有子類別會用 : base(title) 呼叫。

三種放在一起比

一般類別abstract 類別介面
可以 new 嗎可以不行不行
裡面有寫好的程式嗎有可以有，也可以有「只有簽章」的 abstract 方法只有簽章，沒有本體
子類別一定要做什麼不用把每個 abstract 方法 override 寫完把每個方法都寫出來（實作）
一個類別可以接幾個父類別只能有一個介面可以同時實作很多個
讀法「X 是一種 Y」「X 做得到 Y」

.NET 本身到處是這兩種東西：所有集合都實作 IEnumerable<T> 這個介面，所以 foreach 和 LINQ 對 List、陣列都能用；框架給你繼承的父類別很多是 abstract，自己不能 new，一定要寫子類別才用得到。

7. 練習：單檔程式

和簽章頁一樣用單檔程式（file-based apps）：建 class-lab.cs，在那個資料夾執行 dotnet run class-lab.cs。

題 1：建構子、繼承、介面各寫一個

需求，三小步都在同一個檔案：

  1. 類別 Author：一個 private readonly string name 欄位；建構子 Author(string name)，參數名稱故意和欄位一樣，本體先印「Author 建構子」再用 this. 設定欄位；方法 Describe() 回傳「作者：小明」這種字串。new Author("小明") 然後印 Describe()
  2. 類別 Staff : Author：多一個 department 欄位；建構子 Staff(string name, string department) 用 : base(name) 把名字交上去，本體印「Staff 建構子」；Describe() 要 override，結果是父類別的結果再加「（編輯部）」。new Staff("小華", "編輯部")，看兩行「建構子」印出的順序
  3. 介面 IPrintable，只有一個方法 void Print()。讓 Author 實作它，內容是印出 Describe()。把第 1、2 步的兩個物件放進 List<IPrintable>，迴圈呼叫 Print()，看 Staff 那筆印的是哪個版本

💡 提示：第 2 步要 override，父類別的 Describe 就得先標 virtual。第 3 步 Staff 不用再寫 : IPrintable，繼承 Author 就一起繼承了它實作的介面。

✅ 驗收：(1) 一行「Author 建構子」加一行「作者：小明」；(2) 先「Author 建構子」再「Staff 建構子」，最後「作者：小華（編輯部）」；(3) 兩行作者，Staff 那行有部門

參考答案（寫完再打開）

class-lab.cs

Console.WriteLine("== (1) 建構子和 this");
var ming = new Author("小明");
Console.WriteLine(ming.Describe());

Console.WriteLine("== (2) 繼承：建構子順序和 override");
var hua = new Staff("小華", "編輯部");
Console.WriteLine(hua.Describe());

Console.WriteLine("== (3) 介面");
List<IPrintable> items = [ming, hua];
foreach (var item in items)
{
    item.Print();
}

interface IPrintable
{
    void Print();
}

class Author : IPrintable
{
    private readonly string name;

    public Author(string name)
    {
        Console.WriteLine("  Author 建構子");
        this.name = name;
    }

    public virtual string Describe() => $"作者：{name}";

    public void Print() => Console.WriteLine($"  {Describe()}");
}

class Staff : Author
{
    private readonly string department;

    public Staff(string name, string department) : base(name)
    {
        Console.WriteLine("  Staff 建構子");
        this.department = department;
    }

    public override string Describe() => $"{base.Describe()}（{department}）";
}

輸出（實際執行）

== (1) 建構子和 this
  Author 建構子
作者：小明
== (2) 繼承：建構子順序和 override
  Author 建構子
  Staff 建構子
作者：小華（編輯部）
== (3) 介面
  作者：小明
  作者：小華（編輯部）

三個觀察：

  • (2) 的兩行「建構子」順序是先 Author 再 Staff：: base(name) 讓父類別先跑完
  • (3) 的 Print() 寫在 Author 裡，本體呼叫的是 Describe()，也就是 this.Describe()。對 Staff 物件呼叫時 this 是 Staff，所以跑的是 override 過的版本，印出有部門的那行
  • List<IPrintable> 裡放的是 Author 和 Staff 兩種物件，迴圈那行只知道「它做得到 Print」，不用知道實際是哪個類別
