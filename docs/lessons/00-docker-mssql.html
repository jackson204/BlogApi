1. 這一課要解決的問題

部落格要存文章、作者、標籤，所以一定需要資料庫。傳統做法是在 Windows 上安裝 SQL Server，但會遇到這些麻煩：

  • 安裝檔很大、會常駐好幾個 Windows 服務，不用時也在吃記憶體
  • 想換版本（2019 → 2022）或重來一次，要解除安裝、重裝
  • 換電腦或跟別人合作時，每個人的環境都要重新設定，很難保證一樣

Docker 的想法：把「SQL Server + 它需要的作業系統環境」打包成一個盒子，要用就開、不用就關、壞了就丟掉重開。

本機安裝 SQL ServerDocker 跑 SQL Server
安裝下載安裝檔、一步一步設定一行指令
移除解除安裝，常有殘留docker rm 就乾淨了
換版本很麻煩改一個 tag
團隊一致性靠文件跟運氣同一份 docker-compose.yml

2. 原理

2-1. image 和 container：就像 class 和物件

2-2. port 對應：從 Windows 怎麼連進盒子裡？

container 有自己獨立的網路，SQL Server 在盒子裡聽 1433 port。要讓 Windows 上的 Rider 或你的 API 連得到，必須把 Windows 的某個 port「接」到盒子裡的 1433。寫法是 -p 主機port:容器port。

❓ 常見問題：兩邊都是 1433，可以用不一樣的嗎？

可以。兩個數字分別屬於不同的世界：

  • 冒號左邊（主機 port）：在 Windows 上開的入口，可以自己決定。你的程式連的是這個數字。
  • 冒號右邊（容器 port）：盒子裡 SQL Server 實際在聽的 port。SQL Server 預設就是 1433，所以通常不改。

比喻：大樓的大門門牌（左邊）可以隨你換，但住戶的房間號碼（右邊）是固定的，警衛負責把大門的訪客帶到房間。

flowchart LR subgraph A["寫法 -p 1433:1433"] W1["Windows
localhost:1433"] --> C1["容器內
SQL Server :1433"] end subgraph B["寫法 -p 14330:1433"] W2["Windows
localhost:14330"] --> C2["容器內
SQL Server :1433"] end
左邊換成 14330 之後，連線字串也要跟著改成 Server=localhost,14330；容器裡面還是 1433

什麼時候會用不一樣的？

  • Windows 本機已經裝了 SQL Server，1433 被佔用 → 左邊改成 14330
  • 同時跑兩個專案的資料庫 → 一個 1433:1433，另一個 1434:1433。兩個容器內部都是 1433，互不衝突，因為每個容器有自己獨立的網路

2-3. volume：container 刪掉，資料要留著

container 被刪除時，裡面的檔案也會一起不見。資料庫檔案是最不能丟的東西，所以要把 SQL Server 存資料的資料夾 /var/opt/mssql 掛到 volume 上。volume 由 Docker 另外保管，跟 container 的生命週期分開。

3. 用法

3-1. 簡單版：一行 docker run

正式語法（Docker 官方文件的寫法，[ ] 代表可以省略）：

docker run [OPTIONS] IMAGE[:TAG] [COMMAND]
  • OPTIONS：各種參數，例如 -d、--name、-p、-e、-v。順序不重要，但一定要寫在 image 名稱前面
  • IMAGE[:TAG]：要用哪個 image、哪個版本；沒寫 tag 就是 latest

先用 nginx（一個網頁伺服器）練習，它啟動快、看得到畫面：

docker run -d --name demo-nginx -p 8080:80 nginx:1.27

參數很多時可以換行。PowerShell 的換行符號是行尾的 `（反引號，鍵盤 Esc 下面那顆），Git Bash 則是 \：

docker run -d `
  --name demo-nginx `
  -p 8080:80 `
  nginx:1.27

用瀏覽器開 http://localhost:8080 會看到 nginx 歡迎頁。各參數的意思：

參數意思
-ddetached，在背景執行，不佔住終端機
--name demo-nginx幫 container 取名字，之後用名字操作它
-p 8080:80Windows 的 8080 → 容器裡的 80
-e KEY=VALUE設定環境變數（SQL Server 用它來設密碼）
-v 名稱:路徑把 volume 掛到容器內的路徑
nginx:1.27image 名稱:tag（tag 就是版本）

玩完記得清掉：docker rm -f demo-nginx

📖 寫法要去哪裡查？

  • 指令本身的參數：Docker 官方 docker run 參考文件，或直接在終端機打 docker run --help
  • 某個 image 需要哪些環境變數：每個 image 規定的都不一樣，要看那個 image 自己的說明頁。SQL Server 看 Microsoft 官方的 Quickstart：用 Docker 執行 SQL Server 容器，或 Docker Hub 上的 microsoft/mssql-server 頁面

題 1 要用的 ACCEPT_EULA、MSSQL_SA_PASSWORD，就是從 Microsoft 的文件裡來的，不是 Docker 本身的規定。

3-2. 常用指令速查

3-3. 進階版：docker compose

docker run 的參數一長就很難記，也不好跟別人分享。docker compose 把這些設定寫成一個 YAML 檔，之後只要：

docker compose up -d     # 依照 docker-compose.yml 建立並啟動
docker compose down      # 停止並刪除 container（volume 會保留）
docker compose down -v   # 連 volume 一起刪掉（資料會清空！）

"SQL Server is now ready for client connections"

4. 練習題

⚠️ 開始前：先打開 Docker Desktop，等左下角顯示 Engine running。

題 1：用 docker run 啟動 SQL Server

需求：

  • image：mcr.microsoft.com/mssql/server:2022-latest
  • container 名稱：blog-mssql，在背景執行
  • 環境變數：ACCEPT_EULA=Y，MSSQL_SA_PASSWORD=Blog_Dev_2026!
  • Windows 的 1433 對應到容器的 1433
  • 這一題先不要掛 volume

💡 提示：每個需求對應哪個參數（對照「3-1」的參數表，照 docker run [OPTIONS] IMAGE 的順序組起來）

需求用哪個
在背景執行-d
container 名稱--name
環境變數（兩個）-e，一個變數寫一次，所以要寫兩次
Windows 1433 → 容器 1433-p 主機:容器
image放在最後面

如果組不出來，可以先看 Microsoft Quickstart 文件裡的範例指令，跟上面的需求比對，看看哪些地方要改。

✅ 驗收：docker ps 看到 blog-mssql 是 Up；docker logs blog-mssql 最後出現 SQL Server is now ready for client connections

參考答案（寫完再打開） 
docker run -d --name blog-mssql `
  -e "ACCEPT_EULA=Y" `
  -e "MSSQL_SA_PASSWORD=Blog_Dev_2026!" `
  -p 1433:1433 `
  mcr.microsoft.com/mssql/server:2022-latest

docker ps
docker logs blog-mssql

如果 docker ps 看不到它，但 docker ps -a 顯示 Exited，最常見的原因是密碼太簡單。SQL Server 要求至少 8 碼，並包含大寫、小寫、數字、符號其中三種。用 docker logs 可以看到錯誤訊息。

題 2：親眼看資料消失

需求：

  1. 用 docker exec 進到容器，執行容器內建的 sqlcmd（路徑 /opt/mssql-tools18/bin/sqlcmd）
  2. 建立一個資料庫 TestDb，確認看得到它
  3. 把 container 刪掉（rm -f），再用題 1 的指令重新啟動
  4. 再查一次：TestDb 還在嗎？

✅ 驗收：你能用自己的話說出「為什麼 TestDb 不見了」

參考答案（寫完再打開） 
# 進入 sqlcmd 互動模式（-C 代表信任自簽憑證）
docker exec -it blog-mssql /opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -P "Blog_Dev_2026!" -C
CREATE DATABASE TestDb;
GO
SELECT name FROM sys.databases;
GO
-- 輸入 exit 離開
docker rm -f blog-mssql
# 再執行一次題 1 的 docker run ...（等 10~30 秒）
docker exec -it blog-mssql /opt/mssql-tools18/bin/sqlcmd -S localhost -U sa -P "Blog_Dev_2026!" -C -Q "SELECT name FROM sys.databases"

為什麼不見了？資料庫檔案存在容器內的 /var/opt/mssql，容器被刪除時這個資料夾也跟著刪除。新的 container 是從乾淨的 image 重新長出來的，就像重新 new 一個物件，舊物件裡的欄位值不會帶過來。

👉 解法是 volume，下一題用 compose 一起處理。

題 3：改寫成 docker-compose.yml（加上 volume）

需求：

  • 建立資料夾 %USERPROFILE%\RiderProjects\BlogApi（%USERPROFILE% 是 Windows 的使用者資料夾，例如 C:\Users\你的帳號），在裡面新增 docker-compose.yml
  • 內容等同題 1，另外加上：名為 mssql-data 的 volume 掛到 /var/opt/mssql
  • 密碼不要直接寫在 yml 裡，改放在同資料夾的 .env 檔，yml 用 ${變數名} 讀取
  • 加上 restart: unless-stopped，讓 Docker Desktop 重開後自動啟動

開始前先清掉題 1、2 的 container：docker rm -f blog-mssql

✅ 驗收：docker compose up -d 啟動 → 建立 TestDb → docker compose down → 再 up -d → TestDb 還在

參考答案（寫完再打開）

BlogApi/docker-compose.yml

services:
  mssql:
    image: mcr.microsoft.com/mssql/server:2022-latest
    container_name: blog-mssql
    environment:
      ACCEPT_EULA: "Y"
      MSSQL_SA_PASSWORD: ${MSSQL_SA_PASSWORD}
    ports:
      - "1433:1433"
    volumes:
      - mssql-data:/var/opt/mssql
    restart: unless-stopped

volumes:
  mssql-data:

BlogApi/.env

MSSQL_SA_PASSWORD=Blog_Dev_2026!

BlogApi/.gitignore（之後用 git 時，避免把密碼推上去）

.env
cd $HOME\RiderProjects\BlogApi   # PowerShell 的 $HOME 就是使用者資料夾
docker compose config   # 先檢查：會印出套用 .env 之後的完整設定，語法錯誤會在這裡報出來
docker compose up -d

重點：

  • 最下面的 volumes: 是宣告有這個 volume；service 裡的 volumes: 是使用它
  • docker compose down 不會刪 volume，所以資料留著；加了 -v 才會刪

5. 連線字串：給下一課用

.NET 程式連資料庫靠的是一串 key=value; 組成的文字，叫做連線字串：

Server=localhost,1433;Database=BlogDb;User Id=sa;Password=Blog_Dev_2026!;TrustServerCertificate=True
片段意思
Server=localhost,1433主機和 port。注意 SQL Server 用逗號分隔 port，不是冒號
Database=BlogDb要連哪個資料庫
User Id=sa;Password=...帳號密碼（sa 是最高權限帳號，只適合開發用）
TrustServerCertificate=True新版 SqlClient 預設會加密連線並驗證憑證；容器是自簽憑證，不加這個會連不上（版本細節見下方）

❓ 「新版 SqlClient」是指哪一版？

套件版本Encrypt 預設值誰會用到
System.Data.SqlClient（舊套件，已不再更新）False.NET Framework 時代的專案
Microsoft.Data.SqlClient 3.x 以前FalseEF Core 6 以前
Microsoft.Data.SqlClient 4.0 起（2021-11）TrueEF Core 7 以後（EF Core 7 改用 SqlClient 5.0）

本課程用的 EF Core 10.0.13 依賴的是 Microsoft.Data.SqlClient 6.1.7，所以會遇到。Encrypt=True 時用戶端會驗證伺服器憑證是不是受信任的機構簽發的；容器的憑證是 SQL Server 自己產生的（自簽），驗證不會通過，所以開發環境要加 TrustServerCertificate=True 跳過驗證。

正式環境不建議跳過，應該幫 SQL Server 安裝正式的憑證。官方說明：EF Core 7 中斷性變更（Encrypt 預設為 true）

用 service 名稱" --> D2["mssql container"] end
在容器裡面，localhost 指的是「容器自己」，所以要改用 compose 的 service 名稱

題 5：準備好連線字串

下一課會建立 Web API 專案，專案裡會有 appsettings.Development.json。先想好：連線字串要放在這個 JSON 的哪個位置、key 要叫什麼？

參考答案（寫完再打開）

appsettings.Development.json（下一課建立專案後再加）

{
  "ConnectionStrings": {
    "BlogDb": "Server=localhost,1433;Database=BlogDb;User Id=sa;Password=Blog_Dev_2026!;TrustServerCertificate=True"
  }
}

ConnectionStrings 是 .NET 約定的區段名稱，之後可以用 builder.Configuration.GetConnectionString("BlogDb") 直接讀出來。

6. 優缺點 & 常見坑

優點

  • 環境乾淨、可以重來，弄壞了 down -v 再 up 就好
  • 設定檔就是文件，docker-compose.yml 放進專案，別人也能一鍵啟動

缺點

  • Docker Desktop 本身也會佔記憶體（WSL2），SQL Server 容器至少需要約 2 GB
  • 多了一層網路和檔案系統，出問題時要多一個地方排查
