補充：query string 怎麼變成方法參數（以 ASP.NET Core 為例）

Controller 方法多了一個 string? keyword 參數，它怎麼從網址的 ?keyword=docker 對上？沒帶的時候是什麼？值轉不成數字會怎樣？Minimal API 和 Controller 的規則哪裡不一樣？

這頁接在「網址與 query string」之後，那一篇講網址本身的規則，這一篇講它進到程式之後的事。需要先寫過 Controller。每一條規則旁邊都附實測結果（.NET SDK 10.0.303）。

目錄
  1. 兩步：先用路徑找方法，再填參數
  2. 填參數：從沒有參數開始，一步加一樣
  3. 路徑裡的值轉不成數字時：404 還是 400
  4. 直接讀原始的網址，以及自己組 query string
  5. 小實驗：自己寫幾支 API，看參數拿到什麼

1. 兩步：先用路徑找方法，再填參數

請求進來後分兩步：先用路徑找方法（路由），再把請求的各部分填進方法參數（Model Binding）。query string 只參與第二步，不影響找到哪個方法。

flowchart LR REQ["GET /api/items/5?keyword=docker"] --> ROUTE{"路由比對
只看路徑 /api/items/5"} ROUTE -- "沒有方法認領" --> NF["404"] ROUTE -- "找到方法" --> BIND["Model Binding
把請求各部分填進參數"] BIND --> P1["路徑佔位符 {id}
int id = 5"] BIND --> P2["query string
string? keyword = docker"] BIND --> P3["body 的 JSON
物件型別的參數"] P1 --> CALL["呼叫方法"] P2 --> CALL P3 --> CALL
路由不看 ? 後面的東西：/api/items/5 和 /api/items/5?keyword=x 找到的是同一個方法（實測兩個都回 id = 5）

2. 填參數：從沒有參數開始，一步加一樣

這一節只看第二步「填參數」。從一個沒有參數的方法開始，每一步只加一樣東西，送同樣的幾個請求，看參數拿到什麼。

程式裡的顏色：藍色是這一步多出來的部分。每一步的輸出都實際執行過。

第 1 步：方法沒有參數，query string 帶了也沒有人讀

一個 .cs 檔就能執行，不用開專案。Controller 類別和啟動網站的程式寫在同一個檔案裡：

query-lab.cs

#:sdk Microsoft.NET.Sdk.Web
// 單檔程式預設以 Native AOT 的設定編譯，那組設定不支援 MVC Controller（啟動就會丟 NotSupportedException）
// 這一行把 AOT 關掉，AddControllers / MapControllers 才能用
#:property PublishAot=false

using Microsoft.AspNetCore.Mvc;

WebApplicationBuilder builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllers();
WebApplication app = builder.Build();
app.MapControllers();
// 指定網址和 port 啟動；終端機按 Ctrl+C 停掉。port 被佔用就換一個數字
app.Run("http://localhost:5060");

[ApiController]
[Route("api/[controller]")]
public class ItemsController : ControllerBase
{
    [HttpGet]
    public string GetAll()
    {
        return "all items";
    }
}
# 放在任何「沒有 .csproj」的資料夾
dotnet run query-lab.cs

另開一個終端機，送兩個請求，一個不帶 query string、一個帶：

curl "http://localhost:5060/api/items"
# all items

curl "http://localhost:5060/api/items?keyword=docker"
# all items

兩個結果一樣。路由只看路徑 /api/items，兩個請求找到同一個方法；方法沒有參數，?keyword=docker 就沒有人讀。

後面每一步只列 ItemsController 裡有變動的方法，檔案其他部分不變。改完存檔，按 Ctrl+C 停掉再重新 dotnet run。

第 2 步：加一個參數 string? keyword

要讀到 keyword，在方法上加一個同名的參數：

[HttpGet]
public string GetAll(string? keyword)
{
    // 有值就加上引號，沒有值印 null：這樣空字串和 null 看得出差別
    string keywordText = keyword is null ? "null" : "\"" + keyword + "\"";
    return "keyword = " + keywordText;
}
curl "http://localhost:5060/api/items?keyword=docker"
# keyword = "docker"

curl "http://localhost:5060/api/items?Keyword=docker"
# keyword = "docker"                 ← 大小寫不同也對得上

呼叫方法之前，框架拿參數的名稱 keyword 去 query string 找同名的那一組，把值填進參數。比對名稱時不分大小寫。

第 3 步：同一支程式，改送「沒帶」和「值是空的」

程式不動，換兩個請求：

curl "http://localhost:5060/api/items"
# keyword = null                     ← 沒帶

curl "http://localhost:5060/api/items?keyword="
# keyword = null                     ← 名稱有、值是空的
  • 沒帶的時候參數是 null，所以型別寫 string?，方法裡要先判斷是不是 null 再用
  • ?keyword= 拿到的也是 null，不是空字串：Controller 預設把空字串轉成 null

第 4 步：加第二個參數 int page = 1

再加一個頁數。參數之間用逗號隔開，query string 裡用 & 隔開，兩邊的順序不用一樣，只看名稱：

[HttpGet]
public string GetAll(string? keyword, int page = 1)
{
    string keywordText = keyword is null ? "null" : "\"" + keyword + "\"";
    return "keyword = " + keywordText + "\npage = " + page;
}
curl "http://localhost:5060/api/items?keyword=docker&page=2"
# keyword = "docker"
# page = 2

curl "http://localhost:5060/api/items"
# keyword = null
# page = 1                           ← 沒帶，用預設值

query string 的值都是文字，page=2 送來的是 "2"。參數的型別是 int，框架先把 "2" 轉成數字 2 再填進去。沒帶 page 時，用參數後面寫的預設值 1。

第 5 步：值轉不成 int

程式不動，把 page 送成不是數字的字：

curl -i "http://localhost:5060/api/items?page=abc"
# HTTP/1.1 400 Bad Request
# Content-Type: application/problem+json; charset=utf-8
# {"type":"https://tools.ietf.org/html/rfc9110#section-15.5.1","title":"One or more validation errors occurred.",
#  "status":400,"errors":{"page":["The value 'abc' is not valid."]},"traceId":"00-…"}

回應不是方法回傳的那兩行文字，而是框架產生的一段 JSON，errors 裡寫了是哪個參數、哪個值不對。abc 填不進 int，框架直接回 400。

第 6 步：int 參數不寫預設值

第 4 步的 = 1 如果沒寫會怎樣？另外加一個方法來看，參數一樣叫 page，但沒有預設值：

[HttpGet("strict")]
public string Strict(int page)
{
    return "page = " + page;
}
curl -i "http://localhost:5060/api/items/strict"
# HTTP/1.1 200 OK                    ← 沒帶也能進方法
# page = 0

沒有錯誤，page 是 0：int 不能是 null，沒帶的時候拿到的是 int 自己的預設值 0。方法裡分不出「用戶端送了 0」和「用戶端沒送」。

什麼時候寫預設值：沒帶的時候有一個合理的值可以用，例如頁數沒帶就是第 1 頁。

第 7 步：同一個名稱帶多個值，參數寫成陣列

query string 裡同一個名稱可以出現很多次，例如 ?tag=a&tag=b。要全部拿到，參數的型別寫成陣列。先照前面的寫法，只加參數：

[HttpGet]
public string GetAll(string? keyword, int page = 1, string[]? tag = null)
{
    string keywordText = keyword is null ? "null" : "\"" + keyword + "\"";
    string tagText = tag is null ? "null" : "[" + string.Join(", ", tag) + "]  count=" + tag.Length;
    return "keyword = " + keywordText + "\npage = " + page + "\ntag = " + tagText;
}
curl "http://localhost:5060/api/items?tag=a&tag=b"
# keyword = null
# page = 1
# tag = null                         ← 明明帶了兩個 tag

沒有錯誤訊息，但 tag 是 null。原因在框架怎麼決定「這個參數從請求的哪裡拿」：

  • string、int 這類單一的值：從路徑或 query string 拿
  • 陣列和物件：Controller 預設認定要從 body 的 JSON 拿

這個 GET 請求沒有 body，參數又允許是 null，所以拿到 null。query string 裡的 tag 沒有人讀。

第 8 步：加上 [FromQuery]，指定從 query string 拿

參數前面加 [FromQuery]，明確告訴框架這個參數要從 query string 拿：

[HttpGet]
public string GetAll(string? keyword, int page = 1, [FromQuery] string[]? tag = null)
{
    string keywordText = keyword is null ? "null" : "\"" + keyword + "\"";
    string tagText = tag is null ? "null" : "[" + string.Join(", ", tag) + "]  count=" + tag.Length;
    return "keyword = " + keywordText + "\npage = " + page + "\ntag = " + tagText;
}
curl "http://localhost:5060/api/items?tag=a&tag=b"
# keyword = null
# page = 1
# tag = [a, b]  count=2

curl "http://localhost:5060/api/items"
# keyword = null
# page = 1
# tag = null                         ← 沒帶的陣列是 null

陣列參數如果寫成不可為 null、也沒有預設值的 string[] tag，漏了 [FromQuery] 時拿到的不是 null，而是直接回錯誤。另外加一個方法來看：

[HttpGet("tags")]
public string Tags(string[] tag)
{
    return "tag = [" + string.Join(", ", tag) + "]  count=" + tag.Length;
}
curl -i "http://localhost:5060/api/items/tags?tag=a&tag=b"
# HTTP/1.1 415 Unsupported Media Type   ← 被當成要從 body 拿，GET 請求沒有 body
# {"type":"https://tools.ietf.org/html/rfc9110#section-15.5.16","title":"Unsupported Media Type","status":415,"traceId":"00-…"}

GET 的方法收到 415，先檢查是不是有陣列或物件參數少了 [FromQuery]。

第 9 步：網址上的名稱和參數名不同

網址上想用短一點的 ?q=docker，程式裡的參數還是想叫 keyword。前面的規則是名稱一樣才對得上，所以要另外指定。再加一個方法：

[HttpGet("q")]
public string Renamed([FromQuery(Name = "q")] string? keyword)
{
    string keywordText = keyword is null ? "null" : "\"" + keyword + "\"";
    return "keyword = " + keywordText;
}
curl "http://localhost:5060/api/items/q?q=docker"
# keyword = "docker"

curl "http://localhost:5060/api/items/q?keyword=docker"
# keyword = null                     ← 指定了 Name = "q"，keyword 這個名稱就不認

第 10 步：參數多了，打包成一個類別

篩選條件再多下去，方法的參數會排成很長一串。可以把它們寫成一個類別的屬性，方法只收一個參數：

// 加在 ItemsController 裡
[HttpGet("search")]
public string Search([FromQuery] SearchQuery query)
{
    string keywordText = query.Keyword is null ? "null" : "\"" + query.Keyword + "\"";
    string tagText = query.Tag is null ? "null" : "[" + string.Join(", ", query.Tag) + "]  count=" + query.Tag.Length;
    return "keyword = " + keywordText + "\npage = " + query.Page + "\ntag = " + tagText;
}

// 加在檔案最後面，ItemsController 的外面
public class SearchQuery
{
    public string? Keyword { get; set; }
    public int Page { get; set; } = 1;
    public string[]? Tag { get; set; }
}
curl "http://localhost:5060/api/items/search?keyword=docker&page=2&tag=a&tag=b"
# keyword = "docker"
# page = 2
# tag = [a, b]  count=2

curl "http://localhost:5060/api/items/search"
# keyword = null
# page = 1                           ← 屬性的初始值
# tag = null
  • 屬性名稱對應 query string 的名稱，每個屬性各自從 query string 拿，規則和單獨的參數一樣
  • SearchQuery 是物件，照第 7 步的規則會被認定從 body 拿，所以一定要寫 [FromQuery]
  • 沒帶的屬性維持類別裡寫的初始值：Page 是 1

Minimal API 的寫法，和 Controller 不一樣的地方

ASP.NET Core 還有另一種寫 API 的方式叫 Minimal API：不寫 Controller 類別，參數直接寫在 lambda 上。

// 名稱和 query string 一樣就會對上：?name=amy → name = "amy"，沒帶是 null
app.MapGet("/hello", (string? name) => "hi " + (name ?? "stranger"));

下面這幾條兩邊相同（實測）：

  • 名稱一樣就對上，不分大小寫
  • string? keyword 沒帶是 null；int page = 1 沒帶是 1
  • [FromQuery(Name = "q")] 的寫法和結果

不同的地方列在下表，結果全部是實測（.NET SDK 10.0.303）：

情況Controller（[ApiController]）Minimal API
?keyword=，值是空的null""（空字串）
int page 沒有預設值，沒帶200，page = 0400，沒有內容。視為必填
?page=abc，轉不成 int400，內容說明哪個參數錯400，沒有內容
陣列 string[]? tag要加 [FromQuery]。沒帶是 null直接宣告就行。沒帶是空陣列（count=0）
打包成類別參數前寫 [FromQuery]。屬性初始值有效參數前寫 [AsParameters]。屬性初始值不算

最後一列的差別：Minimal API 的 [AsParameters] 不看類別屬性的初始值。public int Page { get; set; } = 1 不算預設值，沒帶 page 會回 400。要讓它可以省略，改用 record，把預設值寫在建構子參數上：

// Controller 的 [FromQuery] 用：屬性初始值就是沒帶時的值，?keyword=docker&page=2&tag=a&tag=b
public class SearchQuery
{
    public string? Keyword { get; set; }
    public int Page { get; set; } = 1;
    public string[]? Tag { get; set; }
}

// Minimal API 的 [AsParameters] 用：預設值要寫在建構子參數上，屬性初始值它不看
// 用上面那個 class 接 /items/search 時，沒帶 page 會直接 400
public record SearchQuery2(string? Keyword, int Page = 1, string[]? Tag = null);

3. 路徑裡的值轉不成數字時：404 還是 400

路徑佔位符 {id} 對應的參數是 int，有人卻送了 docker。結果是 404 還是 400，看路由樣板有沒有寫 :int。

第 1 步：路由樣板寫 {id}，參數是 int

在第 2 節的 ItemsController 裡再加一個方法。路由樣板裡的 {id} 是佔位符，路徑那一段的字會填進同名的參數：

[HttpGet("{id}")]
public string GetById(int id)
{
    return "id = " + id;
}
curl "http://localhost:5060/api/items/5"
# id = 5

curl "http://localhost:5060/api/items/5?keyword=x"
# id = 5                             ← query string 不影響找到哪個方法

curl -i "http://localhost:5060/api/items/docker"
# HTTP/1.1 400 Bad Request
# Content-Type: application/problem+json; charset=utf-8
# {"type":"https://tools.ietf.org/html/rfc9110#section-15.5.1","title":"One or more validation errors occurred.",
#  "status":400,"errors":{"id":["The value 'docker' is not valid."]},"traceId":"00-…"}

{id} 沒有限制那一段是什麼字，所以 /api/items/docker 也找到這個方法。接著要把 docker 填進 int id，轉不成數字，回 400。和第 2 節第 5 步的 ?page=abc 是同一種錯。

第 2 步：加上 :int，不是整數就不認領

只改路由樣板，在佔位符的名稱後面加 :int：

[HttpGet("{id:int}")]
public string GetById(int id)
{
    return "id = " + id;
}
curl "http://localhost:5060/api/items/5"
# id = 5

curl -i "http://localhost:5060/api/items/docker"
# HTTP/1.1 404 Not Found              ← docker 不是整數，這個方法不認領

:int 叫路由約束（route constraint）：那一段是整數，這個方法才認領。docker 不是整數，沒有任何方法認領這個網址，回 404。

兩種寫法停在不同的一步

兩步的方法都是 GetById(int id)，送的都是 GET /api/items/docker，差別只有路由樣板。對照第 1 節的「先找方法，再填參數」：

沒寫 :int有寫 :int
用路徑找方法那一段是什麼都可以，這個方法認領docker 不是整數，這個方法不認領
把值填進 int iddocker 轉不成 int，填不進去沒有走到這一步
結果400：有方法，但送來的值不對404：沒有方法處理這個網址

什麼時候寫 :int

  • 寫：參數是數字就寫。不是數字的網址在找方法那一步就被擋掉，回 404
  • 不寫：想讓用戶端知道「網址對了，是值的格式不對」時。不寫 :int 會回 400，內容還會說明是哪個參數

寫了 :int 之後，同一層還可以再放一個接文字的佔位符，兩個方法各接各的（實測）：

[HttpGet("{id:int}")]
public string GetById(int id)
{
    return "id = " + id;
}

[HttpGet("{slug}")]
public string GetBySlug(string slug)
{
    return "slug = " + slug;
}
curl "http://localhost:5060/api/items/5"
# id = 5
curl "http://localhost:5060/api/items/docker"
# slug = docker

兩個都不寫限制（{id} 和 {slug}）時，同一個網址兩個方法都認領，框架分不出要呼叫哪一個，兩個網址都回 500（AmbiguousMatchException）。

固定文字的路徑不受影響：/api/items/strict 不管 {id} 有沒有寫 :int，都是由 [HttpGet("strict")] 那個方法處理（實測）。

不管哪一種，搜尋條件都不適合放在路徑裡，放 query string：/api/items?keyword=docker。

4. 直接讀原始的網址，以及自己組 query string

不透過方法參數，也可以直接讀請求的網址。Controller 的方法裡用 Request 屬性，網址的三段各在一個地方：

  • Request.Host：主機和 port
  • Request.Path：路徑
  • Request.QueryString：query string 的原始文字

注意 Request.QueryString.Value 是含開頭 ? 的整串，沒有 query string 時是空字串。

要讀某一個名稱的值，用 Request.Query["keyword"]。它的型別是 StringValues，可以有多個值：?keyword=a&keyword=b 讀到的 Count 是 2，沒帶時 Count 是 0（實測）。

Minimal API 沒有 Request 屬性，在 lambda 上加一個 HttpContext context 參數，寫成 context.Request.Query["keyword"]、context.Request.QueryString.Value。

自己組一條帶 query string 的網址

程式要自己組出一條帶 query string 的網址時，不要用字串相加，改用會自動編碼的工具：

  • 前端：URLSearchParams 或 encodeURIComponent
  • C# 當呼叫端：Uri.EscapeDataString

收的那一邊（ASP.NET Core）解碼也是自動的，方法參數拿到的已經是原字。

5. 小實驗：自己寫幾支 API，看參數拿到什麼

第 2、3 節是 Controller 這一邊一步一步加出來的。這裡換成自己寫：同一組參數，Minimal API 和 Controller 各寫一份，把第 2 節最後那張對照表的差異親眼看一次。

不用開專案，一個 .cs 檔就能起網站。/echo 那一段在「網址與 query string」已經有現成的程式，這裡接著往同一個檔案加。

正式語法：.NET 10 單檔程式，參數直接寫在 lambda 上

// 第一行：告訴 SDK 這是 Web 專案，不然沒有 WebApplication 這些型別
#:sdk Microsoft.NET.Sdk.Web
// 單檔程式預設以 Native AOT 的設定編譯，那組設定不支援 MVC Controller（啟動就會丟 NotSupportedException）
// 這一行把 AOT 關掉，AddControllers / MapControllers 才能用。只寫 Minimal API 的話可以不加
#:property PublishAot=false

WebApplicationBuilder builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllers();     // 要用 Controller 才需要這兩行
WebApplication app = builder.Build();
app.MapControllers();

// 參數直接宣告在 lambda 上：名稱和 query string 一樣就會對上，?name=amy → name = "amy"
app.MapGet("/hello", (string? name) => "hi " + (name ?? "stranger"));

// 路徑佔位符：{id:int} 只接整數
app.MapGet("/hello/{id:int}", (int id) => "id = " + id);

實驗 2：/items，參數怎麼對上、沒帶的時候是什麼

需求：

  • Minimal API GET /items：參數 string? keyword、int page = 1、string[]? tag，把三個值印出來，null、空字串、空陣列要看得出差別
  • Minimal API GET /items/strict：參數 int page，沒有預設值
  • Minimal API GET /items/search：把三個條件打包成 SearchQuery 類別，用 [AsParameters] 接；再寫一支 GET /items/search2，改接 record 版的 SearchQuery2；還有 GET /items/q，參數 [FromQuery(Name = "q")] string? keyword
  • Controller ItemsController，路由 api/[controller]：GET /api/items、GET /api/items/strict、GET /api/items/search（[FromQuery] SearchQuery）三支和上面對應；再加 GET /api/items/tags（string[] tag 先不加 [FromQuery]）和 GET /api/items/q（[FromQuery(Name = "q")] string? keyword）
  • 對 /items 和 /api/items 各打：不帶參數、?keyword=docker&page=2、?Keyword=docker、?keyword=、?tag=a&tag=b、?page=abc；對兩個 strict、/items/search、/items/search2 各打一次不帶參數

💡 提示

需求用什麼
要用 Controllerbuilder.Services.AddControllers()、app.MapControllers()，檔案最上面加 #:property PublishAot=false
Controller 類別寫在哪同一個檔案，放在頂層語句（app.Run）後面；using Microsoft.AspNetCore.Mvc;
看 400 / 415 回應的內容curl -i
打包成類別Minimal API 用 [AsParameters]，Controller 用 [FromQuery]；類別的屬性要有 set。record 版把預設值寫在建構子參數上
兩邊印同一種格式寫一個 static 方法把 keyword、page、tag 印成文字，lambda 和 Controller 都呼叫它

🧪 先故意少做一件事：Controller 的 string[] tag 先不加 [FromQuery]，打 /api/items/tags?tag=a&tag=b 看狀態碼和回應內容，再加上去比較。

✅ 驗收：第 2 節最後那張對照表的差異（空字串、沒帶的 int、陣列要加 FromQuery 否則 415、類別的預設值），兩邊都親眼看到

url-lab.cs（實驗 2 的部分，接在實驗 1 的 /echo 後面）

#:sdk Microsoft.NET.Sdk.Web
// 單檔程式預設以 Native AOT 的設定編譯，那組設定不支援 MVC Controller（啟動就會丟 NotSupportedException）
// 這一行把 AOT 關掉，AddControllers / MapControllers 才能用
#:property PublishAot=false

using Microsoft.AspNetCore.Mvc;
using Microsoft.Extensions.Primitives;

WebApplicationBuilder builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllers();
WebApplication app = builder.Build();
app.MapControllers();

// （/echo 同實驗 1）

// Minimal API：參數直接宣告在 lambda 上，名稱和 query string 一樣就會對上
app.MapGet("/items", (string? keyword, int page = 1, string[]? tag = null) => Format.Describe(keyword, page, tag));

// 沒有預設值、也不可為 null 的 int：沒帶會怎樣？
app.MapGet("/items/strict", (int page) => "page = " + page);

// 多個條件打包成一個類別：[AsParameters] 讓每個屬性各自從 query string 拿
app.MapGet("/items/search", ([AsParameters] SearchQuery query) => Format.Describe(query.Keyword, query.Page, query.Tag));

// 網址上的名稱和參數名不同：用 Name 指定（Minimal API 版）
app.MapGet("/items/q", ([FromQuery(Name = "q")] string? keyword) => "keyword = " + (keyword ?? "null"));

// 打包成 record：建構子參數的預設值會被當成「沒帶時的值」
app.MapGet("/items/search2", ([AsParameters] SearchQuery2 query) => Format.Describe(query.Keyword, query.Page, query.Tag));

app.Run("http://localhost:5060");

// Controller：同樣的參數寫在方法上
[ApiController]
[Route("api/[controller]")]
public class ItemsController : ControllerBase
{
    [HttpGet]
    public string GetAll(string? keyword, int page = 1, [FromQuery] string[]? tag = null)
        => Format.Describe(keyword, page, tag);

    // 沒有預設值、也不可為 null 的 int
    [HttpGet("strict")]
    public string Strict(int page) => "page = " + page;

    // 陣列參數「不加」[FromQuery]，看框架自己會從哪裡拿
    [HttpGet("tags")]
    public string Tags(string[] tag) => "tag = [" + string.Join(", ", tag) + "]  count=" + tag.Length;

    // 網址上的名稱和參數名不同：用 Name 指定
    [HttpGet("q")]
    public string Renamed([FromQuery(Name = "q")] string? keyword) => "keyword = " + (keyword ?? "null");

    // 多個條件打包成一個類別：[FromQuery] 讓每個屬性各自從 query string 拿
    [HttpGet("search")]
    public string Search([FromQuery] SearchQuery query) => Format.Describe(query.Keyword, query.Page, query.Tag);
}

// 把篩選條件打包成一個類別：屬性名稱對應 query string 的名稱
public class SearchQuery
{
    public string? Keyword { get; set; }
    public int Page { get; set; } = 1;
    public string[]? Tag { get; set; }
}

// 同樣的條件改用 record 寫：Page 的預設值寫在建構子參數上
public record SearchQuery2(string? Keyword, int Page = 1, string[]? Tag = null);

// 把參數的值印成文字，null、空字串、空陣列都看得出差別
public static class Format
{
    public static string Describe(string? keyword, int page, string[]? tag)
    {
        string keywordText = keyword is null ? "null" : "\"" + keyword + "\"";
        string tagText = tag is null
            ? "null"
            : "[" + string.Join(", ", tag.Select(t => "\"" + t + "\"")) + "]  count=" + tag.Length;
        return "keyword = " + keywordText + "\npage = " + page + "\ntag = " + tagText;
    }
}

實驗 3：/items/{id:int}，路徑佔位符和 :int 限制

需求：

  • Minimal API：GET /items/{id:int} 和 GET /loose/{id}（沒有 :int），兩個都接 int id
  • Controller：[HttpGet("{id:int}")] 和 [HttpGet("loose/{id}")]
  • 打 /items/5、/items/docker、/loose/docker、/items/5?keyword=x，Controller 版也各打一次

💡 提示

需求用什麼
路徑佔位符只接整數路由樣板寫 {id:int}，:int 是路由約束（route constraint）
/items/strict 和 /items/{id:int} 會不會打架不會：strict 不是整數，{id:int} 不認領

✅ 驗收：/items/docker 是 404、/loose/docker 是 400、/items/5?keyword=x 和 /items/5 結果一樣

參考答案（寫完再打開）
