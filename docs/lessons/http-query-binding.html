1. 兩步：先用路徑找方法，再填參數

請求進來後分兩步：先用路徑找方法（路由），再把請求的各部分填進方法參數（Model Binding）。query string 只參與第二步，不影響找到哪個方法。

flowchart LR REQ["GET /api/items/5?keyword=docker"] --> ROUTE{"路由比對
只看路徑 /api/items/5"} ROUTE -- "沒有方法認領" --> NF["404"] ROUTE -- "找到方法" --> BIND["Model Binding
把請求各部分填進參數"] BIND --> P1["路徑佔位符 {id}
int id = 5"] BIND --> P2["query string
string? keyword = docker"] BIND --> P3["body 的 JSON
物件型別的參數"] P1 --> CALL["呼叫方法"] P2 --> CALL P3 --> CALL
路由不看 ? 後面的東西：/api/items/5 和 /api/items/5?keyword=x 找到的是同一個方法（實測兩個都回 id = 5）

正式語法：Minimal API 和 Controller 對照

ASP.NET Core 有兩種寫 API 的方式：Minimal API（參數寫在 lambda 上）和 Controller（參數寫在方法上）。從 query string 拿參數的規則大部分一樣，少數地方不同，不同的地方用 ⚠️ 標出來。表裡的結果全部是實測（.NET SDK 10.0.303）：

「多個條件打包成一個類別」的寫法：屬性名稱對應 query string 的名稱，每個屬性各自從 query string 拿，規則和單獨的參數一樣。兩種 API 對「預設值寫在哪」的要求不同：

// Controller 的 [FromQuery] 用：屬性初始值就是沒帶時的值，?keyword=docker&page=2&tag=a&tag=b
public class SearchQuery
{
    public string? Keyword { get; set; }
    public int Page { get; set; } = 1;
    public string[]? Tag { get; set; }
}

// Minimal API 的 [AsParameters] 用：預設值要寫在建構子參數上，屬性初始值它不看
// 用上面那個 class 接 /items/search 時，沒帶 page 會直接 400
public record SearchQuery2(string? Keyword, int Page = 1, string[]? Tag = null);

2. 路徑裡的值轉不成數字時：404 還是 400

路徑佔位符 {id} 對應的參數是 int，有人卻送了 docker。結果是 404 還是 400，看路由樣板有沒有寫 :int。

[HttpGet("{id:int}")]                 // 有寫 :int
public string GetById(int id) => "id = " + id;

[HttpGet("loose/{id}")]               // 沒寫 :int
public string Loose(int id) => "id = " + id;

兩個方法的參數都是 int id，差別只有路由樣板。第 1 節講過請求進來分兩步，這兩種寫法各停在不同的一步：

有寫 :int沒寫 :int
送的請求GET /api/items/dockerGET /api/items/loose/docker
第 1 步：用路徑找方法docker 不是整數，這個方法不認領那一段是什麼都可以，這個方法認領
第 2 步：把值填進 int id沒有走到這一步docker 轉不成 int，填不進去
結果404：沒有方法處理這個網址400：有方法，但送來的值不對

實測：

curl -i http://localhost:5060/api/items/docker
# HTTP/1.1 404 Not Found              ← 路由樣板 {id:int}：不是整數就不認領

curl -i http://localhost:5060/api/items/loose/docker
# HTTP/1.1 400 Bad Request            ← 路由樣板 loose/{id}：認領了，但轉不成 int
# {"title":"One or more validation errors occurred.","status":400,
#  "errors":{"id":["The value 'docker' is not valid."]}}       （節錄）

什麼時候寫 :int：參數是數字就寫。不是數字的網址在第 1 步就被擋掉，回 404；而且同一層可以放固定文字的路徑，例如 /items/strict 不會被 /items/{id:int} 搶走，因為 strict 不是整數。什麼時候不寫：想讓用戶端知道「網址對了，是值的格式不對」時，不寫 :int 會回 400，內容還會說明是哪個參數。

不管哪一種，搜尋條件都不適合放在路徑裡，放 query string：/api/items?keyword=docker。完整的實驗在第 4 節的實驗 3。

3. 直接讀原始的網址，以及自己組 query string

網址的主機、路徑、query string 三段，在程式裡分別放在 Request.Host、Request.Path、Request.QueryString。注意 QueryString.Value 是含開頭 ? 的整串，沒有 query string 時是空字串。

程式要自己組出一條帶 query string 的網址時，不要用字串相加：前端用 URLSearchParams 或 encodeURIComponent，C# 當呼叫端時用 Uri.EscapeDataString，編碼會自動做好。收的那一邊（ASP.NET Core）解碼也是自動的，方法參數拿到的已經是原字。

4. 小實驗：自己寫幾支 API，看參數拿到什麼

前面所有實測輸出都來自這個實驗。不用開專案，一個 .cs 檔就能起網站。/echo 那一段在「網址與 query string」已經有現成的程式，這裡接著往同一個檔案加。

正式語法：.NET 10 單檔程式，參數直接寫在 lambda 上

// 第一行：告訴 SDK 這是 Web 專案，不然沒有 WebApplication 這些型別
#:sdk Microsoft.NET.Sdk.Web
// 單檔程式預設以 Native AOT 的設定編譯，那組設定不支援 MVC Controller（啟動就會丟 NotSupportedException）
// 這一行把 AOT 關掉，AddControllers / MapControllers 才能用。只寫 Minimal API 的話可以不加
#:property PublishAot=false

WebApplicationBuilder builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllers();     // 要用 Controller 才需要這兩行
WebApplication app = builder.Build();
app.MapControllers();

// 參數直接宣告在 lambda 上：名稱和 query string 一樣就會對上，?name=amy → name = "amy"
app.MapGet("/hello", (string? name) => "hi " + (name ?? "stranger"));

// 路徑佔位符：{id:int} 只接整數
app.MapGet("/hello/{id:int}", (int id) => "id = " + id);

// 指定網址和 port 啟動；終端機按 Ctrl+C 停掉。port 被佔用就換一個數字
app.Run("http://localhost:5060");
# 放在任何「沒有 .csproj」的資料夾
dotnet run url-lab.cs

官方文件：File-based apps（#:sdk、#:property 指令在這頁）、Parameter binding in Minimal API applications（lambda 參數怎麼對上 query string、路徑）。

🧪 想看 AOT 那組設定在擋什麼：把 #:property PublishAot=false 拿掉再跑，app.MapControllers() 那行會丟出 NotSupportedException: IsConvertibleType is not initialized when Microsoft.AspNetCore.Mvc.ApiExplorer.IsEnhancedModelMetadataSupported is false。

實驗 2：/items，參數怎麼對上、沒帶的時候是什麼

需求：

  • Minimal API GET /items：參數 string? keyword、int page = 1、string[]? tag，把三個值印出來，null、空字串、空陣列要看得出差別
  • Minimal API GET /items/strict：參數 int page，沒有預設值
  • Minimal API GET /items/search：把三個條件打包成 SearchQuery 類別，用 [AsParameters] 接；再寫一支 GET /items/search2，改接 record 版的 SearchQuery2；還有 GET /items/q，參數 [FromQuery(Name = "q")] string? keyword
  • Controller ItemsController，路由 api/[controller]：GET /api/items、GET /api/items/strict、GET /api/items/search（[FromQuery] SearchQuery）三支和上面對應；再加 GET /api/items/tags（string[] tag 先不加 [FromQuery]）和 GET /api/items/q（[FromQuery(Name = "q")] string? keyword）
  • 對 /items 和 /api/items 各打：不帶參數、?keyword=docker&page=2、?Keyword=docker、?keyword=、?tag=a&tag=b、?page=abc；對兩個 strict、/items/search、/items/search2 各打一次不帶參數

✅ 驗收：第 3 節表格裡標 ⚠️ 的四列差異（空字串、沒帶的 int、陣列要加 FromQuery 否則 415、類別的預設值），兩邊都親眼看到

url-lab.cs（實驗 2 的部分，接在實驗 1 的 /echo 後面）

#:sdk Microsoft.NET.Sdk.Web
// 單檔程式預設以 Native AOT 的設定編譯，那組設定不支援 MVC Controller（啟動就會丟 NotSupportedException）
// 這一行把 AOT 關掉，AddControllers / MapControllers 才能用
#:property PublishAot=false

using Microsoft.AspNetCore.Mvc;
using Microsoft.Extensions.Primitives;

WebApplicationBuilder builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllers();
WebApplication app = builder.Build();
app.MapControllers();

// （/echo 同實驗 1）

// Minimal API：參數直接宣告在 lambda 上，名稱和 query string 一樣就會對上
app.MapGet("/items", (string? keyword, int page = 1, string[]? tag = null) => Format.Describe(keyword, page, tag));

// 沒有預設值、也不可為 null 的 int：沒帶會怎樣？
app.MapGet("/items/strict", (int page) => "page = " + page);

// 多個條件打包成一個類別：[AsParameters] 讓每個屬性各自從 query string 拿
app.MapGet("/items/search", ([AsParameters] SearchQuery query) => Format.Describe(query.Keyword, query.Page, query.Tag));

// 網址上的名稱和參數名不同：用 Name 指定（Minimal API 版）
app.MapGet("/items/q", ([FromQuery(Name = "q")] string? keyword) => "keyword = " + (keyword ?? "null"));

// 打包成 record：建構子參數的預設值會被當成「沒帶時的值」
app.MapGet("/items/search2", ([AsParameters] SearchQuery2 query) => Format.Describe(query.Keyword, query.Page, query.Tag));

app.Run("http://localhost:5060");

// Controller：同樣的參數寫在方法上
[ApiController]
[Route("api/[controller]")]
public class ItemsController : ControllerBase
{
    [HttpGet]
    public string GetAll(string? keyword, int page = 1, [FromQuery] string[]? tag = null)
        => Format.Describe(keyword, page, tag);

    // 沒有預設值、也不可為 null 的 int
    [HttpGet("strict")]
    public string Strict(int page) => "page = " + page;

    // 陣列參數「不加」[FromQuery]，看框架自己會從哪裡拿
    [HttpGet("tags")]
    public string Tags(string[] tag) => "tag = [" + string.Join(", ", tag) + "]  count=" + tag.Length;

    // 網址上的名稱和參數名不同：用 Name 指定
    [HttpGet("q")]
    public string Renamed([FromQuery(Name = "q")] string? keyword) => "keyword = " + (keyword ?? "null");

    // 多個條件打包成一個類別：[FromQuery] 讓每個屬性各自從 query string 拿
    [HttpGet("search")]
    public string Search([FromQuery] SearchQuery query) => Format.Describe(query.Keyword, query.Page, query.Tag);
}

// 把篩選條件打包成一個類別：屬性名稱對應 query string 的名稱
public class SearchQuery
{
    public string? Keyword { get; set; }
    public int Page { get; set; } = 1;
    public string[]? Tag { get; set; }
}

// 同樣的條件改用 record 寫：Page 的預設值寫在建構子參數上
public record SearchQuery2(string? Keyword, int Page = 1, string[]? Tag = null);

// 把參數的值印成文字，null、空字串、空陣列都看得出差別
public static class Format
{
    public static string Describe(string? keyword, int page, string[]? tag)
    {
        string keywordText = keyword is null ? "null" : "\"" + keyword + "\"";
        string tagText = tag is null
            ? "null"
            : "[" + string.Join(", ", tag.Select(t => "\"" + t + "\"")) + "]  count=" + tag.Length;
        return "keyword = " + keywordText + "\npage = " + page + "\ntag = " + tagText;
    }
}

實驗 3：/items/{id:int}，路徑佔位符和 :int 限制

需求：

  • Minimal API：GET /items/{id:int} 和 GET /loose/{id}（沒有 :int），兩個都接 int id
  • Controller：[HttpGet("{id:int}")] 和 [HttpGet("loose/{id}")]
  • 打 /items/5、/items/docker、/loose/docker、/items/5?keyword=x，Controller 版也各打一次

💡 提示

需求用什麼
路徑佔位符只接整數路由樣板寫 {id:int}，:int 是路由約束（route constraint）
/items/strict 和 /items/{id:int} 會不會打架不會：strict 不是整數，{id:int} 不認領

✅ 驗收：/items/docker 是 404、/loose/docker 是 400、/items/5?keyword=x 和 /items/5 結果一樣
