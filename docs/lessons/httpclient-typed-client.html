1. 角色互換：BlogApi 變成用戶端

平常的流程是：前端發請求 → BlogApi 處理 → 回應。這次 BlogApi 在處理請求的中途，自己發出另一個 HTTP 請求給 JSONPlaceholder，等它回應，再把結果交給前端。對 JSONPlaceholder 來說，BlogApi 就是一個用戶端，跟瀏覽器、Postman 沒有差別。

sequenceDiagram participant F as 前端 / .http 檔 participant C as ExternalPostsController participant T as JsonPlaceholderClient participant J as jsonplaceholder.typicode.com F->>C: GET /api/external-posts/1 C->>T: GetPostAsync(1) T->>J: GET /posts/1（BlogApi 當用戶端） J-->>T: 200 + 文章 JSON Note over T: JSON 轉成 JsonPlaceholderPostDto 物件 T-->>C: JsonPlaceholderPostDto C-->>F: 200 + 文章 JSON
外面那一圈（前端 ↔ Controller）你在 01 寫過；裡面那一圈（Client ↔ JSONPlaceholder）是這頁要學的

2. .NET 呼叫 API 的幾種做法

不管哪種做法，真正把 HTTP 請求送出去的都是 System.Net.Http.HttpClient。差別在於誰建立它、誰管理它，以及外面有沒有額外的方便功能。

做法做什麼適合
new HttpClient()自己建立、自己決定什麼時候丟掉Console 小工具、一次性的腳本
IHttpClientFactory.CreateClient()向 DI 要一個 Factory，需要時跟它拿 HttpClient偶爾呼叫一次、設定很簡單
Named ClientAddHttpClient("github", c => …) 先用名稱登記 BaseAddress、Header，用的時候 CreateClient("github")要呼叫好幾個外部服務，各自設定不同
Typed Client寫一個類別專門負責一個外部 API，建構子要一個 HttpClient，由 DI 傳進來Web API 專案的主流做法，這頁練這個
Refit、RestSharp、Flurl第三方套件。Refit 只要宣告 interface，套件會產生呼叫的程式碼端點很多、想少寫重複程式碼
NSwag、Kiota讀對方的 OpenAPI（Swagger）文件，產生整套 client 類別對方有提供 OpenAPI 規格
📎 補充：為什麼不建議到處 new HttpClient()

HttpClient 底下有一個 HttpMessageHandler，它負責開 TCP 連線、重複使用連線。問題出在它的壽命：

寫法會發生什麼
每個請求 using var http = new HttpClient();每次都開新連線。Dispose 之後，作業系統還會讓那條連線停在 TIME_WAIT 狀態一段時間。請求一多，可用的 port 被占滿，新請求連不出去，這叫 socket exhaustion
整個程式共用一個 static HttpClient連線一直重複使用，port 不會被占滿；但連線建立時查到的 DNS 結果也一直沿用，對方換了 IP，你還連舊的
IHttpClientFactory（包含 Typed Client）Factory 保留 handler 重複使用連線，並且每隔一段時間（預設 2 分鐘）換一個新的 handler，新 handler 會重新查 DNS。兩個問題都解決

所以從 Factory 拿到的 HttpClient 不用自己 Dispose，連線由 Factory 管理。官方說明：Guidelines for using HttpClient。

3. Typed Client 的三個零件

零件做什麼目的是什麼
DTO一個 record，屬性對應外部 API 回傳的 JSON 欄位讓 JSON 轉成 C# 物件時，有地方放每個欄位的值
Client 類別建構子要一個 HttpClient；方法裡用它送請求，回傳 DTO「怎麼呼叫 JSONPlaceholder」只寫在這個類別裡，Controller 只呼叫 GetPostAsync(1)，不用知道網址和 JSON
註冊Program.cs 寫 builder.Services.AddHttpClient<Client 類別>(c => …)告訴 DI：有人要這個 Client 類別時，從 Factory 拿一個已經設好 BaseAddress 的 HttpClient，傳進它的建構子

正式語法

要做的事寫法官方文件
註冊 Typed Clientbuilder.Services.AddHttpClient<T>(Action<HttpClient> configureClient)AddHttpClient
設定共同的網址開頭c.BaseAddress = new Uri("https://jsonplaceholder.typicode.com/");HttpClient.BaseAddress
GET 並把 JSON 轉成物件await httpClient.GetFromJsonAsync<T>("posts/1")，回傳 T?GetFromJsonAsync
POST 一個物件（轉成 JSON 送出）await httpClient.PostAsJsonAsync("posts", dto)，回傳 HttpResponseMessagePostAsJsonAsync

兩個細節：

  • 大小寫：JSON 是 userId，C# 屬性是 UserId，GetFromJsonAsync 照樣對得上。它用的是 JsonSerializerDefaults.Web 設定，比對屬性名稱時不分大小寫。
  • Typed Client 的生命週期是 Transient：每次有人要它，DI 就建立一個新的。所以不要把它注入到 Singleton 服務裡，否則那個 Singleton 會一直抓著同一個 HttpClient，Factory 換 handler 的機制就失效了。

4. 練習：串接 JSONPlaceholder

⚠️ 這頁的練習不需要資料庫，但 Program.cs 裡已經有 AddDbContext，啟動時不會連線，所以 Docker 沒開也能跑。

題 1：DTO

需求：

  • 先用瀏覽器打開 https://jsonplaceholder.typicode.com/posts/1，看回傳的 JSON 有哪些欄位、各是什麼型別
  • 新增 Models/External/JsonPlaceholderPostDto.cs，寫一個 record，屬性對應那些欄位

💡 提示：positional record 一行就能寫完，例如 public record Xxx(int A, string B);。namespace 跟著資料夾：BlogApi.Models.External。

✅ 驗收：專案可以建置成功（Rider 的 Build 或 dotnet build）

參考答案（寫完再打開）

BlogApi/Models/External/JsonPlaceholderPostDto.cs

namespace BlogApi.Models.External;

// 對應 JSONPlaceholder 回傳的 { "userId": 1, "id": 1, "title": "…", "body": "…" }
public record JsonPlaceholderPostDto(int UserId, int Id, string Title, string Body);

放在 External 資料夾，是為了和自己資料庫的 Post 分開：Post 長什麼樣子由你決定，這個 DTO 長什麼樣子由 JSONPlaceholder 決定。

題 2：Client 類別

需求：

  • 新增 Clients/JsonPlaceholderClient.cs
  • 建構子要一個 HttpClient，放進 private readonly 欄位（寫法同 01 的 Controller 拿 BlogDbContext）
  • 一個方法 GetPostAsync(int id)，呼叫 posts/{id}，回傳 Task<JsonPlaceholderPostDto?>

💡 提示：第 3 節正式語法表的 GetFromJsonAsync。網址只寫 posts/{id}，前面的 https://… 交給題 3 的 BaseAddress。

✅ 驗收：專案可以建置成功

參考答案（寫完再打開）

BlogApi/Clients/JsonPlaceholderClient.cs

using BlogApi.Models.External;

namespace BlogApi.Clients;

public class JsonPlaceholderClient
{
    // 建構子收到的 HttpClient 放這裡；它的 BaseAddress 已經在 Program.cs 設好
    private readonly HttpClient _httpClient;

    public JsonPlaceholderClient(HttpClient httpClient)
    {
        _httpClient = httpClient;
    }

    public async Task<JsonPlaceholderPostDto?> GetPostAsync(int id)
    {
        // 實際送出的網址 = BaseAddress + "posts/1"
        return await _httpClient.GetFromJsonAsync<JsonPlaceholderPostDto>($"posts/{id}");
    }
}

GetFromJsonAsync 是 System.Net.Http.Json 命名空間的擴充方法。Web 專案的 ImplicitUsings 已經包含它，不用自己寫 using。

題 3：在 Program.cs 註冊

需求：

  • 在 AddDbContext 那段下面，註冊 JsonPlaceholderClient 為 Typed Client
  • BaseAddress 設成 https://jsonplaceholder.typicode.com/（注意結尾的 /）

💡 提示：第 3 節正式語法表的前兩列。lambda 的參數 c 就是之後會傳進你建構子的那個 HttpClient。

✅ 驗收：專案可以建置成功、可以啟動

參考答案（寫完再打開）

BlogApi/Program.cs（新增的部分）

using BlogApi.Clients;

// …AddDbContext 那段下面

// 有人要 JsonPlaceholderClient 時：從 Factory 拿一個 HttpClient，先執行這個 lambda 設好 BaseAddress，
// 再把它傳進 JsonPlaceholderClient 的建構子
builder.Services.AddHttpClient<JsonPlaceholderClient>(c =>
    c.BaseAddress = new Uri("https://jsonplaceholder.typicode.com/"));

和 01 的 AddDbContext 一樣，這一行在啟動時只登記做法，還沒有建立任何 HttpClient。真的有 Controller 要 JsonPlaceholderClient 時才建立。

題 4：Controller 和 .http 檔

需求：

  • 新增 Controllers/ExternalPostsController.cs，路由 api/external-posts
  • 建構子要一個 JsonPlaceholderClient
  • GET api/external-posts/{id}：呼叫 GetPostAsync(id)，回傳結果
  • 在 BlogApi.http 加一個請求打 /api/external-posts/1

💡 提示：Controller 的骨架（[ApiController]、[Route]、ControllerBase、[HttpGet("{id}")]）和 01 的 PostsController 一樣。回傳型別可以用 Task<ActionResult<JsonPlaceholderPostDto>>。

✅ 驗收：送出 .http 的請求，回 200 和第 1 篇文章的 JSON（title 是 sunt aut facere repellat…）

參考答案（寫完再打開）

BlogApi/Controllers/ExternalPostsController.cs

using BlogApi.Clients;
using BlogApi.Models.External;
using Microsoft.AspNetCore.Mvc;

namespace BlogApi.Controllers;

[ApiController]
[Route("api/external-posts")]
public class ExternalPostsController : ControllerBase
{
    private readonly JsonPlaceholderClient _client;

    public ExternalPostsController(JsonPlaceholderClient client)
    {
        _client = client;
    }

    [HttpGet("{id:int}")]
    public async Task<ActionResult<JsonPlaceholderPostDto>> Get(int id)
    {
        JsonPlaceholderPostDto? post = await _client.GetPostAsync(id);
        return post;
    }
}

5. 故意弄壞：四個實驗

每個實驗改一個地方，先猜會發生什麼，再執行，再打開對照。做完記得改回來。

實驗 A：拿掉註冊

把題 3 的 AddHttpClient<JsonPlaceholderClient>(…) 註解掉，重新啟動，送出 .http 的請求。

猜：啟動時就失敗，還是請求進來才失敗？錯誤訊息裡會提到哪個類別？

觀察與解釋（試完再打開）

啟動成功，請求進來才失敗，回 500。錯誤訊息說找不到 JsonPlaceholderClient 這個服務，並提到正在建立的是 ExternalPostsController。

原因：Controller 是請求進來時才建立的。DI 要建立 ExternalPostsController，看到建構子要一個 JsonPlaceholderClient，去登記簿裡找，沒有登記過，只好放棄。這和 01 拿掉 AddDbContext 是同一件事。

實驗 B：DTO 屬性名稱寫錯

把 DTO 的 Body 改成 Content，重新啟動，送出請求。

猜：會報錯嗎？回應裡會看到什麼？

觀察與解釋（試完再打開）

不會報錯，回 200。其他欄位都正常，只有 content 是空的（string 的預設值 null）。實測轉出來的物件：

WrongDto { UserId = 1, Id = 1, Title = sunt aut facere …, Content =  }

原因：轉換時，JSON 裡的 body 找不到同名屬性，就被略過；DTO 的 Content 在 JSON 裡找不到對應欄位，就留預設值。兩邊都不算錯誤。

這是串接外部 API 最常見的 bug：不報錯，資料默默變成空的。名稱一定要對著對方的 JSON 寫；名稱想取不一樣時，用 [JsonPropertyName("body")] 指定對應的 JSON 欄位。

實驗 C：BaseAddress 結尾的斜線

把 BaseAddress 改成 https://jsonplaceholder.typicode.com/posts（沒有結尾 /），Client 裡的網址改成只有 $"{id}"。送出請求。再把 BaseAddress 結尾補上 /，送一次。

猜：兩次實際送出去的網址各是什麼？

觀察與解釋（試完再打開）

用 new Uri(baseAddress, 相對網址) 實測四種組合：

BaseAddress相對網址實際送出
…typicode.com/posts1…typicode.com/1 ❌
…typicode.com/posts/1…typicode.com/1 ❌
…typicode.com/posts/1…typicode.com/posts/1 ✅
…typicode.com/posts//1…typicode.com/1 ❌

規則跟瀏覽器解析相對連結一樣：BaseAddress 最後一個 / 後面的部分（這裡的 posts）會被當成「檔名」換掉；相對網址開頭是 / 的話，直接從網域根目錄開始。

記法：BaseAddress 結尾加 /，相對網址開頭不加 /。

實驗 D：要一篇不存在的文章

全部改回正確版本，送出 GET /api/external-posts/99999。

猜：前端收到 404 還是別的？

觀察與解釋（試完再打開）

前端收到 500，不是 404。JSONPlaceholder 確實回了 404，但 GetFromJsonAsync 看到不是 2xx 的狀態碼，就丟出例外：

System.Net.Http.HttpRequestException: Response status code does not indicate success: 404 (Not Found).

例外一路往上，Controller 沒有處理，ASP.NET Core 就回 500。對前端來說，「文章不存在」和「伺服器壞了」看起來一樣，這不對。下一題修它。

6. 練習：對方回 404 時怎麼辦

題 5：把 404 轉成 404

需求：

  • 改 GetPostAsync：對方回 404 時回傳 null，其他失敗照樣丟例外
  • 改 Controller：拿到 null 就回 NotFound()

💡 提示

需求用什麼
送請求，但先不轉 JSONHttpResponseMessage response = await _httpClient.GetAsync(網址);
看狀態碼response.StatusCode == HttpStatusCode.NotFound（using System.Net;）
不是 2xx 就丟例外response.EnsureSuccessStatusCode();
把回應內容轉成物件await response.Content.ReadFromJsonAsync<T>()

✅ 驗收：/api/external-posts/1 回 200 和文章；/api/external-posts/99999 回 404

參考答案（寫完再打開）

BlogApi/Clients/JsonPlaceholderClient.cs（GetPostAsync 改成）

public async Task<JsonPlaceholderPostDto?> GetPostAsync(int id)
{
    HttpResponseMessage response = await _httpClient.GetAsync($"posts/{id}");

    // 對方說找不到：這是正常情況，用 null 告訴呼叫的人「沒有這篇」
    if (response.StatusCode == HttpStatusCode.NotFound)
    {
        return null;
    }

    // 其他非 2xx（500、503…）是對方真的出問題，照樣丟 HttpRequestException
    response.EnsureSuccessStatusCode();

    return await response.Content.ReadFromJsonAsync<JsonPlaceholderPostDto>();
}

檔案最上面要加 using System.Net;，HttpStatusCode 在這個命名空間。

BlogApi/Controllers/ExternalPostsController.cs（Get 改成）

[HttpGet("{id:int}")]
public async Task<ActionResult<JsonPlaceholderPostDto>> Get(int id)
{
    JsonPlaceholderPostDto? post = await _client.GetPostAsync(id);
    if (post is null)
    {
        return NotFound();
    }
    return post;
}

為什麼不在 Controller 裡 try/catch HttpRequestException：Controller 不該知道底下用的是 HTTP。「找不到」由 Client 翻譯成 null，Controller 只判斷 null，和 01 查資料庫找不到時的寫法一樣。

延伸問題

  1. JSONPlaceholder 偶爾很慢，或暫時回 503。安裝 Microsoft.Extensions.Http.Resilience 套件，在 AddHttpClient<…>(…) 後面接 .AddStandardResilienceHandler()，它預設做了哪些事（重試幾次、逾時多久）？
  2. 外部 API 要求每個請求都帶 Authorization: Bearer xxx。寫在每個方法裡、寫在註冊的 lambda 裡（c.DefaultRequestHeaders）、寫成一個 DelegatingHandler，三種差在哪？金鑰要放在哪裡（提示：01 的 User Secrets）？
  3. 前端打你的 API 打到一半就關掉分頁，你的 API 還在等 JSONPlaceholder 回應，要怎麼讓它也停下來？（提示：CancellationToken，Controller 的方法可以直接收一個）
  4. 如果把 JsonPlaceholderClient 注入到一個用 AddSingleton 註冊的服務裡，第 2 節補充說的「每 2 分鐘換 handler」還有效嗎？
