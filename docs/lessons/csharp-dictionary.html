C# 補充：Dictionary（key 與 value）

Dictionary 是「用 key 找 value」的對照表。這頁講怎麼建立與讀取、key 不存在時怎麼辦、pair.Key 與 pair.Value 是什麼、怎麼用 value 反過來找 key，以及怎麼從清單做出 Dictionary。

DictionarykeyvalueKeyValuePairTryGetValueGetValueOrDefaultContainsKeyToDictionaryGroupBy對應表反查

📌 這頁是 C# 語法，和專案無關。程式裡看到 Dictionary<…, …>、pair.Key、pair.Value、TryGetValue 看不懂時回來查。

每一節都從最簡單的寫法開始，一步只多一樣東西。頁面上的輸出和例外訊息都是單檔程式實際執行的結果（.NET 10）。丟例外的地方，「輸出」只列例外的型別和訊息那一行；實際執行時那一行前面還有 Unhandled exception.，後面接著幾行出錯位置，程式在那裡結束。

1. Dictionary 是什麼：用 key 找 value

要記三樣商品的價格，之後用商品名稱查價格。這一節先只用 List 做，看它哪裡不夠，再換成 Dictionary。

程式裡的顏色：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或不建議的寫法。

第 1 步：用兩個 List，一個放名稱、一個放價格

List 只能用「第幾個」拿東西。所以查價格要分兩段：先在名稱的清單裡找出咖啡排第幾個，再用同一個位置到價格的清單拿。

var names = new List<string> { "可樂", "綠茶", "咖啡" };
var prices = new List<int> { 30, 25, 60 };

int index = names.IndexOf("咖啡");     // 咖啡排第幾個 → 2
Console.WriteLine(prices[index]);      // 價格清單的第 2 個

// 輸出：
// 60

查得到。但兩個清單要靠「位置一樣」才對得起來。只要其中一個清單少了一筆，另一個忘了跟著改，就會查到別人的價格：

names.Remove("綠茶");                  // 名稱清單拿掉綠茶，價格清單忘了拿

index = names.IndexOf("咖啡");         // 咖啡現在排第 1 個
Console.WriteLine(prices[index]);      // 價格清單的第 1 個是綠茶的 25

// 輸出：
// 25

咖啡變成 25 元，而且沒有任何錯誤訊息。問題出在名稱和價格分開放在兩個地方。

第 2 步：改用 Dictionary，名稱和價格放在同一筆

Dictionary 的每一筆是一對：key（用來找的）與 value（找到的內容）。商品名稱當 key，價格當 value，兩個一起放進去：

var price = new Dictionary<string, int>();
price["可樂"] = 30;
price["綠茶"] = 25;
price["咖啡"] = 60;

Console.WriteLine(price["咖啡"]);     // 直接用名稱查，不用先找位置

// 輸出：
// 60
  • Dictionary<string, int>：尖括號裡第一個是 key 的型別，第二個是 value 的型別。這裡 key 是 string（商品名稱），value 是 int（價格）。key 常見的是 string、int、enum
  • price["可樂"] = 30;：放進一對，key 是 "可樂"、value 是 30
  • price["咖啡"]：中括號裡寫 key，拿到那個 key 的 value

名稱和價格是同一筆，不會再有「位置對不上」的問題。

第 3 步：建立的時候一起寫內容

第 2 步每放一對就要寫一次 price。內容一開始就知道時，可以在 new 後面接大括號，一行寫一對：

var price = new Dictionary<string, int>
{
    ["可樂"] = 30,
    ["綠茶"] = 25,
    ["咖啡"] = 60,
};

Console.WriteLine(price["咖啡"]);

// 輸出：
// 60

做出來的 price 和第 2 步的一樣。這頁後面的範例都用這種寫法建立 price。

第 4 步：問有幾筆、有沒有某個 key

Console.WriteLine(price.Count);                 // 有幾筆
Console.WriteLine(price.ContainsKey("咖啡"));   // 有沒有「咖啡」這個 key
Console.WriteLine(price.ContainsKey("牛奶"));

// 輸出：
// 3
// True
// False

List 和 Dictionary 的差別

List<T>Dictionary<TKey, TValue>
怎麼找位置：list[0]key：price["可樂"]
找的速度要找特定內容得一個一個看直接跳到那個 key，資料再多也一樣快
能不能重複內容可以重複key 不能重複，value 可以
適合一串有順序的東西對照表、用編號或名稱查資料

2. key 不存在時：三種讀法

店裡沒有賣牛奶，price 裡沒有 "牛奶" 這個 key。這一節看用中括號讀一個不存在的 key 會怎樣，再一步一步換成不會出錯的讀法。每一步用的都是第 1 節那個有可樂、綠茶、咖啡的 price。

顏色和前面一樣：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或不建議的寫法。

第 1 步：用中括號讀不存在的 key，程式停掉

Console.WriteLine(price["可樂"]);
Console.WriteLine(price["牛奶"]);

// 輸出：
// 30
// KeyNotFoundException: The given key '牛奶' was not present in the dictionary.

中括號的讀法在 key 不存在時會丟出 KeyNotFoundException。沒有人接住這個例外，程式就停在這一行：實際執行時，在這一行後面再加一行 Console.WriteLine，它沒有印出來。

第 2 步：先用 ContainsKey 問有沒有，再讀

第 1 節已經有 ContainsKey。先問一次，有才讀：

if (price.ContainsKey("牛奶"))
{
    Console.WriteLine(price["牛奶"]);
}
else
{
    Console.WriteLine("沒有賣牛奶");
}

// 輸出：
// 沒有賣牛奶

不會丟例外了。但 "牛奶" 這個 key 寫了兩次，Dictionary 也找了兩次：ContainsKey 找一次，中括號再找一次。

第 3 步：TryGetValue，找一次就同時知道「有沒有」和「是多少」

TryGetValue 一次給兩個結果。先不放進 if，把兩個結果分別印出來看：

bool found = price.TryGetValue("牛奶", out var m);
Console.WriteLine(found);     // 有沒有找到
Console.WriteLine(m);         // 找到的 value

bool found2 = price.TryGetValue("可樂", out var c);
Console.WriteLine(found2);
Console.WriteLine(c);

// 輸出：
// False
// 0
// True
// 30
  • 回傳值是 bool：有沒有找到
  • out var m：在這裡宣告一個變數 m，TryGetValue 把找到的 value 放進去。out 的意思是「這個參數是方法往外給結果用的」
  • 找不到時 m 是 value 型別的 default，int 的 default 是 0（default 與可空型別那一頁）。這個 0 不是牛奶的價格，所以要先看回傳值，是 true 才用 m

回傳值是 bool，可以直接放進 if。第 2 步改寫成：

if (price.TryGetValue("牛奶", out var p))
{
    Console.WriteLine(p);          // 這裡用 p，不用再寫 price["牛奶"]
}
else
{
    Console.WriteLine("沒有賣牛奶");
}

// 輸出：
// 沒有賣牛奶

✗ 先 ContainsKey 再中括號

if (price.ContainsKey("牛奶"))
{
    Console.WriteLine(price["牛奶"]);
}

key 寫兩次，找兩次。

✓ TryGetValue

if (price.TryGetValue("牛奶", out var p))
{
    Console.WriteLine(p);
}

key 寫一次，找一次。

第 4 步：GetValueOrDefault，沒有就用預設值

有時候不需要分「有」和「沒有」兩條路，只是想要「沒有就當成 0」。用第 3 步的寫法要這麼多行：

int milk;
if (price.TryGetValue("牛奶", out var found3))
{
    milk = found3;
}
else
{
    milk = 0;
}
Console.WriteLine(milk);

// 輸出：
// 0

GetValueOrDefault 一行做完同一件事。第二個參數可以指定「沒有的時候要回傳什麼」：

Console.WriteLine(price.GetValueOrDefault("牛奶"));        // 沒有 → int 的 default
Console.WriteLine(price.GetValueOrDefault("牛奶", -1));    // 沒有 → 自己指定的 -1
Console.WriteLine(price.GetValueOrDefault("可樂", -1));    // 有 → 原本的 value

// 輸出：
// 0
// -1
// 30

三種讀法什麼時候用

  • price[key]：key 不存在時丟 KeyNotFoundException。用在確定一定有的時候；沒有就代表程式有錯，停下來才看得到
  • price.TryGetValue(key, out var p)：key 不存在時回傳 false，p 是 value 型別的 default。用在不確定有沒有，而且兩種情況要分開處理的時候
  • price.GetValueOrDefault(key, 預設值)：key 不存在時回傳預設值。用在沒有就用預設值、不用分開處理的時候

3. 新增、修改、移除

第 1 節用 price["可樂"] = 30; 放東西進去。這一節看同一個寫法在 key 已經存在時會做什麼，再看另外兩個只新增、不覆蓋的方法，最後是移除。開頭的 price 是可樂 30、綠茶 25、咖啡 60，每一步接著上一步的結果往下做。

顏色和前面一樣：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或不建議的寫法。

第 1 步：key 還沒有，中括號是新增

price["牛奶"] = 40;

Console.WriteLine(price.Count);
Console.WriteLine(price["牛奶"]);

// 輸出：
// 4
// 40

原本 3 筆，多了牛奶變成 4 筆。

第 2 步：key 已經有，同一個寫法變成修改

price["可樂"] = 35;

Console.WriteLine(price.Count);
Console.WriteLine(price["可樂"]);

// 輸出：
// 4
// 35

還是 4 筆，可樂從 30 變成 35。中括號的規則是「沒有就新增，有就把 value 換掉」。

要改價格時這很方便。但如果本意是「新增一樣新商品」，而那個名稱其實已經有了，原本的價格會直接被換掉，沒有任何提示。

第 3 步：Add，key 重複就丟例外

Add 只做新增。key 已經存在時不覆蓋，直接丟例外：

price.Add("紅茶", 20);            // 沒有紅茶 → 新增
Console.WriteLine(price.Count);

price.Add("可樂", 99);            // 已經有可樂

// 輸出：
// 5
// ArgumentException: An item with the same key has already been added. Key: 可樂

接住這個例外之後再看，可樂還是 35，沒有被改成 99。

第 4 步：TryAdd，key 重複就不動，用回傳值告訴你

重複不算錯誤、只是「已經有了就不用加」的時候，用 TryAdd。它不丟例外，回傳 bool 表示有沒有加進去：

Console.WriteLine(price.TryAdd("可樂", 99));   // 已經有可樂 → 不動
Console.WriteLine(price["可樂"]);

Console.WriteLine(price.TryAdd("奶茶", 45));   // 沒有奶茶 → 新增
Console.WriteLine(price["奶茶"]);

// 輸出：
// False
// 35
// True
// 45

第 5 步：Remove，移除一筆

Console.WriteLine(price.Remove("牛奶"));        // 有牛奶 → 移除
Console.WriteLine(price.ContainsKey("牛奶"));

Console.WriteLine(price.Remove("牛奶"));        // 已經沒有牛奶了

// 輸出：
// True
// False
// False

Remove 回傳有沒有移除到東西。key 不存在時回傳 false，不丟例外。

三種放進去的寫法什麼時候用

  • price[key] = 值：key 已經存在就覆蓋，不存在就新增。用在「有就改、沒有就加」
  • price.Add(key, 值)：key 已經存在就丟 ArgumentException，不存在就新增。用在「重複就是錯誤，要立刻知道」
  • price.TryAdd(key, 值)：key 已經存在就不動、回傳 false，不存在就新增、回傳 true。用在「已經有了就保留原本的」

4. 逐筆走過：pair.Key 與 pair.Value

前面都是指定一個 key 去拿 value。這一節要把 price 裡的每一筆都走過一次。開頭的 price 重新用可樂 30、綠茶 25、咖啡 60。

顏色和前面一樣：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或不建議的寫法。

第 1 步：foreach 每一圈拿到的是「一對」

foreach (var pair in price)
{
    Console.WriteLine(pair);
}

// 輸出：
// [可樂, 30]
// [綠茶, 25]
// [咖啡, 60]

對 List<int> 做 foreach，每一圈拿到一個 int。對 Dictionary 做 foreach，每一圈拿到的是 key 和 value 兩個一起。pair 這個名字是自己取的。

直接印 pair 只能得到 [可樂, 30] 這種固定的樣子。想印成「可樂 賣 30 元」，要能分別拿到左邊和右邊。

第 2 步：pair.Key 拿左邊，pair.Value 拿右邊

foreach (var pair in price)
{
    Console.WriteLine($"{pair.Key} 賣 {pair.Value} 元");
}

// 輸出：
// 可樂 賣 30 元
// 綠茶 賣 25 元
// 咖啡 賣 60 元

pair 的型別是 KeyValuePair<string, int>，它只有兩個屬性：.Key 和 .Value。不用 var、把型別寫出來就是 foreach (KeyValuePair<string, int> pair in price)，結果一樣。

LINQ 裡的 pair => pair.Value，pair 就是這個東西。

第 3 步：在 foreach 裡直接拆成兩個變數

每次都寫 pair.Key、pair.Value 看不出左邊和右邊各是什麼。可以在 foreach 的括號裡直接給兩個名字：

foreach (var (name, amount) in price)
{
    Console.WriteLine($"{name} 賣 {amount} 元");
}

// 輸出：
// 可樂 賣 30 元
// 綠茶 賣 25 元
// 咖啡 賣 60 元

括號裡第一個名字拿到 key，第二個拿到 value。

第 4 步：只要 key，或只要 value

foreach (var name in price.Keys)
{
    Console.WriteLine(name);
}

foreach (var amount in price.Values)
{
    Console.WriteLine(amount);
}

// 輸出：
// 可樂
// 綠茶
// 咖啡
// 30
// 25
// 60

第 5 步：走過的順序不一定是放進去的順序

到目前為止，印出來的順序都剛好是放進去的順序。移除可樂、再放進牛奶，然後再走一次：

price.Remove("可樂");
price["牛奶"] = 40;               // 牛奶是最後才放進去的

foreach (var pair in price)
{
    Console.WriteLine($"{pair.Key} 賣 {pair.Value} 元");
}

// 輸出：
// 牛奶 賣 40 元
// 綠茶 賣 25 元
// 咖啡 賣 60 元

最後放進去的牛奶排在第一個。不要依賴 Dictionary 走過的順序，它不保證。

第 6 步：需要固定順序時自己排序

foreach (var pair in price.OrderBy(pair => pair.Value))
{
    Console.WriteLine($"{pair.Key} 賣 {pair.Value} 元");
}

// 輸出：
// 綠茶 賣 25 元
// 牛奶 賣 40 元
// 咖啡 賣 60 元

OrderBy(pair => pair.Value) 的意思是「每一對用它的 value 來比，由小排到大」。要照 key 排就寫 price.OrderBy(pair => pair.Key)。

5. 用 LINQ 查：用 value 反過來找 key

Dictionary 只能用 key 找 value。這一節要做反方向的事：給一個 value，找出哪些 key 對到它。先用 foreach 寫，再一步換一段成 LINQ。

顏色和前面一樣：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或不建議的寫法。

範例是一張對應表：左邊是資料庫裡的狀態，右邊是顯示給使用者的文字。每一步都用這個 progress：

var progress = new Dictionary<string, string>
{
    ["Pending"] = "進行中",
    ["Paid"] = "進行中",
    ["Shipped"] = "已完成",
    ["Cancelled"] = "已取消",
};

第 1 步：正方向，用 key 找 value

Console.WriteLine(progress["Paid"]);

// 輸出：
// 進行中

第 2 步：反方向，把 value 寫進中括號行不通

現在問題反過來：哪些狀態會顯示成「進行中」？直接把 "進行中" 寫進中括號試試看：

Console.WriteLine(progress["進行中"]);

// 輸出：
// KeyNotFoundException: The given key '進行中' was not present in the dictionary.

中括號裡的東西一律被當成 key。"進行中" 是 value，不是 key，所以找不到。

第 3 步：用 foreach 一對一對看，value 符合就記下 key

用第 4 節的 foreach：每一對都看它的 pair.Value，符合就把 pair.Key 加進一個清單。

var keys = new List<string>();
foreach (var pair in progress)
{
    if (pair.Value == "進行中")
    {
        keys.Add(pair.Key);
    }
}

foreach (var key in keys)
{
    Console.WriteLine(key);
}

// 輸出：
// Pending
// Paid

找到兩個。這段程式做了三件事：過濾（if）、取出 key（pair.Key）、放進清單（keys.Add）。LINQ 有三個方法各做其中一件，下面一次換一個。

第 4 步：Where 做過濾

var matched = progress.Where(pair => pair.Value == "進行中");

foreach (var pair in matched)
{
    Console.WriteLine(pair);
}

// 輸出：
// [Pending, 進行中]
// [Paid, 進行中]

Where 把第 3 步的 if 條件搬進括號裡：只留下 value 是「進行中」的那幾對。留下來的還是一對一對的 pair，key 和 value 都在。

第 5 步：Select 從每一對取出 key

var matchedKeys = progress
    .Where(pair => pair.Value == "進行中")
    .Select(pair => pair.Key);

foreach (var key in matchedKeys)
{
    Console.WriteLine(key);
}

// 輸出：
// Pending
// Paid

Select(pair => pair.Key) 把留下來的每一對換成它的 key。現在走過的每一個是 string，不是 pair。

第 6 步：ToList 收成清單

List<string> list = progress
    .Where(pair => pair.Value == "進行中")    // ① 只留下 value 是「進行中」的那幾對
    .Select(pair => pair.Key)                 // ② 取出它們的 key
    .ToList();                                // ③ 收成清單

Console.WriteLine(list.Count);
Console.WriteLine(list[0]);
Console.WriteLine(list[1]);

// 輸出：
// 2
// Pending
// Paid

結果和第 3 步的 keys 一樣，是一個 List<string>，可以用 .Count 和 [位置]。這裡的 .ToList() 只在記憶體裡跑，不連資料庫：它處理的是 progress 這個已經在記憶體裡的 Dictionary。

找一個沒有任何 key 對到的 value：

List<string> none = progress
    .Where(pair => pair.Value == "退貨中")
    .Select(pair => pair.Key)
    .ToList();

Console.WriteLine(none.Count);

// 輸出：
// 0

找不到時是空清單，不會丟例外。

第 7 步：條件可以換成別的

Where 括號裡不一定要用 ==。換回第 1 節的 price（可樂 30、綠茶 25、咖啡 60），找出比 28 元貴的商品：

List<string> expensive = price
    .Where(pair => pair.Value > 28)
    .Select(pair => pair.Key)
    .ToList();

foreach (var name in expensive)
{
    Console.WriteLine(name);
}

// 輸出：
// 可樂
// 咖啡

兩個方向的差別

方向寫法結果有幾個
key → valueprogress["Paid"]剛好一個（key 不重複）
value → key.Where(pair => pair.Value == …).Select(pair => pair.Key)零個、一個或多個（value 可以重複）

反查的實際用途：使用者選的是顯示用的狀態，要先換成資料庫裡的狀態才能查。見 enum 那一頁講對應表的那一節。

6. 從清單做出 Dictionary

資料常常一開始是一個清單，例如一串商品。這一節從「在清單裡找某個 Id 的商品」開始，一步一步走到用 ToDictionary 一行把清單轉成 Dictionary。

顏色和前面一樣：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或不建議的寫法。

每一步都用這份資料和這個類別：

var products = new List<Product>
{
    new Product { Id = 1, Category = "飲料", Name = "可樂", Price = 30 },
    new Product { Id = 2, Category = "飲料", Name = "綠茶", Price = 25 },
    new Product { Id = 3, Category = "零食", Name = "餅乾", Price = 35 },
};

class Product
{
    public int Id { get; set; }
    public string Category { get; set; } = "";
    public string Name { get; set; } = "";
    public int Price { get; set; }
}

第 1 步：在清單裡找，要一筆一筆比

foreach (var p in products)
{
    if (p.Id == 2)
    {
        Console.WriteLine(p.Name);
    }
}

// 輸出：
// 綠茶

找得到。但每找一個 Id 都要從第一筆開始比。要找很多次時，同樣的迴圈就要跑很多次。

第 2 步：先自己做一張「Id → 商品」的對照表

先把清單走過一次，每個商品用它的 Id 當 key 放進 Dictionary。之後要找哪個 Id，都用中括號直接拿：

var byId = new Dictionary<int, Product>();
foreach (var p in products)
{
    byId[p.Id] = p;
}

Console.WriteLine(byId[2].Name);
Console.WriteLine(byId[3].Name);

// 輸出：
// 綠茶
// 餅乾

這個 Dictionary 的 key 是 int（Id），value 是整個 Product 物件，所以 byId[2] 後面可以接 .Name。

第 3 步：ToDictionary，一行做完第 2 步的迴圈

var byId = products.ToDictionary(p => p.Id);

Console.WriteLine(byId[2].Name);
Console.WriteLine(byId[3].Name);

// 輸出：
// 綠茶
// 餅乾

括號裡的 p => p.Id 回答一個問題：每一個商品要用什麼當 key。value 沒有指定，就是整個商品。得到的型別和第 2 步一樣，是 Dictionary<int, Product>。

第 4 步：value 只要其中一個屬性

只想要「名稱 → 價格」，不需要整個商品時，再給第二個 lambda，指定 value 要放什麼：

var nameToPrice = products.ToDictionary(p => p.Name, p => p.Price);

Console.WriteLine(nameToPrice["餅乾"]);

// 輸出：
// 35

第一個 lambda 決定 key，第二個決定 value。得到的是 Dictionary<string, int>。

第 5 步：key 重複時，ToDictionary 丟例外

改用 Category 當 key。可樂和綠茶都是「飲料」，key 會重複：

var byCategory = products.ToDictionary(p => p.Category);

// 輸出：
// ArgumentException: An item with the same key has already been added. Key: 飲料

訊息和第 3 節的 Add 一樣。如果用第 2 步那種迴圈加中括號的寫法（byCategory[p.Category] = p;），不會丟例外，但中括號遇到重複的 key 是覆蓋：實際執行的結果是只剩 2 筆，byCategory["飲料"] 是綠茶，可樂不見了。

一個分類本來就有多個商品，問題不在重複，在於 value 只能放一個商品。

第 6 步：一個 key 對到多個，value 改放清單

把 value 的型別改成 List<string>，一個分類對到一串商品名稱。先用迴圈寫：

var groups = new Dictionary<string, List<string>>();
foreach (var p in products)
{
    // 這個分類第一次出現：先放一個空清單進去
    if (!groups.ContainsKey(p.Category))
    {
        groups[p.Category] = new List<string>();
    }

    // 把商品名稱加進這個分類的清單
    groups[p.Category].Add(p.Name);
}

foreach (var pair in groups)
{
    Console.WriteLine($"{pair.Key}：{pair.Value.Count} 個");
    foreach (var name in pair.Value)
    {
        Console.WriteLine($"  {name}");
    }
}

// 輸出：
// 飲料：2 個
//   可樂
//   綠茶
// 零食：1 個
//   餅乾

這裡 pair.Value 是一個 List<string>，所以可以 .Count，也可以再用一層 foreach 走過。

第 7 步：GroupBy 把商品照分類分組

第 6 步的迴圈做的事是「同一個分類的放在一起」。LINQ 的 GroupBy 就是做這件事。先只分組，把每一組印出來看：

foreach (var g in products.GroupBy(p => p.Category))
{
    Console.WriteLine($"{g.Key}：{g.Count()} 個");
    foreach (var p in g)
    {
        Console.WriteLine($"  {p.Name}");
    }
}

// 輸出：
// 飲料：2 個
//   可樂
//   綠茶
// 零食：1 個
//   餅乾
  • GroupBy(p => p.Category)：括號裡回答「每個商品要照什麼分組」。這裡分成兩組
  • 外層 foreach 走過的每一個 g 是一組，不是一個商品。g.Key 是這一組共同的分類名稱
  • g 本身可以再用 foreach 走過，裡面是這一組的商品

第 8 步：分好的組再接 ToDictionary

每一組的 g.Key 都不一樣，可以拿來當 key。用第 4 步的寫法，兩個 lambda 各決定 key 和 value，只是現在走過的每一個是一組：

var groups = products
    .GroupBy(p => p.Category)
    .ToDictionary(g => g.Key, g => g.Select(p => p.Name).ToList());

// 用第 6 步同一段 foreach 印出來，輸出：
// 飲料：2 個
//   可樂
//   綠茶
// 零食：1 個
//   餅乾
  • 第一個 lambda g => g.Key：這一組的分類名稱當 key
  • 第二個 lambda g => g.Select(p => p.Name).ToList()：這一組裡的每個商品取出名稱，收成清單，當 value。Select 和 ToList 是第 5 節用過的那兩個

得到的型別和第 6 步一樣，是 Dictionary<string, List<string>>。key 不會重複，所以不會再有第 5 步的例外。

7. key 怎麼算「相同」

兩個 key 要「相同」才會找到同一筆。這一節看字串當 key 時，大小寫不同算不算相同。

顏色和前面一樣：藍色是這一步多出來的寫法，綠色是使用的地方跟著變的寫法，紅色是會出錯或不建議的寫法。

第 1 步：字串當 key，預設區分大小寫

var a = new Dictionary<string, int>
{
    ["Cola"] = 30,
};

Console.WriteLine(a.ContainsKey("Cola"));
Console.WriteLine(a.ContainsKey("cola"));    // c 是小寫

a["cola"] = 99;
Console.WriteLine(a.Count);

// 輸出：
// True
// False
// 2

"Cola" 和 "cola" 被當成兩個不同的 key：用小寫找不到，用小寫放進去會多出一筆，不是修改原本那筆。

第 2 步：建立時傳 StringComparer.OrdinalIgnoreCase，不分大小寫

var b = new Dictionary<string, int>(StringComparer.OrdinalIgnoreCase)
{
    ["Cola"] = 30,
};

Console.WriteLine(b.ContainsKey("cola"));
Console.WriteLine(b["COLA"]);

b["cola"] = 99;
Console.WriteLine(b.Count);
Console.WriteLine(b["Cola"]);

// 輸出：
// True
// 30
// 1
// 99

小括號裡傳的是「這個 Dictionary 要怎麼比較 key」。傳了 StringComparer.OrdinalIgnoreCase 之後，"Cola"、"cola"、"COLA" 都是同一個 key，所以 b["cola"] = 99 是修改原本那筆，還是 1 筆。

其他型別的 key，以及 null

  • int、enum 當 key 最單純，值一樣就是同一個 key
  • key 不能是 null：把 null 當 key 放進去，實際執行會丟 ArgumentNullException: Value cannot be null. (Parameter 'key')
  • value 可以是 null：Dictionary<string, string?> 可以寫 d["可樂"] = null;，這一筆照樣算在 Count 裡
  • Dictionary 和 JSON 的物件長得很像（都是「名字：值」），兩者可以互轉，見 JSON 那一頁第 6 節
