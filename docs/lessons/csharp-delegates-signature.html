1. 方法簽章是什麼

這頁說的簽章（signature），就是一個方法「怎麼呼叫它、它回什麼」：名稱、參數、回傳型別。大括號裡的本體不算，你呼叫別人的方法時也看不到本體，看得到的只有簽章。先用一個簡單的方法認識五個部分：

呼叫時用得到的只有 ②③④⑤；① 決定誰能呼叫、要不要先 new 物件

簡單範例：三種呼叫方式（實際執行過）

Console.WriteLine(StringTools.Repeat("ab"));             // count 沒給，用預設值 2 → abab
Console.WriteLine(StringTools.Repeat("ab", 3));          // 照順序給 → ababab
Console.WriteLine(StringTools.Repeat("ab", count: 1));   // 用名稱指定 → ab

static class StringTools
{
    public static string Repeat(string text, int count = 2)
    {
        return string.Concat(Enumerable.Repeat(text, count));
    }
}

static 的方法用「類別名稱.方法」呼叫，不用先 new 一個物件。StringTools 是放工具方法的類別，裡面只有 static 方法，所以類別也標 static，表示它不能被 new。

你自己寫過的方法

第 1 課 PostsController 的其中一個：

public async Task<ActionResult<Post>> GetById(int id)
片段是哪個部分意思
public①誰都能呼叫；沒有 static，所以要有一個 PostsController 物件才能呼叫（這個物件是框架 new 的，第 3 課）
async修飾詞，不是簽章的一部分告訴編譯器本體裡會有 await。呼叫的人看不到它，只看得到回傳型別是 Task<…>
Task<ActionResult<Post>>②三層包起來：Task 包著 ActionResult 包著 Post。讀法是「最後會給你一個 ActionResult，裡面是 Post」
GetById③名稱
int id④一個參數，型別 int、名稱 id；路由的 {id} 就是填到這裡

名稱後面的角括號：泛型

你早就用過 List<string>、List<Post>。寫 List 的人不知道你要裝什麼，所以留一個洞 <T>，用的人呼叫時才填型別。方法也可以有這種洞：

public static IServiceCollection AddDbContext<TContext>(…)   // 定義：留一個洞叫 TContext
    where TContext : DbContext                                 // 限制：填進來的型別必須繼承 DbContext

builder.Services.AddDbContext<BlogDbContext>(…);               // 呼叫：填 BlogDbContext

where 那行叫泛型限制。BlogDbContext : DbContext 所以可以填；填 string 會編譯錯誤。有了限制，方法本體才能放心把 TContext 當 DbContext 用。

看簽章時會遇到的記號

看到什麼代表什麼讀法
static不用 new 物件，用類別名稱呼叫StringTools.Repeat(…)
void 在回傳型別的位置不回傳呼叫完沒有值可以接
名稱後面的 <T>泛型參數，呼叫時填型別AddDbContext<BlogDbContext>
where T : 某型別泛型限制填進去的型別必須是那個型別或它的子類別
參數後面的 = 2、= null選擇性參數，有預設值可以不給；要跳過前面的用名稱指定 count: 1
string?、Action<…>?可能是 null接到值要先檢查，或知道這個方法允許你傳 null
Task<X> 在回傳型別非同步方法，最後會給你一個 X要 await 才拿得到 X
第一個參數前面有 this擴充方法下一節

2. 擴充方法：第一個參數前面的 this

想對 string 加一個 IsLongTitle()，判斷標題夠不夠長。但 string 是 .NET 的類別，你改不了它的程式碼。C# 的解法是擴充方法（extension method）：方法寫在你自己的 static class 裡，只要第一個參數前面加 this，呼叫時就可以寫得像那個型別本來就有的方法。

簡單範例：對 string 加一個方法（實際執行過）

Console.WriteLine("EF Core 入門".IsLongTitle());                     // 擴充方法的寫法
Console.WriteLine(StringExtensions.IsLongTitle("EF Core 入門"));    // 編譯器實際翻成的樣子，也合法

static class StringExtensions
{
    // this string? title：第一個參數加 this，這個方法就能用 "…".IsLongTitle() 的寫法呼叫
    public static bool IsLongTitle(this string? title)
    {
        Console.WriteLine($"  IsLongTitle 被呼叫了，title 是 {(title is null ? "null" : $"「{title}」")}");
        return title is not null && title.Length > 5;
    }
}

// 輸出：
//   IsLongTitle 被呼叫了，title 是 「EF Core 入門」
// True
//   IsLongTitle 被呼叫了，title 是 「EF Core 入門」
// True

兩種呼叫寫法跑的是同一個方法。"EF Core 入門".IsLongTitle() 只是編譯器幫你改寫成 StringExtensions.IsLongTitle("EF Core 入門")，點前面的東西變成第一個參數。所以擴充方法沒有魔法，它就是一個 static 方法加一個語法糖。

寫法的三個條件

條件為什麼
放在 static class 裡擴充方法是工具方法，不需要物件
方法本身是 static同上
第一個參數前面加 this告訴編譯器「點前面的東西填到這裡」。this 後面的型別，就是這個方法能掛在誰身上

你早就在用的擴充方法

第 1 課寫過的這些，全部都是別人加上去的擴充方法：

你寫的簽章的第一個參數所以它掛在
_db.Posts.Where(p => …)、.ToListAsync()this IQueryable<T>任何 IQueryable<T>，DbSet<Post> 有實作它，所以能用（第 1 課 2-4）
builder.Services.AddControllers()、.AddDbContext(…)this IServiceCollectionbuilder.Services，它的型別就是 IServiceCollection

這就是為什麼 builder.Services.AddDbContext(…) 看起來像 IServiceCollection 自己的方法：IServiceCollection 本身只有加減服務的幾個方法，AddControllers、AddDbContext、第 3 課的 AddScoped 都是各個套件用擴充方法掛上去的。這也是為什麼每個套件都要你 using 它的 namespace，不然編譯器找不到那個 static class。

進階範例：對集合加方法（實際執行過）

var titles = new List<string> { "Docker 入門", "EF Core 關聯：一對多", "Hi" };
titles.PrintAll();

static class ListExtensions
{
    public static void PrintAll(this List<string> items)
    {
        foreach (var item in items)
        {
            Console.WriteLine($"  - {item}");
        }
    }
}

// 輸出：
//   - Docker 入門
//   - EF Core 關聯：一對多
//   - Hi

「對集合加方法」正是 LINQ 在做的事：Where、Select、OrderBy 全是掛在 IEnumerable<T> 和 IQueryable<T> 上的擴充方法，差別只在它們多收一個委派當參數（下一節）。

規則和坑

情況會怎樣
沒有 using 到那個 static class 的 namespace編譯器說找不到這個方法。Rider 會提示要加哪個 using
Rider 的自動完成裡擴充方法會標 (extension)，可以分辨哪些是型別本來有的
想加欄位或屬性不行，擴充方法只能加方法
型別本來就有同名方法本來的優先，擴充方法不會被呼叫
點前面的東西是 null照樣進到方法裡，因為它只是第一個參數。一般的實例成員對 null 呼叫會直接炸（實際執行過，見下）
string? nothing = null;
Console.WriteLine(nothing.IsLongTitle());   // 擴充方法：照樣進到方法裡
try
{
    Console.WriteLine(nothing!.Length);      // 一般的實例成員：直接炸
}
catch (NullReferenceException ex)
{
    Console.WriteLine($"NullReferenceException: {ex.Message}");
}

// 輸出：
//   IsLongTitle 被呼叫了，title 是 null
// False
// NullReferenceException: Object reference not set to an instance of an object.

所以擴充方法的第一個參數宣告成 string?，方法裡面要自己處理 null。

3. 委派：Action 和 Func

看 AddDbContext 的簽章時，會看到參數型別是 Action<DbContextOptionsBuilder>。要看懂它，得先知道什麼是委派（delegate）。

委派就是「裝著一個方法的變數」的型別。一般的變數裝的是值（數字、字串），委派裝的是「一段可以執行的程式」。它是一種型別，可以用 delegate 關鍵字自己定義：

// 定義一種委派型別：裝「收一個 string、回傳 bool」的方法
delegate bool TitleTest(string title);

TitleTest test = title => title.Length > 5;   // 把一段程式裝進去
Console.WriteLine(test("Docker 入門"));         // → True
Console.WriteLine(test("Hi"));                  // → False

實務上幾乎不用自己定義，因為 .NET 內建兩種泛型的委派，把「收什麼、回什麼」用角括號填就好：

Action 只做事、不回傳；Func 最後一個型別是回傳值，回傳什麼型別，看 lambda 最後算出來的是什麼
ActionFunc
回傳值沒有（等於 void 方法）有，角括號裡最後一個型別就是回傳型別
寫法Action<參數1, 參數2, …>Func<參數1, 參數2, …, 回傳>
例子Action<string>＝收一個 string、不回傳Func<int, int, int>＝收兩個 int、回傳 int
對應上面的 TitleTestFunc<string, bool>，不用另外定義型別

簡單範例：先用具名方法，再改用 lambda（實際執行過）

// 1. 先用具名方法
void SayHello() => Console.WriteLine("Hello");
int Add(int a, int b) => a + b;

Action hello = SayHello;          // 把「方法」裝進變數（注意：SayHello 後面沒有括號）
Func<int, int, int> add = Add;
hello();                          // 執行變數裡的方法 → Hello
Console.WriteLine(add(1, 2));     // → 3

// 2. 改用 lambda，不用另外取名字
Action<string> greet = name => Console.WriteLine($"Hi, {name}");
Func<int, int, int> multiply = (a, b) => a * b;
Func<string, bool> isLong = title => title.Length > 5;
greet("小明");                     // → Hi, 小明
Console.WriteLine(multiply(3, 4)); // → 12
Console.WriteLine(isLong("EF Core 入門")); // → True

lambda 的讀法：參數 => 要做的事。=> 念成「goes to」，左邊是參數，右邊是內容。只有一個參數時可以省略括號，像 name => …；兩個以上要加括號，像 (a, b) => …。參數的型別不用寫，編譯器從委派的型別推出來：Func<string, bool> 的 lambda，title 就是 string。

進階範例：把方法當參數傳給別人，由別人決定什麼時候執行（實際執行過）

void RunLater(Action<string> action)
{
    Console.WriteLine("RunLater 開始，還沒執行 action");
    action("由 RunLater 傳進來的值");   // 由 RunLater 決定什麼時候執行、傳什麼值
    Console.WriteLine("RunLater 結束");
}

RunLater(text => Console.WriteLine($"action 執行了：{text}"));

// 輸出：
// RunLater 開始，還沒執行 action
// action 執行了：由 RunLater 傳進來的值
// RunLater 結束

這就是 AddDbContext 的模式：

  • 你傳進去的 options => options.UseSqlServer(…) 是一個 Action<DbContextOptionsBuilder>
  • options 是 EF Core 之後會傳進來的，就像上面的 text 是 RunLater 傳進來的
  • 什麼時候執行，由 EF Core 決定，見第 1 課 3-8「串起來」

你其實早就用過 Func 了：_db.Posts.Where(p => p.Title.Contains(keyword)) 裡的 p => …，寫法就是一個「收 Post、回傳 bool」的 lambda，也就是第 2 節說的「擴充方法多收一個委派當參數」。（細節：EF Core 實際收的型別是 Expression<Func<Post, bool>>，它會把這段 lambda 當成「資料」拆開，才能翻成 SQL；後面的課再細講。）

4. 拆解 AddDbContext 那一行

三件事現在都看過了，把它們套回你寫過的那一行。先看 AddDbContext 的簽章，第 2 個參數 optionsAction 的型別就是 Action<DbContextOptionsBuilder>，你那段 options => options.UseSqlServer(…) 就是填進這個參數的「方法」：

AddDbContext 當下只把 lambda 收起來；之後要建 BlogDbContext 時，EF Core 才 new 一個 options、呼叫它

這行其實是三個方法一層包一層。要看懂它在寫什麼，由內往外讀最好懂。這是讀的順序，不是執行的順序：② ③ 寫在 lambda 裡面，程式啟動時只有 ① 執行，② ③ 要等 lambda 被呼叫才跑（見第 1 課 3-5）。

讀法：③ 的回傳值交給 ②；②③ 所在的整段 lambda 當成參數交給 ①（交出去時不執行）

下面是這三個方法在 EF Core 10 / .NET 10 的真正簽章（用反射從套件讀出來的，只列出這一行用到的那個多載）：

③ Microsoft.Extensions.Configuration.ConfigurationExtensions

public static string? GetConnectionString(
    this IConfiguration configuration,
    string name)

② Microsoft.EntityFrameworkCore.SqlServerDbContextOptionsExtensions

public static DbContextOptionsBuilder UseSqlServer(
    this DbContextOptionsBuilder optionsBuilder,
    string? connectionString,
    Action<SqlServerDbContextOptionsBuilder>? sqlServerOptionsAction = null)

① Microsoft.Extensions.DependencyInjection.EntityFrameworkServiceCollectionExtensions

public static IServiceCollection AddDbContext<TContext>(
    this IServiceCollection serviceCollection,
    Action<DbContextOptionsBuilder>? optionsAction = null,
    ServiceLifetime contextLifetime = ServiceLifetime.Scoped,
    ServiceLifetime optionsLifetime = ServiceLifetime.Scoped)
    where TContext : DbContext

在 Rider 裡按 Ctrl + 左鍵跳進 AddDbContext，會比上面多看到兩個東西：

public static IServiceCollection AddDbContext
    <[DynamicallyAccessedMembers(DbContext.DynamicallyAccessedMemberTypes)] TContext>(
        this IServiceCollection serviceCollection,
        Action<DbContextOptionsBuilder>? optionsAction = null,
        ServiceLifetime contextLifetime = ServiceLifetime.Scoped,
        ServiceLifetime optionsLifetime = ServiceLifetime.Scoped)
    where TContext : DbContext
    => AddDbContext<TContext, TContext>(serviceCollection, optionsAction, contextLifetime, optionsLifetime);
  • [DynamicallyAccessedMembers(…)]：掛在 TContext 上的屬性，是給「裁剪（trimming）」和 AOT 編譯用的標記，告訴工具這個型別的建構子會被反射用到、不能砍掉。看簽章時可以略過，它不影響你怎麼呼叫
  • => AddDbContext<TContext, TContext>(…)：方法本體。這個多載自己不做事，只是把四個參數原封不動轉交給另一個有兩個泛型參數的多載（第一個是「要注入的型別」、第二個是「實際建的型別」，兩個填一樣就是我們的情況）。=> 在這裡是「方法本體只有一句 return」的簡寫，不是 lambda

簽章怎麼讀：逐一對照

看到什麼代表什麼在哪一節對應到我們那一行
static + 第一個參數有 this擴充方法第 2 節this IServiceCollection → 所以寫成 builder.Services.AddDbContext(…)
方法名稱後面的 <TContext>泛型參數，呼叫時填型別第 1 節AddDbContext<BlogDbContext>
where TContext : DbContext泛型限制第 1 節BlogDbContext : DbContext，所以可以；填 string 會編譯錯誤
Action<DbContextOptionsBuilder>委派：「一個收 DbContextOptionsBuilder、沒有回傳值的方法」，用 lambda 寫第 3 節options => options.UseSqlServer(…)，這裡的 options 型別就是 DbContextOptionsBuilder
= null、= ServiceLifetime.Scoped選擇性參數，沒傳就用預設值第 1 節我們只傳了 lambda，所以生命週期都是 Scoped（一個請求一個，第 3 課講）
string?可能是 null第 1 節連線字串名稱打錯時，GetConnectionString 回傳 null，啟動後會出現第 1 課常見坑裡的 Value cannot be null
回傳型別和 this 參數型別相同可以串接呼叫（Fluent API）UseSqlServer 回傳 DbContextOptionsBuilder，後面還能再接 .LogTo(…) 這類設定

5. 練習：單檔程式

不用開專案。.NET 10 可以直接執行一個 .cs 檔（file-based apps）：隨便找個資料夾建 signature-lab.cs，在那個資料夾執行 dotnet run signature-lab.cs。

題 1：擴充方法、Func、Action 各寫一個

需求，三小步都在同一個檔案：

  1. 一個 List<string> 放三個標題："Docker 入門"、"EF Core 關聯：一對多"、"Hi"。寫擴充方法 IsLongTitle(this string title)，長度大於 5 回 true；對三個標題各呼叫一次並印出結果
  2. 寫一個方法 int CountIf(List<string> items, Func<string, bool> test)，數有幾個標題通過 test。呼叫兩次：一次傳 lambda（標題含 "Docker"），一次直接傳 StringExtensions.IsLongTitle（方法名稱，不加括號）
  3. 寫一個方法 void ForEachTitle(List<string> items, Action<string> action)，對每個標題做一次 action。用 lambda 印出「標題：xxx」

💡 提示：單檔程式裡，方法可以直接寫在最上層的程式碼後面；static class 也可以放在檔案最後面。第 2 步傳方法名稱的寫法，就是第 3 節 Action hello = SayHello; 那件事。

✅ 驗收：輸出依序是三行 True / True / False、兩個數字 1 和 2、三行「標題：…」

參考答案（寫完再打開）

signature-lab.cs

var titles = new List<string> { "Docker 入門", "EF Core 關聯：一對多", "Hi" };

Console.WriteLine("== (1) 擴充方法");
foreach (var title in titles)
{
    Console.WriteLine($"{title} → {title.IsLongTitle()}");
}

Console.WriteLine("== (2) 收 Func 的方法");
Console.WriteLine(CountIf(titles, title => title.Contains("Docker")));   // 傳 lambda
Console.WriteLine(CountIf(titles, StringExtensions.IsLongTitle));        // 傳方法名稱，不加括號

Console.WriteLine("== (3) 收 Action 的方法");
ForEachTitle(titles, title => Console.WriteLine($"標題：{title}"));

// 收一個「收 string、回傳 bool」的方法，數有幾個標題通過
int CountIf(List<string> items, Func<string, bool> test)
{
    var count = 0;
    foreach (var item in items)
    {
        if (test(item))
        {
            count++;
        }
    }
    return count;
}

// 收一個「收 string、不回傳」的方法，對每個標題做一次
void ForEachTitle(List<string> items, Action<string> action)
{
    foreach (var item in items)
    {
        action(item);
    }
}

static class StringExtensions
{
    public static bool IsLongTitle(this string title) => title.Length > 5;
}

三個觀察：

  • CountIf(titles, StringExtensions.IsLongTitle)：擴充方法也是普通的 static 方法，所以可以當方法名稱傳進去。它「收一個 string、回傳 bool」，剛好符合 Func<string, bool>
  • 如果把 IsLongTitle 改成 (this string title, int min = 5) 加一個選擇性參數，lambda 照樣能用，但傳方法名稱那行會編譯錯誤：error CS0123: 'IsLongTitle' 沒有任何多載符合委派 'Func<string, bool>'。方法名稱轉成委派時，選擇性參數不算數，參數要一模一樣
  • CountIf 和 ForEachTitle 就是縮小版的 LINQ Count(…) 和 ForEach(…)：方法本身只管「走訪」，要做什麼由呼叫的人用委派決定
