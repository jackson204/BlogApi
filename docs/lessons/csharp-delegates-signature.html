1. 方法簽章是什麼

簽章（signature）是一個方法「怎麼呼叫它、它回什麼」：名稱、參數、回傳型別。大括號裡的本體不算，呼叫別人的方法時也看不到本體，看得到的只有簽章。這一節從最短的簽章開始，一步加一個記號，每一步都看簽章多了什麼、呼叫的地方跟著怎麼變。

程式裡的顏色：藍色是這一步多出來的記號，綠色是呼叫的地方跟著變的寫法，紅色是會出錯的寫法。每一步的輸出和錯誤訊息都實際執行過。

第 1 步：最短的簽章，用物件呼叫

var tools = new StringTools();
Console.WriteLine(tools.Repeat("ab"));

class StringTools
{
    public string Repeat(string text)
    {
        return text + text;
    }
}

// 輸出：
// abab

藍色那一行就是簽章，有四段：

  • public：誰都能呼叫
  • string：回傳型別，呼叫完會拿到一個字串
  • Repeat：名稱
  • (string text)：一個參數，型別 string、名稱 text

呼叫前要先 new 一個 StringTools 物件，再用「物件.方法」呼叫。

第 2 步：方法加上 static，不用先 new

StringTools 的物件裡沒有任何資料，Repeat 只靠參數就算得出結果。第 1 步的 new 只是為了能呼叫方法，沒有別的用處。方法加上 static，就可以用「類別名稱.方法」直接呼叫：

Console.WriteLine(StringTools.Repeat("ab"));     // 點前面是類別名稱，沒有 new

class StringTools
{
    public static string Repeat(string text)
    {
        return text + text;
    }
}

// 輸出：
// abab

有沒有 static，決定點前面要寫什麼。寫反了編譯不會過：

// 方法有 static，卻用物件呼叫
var tools = new StringTools();
tools.Repeat("ab");
error CS0176: 成員 'StringTools.Repeat(string)' 無法以執行個體參考進行存取; 請改用類型名稱

// 方法沒有 static，卻用類別名稱呼叫
StringTools.Repeat("ab");
error CS0120: 需要有物件參考，才可使用非靜態欄位、方法或屬性 'StringTools.Repeat(string)'

錯誤訊息裡的「執行個體」就是物件，「類型名稱」就是類別名稱。

第 3 步：類別也加上 static，不能被 new

第 2 步之後，new StringTools() 還是寫得出來，只是 new 出來的物件什麼都不能做。類別裡只有 static 方法時，類別本身也標 static，明確表示它不是拿來 new 的：

static class StringTools
{
    public static string Repeat(string text)
    {
        return text + text;
    }
}

var tools = new StringTools();
error CS0712: 無法建立靜態類別 'StringTools' 的執行個體

static class 裡面的方法也都必須是 static，漏寫一個會得到 error CS0708: 不可在靜態類別中宣告執行個體成員。

什麼時候用 static：方法只靠參數就能算出結果，不需要記住任何東西，例如字串處理、數學計算這類工具方法。什麼時候不用：方法要用到物件自己的資料時，例如每個物件有自己的名稱、自己的清單。static 和物件的關係，在類別與物件頁第 4 節。

第 4 步：多一個參數

想指定重複幾次，就多一個參數。參數之間用逗號隔開，呼叫時照順序給：

Console.WriteLine(StringTools.Repeat("ab", 3));

static class StringTools
{
    public static string Repeat(string text, int count)
    {
        return string.Concat(Enumerable.Repeat(text, count));
    }
}

// 輸出：
// ababab

現在 count 一定要給。只給一個參數會編譯錯誤：

StringTools.Repeat("ab");
error CS7036: 未提供任何可對應到 'StringTools.Repeat(string, int)' 之必要參數 'count' 的引數

第 5 步：參數給預設值，可以不傳

大部分時候都是重複兩次，每次都要寫 , 2 很囉嗦。在參數後面寫 = 2，沒給的時候就用 2。這種參數叫選擇性參數：

Console.WriteLine(StringTools.Repeat("ab"));             // count 沒給，用預設值 2 → abab
Console.WriteLine(StringTools.Repeat("ab", 3));          // 照順序給 → ababab
Console.WriteLine(StringTools.Repeat("ab", count: 1));   // 用名稱指定 → ab

static class StringTools
{
    public static string Repeat(string text, int count = 2)
    {
        return string.Concat(Enumerable.Repeat(text, count));
    }
}

到這裡，一個簽章常見的五個部分都出現過了：

呼叫時用得到的只有 ②③④⑤；① 決定誰能呼叫、要不要先 new 物件

第 6 步：回傳型別寫 void，不回傳

接下來三步看的都是回傳型別那一段。方法只做事、不給結果時，回傳型別寫 void：

Printer.Print("hi");                // 單獨一行呼叫

static class Printer
{
    public static void Print(string text)
    {
        Console.WriteLine(text);
    }
}

var x = Printer.Print("hi");
error CS0815: 無法將 void 指派給隱含類型變數

呼叫完沒有值可以接。

第 7 步：型別後面有 ?，可能是 null

方法可能找不到東西時，回傳型別後面加 ?，告訴呼叫的人「可能拿到 null」：

string? name = FindName(5);
if (name != null)                  // 先檢查再用
{
    Console.WriteLine(name.Length);
}

static string? FindName(int id)
{
    return id == 1 ? "first" : null;
}

Console.WriteLine(name.Length);     // 不檢查就用
warning CS8602: 可能 null 參考的取值 (dereference)。
執行時 name 是 null，丟出 NullReferenceException

? 寫在參數的型別後面，意思是這個方法允許你傳 null，例如 Action<…>? configure = null。

第 8 步：回傳型別是 Task<string>，要 await

要等一段時間才有結果的方法（讀檔案、查資料庫、呼叫別的網站），回傳型別會包一層 Task<…>：

var reader = new TitleReader();
string title = await reader.ReadTitleAsync(5);    // await 之後拿到的是 string
Console.WriteLine(title);

class TitleReader
{
    public async Task<string> ReadTitleAsync(int id)
    {
        await Task.Delay(100);
        return $"第 {id} 篇的標題";
    }
}

// 輸出：
// 第 5 篇的標題

等的時候發生什麼事，在 Task 與 async / await 頁。把這個簽章拆開來看：

public async Task<string> ReadTitleAsync(int id)
\____/ \___/ \__________/ \____________/ \____/
 [1]    [*]      [2]           [3]        [4]

[1] 到 [4] 就是第 5 步那張圖的 ① 到 ④，[*] 是多出來的一個字：

  • [1] public：誰都能呼叫。這裡沒有 static，所以要先有一個物件才能呼叫
  • [*] async：修飾詞，不是簽章的一部分。它告訴編譯器本體裡會有 await；呼叫的人看不到它，只看得到回傳型別是 Task<…>
  • [2] Task<string>：回傳型別。不是直接給你 string，是「一件還在做的事，做完會給你一個 string」。呼叫的人要 await 才拿得到 string
  • [3] ReadTitleAsync：名稱。非同步方法習慣用 Async 結尾
  • [4] int id：一個參數，型別 int、名稱 id

第 9 步：名稱後面的 <T>，呼叫時填型別

List<string> 就是這種寫法：寫 List 的人不知道你要裝什麼，所以留一個洞 <T>，用的人呼叫時才填型別。方法也可以有這種洞，而且可以用 where 限制洞裡能填什麼（實際執行過）：

Console.WriteLine(Describe<Staff>(new Staff("小華", "編輯部")));   // 呼叫：填 Staff
Console.WriteLine(Describe(new Author("小明")));                   // 編譯器從參數推出 T 是 Author，可以不寫

// 定義：留一個洞叫 T，限制 T 必須是 Author 或它的子類別
static string Describe<T>(T item) where T : Author
{
    return $"{typeof(T).Name}：{item.Name}";    // 有了限制，才能放心用 Author 的 Name
}

class Author
{
    public string Name { get; }

    public Author(string name)
    {
        Name = name;
    }
}

class Staff : Author
{
    public string Department { get; }

    public Staff(string name, string department) : base(name)
    {
        Department = department;
    }
}

// 輸出：
// Staff：小華
// Author：小明

where 那行叫泛型限制。Staff : Author 所以可以填；填 string 會編譯錯誤：

Console.WriteLine(Describe("x"));          // 填 string：不是 Author

// 編譯錯誤：
// error CS0311: 類型 'string' 不可用做為泛型類型或方法 'Describe<T>(T)' 中的類型參數 'T'。沒有從 'string' 到 'Author' 的隱含參考轉換。

第 4 節的 AddDbContext<TContext>(…) where TContext : DbContext 讀法完全一樣：填進去的型別必須是 DbContext 或它的子類別。

九步出現過的記號

之後看到陌生的簽章，先找裡面有哪些記號：

  • static：不用先 new 物件，用類別名稱呼叫。第 2 步、第 3 步
  • 參數後面的 = 2、= null：選擇性參數，可以不給。第 5 步
  • void 在回傳型別的位置：不回傳。第 6 步
  • 型別後面的 ?：可能是 null。第 7 步
  • Task<X> 在回傳型別的位置：要 await 才拿得到 X。第 8 步
  • 名稱後面的 <T>：泛型參數，呼叫時填型別。第 9 步
  • where T : 某型別：泛型限制，填進去的型別必須是那個型別或它的子類別。第 9 步
  • 第一個參數前面有 this：擴充方法，下一節

2. 擴充方法：第一個參數前面的 this

想讓字串多一個 IsLongTitle() 方法，判斷標題夠不夠長，寫成 "EF Core 入門".IsLongTitle()。但 string 是 .NET 的類別，改不了它的程式碼。擴充方法（extension method）可以做到，而且它只是一般的 static 方法多寫一個字。下面從一般的方法開始，一步加一樣東西。

第 1 步：先寫成一般的 static 方法

改不了 string，就把方法寫在自己的類別裡，字串當參數傳進去（實際執行過）：

Console.WriteLine(StringExtensions.IsLongTitle("EF Core 入門"));
Console.WriteLine(StringExtensions.IsLongTitle("Hi"));

static class StringExtensions
{
    public static bool IsLongTitle(string title)
    {
        return title.Length > 5;
    }
}

// 輸出：
// True
// False

功能有了。這是第 1 節講過的 static 方法，用「類別名稱.方法」呼叫。

第 2 步：這種寫法哪裡不方便

呼叫的人要先知道方法放在 StringExtensions 這個類別裡。連續呼叫兩個方法時，還得從裡面往外讀。假設類別裡另外有 TrimTitle（去掉前後空白）和 Shorten（太長就截短）：

✗ 一般的 static 方法：從裡面往外讀

StringExtensions.Shorten(
    StringExtensions.TrimTitle(title))

先做的 TrimTitle 寫在裡面，後做的 Shorten 寫在外面，順序和閱讀方向相反。

✓ 想要的寫法：從左往右讀

title.TrimTitle().Shorten()

先做的寫在前面，而且不用寫類別名稱。

但第 1 步的程式直接這樣呼叫，編譯不會過（實際編譯過）：

Console.WriteLine("EF Core 入門".IsLongTitle());

error CS1061: 'string' 未包含 'IsLongTitle' 的定義，也找不到可接受類型 'string' 第一個引數的可存取擴充方法 'IsLongTitle'

編譯器在 string 裡找不到 IsLongTitle。它不知道 StringExtensions 裡那個方法是要給字串用的。

第 3 步：第一個參數前面加一個字 this

只多寫 this 這一個字，其他都不動（實際執行過）：

Console.WriteLine("EF Core 入門".IsLongTitle());                    // 新的寫法：現在可以編譯了
Console.WriteLine(StringExtensions.IsLongTitle("EF Core 入門"));   // 第 1 步的寫法：照樣可以用

static class StringExtensions
{
    public static bool IsLongTitle(this string title)
    {
        return title.Length > 5;
    }
}

// 輸出：
// True
// True

this 告訴編譯器：這個方法可以用「字串.方法」的寫法呼叫，點前面的東西填進這個參數。編譯器看到新的寫法，會把它改寫成第 1 步的寫法：

"EF Core 入門".IsLongTitle()     →     StringExtensions.IsLongTitle("EF Core 入門")

兩種寫法跑的是同一個方法。第 2 步想要的連續呼叫也可以寫了：三個方法的第一個參數都加上 this 之後，title.TrimTitle().Shorten() 和 StringExtensions.Shorten(StringExtensions.TrimTitle(title)) 的結果一樣（實際執行過）。

這裡的 this 是參數修飾詞。它和類別裡代表「這個物件自己」的 this（例如 this.name = name）不是同一件事，那個在類別與物件頁第 2 節。

第 4 步：整理成一條格式

擴充方法都長這樣，有顏色的三個地方是固定要寫的：

static class 類別名稱
{
    public static 回傳型別 方法名稱(this 要掛上去的型別 參數名稱, 其他參數)
    {
        …
    }
}
  • static 類別是 static
  • static 方法是 static
  • this 寫在第一個參數前面
  • 要掛上去的型別 this 後面的型別，決定這個方法可以掛在誰身上。寫 this string 就是每個字串都能呼叫

呼叫的寫法也是固定的對應，點前面的東西變成第一個參數，括號裡的往後排：

x.方法(a, b)     等於     類別名稱.方法(x, a, b)

三個固定要寫的地方，各拿掉一次會怎樣（錯誤訊息都是實際編譯出來的）：

類別拿掉 static

class StringExtensions
{
    public static bool IsLongTitle(this string title) { … }
}

error CS1106: 擴充方法必須在非泛型靜態類別中定義

方法拿掉 static

static class StringExtensions
{
    public bool IsLongTitle(this string title) { … }
}

error CS1105: 擴充方法必須為靜態

this 寫在第二個參數前面

static class StringExtensions
{
    public static bool IsLongerThan(string title, this int length) { … }
}

error CS1100: 方法 'IsLongerThan' 具有參數修飾元 'this'，但其不在第一個參數上

.NET 裡到處都是擴充方法

下面這些常用的方法，全都不是那個型別自己的，是別的套件用擴充方法掛上去的：

方法簽章的第一個參數所以能掛在
LINQ 的 Where、Select、OrderBythis IEnumerable<T>（另一套是 this IQueryable<T>）任何集合：List<T>、陣列、EF Core 的 DbSet<T>
AddControllers()、AddDbContext(…)this IServiceCollectionASP.NET Core 的 builder.Services，它的型別就是 IServiceCollection
UseSqlServer(…)this DbContextOptionsBuilder第 4 節 lambda 收到的 options
GetConnectionString("…")this IConfigurationbuilder.Configuration

這就是為什麼 builder.Services.AddDbContext(…) 看起來像 IServiceCollection 自己的方法：IServiceCollection 本身只有加減服務的幾個方法，AddControllers、AddDbContext 都是各個套件用擴充方法掛上去的。這也是為什麼每個套件都要你 using 它的 namespace，不然編譯器找不到那個 static class。

進階範例：對集合加方法（實際執行過）

var titles = new List<string> { "Docker 入門", "EF Core 關聯：一對多", "Hi" };
titles.PrintAll();

static class ListExtensions
{
    public static void PrintAll(this List<string> items)
    {
        foreach (var item in items)
        {
            Console.WriteLine($"  - {item}");
        }
    }
}

// 輸出：
//   - Docker 入門
//   - EF Core 關聯：一對多
//   - Hi

「對集合加方法」正是 LINQ 在做的事：Where、Select、OrderBy 全是掛在 IEnumerable<T> 和 IQueryable<T> 上的擴充方法，差別只在它們多收一個委派當參數（下一節）。

規則和坑

情況會怎樣
沒有 using 到那個 static class 的 namespace編譯器說找不到這個方法。Rider 會提示要加哪個 using
Rider 的自動完成裡擴充方法會標 (extension)，可以分辨哪些是型別本來有的
想加欄位或屬性不行，擴充方法只能加方法
型別本來就有同名方法本來的優先，擴充方法不會被呼叫
點前面的東西是 null照樣進到方法裡，因為它只是第一個參數。一般的實例成員對 null 呼叫會直接炸（實際執行過，見下）

最後一列用程式看。先把 IsLongTitle 的參數改成 string?（可以是 null），方法裡加上 null 的檢查，再多印一行訊息，好看出方法有沒有被呼叫（實際執行過）：

static class StringExtensions
{
    public static bool IsLongTitle(this string? title)
    {
        Console.WriteLine($"  IsLongTitle 被呼叫了，title 是 {(title is null ? "null" : $"「{title}」")}");
        return title is not null && title.Length > 5;
    }
}
string? nothing = null;
Console.WriteLine(nothing.IsLongTitle());   // 擴充方法：照樣進到方法裡
try
{
    Console.WriteLine(nothing!.Length);      // 一般的實例成員：直接炸
}
catch (NullReferenceException ex)
{
    Console.WriteLine($"NullReferenceException: {ex.Message}");
}

// 輸出：
//   IsLongTitle 被呼叫了，title 是 null
// False
// NullReferenceException: Object reference not set to an instance of an object.

所以點前面的東西可能是 null 時，擴充方法的第一個參數要宣告成 string?，方法裡面自己處理 null。

3. 委派：Action 和 Func

第 4 節要拆的 AddDbContext，簽章裡有一個參數的型別是 Action<DbContextOptionsBuilder>。要看懂它，得先知道什麼是委派（delegate）。

委派就是「裝著一個方法的變數」的型別。一般的變數裝的是值（數字、字串），委派裝的是「一段可以執行的程式」。它是一種型別，可以用 delegate 關鍵字自己定義：

// 定義一種委派型別：裝「收一個 string、回傳 bool」的方法
delegate bool TitleTest(string title);

TitleTest test = title => title.Length > 5;   // 把一段程式裝進去
Console.WriteLine(test("Docker 入門"));         // → True
Console.WriteLine(test("Hi"));                  // → False

實務上幾乎不用自己定義，因為 .NET 內建兩種泛型的委派，把「收什麼、回什麼」用角括號填就好：

Action 只做事、不回傳；Func 最後一個型別是回傳值，回傳什麼型別，看 lambda 最後算出來的是什麼
ActionFunc
回傳值沒有（等於 void 方法）有，角括號裡最後一個型別就是回傳型別
寫法Action<參數1, 參數2, …>Func<參數1, 參數2, …, 回傳>
例子Action<string>＝收一個 string、不回傳Func<int, int, int>＝收兩個 int、回傳 int
對應上面的 TitleTestFunc<string, bool>，不用另外定義型別

簡單範例：先用具名方法，再改用 lambda（實際執行過）

// 1. 先用具名方法
void SayHello() => Console.WriteLine("Hello");
int Add(int a, int b) => a + b;

Action hello = SayHello;          // 把「方法」裝進變數（注意：SayHello 後面沒有括號）
Func<int, int, int> add = Add;
hello();                          // 執行變數裡的方法 → Hello
Console.WriteLine(add(1, 2));     // → 3

// 2. 改用 lambda，不用另外取名字
Action<string> greet = name => Console.WriteLine($"Hi, {name}");
Func<int, int, int> multiply = (a, b) => a * b;
Func<string, bool> isLong = title => title.Length > 5;
greet("小明");                     // → Hi, 小明
Console.WriteLine(multiply(3, 4)); // → 12
Console.WriteLine(isLong("EF Core 入門")); // → True

lambda 的讀法：參數 => 要做的事。=> 念成「goes to」，左邊是參數，右邊是內容。只有一個參數時可以省略括號，像 name => …；兩個以上要加括號，像 (a, b) => …。參數的型別不用寫，編譯器從委派的型別推出來：Func<string, bool> 的 lambda，title 就是 string。

進階範例：把方法當參數傳給別人，由別人決定什麼時候執行（實際執行過）

void RunLater(Action<string> action)
{
    Console.WriteLine("RunLater 開始，還沒執行 action");
    action("由 RunLater 傳進來的值");   // 由 RunLater 決定什麼時候執行、傳什麼值
    Console.WriteLine("RunLater 結束");
}

RunLater(text => Console.WriteLine($"action 執行了：{text}"));

// 輸出：
// RunLater 開始，還沒執行 action
// action 執行了：由 RunLater 傳進來的值
// RunLater 結束

第 4 節的 AddDbContext 就是這個模式：

  • 傳進去的 options => options.UseSqlServer(…) 是一個 Action<DbContextOptionsBuilder>
  • options 是 EF Core 之後會傳進來的，就像上面的 text 是 RunLater 傳進來的
  • 什麼時候執行，由 EF Core 決定，不是寫那一行的時候

LINQ 也是同一件事：titles.Where(t => t.Length > 5) 裡的 t => … 就是一個「收一個元素、回傳 bool」的 lambda，也就是第 2 節說的「擴充方法多收一個委派當參數」。（細節：EF Core 的 IQueryable<T> 版本實際收的型別是 Expression<Func<T, bool>>，它會把這段 lambda 當成「資料」拆開，才能翻成 SQL；這頁不展開。）

4. 拆解一整行：以 EF Core 的 AddDbContext 為例

三件事現在都看過了，把它們套到一行真實的程式碼上。EF Core 註冊 DbContext 的那一行通常長這樣（例子裡的 DbContext 叫 BlogDbContext，連線字串的名稱叫 BlogDb）：

builder.Services.AddDbContext<BlogDbContext>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("BlogDb")));

先看 AddDbContext 的簽章，第 2 個參數 optionsAction 的型別就是 Action<DbContextOptionsBuilder>，那段 options => options.UseSqlServer(…) 就是填進這個參數的「方法」：

AddDbContext 當下只把 lambda 收起來；之後要建 BlogDbContext 時，EF Core 才 new 一個 options、呼叫它

這行其實是三個方法一層包一層。要看懂它在寫什麼，由內往外讀最好懂。這是讀的順序，不是執行的順序：② ③ 寫在 lambda 裡面，程式啟動時只有 ① 執行，② ③ 要等 lambda 被呼叫才跑。

讀法：③ 的回傳值交給 ②；②③ 所在的整段 lambda 當成參數交給 ①（交出去時不執行）

下面是這三個方法在 EF Core 10 / .NET 10 的真正簽章（用反射從套件讀出來的，只列出這一行用到的那個多載）：

③ Microsoft.Extensions.Configuration.ConfigurationExtensions

public static string? GetConnectionString(
    this IConfiguration configuration,
    string name)

② Microsoft.EntityFrameworkCore.SqlServerDbContextOptionsExtensions

public static DbContextOptionsBuilder UseSqlServer(
    this DbContextOptionsBuilder optionsBuilder,
    string? connectionString,
    Action<SqlServerDbContextOptionsBuilder>? sqlServerOptionsAction = null)

① Microsoft.Extensions.DependencyInjection.EntityFrameworkServiceCollectionExtensions

public static IServiceCollection AddDbContext<TContext>(
    this IServiceCollection serviceCollection,
    Action<DbContextOptionsBuilder>? optionsAction = null,
    ServiceLifetime contextLifetime = ServiceLifetime.Scoped,
    ServiceLifetime optionsLifetime = ServiceLifetime.Scoped)
    where TContext : DbContext

在 Rider 裡按 Ctrl + 左鍵跳進 AddDbContext，會比上面多看到兩個東西：

public static IServiceCollection AddDbContext
    <[DynamicallyAccessedMembers(DbContext.DynamicallyAccessedMemberTypes)] TContext>(
        this IServiceCollection serviceCollection,
        Action<DbContextOptionsBuilder>? optionsAction = null,
        ServiceLifetime contextLifetime = ServiceLifetime.Scoped,
        ServiceLifetime optionsLifetime = ServiceLifetime.Scoped)
    where TContext : DbContext

  • [DynamicallyAccessedMembers(…)]：掛在 TContext 上的屬性，是給「裁剪（trimming）」和 AOT 編譯用的標記，告訴工具這個型別的建構子會被反射用到、不能砍掉。看簽章時可以略過，它不影響你怎麼呼叫
  • => AddDbContext<TContext, TContext>(…)：方法本體。這個多載自己不做事，只是把四個參數原封不動轉交給另一個有兩個泛型參數的多載（第一個是「要注入的型別」、第二個是「實際建的型別」，兩個填一樣就是我們的情況）。=> 在這裡是「方法本體只有一句 return」的簡寫，不是 lambda

5. 練習：單檔程式

不用開專案。.NET 10 可以直接執行一個 .cs 檔（file-based apps）：隨便找個資料夾建 signature-lab.cs，在那個資料夾執行 dotnet run signature-lab.cs。

題 1：擴充方法、Func、Action 各寫一個

需求，三小步都在同一個檔案：

  1. 一個 List<string> 放三個標題："Docker 入門"、"EF Core 關聯：一對多"、"Hi"。寫擴充方法 IsLongTitle(this string title)，長度大於 5 回 true；對三個標題各呼叫一次並印出結果
  2. 寫一個方法 int CountIf(List<string> items, Func<string, bool> test)，數有幾個標題通過 test。呼叫兩次：一次傳 lambda（標題含 "Docker"），一次直接傳 StringExtensions.IsLongTitle（方法名稱，不加括號）
  3. 寫一個方法 void ForEachTitle(List<string> items, Action<string> action)，對每個標題做一次 action。用 lambda 印出「標題：xxx」

💡 提示：單檔程式裡，方法可以直接寫在最上層的程式碼後面；static class 也可以放在檔案最後面。第 2 步傳方法名稱的寫法，就是第 3 節 Action hello = SayHello; 那件事。

✅ 驗收：輸出依序是三行 True / True / False、兩個數字 1 和 2、三行「標題：…」

參考答案（寫完再打開）

signature-lab.cs

var titles = new List<string> { "Docker 入門", "EF Core 關聯：一對多", "Hi" };

Console.WriteLine("== (1) 擴充方法");
foreach (var title in titles)
{
    Console.WriteLine($"{title} → {title.IsLongTitle()}");
}

Console.WriteLine("== (2) 收 Func 的方法");
Console.WriteLine(CountIf(titles, title => title.Contains("Docker")));   // 傳 lambda
Console.WriteLine(CountIf(titles, StringExtensions.IsLongTitle));        // 傳方法名稱，不加括號

Console.WriteLine("== (3) 收 Action 的方法");
ForEachTitle(titles, title => Console.WriteLine($"標題：{title}"));

// 收一個「收 string、回傳 bool」的方法，數有幾個標題通過
int CountIf(List<string> items, Func<string, bool> test)
{
    var count = 0;
    foreach (var item in items)
    {
        if (test(item))
        {
            count++;
        }
    }
    return count;
}

// 收一個「收 string、不回傳」的方法，對每個標題做一次
void ForEachTitle(List<string> items, Action<string> action)
{
    foreach (var item in items)
    {
        action(item);
    }
}

static class StringExtensions
{
    public static bool IsLongTitle(this string title) => title.Length > 5;
}

三個觀察：

  • CountIf(titles, StringExtensions.IsLongTitle)：擴充方法也是普通的 static 方法，所以可以當方法名稱傳進去。它「收一個 string、回傳 bool」，剛好符合 Func<string, bool>
  • 如果把 IsLongTitle 改成 (this string title, int min = 5) 加一個選擇性參數，lambda 照樣能用，但傳方法名稱那行會編譯錯誤：error CS0123: 'IsLongTitle' 沒有任何多載符合委派 'Func<string, bool>'。方法名稱轉成委派時，選擇性參數不算數，參數要一模一樣
  • CountIf 和 ForEachTitle 就是縮小版的 LINQ Count(…) 和 ForEach(…)：方法本身只管「走訪」，要做什麼由呼叫的人用委派決定
