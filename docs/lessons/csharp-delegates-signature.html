1. 先認識 Action 和 Func

看 AddDbContext 的簽章時，會看到參數型別是 Action<DbContextOptionsBuilder>。要看懂它，得先知道什麼是委派（delegate）。

委派就是「裝著一個方法的變數」。一般的變數裝的是值（數字、字串），委派裝的是「一段可以執行的程式」。.NET 內建兩種最常用的委派：

Action 只做事、不回傳；Func 最後一個型別是回傳值
ActionFunc
回傳值沒有（等於 void 方法）有，角括號裡最後一個型別就是回傳型別
寫法Action<參數1, 參數2, …>Func<參數1, 參數2, …, 回傳>
例子Action<string>＝收一個 string、不回傳Func<int, int, int>＝收兩個 int、回傳 int

簡單範例：先用具名方法，再改用 lambda（實際執行過）

// 1. 先用具名方法
void SayHello() => Console.WriteLine("Hello");
int Add(int a, int b) => a + b;

Action hello = SayHello;          // 把「方法」裝進變數（注意：SayHello 後面沒有括號）
Func<int, int, int> add = Add;
hello();                          // 執行變數裡的方法 → Hello
Console.WriteLine(add(1, 2));     // → 3

// 2. 改用 lambda，不用另外取名字
Action<string> greet = name => Console.WriteLine($"Hi, {name}");
Func<int, int, int> multiply = (a, b) => a * b;
Func<string, bool> isLong = title => title.Length > 5;
greet("小明");                     // → Hi, 小明
Console.WriteLine(multiply(3, 4)); // → 12
Console.WriteLine(isLong("EF Core 入門")); // → True

lambda 的讀法：參數 => 要做的事。=> 念成「goes to」，左邊是參數，右邊是內容。只有一個參數時可以省略括號，像 name => …；兩個以上要加括號，像 (a, b) => …。

進階範例：把方法當參數傳給別人，由別人決定什麼時候執行（實際執行過）

void RunLater(Action<string> action)
{
    Console.WriteLine("RunLater 開始，還沒執行 action");
    action("由 RunLater 傳進來的值");   // 由 RunLater 決定什麼時候執行、傳什麼值
}

RunLater(text => Console.WriteLine($"action 執行了：{text}"));

// 輸出：
// RunLater 開始，還沒執行 action
// action 執行了：由 RunLater 傳進來的值

這就是 AddDbContext 的模式：

  • 你傳進去的 options => options.UseSqlServer(…) 是一個 Action<DbContextOptionsBuilder>
  • options 是 EF Core 之後會傳進來的，就像上面的 text 是 RunLater 傳進來的
  • 什麼時候執行，由 EF Core 決定，見第 1 課 3-8「串起來」

你其實早就用過 Func 了：_db.Posts.Where(p => p.Title.Contains(keyword)) 裡的 p => …，寫法就是一個「收 Post、回傳 bool」的 lambda。（細節：EF Core 實際收的型別是 Expression<Func<Post, bool>>，它會把這段 lambda 當成「資料」拆開，才能翻成 SQL；後面的課再細講。）

2. 學會看方法簽章：拆解 AddDbContext 那一行

這行其實是三個方法一層包一層。括號最裡面的先執行，所以要由內往外讀：

③ 的回傳值餵給 ②，② 所在的整段 lambda 再餵給 ①

下面是這三個方法在 EF Core 10 / .NET 10 的真正簽章（用反射從套件讀出來的，只列出這一行用到的那個多載）：

③ Microsoft.Extensions.Configuration.ConfigurationExtensions

public static string? GetConnectionString(
    this IConfiguration configuration,
    string name)

② Microsoft.EntityFrameworkCore.SqlServerDbContextOptionsExtensions

public static DbContextOptionsBuilder UseSqlServer(
    this DbContextOptionsBuilder optionsBuilder,
    string? connectionString,
    Action<SqlServerDbContextOptionsBuilder>? sqlServerOptionsAction = null)

① Microsoft.Extensions.DependencyInjection.EntityFrameworkServiceCollectionExtensions

public static IServiceCollection AddDbContext<TContext>(
    this IServiceCollection serviceCollection,
    Action<DbContextOptionsBuilder>? optionsAction = null,
    ServiceLifetime contextLifetime = ServiceLifetime.Scoped,
    ServiceLifetime optionsLifetime = ServiceLifetime.Scoped)
    where TContext : DbContext

簽章怎麼讀：逐一對照

看到什麼代表什麼對應到我們那一行
static + 第一個參數有 this擴充方法（extension method）。可以像「那個型別本來就有的方法」一樣，用 . 呼叫this IServiceCollection → 所以寫成 builder.Services.AddDbContext(…)，builder.Services 的型別就是 IServiceCollection
方法名稱後面的 <TContext>泛型參數，呼叫時填入型別AddDbContext<BlogDbContext>
where TContext : DbContext泛型限制：填進去的型別必須繼承 DbContextBlogDbContext : DbContext，所以可以；填 string 會編譯錯誤
Action<DbContextOptionsBuilder>委派：「一個收 DbContextOptionsBuilder、沒有回傳值的方法」。可以用 lambda 寫options => options.UseSqlServer(…)，這裡的 options 型別就是 DbContextOptionsBuilder
= null、= ServiceLifetime.Scoped選擇性參數：沒傳就用預設值我們只傳了 lambda，所以生命週期都是 Scoped（一個請求一個，第 3 課講）
string?可能是 null連線字串名稱打錯時，GetConnectionString 回傳 null，啟動後會出現第 1 課常見坑裡的 Value cannot be null
回傳型別和 this 參數型別相同可以串接呼叫（Fluent API）UseSqlServer 回傳 DbContextOptionsBuilder，後面還能再接 .LogTo(…) 這類設定

🔍 在 Rider 裡自己查簽章

  • 滑鼠停在方法名稱上：跳出說明視窗，顯示簽章和文件註解
  • Ctrl + 滑鼠左鍵（Go to Declaration）：跳到方法的定義。套件的程式碼會顯示反編譯或 SourceLink 下載的原始碼
  • 游標放在括號裡，叫出 Parameter Info：顯示所有多載，例如 AddDbContext 有 6 個多載。快捷鍵依 keymap 不同：Visual Studio keymap 是 Ctrl+Shift+Space，IntelliJ keymap 是 Ctrl+P
  • 官方 API 文件：AddDbContext、UseSqlServer、GetConnectionString
