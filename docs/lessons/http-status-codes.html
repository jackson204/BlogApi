1. 狀態碼是什麼

狀態碼是伺服器回應第一行的三位數字，用來告訴用戶端「這次請求的結果是哪一種」。用戶端先看這個數字，再決定要不要讀後面的內容。

HTTP/1.1 404 Not Found            ← 第一行：協定版本、狀態碼、說明文字
Content-Type: application/json    ← header
                                  ← 空一行
{"error":"找不到這筆資料"}          ← 內容（body），可以沒有

數字後面的 Not Found 只是給人看的說明文字，程式判斷結果時只看數字。

有狀態碼，用戶端才不用去讀內容猜結果：同樣是收到一段 JSON，200 代表它是要的資料，404 代表它是錯誤說明。

2. 第一位數字分五類

範圍意思用戶端接下來該做什麼
1xx處理中的通知平常寫 API 幾乎不會碰到
2xx成功照常使用回應
3xx要的東西在別的地方，或你手上的還能用照回應的指示去另一個網址，或用自己留著的那一份
4xx用戶端送來的請求有問題改請求再送。原樣重送只會得到一樣的結果
5xx伺服器自己出錯請求沒有錯，不用改。等伺服器修好或晚一點再試

最重要的是分清楚 4xx 是送的人的問題，5xx 是伺服器的問題。寫 API 的人選錯這兩類，用戶端就會往錯的方向找原因。

3. 常用的狀態碼

狀態碼意思典型情況
200 OK成功，內容就是要的資料查詢資料
201 Created成功，而且新增了一筆資料新增。通常附一個 Location header，寫新資料的網址
204 No Content成功，沒有內容要回修改、刪除
301 Moved Permanently這個網址永久搬到別處網站改網址。新網址寫在 Location header
302 Found這一次先去另一個網址登入後導回原本的頁面
304 Not Modified你手上那一份還是最新的，不重傳瀏覽器快取，見「HTTP 快取」
400 Bad Request請求的格式或內容不對必填欄位沒填、JSON 寫壞了
401 Unauthorized不知道你是誰沒登入、登入過期
403 Forbidden知道你是誰，但你不能做這件事一般使用者呼叫管理員的功能
404 Not Found沒有這個網址，或這筆資料不存在網址打錯、查一筆已經刪掉的資料
405 Method Not Allowed網址有，但不接受這個動詞對只接受 GET 的網址送 POST
409 Conflict請求本身沒錯，但和現有的資料衝突註冊時帳號已經有人用了
500 Internal Server Error伺服器的程式出錯程式丟出沒有人處理的例外
503 Service Unavailable伺服器暫時沒辦法服務維護中、負載太高

狀態碼有幾十個，寫 API 平常用到的就是上面這些。其餘的遇到再查：MDN：HTTP 狀態碼。

4. 容易選錯的幾組

失敗了卻回 200

✗ 不建議：一律回 200，錯誤寫在內容裡

HTTP/1.1 200 OK

{"success":false,"error":"找不到資料"}

用戶端要先讀內容、再看 success 才知道失敗了。瀏覽器的開發人員工具、監控工具、快取都只看狀態碼，會把它當成成功。

✓ 建議：狀態碼就說出結果

HTTP/1.1 404 Not Found

{"error":"找不到資料"}

只看第一行就知道失敗，而且知道是哪一種失敗。內容留給補充說明。

401 和 403

401 Unauthorized403 Forbidden
伺服器知道你是誰嗎不知道知道
用戶端該做什麼去登入，登入後再送一次登入也沒用，這個帳號就是不能做

401 的英文是 Unauthorized，意思卻是「還沒驗證身分」，不是「沒有權限」。沒有權限是 403。

404 和 405

404 Not Found405 Method Not Allowed
網址存在嗎不存在（或那筆資料不存在）存在
問題在哪路徑動詞
用戶端該檢查什麼網址有沒有打錯、編號對不對GET、POST、PUT、DELETE 有沒有選錯

405 的回應通常帶一個 Allow header，列出這個網址接受哪些動詞。

400 和 500

400 Bad Request500 Internal Server Error
誰的問題送請求的人伺服器的程式
誰要修用戶端改請求寫 API 的人改程式

判斷方法：同一個請求，把內容改對之後會不會成功。會就是 400，不管怎麼送都失敗就是 500。使用者輸入錯誤造成的失敗回 500，寫 API 的人會收到一堆其實不用修的錯誤通知；程式的錯回 400，用戶端會白白去檢查自己送的資料。

5. 小實驗：一個小網站，每條路徑回一種狀態碼

不用開專案，一個 .cs 檔就能起網站（.NET 10）。下面的輸出都是實際執行的結果。

status-lab.cs

// 第一行：告訴 SDK 這是 Web 專案，不然沒有 WebApplication 這些型別
#:sdk Microsoft.NET.Sdk.Web
#:property PublishAot=false

var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

// 2xx：成功
app.MapGet("/items", () => Results.Ok(new[] { "apple", "banana" }));                 // 200
app.MapPost("/items", (Item item) => Results.Created("/items/3", item));            // 201
app.MapDelete("/items/1", () => Results.NoContent());                               // 204

// 3xx：要去別的地方拿
app.MapGet("/old-items", () => Results.Redirect("/items"));                         // 302

// 4xx：用戶端送來的請求有問題
app.MapGet("/search", (string? keyword) =>
    keyword is null ? Results.BadRequest("keyword 必填") : Results.Ok(keyword));    // 400 或 200
app.MapGet("/me", () => Results.Unauthorized());                                    // 401
app.MapGet("/admin", () => Results.StatusCode(403));                                // 403
app.MapGet("/items/99", () => Results.NotFound());                                  // 404
app.MapPost("/items/duplicate", () => Results.Conflict("名稱已經存在"));            // 409

// 5xx：伺服器自己出錯
app.MapGet("/boom", string () => throw new InvalidOperationException("程式出錯了")); // 500

// 失敗卻回 200 的寫法（不建議）
app.MapGet("/fake", () => Results.Ok(new { success = false, error = "找不到資料" })); // 200

app.Run("http://localhost:5061");

public record Item(string Name);
# 放在任何「沒有 .csproj」的資料夾
dotnet run status-lab.cs

另開一個終端機，用 curl -i 送請求。-i 會把回應的第一行和 header 一起印出來；Windows 的 PowerShell 裡要打 curl.exe。

curl.exe -i http://localhost:5061/items
curl.exe -i http://localhost:5061/items/99
curl.exe -i -X DELETE http://localhost:5061/items/1

POST 要帶 JSON 內容，在命令列要處理引號，用 Postman 這類工具送比較方便。

每條路徑的結果（只列第一行、相關的 header 和內容）：

GET    /items               → HTTP/1.1 200 OK                     ["apple","banana"]
POST   /items               → HTTP/1.1 201 Created                Location: /items/3     {"name":"cherry"}
DELETE /items/1             → HTTP/1.1 204 No Content             沒有內容
GET    /old-items           → HTTP/1.1 302 Found                  Location: /items
GET    /search              → HTTP/1.1 400 Bad Request            "keyword 必填"
GET    /search?keyword=a    → HTTP/1.1 200 OK                     "a"
GET    /me                  → HTTP/1.1 401 Unauthorized
GET    /admin               → HTTP/1.1 403 Forbidden
GET    /items/99            → HTTP/1.1 404 Not Found
POST   /items/duplicate     → HTTP/1.1 409 Conflict               "名稱已經存在"
GET    /boom                → HTTP/1.1 500 Internal Server Error
GET    /fake                → HTTP/1.1 200 OK                     {"success":false,"error":"找不到資料"}

值得看的幾條：

  • /search 沒帶 keyword 是 400，帶了就是 200。同一個網址，把請求改對就成功，這就是 4xx 的意思
  • /boom 不管怎麼送都是 500，問題在伺服器的程式
  • /fake 的第一行和 /items 一模一樣都是 200 OK，只看狀態碼分不出它其實失敗了
  • /old-items 用瀏覽器打開會直接看到 /items 的內容，因為瀏覽器看到 302 會自動去 Location 寫的網址。curl 預設不會跟著去，所以看得到 302 本身

程式裡沒有寫，伺服器自己回的狀態碼

上面每一條都是程式自己決定回什麼。下面這幾個請求沒有任何一行程式處理，狀態碼是框架回的：

GET  /nothing               → HTTP/1.1 404 Not Found              沒有任何一條路徑是 /nothing
PUT  /items                 → HTTP/1.1 405 Method Not Allowed     Allow: GET, POST
POST /items  內容是 {name   → HTTP/1.1 400 Bad Request            JSON 寫壞了，轉不成 Item

PUT /items 的回應帶了 Allow: GET, POST：/items 這個網址存在，但只接受這兩個動詞。

6. 以 ASP.NET Core 為例：哪些是框架自動回的

狀態碼誰決定的什麼情況
200、201、204程式處理請求的方法回傳什麼，就是什麼
404程式或框架程式：找不到那筆資料，自己回 404。框架：沒有任何方法對應這個路徑
405框架路徑有方法對應，但沒有一個接這個動詞
400程式或框架程式：自己檢查出資料不對。框架：送來的內容轉不成方法要的參數
401、403框架設定了登入和權限檢查之後，沒通過檢查的請求由框架擋下
500框架處理請求的方法丟出例外，沒有人接住

看到一個狀態碼，先分辨是自己的程式回的還是框架回的，再決定去哪裡找原因：自己回的去看那個方法，框架回的去看網址、動詞、送出的內容，或是啟動時的設定。
