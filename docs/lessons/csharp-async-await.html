1. 「等」有兩種等法

程式常常要等：等資料庫回資料、等檔案讀完、等網路回應。這一節用「等 1 秒」當例子，先寫最直接的等法，看等的那 1 秒裡執行緒在做什麼，再換成另一種等法。執行緒（thread）是實際在跑程式碼的那個東西，一條執行緒同一時間只能做一件事。

程式裡的顏色：藍色是這一步要看的那一行。兩個程式都印「從開始經過幾毫秒」和「現在是哪一條執行緒在跑」。

第 1 步：Thread.Sleep，停在原地等

using System.Diagnostics;

var sw = Stopwatch.StartNew();

Log("開始等");
Thread.Sleep(1000);
Log("等完了");

// 印出：經過幾毫秒、現在是哪一條執行緒在跑
void Log(string msg)
{
    Console.WriteLine($"[{sw.ElapsedMilliseconds,5} ms] 執行緒 {Environment.CurrentManagedThreadId}：{msg}");
}

// 輸出：
// [    0 ms] 執行緒 2：開始等
// [ 1005 ms] 執行緒 2：等完了

前後都是執行緒 2。它在 Thread.Sleep(1000) 那一行停了 1 秒，這 1 秒裡它什麼都沒做，也不能去做別的事。這種等法叫卡住等（同步）。

第 2 步：只換一行，改成 await Task.Delay

其他都不動，只把等的那一行換掉：

using System.Diagnostics;

var sw = Stopwatch.StartNew();

Log("開始等");
await Task.Delay(1000);
Log("等完了");

void Log(string msg)
{
    Console.WriteLine($"[{sw.ElapsedMilliseconds,5} ms] 執行緒 {Environment.CurrentManagedThreadId}：{msg}");
}

// 輸出：
// [    0 ms] 執行緒 2：開始等
// [ 1010 ms] 執行緒 5：等完了

一樣等了 1 秒，但「等完了」是執行緒 5 印的。原本的執行緒 2 在等的那 1 秒沒有停在原地，它被放走了；1 秒到了，由另一條執行緒接著跑剩下的部分。這種等法叫放掉等（非同步）。

為什麼在乎這個：一條執行緒同一時間只能做一件事。伺服器同時進來 100 個請求，每個都卡住等 1 秒，就要 100 條執行緒停在原地；放掉等的話，幾條執行緒就能輪流照顧 100 個請求。Web API 裡的方法幾乎都寫成放掉等的版本，原因就是這個。（這一段是說明，這頁沒有用 100 個請求實測。）

2. Task：一件還在做的事的收據

上一節那一行 await Task.Delay(1000) 裡有兩樣東西：Task.Delay(1000) 回傳的東西，和前面的 await。這一節從一個普通的方法開始，一步一步把它改成放掉等的版本，看 Task 是在哪一步、為了什麼出現的。

程式裡的顏色：藍色是這一步多出來或換掉的寫法，綠色是呼叫的地方跟著變的寫法，紅色是編譯不過的寫法。每一步的輸出和錯誤訊息都實際執行過。

第 1 步：普通的方法，回傳 string

string title = LoadTitle();
Console.WriteLine(title);

string LoadTitle()
{
    Thread.Sleep(500);              // 假裝去資料庫讀，要 0.5 秒
    return "Docker 入門";
}

// 輸出：
// Docker 入門

呼叫 LoadTitle()，0.5 秒後拿到一個 string。方法裡用的是第 1 節的卡住等。

第 2 步：本體換成 await Task.Delay，編譯不過

照第 1 節的做法，把 Thread.Sleep(500) 換成 await Task.Delay(500)：

string LoadTitle()
{
    await Task.Delay(500);
    return "Docker 入門";
}

error CS4032: await' 運算子只可用在非同步方法中。請考慮以 'async' 修飾元標記此方法，並將其傳回類型變更為 'Task<string>'。

訊息開頭少一個引號，是編譯器實際印出來的樣子。它要求兩件事：方法標上 async、回傳型別改成 Task<string>。下面一次做一件。

第 3 步：加上 async，還是不過

async string LoadTitle()
{
    await Task.Delay(500);
    return "Docker 入門";
}

error CS1983: 非同步方法的傳回類型必須為 void、Task、Task<T>、task-like 類型、IAsyncEnumerable<T> 或 IAsyncEnumerator<T>

async 是修飾詞，告訴編譯器「這個方法的本體裡有 await，請把本體改寫成可以暫停、再繼續的形式」。await 的錯誤消失了，換成回傳型別的錯誤。

回傳型別不能是 string 的原因：放掉等的方法碰到 await 會先暫停，回到呼叫它的人那裡。那個時候標題還沒讀到，沒有 string 可以交出去。它得先交出別的東西。

第 4 步：回傳型別改成 Task<string>，換呼叫的地方不過

string title = LoadTitle();
Console.WriteLine(title);

async Task<string> LoadTitle()
{
    await Task.Delay(500);
    return "Docker 入門";
}

error CS0029: 無法將類型 'System.Threading.Tasks.Task<string>' 隱含轉換成 'string'

方法本身編譯過了。本體的 return "Docker 入門" 沒有改，return 的還是 string。錯誤在第一行：呼叫 LoadTitle() 拿到的不再是 string，是 Task<string>。

第 5 步：用 Task<string> 接，看拿到的是什麼

Task<string> task = LoadTitle();
Console.WriteLine($"拿到 Task，IsCompleted = {task.IsCompleted}");

async Task<string> LoadTitle()
{
    await Task.Delay(500);
    return "Docker 入門";
}

// 輸出：
// 拿到 Task，IsCompleted = False

LoadTitle() 回來的時候，IsCompleted 是 False：標題還沒讀完，呼叫的人已經先拿到一個 Task<string>。它像一張收據，代表「這件事在做了，做完會有一個 string」，上面查得到做完了沒。這個程式印完這一行就結束了，標題還沒拿到。

第 6 步：await 這個 Task，拿到 string

Task<string> task = LoadTitle();
Console.WriteLine($"拿到 Task，IsCompleted = {task.IsCompleted}");

string title = await task;
Console.WriteLine($"await 之後，IsCompleted = {task.IsCompleted}，結果 = {title}");

async Task<string> LoadTitle()
{
    await Task.Delay(500);
    return "Docker 入門";
}

// 輸出：
// 拿到 Task，IsCompleted = False
// await 之後，IsCompleted = True，結果 = Docker 入門

await task 等這個 Task 變成完成，再把裡面的 string 拿出來。IsCompleted 從 False 變成 True，結果就是本體 return 的那個字串。

第 7 步：做完沒有結果的事，回傳型別寫 Task

存檔這類事情做完沒有東西要回傳。同步的寫法是 void，放掉等的版本回傳型別寫 Task，不帶角括號：

Task saving = SaveAsync();
Console.WriteLine($"拿到 Task，IsCompleted = {saving.IsCompleted}");

await saving;
Console.WriteLine($"await 之後，IsCompleted = {saving.IsCompleted}");

async Task SaveAsync()
{
    await Task.Delay(500);          // 假裝寫入，沒有東西要回傳
}

// 輸出：
// 拿到 Task，IsCompleted = False
// await 之後，IsCompleted = True

一樣是先拿到收據、await 之後變成完成，只是沒有結果可以拿。硬要接會編譯錯誤：

string x = await SaveAsync();

error CS0029: 無法將類型 'void' 隱含轉換成 'string'

方法名稱結尾的 Async 是慣例，不是語法：看到它就知道回傳的是 Task、要 await。前面的 LoadTitle 照慣例應該叫 LoadTitleAsync，這頁接下來的範例都照這個慣例命名。

七步整理

回傳型別意思方法本體 return 什麼await 之後拿到什麼
Task一件還在做的事，做完沒有結果什麼都不用 return什麼都沒有，只知道做完了
Task<string>一件還在做的事，做完會給你一個 stringreturn "…";，直接 return string一個 string

一個放掉等的方法有三個記號：

  • 回傳型別 Task<string>：呼叫的人拿到的是收據，不是 string。這是簽章的一部分，呼叫的人看得到
  • async：修飾詞，讓本體可以寫 await。它不是簽章的一部分（簽章頁第 1 節），而且本體裡有 await 的方法一定要標它，不標就是第 2 步的 CS4032
  • 本體的 return "Docker 入門"：return 的是 string。建立 Task<string> 的程式是編譯器產生的，本體裡不用寫；本體執行到 return，那個 Task 就變成完成，結果是 return 的值

3. await：等它做完，拆出結果

await 做兩件事：等這張收據變成完成，然後把結果拆出來（Task<string> 拆成 string）。關鍵在「等」的方式：碰到 await 時，如果事情還沒好，這個方法先暫停，把自己的 Task 交回給呼叫它的人，呼叫的人可以先做別的；事情好了，方法再從暫停的那一行接著跑。

下面的程式和第 2 節第 6 步做的事一樣（方法照慣例改名叫 LoadTitleAsync），原本印 IsCompleted 的地方換成六行編了號的 Console.WriteLine，用來看每一行執行的順序（實際執行過）：

Console.WriteLine("1. 呼叫 LoadTitleAsync");
var task = LoadTitleAsync();
Console.WriteLine("3. LoadTitleAsync 回來了，但事情還沒做完，先做別的");
Console.WriteLine("4. 開始 await");
var title = await task;
Console.WriteLine($"6. 拿到結果：{title}");

async Task<string> LoadTitleAsync()
{
    Console.WriteLine("2. LoadTitleAsync 開始，碰到 await 先暫停、把 Task 交回去");
    await Task.Delay(500);
    Console.WriteLine("5. 0.5 秒到了，LoadTitleAsync 從暫停的地方繼續");
    return "Docker 入門";
}

// 輸出：
// 1. 呼叫 LoadTitleAsync
// 2. LoadTitleAsync 開始，碰到 await 先暫停、把 Task 交回去
// 3. LoadTitleAsync 回來了，但事情還沒做完，先做別的
// 4. 開始 await
// 5. 0.5 秒到了，LoadTitleAsync 從暫停的地方繼續
// 6. 拿到結果：Docker 入門
sequenceDiagram participant Top as 最上層程式 participant Load as LoadTitleAsync participant Timer as Task.Delay（計時器） Top->>Load: 1. 呼叫 LoadTitleAsync() Load->>Timer: 2. await Task.Delay(500)，開始計時 Load-->>Top: 先把 Task（收據）交回去，自己暫停 Note over Top: 3. 先做別的事 Note over Top: 4. await task，等收據變成完成 Timer-->>Load: 5. 0.5 秒到了，從暫停的那一行繼續，return 結果 Load-->>Top: 6. Task 完成，await 拆出 string
2 和 3 的順序是重點：LoadTitleAsync 在 await 那行暫停，呼叫它的人先拿到收據繼續跑

注意 2 → 3：呼叫 LoadTitleAsync() 時它有開始跑（印了 2），跑到 await Task.Delay 發現要等，才暫停回來。所以 Task 不是「排隊等著被執行」，是「已經開始、停在等待的那一行」。

第 1 節的執行緒編號也能解釋了：暫停的時候執行緒被放掉；5 和 6 是由哪條執行緒接著跑，看當時誰有空。所以 await 前後不要假設是同一條執行緒。

4. 幾件事一起等：Task.WhenAll

有三件各要 1 秒的事，彼此不相關。這一節從最直接的寫法開始，量它花多久，再一步一步把時間縮短。

程式裡的顏色：藍色是這一步多出來或換掉的寫法，綠色是 await 的位置。三步用的都是同一個 LoadAsync，只在第 1 步列出來。

第 1 步：逐一 await，3 秒

using System.Diagnostics;

var sw = Stopwatch.StartNew();

var a = await LoadAsync("A");
var b = await LoadAsync("B");
var c = await LoadAsync("C");
Console.WriteLine($"花了 {sw.ElapsedMilliseconds} ms：{a}、{b}、{c}");

async Task<string> LoadAsync(string name)
{
    await Task.Delay(1000);         // 每一件都要 1 秒
    return $"{name} 好了";
}

// 輸出：
// 花了 3006 ms：A 好了、B 好了、C 好了

每一行都是「呼叫，然後馬上 await」：A 做完才呼叫 B，B 做完才呼叫 C，三個 1 秒排成一列。

第 2 步：先呼叫三次，再各自 await，1 秒

第 2 節看過，呼叫一個 async 方法會先拿到 Task，不 await 也可以。那就把呼叫和 await 拆開：先把三件事都呼叫出去，拿到三個 Task，再回頭一個一個 await：

Task<string> ta = LoadAsync("A");
Task<string> tb = LoadAsync("B");
Task<string> tc = LoadAsync("C");
Console.WriteLine($"三個都呼叫完了，才過 {sw.ElapsedMilliseconds} ms");

var a = await ta;
var b = await tb;
var c = await tc;
Console.WriteLine($"花了 {sw.ElapsedMilliseconds} ms：{a}、{b}、{c}");

// 輸出：
// 三個都呼叫完了，才過 3 ms
// 花了 1004 ms：A 好了、B 好了、C 好了

呼叫的是同一個方法、一樣三次，差別只在 await 的位置。三次呼叫總共只花 3 ms，因為每一次都在 Task.Delay 那一行暫停、把 Task 交回來，三個計時器幾乎同時開始算。所以總共是 1 秒，不是 3 秒。

第 3 步：三個 await 合成一個，Task.WhenAll

第 2 步要寫三行 await、用三個變數接結果。Task.WhenAll 收好幾個 Task，回傳一個新的 Task，等到全部做完它才完成，只要 await 一次：

Task<string> ta = LoadAsync("A");
Task<string> tb = LoadAsync("B");
Task<string> tc = LoadAsync("C");

string[] all = await Task.WhenAll(ta, tb, tc);
Console.WriteLine($"花了 {sw.ElapsedMilliseconds} ms：{string.Join("、", all)}");

// 輸出：
// 花了 1004 ms：A 好了、B 好了、C 好了

Task.WhenAll(ta, tb, tc) 回傳的是 Task<string[]>，await 之後拿到一個陣列，三個結果照傳進去的順序排好。時間和第 2 步一樣是 1 秒。

這不是「開三條執行緒」：三件事都在等計時器，等的期間不需要執行緒停在原地（這一句是說明，這頁沒有量執行緒的數量）。什麼時候該這樣寫：幾件事彼此不相依（B 不需要 A 的結果）才能一起呼叫出去；B 要用到 A 的結果時，只能像第 1 步那樣先 await A。

5. 常見的坑

五個常見的寫錯方式。每一個都先寫出有問題的版本，看它實際印出什麼，再改成對的版本。

程式裡的顏色：紅色是有問題的那一行，藍色是修正時改的地方。

忘了 await：程式不等它

呼叫 SaveAsync()，但前面沒有寫 await：

Console.WriteLine("開始");
SaveAsync();
Console.WriteLine("結束");
await Task.Delay(1500);             // 只是讓程式晚 1.5 秒結束

async Task SaveAsync()
{
    await Task.Delay(1000);
    Console.WriteLine("SaveAsync 做完了");
}

// 編譯警告：
// warning CS4014: 因為未等候此呼叫，所以在呼叫完成之前會繼續執行目前的方法。請考慮將 'await' 運算子套用至呼叫的結果。
// 輸出：
// 開始
// 結束
// SaveAsync 做完了

「結束」印在「SaveAsync 做完了」前面。沒有 await，最上層的程式拿到 Task 就繼續往下跑，沒有等它。編譯器有發現，印了警告 CS4014，但警告不會擋住執行。（同一個檔案沒有修改就再跑一次，dotnet run 不會重新編譯，這行警告也不會再印。）

把最後那行 await Task.Delay(1500) 拿掉，情況更糟：

Console.WriteLine("開始");
SaveAsync();
Console.WriteLine("結束");

// 輸出：
// 開始
// 結束

「SaveAsync 做完了」沒有印出來：程式在 SaveAsync 做完之前就結束了。

修正只要加一個字：

Console.WriteLine("開始");
await SaveAsync();
Console.WriteLine("結束");

// 輸出：
// 開始
// SaveAsync 做完了
// 結束

順序對了，警告也沒有了。

忘了 await：例外不見了

這次被呼叫的方法會丟例外，外面用 try/catch 包著，但一樣忘了 await：

try
{
    FailAsync();
    Console.WriteLine("try 區塊跑完了");
}
catch (Exception ex)
{
    Console.WriteLine($"catch 到：{ex.Message}");
}

await Task.Delay(500);
Console.WriteLine("程式結束，沒有人接到那個例外");

async Task FailAsync()
{
    await Task.Delay(100);
    throw new InvalidOperationException("存檔失敗");
}

// 輸出（編譯時一樣有 CS4014 警告）：
// try 區塊跑完了
// 程式結束，沒有人接到那個例外

catch 什麼都沒接到，程式也沒有中斷。這是最難找的那種 bug：存檔沒成功，卻沒有任何錯誤訊息。

例外去哪裡了？把 FailAsync() 回傳的 Task 放進變數，過 0.5 秒再看它：

Task task = FailAsync();
Console.WriteLine($"剛呼叫完：IsFaulted = {task.IsFaulted}");

await Task.Delay(500);
Console.WriteLine($"0.5 秒後：IsFaulted = {task.IsFaulted}");
Console.WriteLine($"Task 的 Exception 屬性裡的訊息：{task.Exception!.InnerException!.Message}");

// 輸出：
// 剛呼叫完：IsFaulted = False
// 0.5 秒後：IsFaulted = True
// Task 的 Exception 屬性裡的訊息：存檔失敗

例外有發生，它被記在那個 Task 上：IsFaulted 變成 True，Exception 屬性裡查得到訊息。（task.Exception 的型別是 AggregateException，方法裡丟的那個 InvalidOperationException 在它的 InnerException 屬性，所以要多點一層；後面的 ! 是告訴編譯器「這裡不是 null」。）前一個程式沒有用變數接那個 Task，也沒有 await，所以沒有任何人去看它。

修正一樣是加上 await：

try
{
    await FailAsync();
    Console.WriteLine("try 區塊跑完了");
}
catch (Exception ex)
{
    Console.WriteLine($"catch 到：{ex.Message}");
}

await Task.Delay(500);
Console.WriteLine("程式結束");

// 輸出：
// catch 到：存檔失敗
// 程式結束

await 遇到 IsFaulted 的 Task，會把記在上面的例外丟出來，catch 就接得到了。

例外在 await 那一行才丟出來

上一個坑看到：呼叫 FailAsync() 那一行不會丟例外，await 才會。平常寫 await FailAsync()，兩件事在同一行，沒有差別。把呼叫和 await 分開寫時（第 4 節第 2、3 步就是），try 包錯行就接不到：

Task task;
try
{
    task = FailAsync();            // try 只包住呼叫這一行
    Console.WriteLine("try 區塊跑完了，沒有例外");
}
catch (InvalidOperationException ex)
{
    Console.WriteLine($"catch 到：{ex.Message}");
    return;                        // 結束程式
}

await task;                        // 例外在這一行丟出來，這一行不在 try 裡
Console.WriteLine("這行印不到");

async Task FailAsync()
{
    await Task.Delay(100);
    throw new InvalidOperationException("存檔失敗");
}

// 輸出（程式直接結束）：
// try 區塊跑完了，沒有例外
// Unhandled exception. System.InvalidOperationException: 存檔失敗
//    at Program.<<Main>$>g__FailAsync|0_0() in …\pitfall-throws.cs:line 19
//    at Program.<Main>$(String[] args) in …\pitfall-throws.cs:line 13
//    at Program.<Main>(String[] args)

堆疊的第二行指到第 13 行，就是 await task 那一行。修正是把 try 移到 await 那一行：

Task task = FailAsync();
Console.WriteLine("呼叫完了，沒有例外");

try
{
    await task;
    Console.WriteLine("這行印不到");
}
catch (InvalidOperationException ex)
{
    Console.WriteLine($"catch 到：{ex.Message}");
}

// 輸出：
// 呼叫完了，沒有例外
// catch 到：存檔失敗

規則：try 要包住的是 await 那一行，不是呼叫方法那一行。

.Result：變回卡住等

Task<string> 有一個 Result 屬性，不寫 await 也拿得到結果：

using System.Diagnostics;

var sw = Stopwatch.StartNew();
Console.WriteLine($"執行緒 {Environment.CurrentManagedThreadId}：開始等");
var title = LoadTitleAsync().Result;
Console.WriteLine($"執行緒 {Environment.CurrentManagedThreadId}：{title}，等了 {sw.ElapsedMilliseconds} ms");

async Task<string> LoadTitleAsync()
{
    await Task.Delay(1000);
    return "Docker 入門";
}

// 輸出：
// 執行緒 2：開始等
// 執行緒 2：Docker 入門，等了 1006 ms

結果拿得到，但執行緒編號前後都是 2：它停在 .Result 那一行 1 秒，和第 1 節第 1 步的 Thread.Sleep 一樣是卡住等。沒有結果的 Task 對應的寫法是 .Wait()，實測也一樣，前後都是執行緒 2。

改回 await：

var title = await LoadTitleAsync();

// 輸出：
// 執行緒 2：開始等
// 執行緒 5：Docker 入門，等了 1007 ms

等完之後換成執行緒 5，執行緒 2 在等的時候被放掉了。在 Console 程式裡，.Result 只是讓一條執行緒白白停著；在有畫面的程式（WinForms、WPF）裡會整個卡死，這頁沒示範。原則：拿到 Task 就 await，不要 .Result、.Wait()。

async void：例外讓整個程式結束

第 2 節第 3 步的錯誤訊息裡，async 方法允許的回傳型別有一個是 void。寫寫看：

try
{
    FireAndForget();
    await Task.Delay(500);
    Console.WriteLine("這行印不到");
}
catch (Exception ex)
{
    Console.WriteLine($"catch 到：{ex.Message}");
}

async void FireAndForget()
{
    await Task.Delay(100);
    throw new InvalidOperationException("async void 裡的例外");
}

// 輸出（程式直接結束）：
// Unhandled exception. System.InvalidOperationException: async void 裡的例外
//    at Program.<<Main>$>g__FireAndForget|0_0() in …\pitfall-asyncvoid.cs:line 15
//    at System.Threading.Tasks.Task.<>c.<ThrowAsync>b__124_1(Object state)
//    …

外面有 try/catch，還是整個程式結束。想照前面的做法加上 await，編譯不過：

await FireAndForget();

error CS4008: 無法等候 'void'

回傳 void 的方法沒有交出 Task。呼叫的人沒有東西可以 await，例外也沒有 Task 可以記。和「忘了 await」比：那個例外至少還記在 Task 上，查得到；async void 的例外直接讓程式結束，try/catch 接不到。

修正是把回傳型別改成 Task，呼叫的地方加上 await：

try
{
    await FireAndForget();
    await Task.Delay(500);
    Console.WriteLine("這行印不到");
}
catch (Exception ex)
{
    Console.WriteLine($"catch 到：{ex.Message}");
}

async Task FireAndForget()
{
    await Task.Delay(100);
    throw new InvalidOperationException("async void 裡的例外");
}

// 輸出：
// catch 到：async void 裡的例外

方法名稱和例外的文字都沒有改，只換了藍色那兩個地方。

async 方法的回傳型別一律寫 Task 或 Task<T>。async void 只有事件處理常式那種「語法規定必須是 void」的地方才用。

五個坑整理

  • 呼叫 async 方法但忘了 await：程式不等它就往下走，編譯器給 CS4014 警告。忘了 await：程式不等它
  • 忘了 await 的方法丟了例外：例外只記在 Task 上，catch 接不到，也沒有錯誤訊息。忘了 await：例外不見了
  • 以為例外在呼叫時就會丟：await 那一行才丟出來，try 要包住 await。例外在 await 那一行才丟出來
  • 用 .Result 或 .Wait() 拿結果：變回卡住等。.Result：變回卡住等
  • async void：沒有 Task 可以 await，例外直接讓整個程式結束。async void：例外讓整個程式結束

6. 練習：單檔程式

和前兩頁一樣用單檔程式（file-based apps）：建 async-lab.cs，在那個資料夾執行 dotnet run async-lab.cs。

題 1：await 一個、逐一 await 三個、一起等三個

需求，三小步都在同一個檔案，用 Stopwatch 量每一步花多久：

  1. 寫方法 Task<string> LoadTitleAsync(int id)：await Task.Delay(1000) 假裝讀 1 秒，回傳「文章 1」這種字串。呼叫一次並 await，印結果和耗時
  2. 逐一 await 三次（id 1、2、3），印三個結果和總耗時
  3. 先呼叫三次拿到三張 Task，用 Task.WhenAll 一起等，印三個結果和總耗時

💡 提示：第 3 步 Task.WhenAll 可以直接把三個呼叫寫在括號裡，await 之後拿到的是 string[]。

✅ 驗收：(1) 約 1 秒；(2) 約 3 秒；(3) 約 1 秒，三個結果都在

參考答案（寫完再打開）

async-lab.cs

using System.Diagnostics;

var sw = Stopwatch.StartNew();

Console.WriteLine("== (1) await 一個 Task<string>");
var one = await LoadTitleAsync(1);
Console.WriteLine($"{one}（{sw.ElapsedMilliseconds} ms）");

Console.WriteLine("== (2) 逐一 await 三個");
sw.Restart();
var t1 = await LoadTitleAsync(1);
var t2 = await LoadTitleAsync(2);
var t3 = await LoadTitleAsync(3);
Console.WriteLine($"{t1} / {t2} / {t3}（{sw.ElapsedMilliseconds} ms）");

Console.WriteLine("== (3) Task.WhenAll 一起等");
sw.Restart();
string[] titles = await Task.WhenAll(LoadTitleAsync(1), LoadTitleAsync(2), LoadTitleAsync(3));
Console.WriteLine($"{string.Join(" / ", titles)}（{sw.ElapsedMilliseconds} ms）");

async Task<string> LoadTitleAsync(int id)
{
    await Task.Delay(1000);                 // 假裝去資料庫讀，要 1 秒
    return $"文章 {id}";
}

輸出（實際執行）

== (1) await 一個 Task<string>
文章 1（1007 ms）
== (2) 逐一 await 三個
文章 1 / 文章 2 / 文章 3（3001 ms）
== (3) Task.WhenAll 一起等
文章 1 / 文章 2 / 文章 3（1000 ms）

兩個觀察：

  • (2) 和 (3) 呼叫的是同一個方法、各三次，差別只在 await 的位置：每次都 await 是 3 秒，先拿三張收據再一起等是 1 秒
  • (3) 的 Task.WhenAll(…) 括號裡三個呼叫是依序執行的，但每個都在 Task.Delay 那行就暫停回來，所以三個計時器幾乎同時開始
